# 股权交易法律尽职调查报告（编排入口）

> **来源**：案例库 LWC-2026-0005（国有控股中外合资企业股权交易尽调，354 份资料，125 页报告 + 问题清单 + 编制说明）。律师复核稿，人审待回填；本技能固化流程与检查清单，不固化该案结论。
> 单份合同审查用 `contract-review`；本技能面向**整个目标公司**的资料室尽调。

---

## 目的

把「资料室 → 分章底稿 → 报告」做成可溯源、可覆盖审计、可换模型续写的流程。重大发现要能回到文件与页码；交易结构未知造成的结构性局限要被显式标注，而不是被通用措辞掩盖。

---

## 前置条件：加载审查立场

读取 `commercial-legal/CLAUDE.md`。配置缺失或含 `[PLACEHOLDER]` 时按 `contract-review` 的「临时模式」处理，默认：律师角色、平衡型、中国法律体系。尽调报告的立场由委托方身份决定（投资方 / 受让方 / 贷款人），来自指令而非配置。

## 动态事项确认（先读材料，后提问）

执行 `shared/legal-document-intake/SKILL.md`，并按 `shared/references/due-diligence-playbook.md` 第 1 节判定：

- **阻断项**：委托方身份与报告受众；参考稿 / 模板的使用规则（哪些段落不得参考，版式沿用范围）；
- **交易结构**（受让哪一方股权、比例、是否增资、是否取得控制权）：会改变国资程序、外资程序、经营者集中、优先购买权与控制权变更条款分析。可考虑开工前用一个问题澄清；未答时按「一般情形」继续并列为 `deferred_items` 首项，受影响章节逐章注明；
- **可后置项**：基准日 / 出具日期占位；联网外部检索许可（默认不联网并在报告中声明）。

本类任务为正式对外报告，`execution_profile` 默认 `critical`，开工前必须输出 `INTAKE_DECISION`。LWC-2026-0005 读取了 intake 却未输出决策，是已记录的流程缺口。

## 入口级护栏

- **特殊主体即专章**：目标公司或股东为国资、外商投资企业、上市公司时，报告必须有交易程序章节，依据见 `transaction-procedure-citations.md`。
- **核心经营资源依赖提示**：经营权 / 特许、核心资产租赁、融资三者中两项以上来自同一控股股东体系时，摘要合并提示「控制权变更后可能同时失去支撑」，不得分散在三章各说一句。
- **原件核对**：子代理 / OCR 底稿只用于定位；章程条文、决议版本、委派日期、文号、金额由主笔回原件核对后才进报告。
- **数字勾稽**：金额用两个以上独立来源；只有一个来源时写明；假设性测算（如滞纳金）列假设与敏感性。
- **条号来源**：合资合同条号与章程条号不得混用；取不到原文的地方规定与部门文件不写条号。
- **外部检索声明**：未做企业信用、裁判文书、执行、信用中国核验时在方法说明中声明并进问题清单。
- **个人信息**：含身份证号的底稿留内部目录；发送包正则检查。

## 输出

由 `dd-report-issue-list` 组装三件：

1. **尽调报告**（律师复核稿）：沿用参考稿章节与版式；管理层摘要从正文倒推；每章「法律评析」小节；
2. **问题清单**：补充资料 / 待说明（事实矛盾）/ 需律师决定三分类；
3. **编制说明**：工作流程、资料来源对照、计算方法、已纠正错误、法条核验表。

交付说明列占位符、外部检索与独立复核执行情况；成稿恒标「律师复核稿」。

# 资料室清点与覆盖审计（data-room-inventory）

> **前置**：读取 `shared/references/due-diligence-playbook.md` 第 2、4 节，按其 schema 输出。
> 可被 `equity-transaction-dd/SKILL.md` 编排入口调用，也可通过 `「子技能：data-room-inventory」章节（见本文档）` 单独触发。

---

## 目的

资料室常见 300–500 个文件，重复、多版本、扫描件混杂。没有清单就没有覆盖审计，没有覆盖审计就不能说「资料已全部审阅」。LWC-2026-0005 的覆盖审计发现 6 份未引用的资质证照，补写后暴露了许可证延续申请的时效问题。

---

## 详细步骤

### 步骤 1：递归清点与去重

- 递归遍历全部子目录；每个文件计算 sha256 与大小；
- sha256 相同 → `duplicates_of`；同名不同哈希 → **两个版本**，都保留并在步骤 3 标记版本关系；
- 聚合指纹 = 各文件 sha256 排序后清单的 sha256（供案例库，不入库原文）。

### 步骤 2：提取路径与个人信息

| 类型 | 提取 | 备注 |
|---|---|---|
| docx / xlsx / pptx | 直接读取 | doc / xls 先转换 |
| 有文本层 PDF | pdftotext | — |
| 扫描 PDF / 图片 | OCR，后台任务 | 只用于定位；影响结论的内容由主笔回原件 |
| 加密 / 损坏 | `unreadable` | 进问题清单「补充资料」 |

含身份证号、住址、银行账号的文件标 `contains_pii: true`，其底稿与文本镜像放内部目录。

### 步骤 3：分章映射

默认章节（按目标公司情况增删）：

| 章节 | 典型文件 |
|---|---|
| 01 主体与历史沿革 | 营业执照、登记档案、历次变更、批准证书 |
| 02 股权与出资 | 出资证明、验资 / 审计、股东名册、股权质押 |
| 03 章程与治理 | 历版章程、合资合同、股东会 / 董事会决议、委派函 |
| 04 资质与许可 | 行业许可、特许经营、经营权合同、认证 |
| 05 资产与租赁 | 不动产权证、租赁合同、租金支付凭证、设备清单 |
| 06 重大合同 | 客户、供应商、框架协议、关联交易合同 |
| 07 融资与担保 | 借款 / 委贷合同、征信报告、担保、还款计划 |
| 08 劳动用工 | 花名册、社保、外包 / 派遣合同（交叉引用 employment 对照表） |
| 09 税务与财务 | 审计报告、月报、纳税证明、处罚 |
| 10 诉讼仲裁与处罚 | 判决、裁决、调解书、处罚决定、信用报告 |
| 11 关联交易 | 关联方清单、交易合同、定价依据 |
| 12 其他（环保 / 安全 / 保险 / 知识产权） | 按行业 |

同一文件可映射多章；版本关系（如章程 2019 版 / 2023 版）在章节内并列记录。

### 步骤 4：清单输出

按 playbook 第 2 节 schema 输出 YAML / 表格，并给统计：文件总数、去重后数、按类型与章节分布、OCR 文件数与页数、`unreadable` 数。

### 步骤 5：覆盖审计（装配前复跑）

1. 取底稿全部 `sources.file_id`，与清单比对；
2. 未引用文件逐个标注：无关（写原因）/ 漏读（补底稿）/ 需补章节（补报告）；
3. 输出 `referenced / unique_files` 与未引用清单，交 `dd-report-issue-list` 写入编制说明。

# 分章事实底稿（chapter-fact-memos）

> **前置**：
> 1. 读取 `shared/references/due-diligence-playbook.md` 第 3 节 schema；
> 2. 读取 `data-room-inventory` 的清单与章节映射；
> 3. 子代理参与时，先下发统一规则文件（见步骤 4）。
>
> 可被 `equity-transaction-dd/SKILL.md` 编排入口调用，也可通过 `「子技能：chapter-fact-memos」章节（见本文档）` 单独触发。

---

## 目的

底稿是报告唯一的事实来源。LWC-2026-0005 在撰写与自查阶段共纠正 10 处错误（章程「缺句」误判、同编号决议两个版本、委派函实际日期早一年、文号笔误、释义表主体全称错误、合资合同与章程条号混用、分项加总错误等），全部靠回原件与重算发现，结构指标一个都发现不了。

---

## 详细步骤

### 步骤 1：各章事实清单

| 章节 | 必须提取的事实 | 常见陷阱 |
|---|---|---|
| 主体与沿革 | 设立日期、历次名称 / 住所 / 法定代表人 / 经营范围变更、登记机关 | 批准证书与营业执照日期不一致 |
| 股权与出资 | 各股东持股、出资方式与实缴、出资期限、质押 / 冻结 | 认缴未届期；国资登记日期 |
| 章程与治理 | 现行章程条文（表决、转让、优先购买、委派）、历版差异处数、决议清单与版本 | **两版章程差异数要逐条数**；同编号决议多版本；为备案重新出具的委派函日期 ≠ 实际委派日 |
| 资质与许可 | 许可名称、编号（脱敏）、有效期、延续申请截止日 | 截止日早于报告出具日 |
| 资产与租赁 | 权属、租赁期限、租金标准、**实际支付记录**、欠付与滞纳金计算口径 | 支付凭证只覆盖部分期间；滞纳金为合同约定测算 |
| 重大合同 | 相对方、期限、金额、控制权变更 / 转让限制条款、是否届满未续 | 经营权合同届满未续签 |
| 融资与担保 | 本金、利率、到期日、担保、**12 个月内到期金额** | 合同 / 征信 / 月报三方勾稽 |
| 劳动用工 | 人数口径、外包 / 派遣比例、所属单位 | 用 `dispatch-vs-outsourcing-checklist.md` |
| 税务与财务 | 净资产、营收、处罚、补税 | 当年审计数与下年年初数核对 |
| 诉讼仲裁与处罚 | 案件、金额、状态、原告主体（公司 vs 工会） | 调解结案金额；主体识别 |
| 关联交易 | 关联方、交易类型、金额、定价 | 与控股股东体系的经营依赖 |

### 步骤 2：底稿条目规则

按 playbook schema 逐条记录。强制字段：`sources`（file_id + locator）、`evidence_kind`、`confidence`、`verified_by_author`。

- 条号写明出自哪份文件：「合资合同第 X 条」与「章程第 Y 条」分开；
- 释义表中的主体全称以营业执照 / 批准证书为准，一次定稿全文复用；
- 同一事实多个来源不一致 → `conflicts_with` + 进问题清单「待说明」；
- 日期优先取台账 / 原始凭证，其次决议，最后备案材料。

### 步骤 3：数字勾稽

| 数字 | 来源 A | 来源 B | 来源 C |
|---|---|---|---|
| 借款余额 | 借款合同 | 征信报告 | 财务月报 |
| 应收 / 应付 | 明细表 | 月报 | 审计报告 |
| 年度财务数据 | 当年审计报告 | 下年审计报告年初数 | — |
| 欠付租金 | 合同租金标准 × 期间 | 支付凭证 | 对账 / 访谈口径 |

只有一个来源时在报告中写明「仅据 X」；假设性测算（滞纳金、违约金）列假设、公式与敏感性，并注明「按合同条款与访谈口径测算」。表格分项加总必须重算。

### 步骤 4：子代理分工

- 适合子代理：OCR、分章摘录、清单比对、覆盖审计；
- 统一规则文件：禁止联网；禁止修改原始资料；只补缺口；更正须在原处注明；输出按 schema；
- 并发上限由操作员设定；接口限流中断时按章节重派，不重做已落盘章节；
- **子代理底稿一律 `evidence_kind: summary`**，影响结论的事实由主笔回原件后改 `original_viewed`。

### 步骤 5：落盘

每章一个文件（如 `03-章程与治理.md` / `.yaml`），放仓库外内部目录；报告只引用 `fact_id`。上下文压缩后从底稿续写。

- [ ] 影响结论的事实 `verified_by_author: true`

# 交易程序核查（transaction-procedure-check）

> **前置**：
> 1. 读取 `chapter-fact-memos` 的股权、章程、合资合同、重大合同、融资底稿；
> 2. 读取 `../_shared/transaction-procedure-citations.md`（锚点与验证状态）；
> 3. 读取 `shared/references/subject-qualification-traps.md`（国企 / 上市公司 / 外商投资企业）；
> 4. 每一处条文经 `shared/research-gate/SKILL.md` 取官方原文核对现行版本。
>
> 可被 `equity-transaction-dd/SKILL.md` 编排入口调用，也可通过 `「子技能：transaction-procedure-check」章节（见本文档）` 单独触发。

---

## 目的

交易程序章节是投资方最先翻的章节之一，也是最依赖交易结构的章节。本子技能把「谁转给谁、多少比例、是否取得控制权」拆成可核查的程序路线，并在结构未知时诚实地按一般情形写。

---

## 详细步骤

### 步骤 1：主体属性矩阵

| 维度 | 取值 | 决定 |
|---|---|---|
| 转让方属性 | 国有及国有控股 / 外资 / 民营 / 上市公司 | 国资程序；外资程序；信息披露 |
| 目标公司属性 | 中外合资 / 内资 / 国有控股 | 合资合同与章程关系；国资登记 |
| 受让方属性 | 境内 / 境外；是否已持股 | 负面清单；集中申报；优先购买权 |
| 交易结构 | 受让存量 / 增资 / 混合；比例；是否取得控制权 | 几乎所有程序 |

交易结构未知 → 本章开头写「以下按一般情形分析，待交易结构确认后更新」，并在问题清单「需律师决定」列明。

### 步骤 2：程序路线核查

| 路线 | 核查点 | 锚点（见引用文件） | 常见发现 |
|---|---|---|---|
| 国资交易 | 是否属于国有产权转让 / 增资；评估与核准备案；进场交易或非公开协议转让的条件；国资登记状态 | 《企业国有资产交易监督管理办法》 | 国资登记日期晚于设立；非公开转让条件 |
| 外商投资过渡 | 合资合同是否随《外商投资法》修订；过渡期届满后组织形式与章程调整；原合营合同约定的股权转让办法可否继续适用 | 《外商投资法实施条例》第 44、46 条（已核实） | **未修订的合资合同与新章程并存且冲突** |
| 负面清单与信息报告 | 行业是否在负面清单；变更后信息报告义务 | 现行《外商投资准入特别管理措施（负面清单）》；《外商投资信息报告办法》 | 清单版本按年度核对 |
| 经营者集中 | 营业额是否达申报标准；是否取得控制权 | 《国务院关于经营者集中申报标准的规定》第 3 条 | 门槛数值按现行版本 |
| 优先购买权与章程限制 | 有限公司股东优先购买权；章程另有规定；合资合同一致同意条款 | 《公司法》（2023 修订）股权转让条款；章程；合资合同 | 章程与合资合同口径不一致 |
| 认缴出资 | 认缴期限与过渡期；未届期出资转让的责任 | 《公司法》（2023 修订）及过渡期规定 | 2027-06-30 前调整 |
| 上市公司 | 转让方 / 受让方为上市公司时的决策与信息披露 | 上市公司信息披露规则 `[待验证]` | 股东会权限 |
| 控制权变更触发 | 经营权 / 特许合同、核心资产租赁、委贷与担保中的控制权变更、股权变动通知与解除条款 | 合同原文 | 经营权合同届满未续 + 租赁欠付 + 委贷 12 个月内到期 **同时**来自控股股东体系 |
| 行业许可 | 控制权变更是否触发许可重新审批或备案 | 行业规章 `[待验证]` | 许可到期日 |

### 步骤 3：合资合同 vs 章程

逐条对照股权转让、表决、董事委派、利润分配、终止条款：

| 事项 | 合资合同第 X 条 | 章程第 Y 条 | 冲突 | 现行法处理 |
|---|---|---|---|---|

结论用条件句：「若按合资合同约定……；若按章程……」，并引用实施条例第 46 条口径说明过渡安排 `[待律师复核]`。

### 步骤 4：输出

- 「交易程序路线表」：程序 / 是否适用（是 / 否 / 取决于交易结构）/ 核查结论 / 依据与验证状态 / 待补；
- 「控制权变更触发条款表」：合同 / 条款 / 触发条件 / 后果 / 建议；
- 对经营资源依赖控股股东体系的目标公司，在摘要合并提示。

## 目的

交付三件而不是一件：报告给结论，问题清单给动作，编制说明给可信度。律师据编制说明判断哪些数字可以直接用、哪些要再查。

## 详细步骤

### 步骤 1：报告正文

- 章节与版式沿用参考稿；参考稿中被排除（标黄）的段落不得参考；沿用的既有表格在问题清单说明「系律师此前检索结果，本次未独立核验」；
- 每章结构：事实（引用 `fact_id`）→ 法律评析 → 风险等级 → 建议；
- 交易结构未知的章节开头注明「按一般情形」；
- 条件句与【待核实】用于未回原件核对或单一来源的事实；
- 释义表以 `chapter-fact-memos` 定稿的主体全称为准。

### 步骤 2：管理层摘要

从正文倒推，按风险等级排序，每行注明正文位置。经营资源依赖控股股东体系的提示合并为一行。摘要不得出现正文没有的结论。

### 步骤 3：问题清单三分类

| 分类 | 条目来源 |
|---|---|
| 补充资料 | `data-room-inventory` 的 `unreadable` 与缺失文件；底稿「需补」 |
| 待说明（事实矛盾） | 底稿 `conflicts_with`；访谈口径与文件不一致 |
| 需律师决定 / 复核 | 交易结构、联网检索许可、按通行文本引用未下载原文的条文、测算假设 |

每项：编号 / 事项 / 来源章节 / 影响 / 建议动作。

### 步骤 4：编制说明

1. 工作流程（清点 → 底稿 → 程序核查 → 装配，含子代理分工与规则）；
2. 资料来源对照表（章节 ↔ 主要 `file_id`）；
3. 计算方法（每个测算的公式、假设、来源）；
4. 已纠正错误清单（发现方式：回原件 / 重算 / 交叉比对）；
5. 法条核验表（法规 / 条文 / 版本 / 核验来源 / 状态）；
6. 覆盖审计结果（`referenced / unique_files`，未引用文件及解释）；
7. 未执行事项（外部检索、独立复核）。

### 步骤 5：成稿与 QA

按 `document-delivery-qa.md`：参考稿 DOCX 作包模板 + DSL 生成正文；渲染两次回填目录页码；逐页检查表格与分页；OOXML 校验；发送包正则检查身份证号；内部底稿分目录。

### 步骤 6：交付说明与复核状态

交付说明：占位符（出具日期、尽调期间）、三件文件清单与指纹、外部检索声明、结构指标（仅作解释）。随后按 `shared/legal-document-intake/SKILL.md` 输出 `REVIEW_STATUS`；未做独立复核写 `skipped` 与原因。

### 步骤 7：补充资料第二版

补充资料到达时：单独清点 → 逐份写「对报告的影响」→ 更新受影响 `fact_id` 与章节 → 输出「补充资料核查及修订说明」+ 问题清单第二版；文件名带版本号，不覆盖第一版。
