> **迁移说明**：本子技能包含原 contract-review/SKILL.md 中的「主体资格预检」「交易破坏者检查」「逐项对比」风险识别部分，以及「违约金/责任限制四维识别」和「管辖法律差异检查」中的识别部分。

## 目的

对照团队实践配置文件，从以下四个维度对合同逐条识别风险，输出按严重性分级的风险清单：

1. **主体资格风险** — 合同主体是否具备相应资格（担保权限、代表权限、外汇登记等）
2. **条款偏离风险** — 合同条款偏离审查立场的程度（交易破坏者/高风险/中风险/低风险）
3. **法律强制性风险** — 是否违反民法典强制性规定（如第506条免责无效、第497条格式条款无效）
4. **可执行性风险** — 在合同适用的管辖法律下，特定条款是否可执行

## 详细步骤

### 第一步：定位合同基本信息

快速扫描合同，建立定位表：

| 问题 | 回答 |
|------|------|
| 合同类型 | 买卖合同 / 技术服务合同 / 租赁合同 / 合作协议 / 其他 |
| 我方立场 | 甲方（买方/委托方）/ 乙方（卖方/受托方） |
| 对方当事人 | 名称 + 类型（大公司/中小企业/个人） |
| 合同金额 | 总价/年费（若未写明，见「合同金额处理」） |
| 合同期限 | 期限长度 + 续约机制 |
| 涉及数据处理 | 是（个人信息/重要数据）/ 否 |
| 涉及担保 | 保证/抵押/质押/无 |
| 适用法律/管辖 | 合同约定的管辖法律和争议解决方式 |

**合同金额处理**：先从订单、附件和计价公式归纳金额。若金额只影响审批路由而不影响风险识别，可标记「金额未确认，升级路由待律师判断」并继续。只有金额会改变责任限制、修订策略或当前审批结论且无法推断时，才按 `shared/legal-document-intake/SKILL.md` 询问。

### 第二步：主体资格预检

**对照 `shared/references/subject-qualification-traps.md`**，若合同存在以下情形，**优先核查主体资格**：

| 情形 | 核查内容 | 依据 |
|------|---------|------|
| 担保条款/保证条款 | 担保人是否有权出具（融资担保公司、银行分支机构、上市公司等） | subject-qualification-traps.md |
| 上市公司为一方 | 对外担保是否有董事会/股东会决议 | 民法典第504条 `[待验证]` |
| 国企/事业单位为一方 | 是否有国资委审批或内部决策程序 | 国资监管规则 `[待验证]` |
| 银行分支机构为担保方 | 是否有总行授权文件 | 民法典第504/506条 `[待验证]` |
| 外商投资企业对外担保 | 是否有外汇局备案/登记 | 外汇管理条例 `[待验证]` |

**主体资格问题处理**：若发现问题，在风险清单顶部显著标记，并评估对合同效力的影响。

### 第三步：交易破坏者检查

优先扫描实践配置文件中「交易破坏者」条款（绝不可接受）。若存在，立即标记：

```markdown
## 存在交易破坏者

**第 [X.X] 条** 包含 [交易破坏者名称]。根据团队审查立场，这是硬性的「不」。

- 建议修改：[具体替代表述]
- 对方不让步：放弃，不签

详细风险识别见下文，但此问题不解决，其他识别结果参考意义有限。
```

### 第四步：逐条风险识别

对照实践配置文件，逐条扫描合同，对每个偏离生成识别块：

```markdown
### [第 X.X 条]：[问题名称]

**我方立场（引自实践配置文件）：** [具体立场]

**合同写的是：**
> "[原文引用]"

**偏离类型：** 缺失条款 | 弱于标准 | 弱于备选 | 非典型结构 | 不可接受

**法律风险：** 🔴 关键 | 🟠 高 | 🟡 中等 | 🟢 低
**商业摩擦：** 🔴 阻碍交易 | 🟠 拖慢交易 | 🟡 造成困惑 | 🟢 无感

**为什么重要：** [一到两句白话 — 若保持原样，业务会出什么问题]

**法律依据标签：** [相关法条来源标签，见法律依据子技能输出]
```

**风险等级校准：**

| 等级 | 法律风险含义 | 商业摩擦含义 |
|------|------------|------------|
| 🔴 关键 | 交易破坏者或绝不接受清单条款 | 阻碍交易进行 |
| 🟠 高 | 超出备选范围，强烈推动 | 拖慢谈判/交易 |
| 🟡 中等 | 在备选范围内但未达标准 | 造成日后执行困惑 |
| 🟢 低 | 明确容忍，或纯形式偏离 | 基本无感 |

### 第五步：违约金/责任限制四维识别

**针对责任限制/违约金条款，必须完成以下四个维度**（不得仅写「检查责任限制」）：

**维度 1 — 直接损失 vs 间接损失：**
- 限制是否适用于所有责任，还是仅直接损失？
- 明确陈述两种处理的不同立场

**维度 2 — 基数定义（逐字引用）：**
- 引用合同中「限制金额」的确切表述
- 判断属于哪种基数：(a) 索赔前12个月已付费用；(b) 当前12个月应付费用；(c) 合同总价；(d) 其他
- 若不明确，标记：「基数定义不明确 — [原文] — 可能意味着 [X] 或 [Y]，签署前确认」

**维度 3 — 例外交互：**
- 列举哪些在限制之外（例外），哪些在限制之内
- 评估被限制表面是否有意义：「限制覆盖 [一般违约]，数据泄露/IP/保密例外」

**维度 4 — 与审查立场的对应：**
- 对照配置文件中每个维度的立场（直接限制倍数、间接损失处理、例外清单、基数偏好）

### 第六步：管辖法律差异核查

**在按字面接受审查立场前，核查以下管辖差异：**

| 事项 | 民法典规定 | 核查要点 | 验证状态 |
|------|----------|---------|---------|
| 竞业限制 | 劳动合同法第23-24条（期限≤2年，需支付补偿） | 各地司法实践有差异 | `[管辖法律 — 需验证]` |
| 自动续约格式条款 | 民法典第496条对格式条款有特别规定 | 消费者合同有额外保护 | `[管辖法律 — 需验证]` |

### 第二步：遵循成文法优先原则

**分析基础**：每个法律依据产出必须首先援引现行成文法。

**操作顺序：**
1. 从 `civil-code-contract-citations.md` 检索相关条文（民法典合同编 + 司法解释）

## 详细步骤

### 第一步：确认修改范围

若已有 risk-identification 输出，直接使用其风险条款列表作为修改范围。若单独触发，先运行风险识别（读取步骤见 本文档「子技能：risk-identification」章节）。

确认：
- 修改范围是「全部偏离条款」还是律师指定的特定条款
- 对方当事人类型（大公司 vs 中小企业，影响修改策略和预期）
- 当前谈判阶段（首轮 vs 最后一轮，影响粒度选择）

### 第二步：应用修改粒度原则

**以尽可能小的粒度修改。** 修订是谈判工具，不是重写。Wholesale 替换发出「我们扔掉了你的草稿」的信号；精细修订发出「我们有具体要求」，更容易被接受。

**修改粒度层级（从小到大）：**

| 粒度层级 | 适用场景 | 谈判信号 |
|---------|---------|---------|
| **词** | 单个词语不准确或有歧义 | 最精细，对方感知到被认真阅读 |
| **短语** | 需要补充修饰或替换表述 | 精确，显示具体诉求 |
| **子条款** | 需要重组逻辑或调整结构 | 中等，仍保留对方框架 |
| **句子** | 整句意思与立场冲突 | 较大改动，需说明理由 |
| **整条款** | 对方草稿与立场相差太远 | 最大改动，须主动说明：「我们替换了第X.X条，因为改动范围很大，很高兴带你过一遍差异」 |

**默认选择规则**：
1. 替换一个**词**优先于短语
2. 替换一个**短语**优先于句子
3. 重组一个**子条款**优先于替换句子
4. 替换一个**句子**优先于替换整条款
5. 仅当对方版本与立场相差太远，精细修改比新草稿更难阅读时，才替换整条款

**拿不准时，选更小的粒度。**

### 第三步：生成逐条修改建议

对每个需要修改的条款，生成完整修改建议块：

```markdown
### 修改建议：[第 X.X 条] [条款名称]

**风险等级：** 🔴/🟠/🟡/🟢 [来自风险识别]
**修改粒度：** 词 / 短语 / 子条款 / 句子 / 整条款

**原文：**
> "[合同中原文完整引用]"

**问题：** [一句话说明偏离类型和影响]

**建议修改（[粒度]级）：**
> "[具体替换语言 — 可直接粘贴，用删除线和加粗示意修改位置]"

**修改说明：** [简短说明为何这样修改，引用法条或审查立场]

**如果对方不让步：**
> [来自实践配置文件的备选方案；若无备选，说明「升级到 [人员]」或「可考虑接受，需标注风险」]

**法律依据：** [关键法条引用，来源标签 + 待验证标注，详见 legal-basis 子技能]
```

### 第四步：处理特殊条款类型

**格式条款修改**（对方提供标准合同时）：
- 按民法典第498条，格式条款有争议时作不利于提供方的解释，修改建议须明确
- 提示对方：本条按第498条解释对提供方不利，建议明确表述以避免争议
- 来源：`[模型知识 — 需验证]` `[待验证]`

**违约金/责任限制修改**：
- 按四维分析（来自 risk-identification）针对性修改
- 若需分别修改直接损失限制和间接损失排除，生成两个独立的修改建议
- 明确基数定义的替换语言

**免责条款修改**（涉及民法典第506条）：
- 若条款属于无效免责（人身损害或重大过失），说明「按民法典第506条，本条款无效，无需谈判」
- 若仍需修改以明确约定（如限制至法定最低标准），生成合规替换语言

### 第五步：汇总修改包

在逐条修改建议之后，汇总「修改包」供律师统一传递：

```markdown
## 修改包汇总

以下为本次审查建议的所有修改，已按条款顺序排列，可直接传递给对方。

| 条款 | 风险等级 | 修改粒度 | 摘要 |
|------|---------|---------|------|
| 第X.X条 | 🔴 | 句子级 | [一句话摘要] |
| 第X.X条 | 🟠 | 短语级 | [一句话摘要] |
| ...  | ... | ... | ... |

**传递说明**（根据实践配置文件 ## 文书风格 中的修订语气）：[建议的传递语气/方式]
```

## 检查清单

- [ ] 每个修改建议都有具体替换语言（不是模糊的「建议修改」）
- [ ] 修改粒度已选择最小可行粒度（不过度替换）
- [ ] 整条款替换时已附说明（「替换原因 + 愿意带对方过差异」）
- [ ] 每个修改建议都有「如果对方不让步」的处理（来自配置文件或说明需升级）

## 目的

从实践配置文件中的审查立场出发，将风险识别结果转化为可操作的谈判路线图：

1. **硬底线**（交易破坏者）— 绝不让步的核心条款
2. **让步空间**（可接受备选）— 可在谈判中灵活应对的范围
3. **交易筹码**（有利条款）— 对方给了比标准更多的条款，可用于在其他地方换取让步
4. **谈判节奏建议**（对方类型适应）— 大公司 vs 中小企业的差异策略

## 详细步骤

### 第一步：从审查立场推导谈判三层次

**层次 1 — 硬底线（交易破坏者）**

从实践配置文件「交易破坏者（The one thing）」条款提取：
- 这些是绝不接受的条款
- 谈判策略：坚持，不让步，若对方坚持则考虑放弃交易
- 谈判措辞建议：「这是我们法务合规方面的硬性要求，不在谈判范围内」

**层次 2 — 让步空间（可接受备选）**

从实践配置文件「可接受的备选」提取：
- 这是审查立场的底线范围，可在谈判中让步至此
- 谈判策略：先推标准立场，对方反对则退至备选
- 谈判措辞建议：「我们的首选是 [X]，如果这对你有困难，我们可以接受 [备选]」

**层次 3 — 交易筹码（有利条款）**

从风险识别中「优于我方标准」的条款提取：
- 对方已经给了比我方要求更多的条款
- 谈判策略：不主动提出，留作在其他条款上换取让步
- 记录：「第X.X条对方给了我们比标准更多的条款，这是谈判资本」

### 第二步：对方类型差异化策略

**大公司（标准合同，改动空间小）：**

| 策略维度 | 应对思路 |
|---------|---------|
| 整体姿态 | 接受大框架，精准推动核心风险条款修改 |
| 修改范围 | 聚焦 🔴🟠 风险条款，🟡🟢 非关键时可接受 |
| 传递方式 | 以「法律合规要求」包装硬底线（更难拒绝） |
| 升级信号 | 大公司联系人若无权改，请求升级决策层 |
| 预期管理 | 知会业务方：某些条款可能无法改，需提前了解风险 |

**中小企业（灵活，愿意协商）：**

| 策略维度 | 应对思路 |
|---------|---------|
| 整体姿态 | 全面推动，对方通常比大公司更灵活 |
| 修改范围 | 所有偏离条款均可推动修改 |
| 传递方式 | 解释商业逻辑（共赢），对方更容易理解接受 |
| 风险提示 | 注意中小企业可能存在主体资格、偿付能力风险 |
| 预期管理 | 可能因谈判时间较长影响交易节奏 |

### 第三步：谈判顺序规划

**建议的谈判顺序（优先级）：**

1. 先解决交易破坏者（若存在），否则继续审查意义不大
2. 解决 🔴 关键风险条款（法定无效或绝不接受清单）
3. 推动 🟠 高风险条款（超出备选范围）
4. 在其他条款上让步，换取 🟠 条款的让步
5. 🟡 中等风险在「最后一轮」时可接受
6. 🟢 低风险不花谈判资本

### 第四步：升级路由建议

检查实践配置文件中的升级矩阵，对照：
- 合同金额与审批权限阈值
- 是否存在任何 🔴 关键问题
- 自动升级触发条件（无限责任、知识产权转让、境外管辖等）

```markdown
## 审批路由建议

基于 [金额/风险等级]，本协议需要：

- [ ] **[姓名/角色]** 审批 — [原因]
- [ ] **业务负责人确认** — [具体商业条款需确认]

**建议下一步：** [发送修订给对方 | 升级到合伙人后再回复 | 先获取业务方对X条款的意见]
```

### 第五步：谈判路线图汇总

```markdown
## 谈判路线图

### 硬底线（不让步）

| 条款 | 底线要求 | 谈判措辞建议 |
|------|---------|------------|
| [第X.X条] | [我方坚持的最低要求] | [建议措辞] |

### 让步区间（可谈）

| 条款 | 标准立场 | 可接受底线 | 换取条件 |
|------|---------|---------|---------|
| [第X.X条] | [标准] | [备选] | [需要对方在X换取] |

### 交易筹码（对方已让步，留用）

| 条款 | 对方给的 | 用途 |
|------|---------|------|
| [第X.X条] | [有利条款] | [可换取X条款让步] |

### 建议升级

[升级路由建议]
```
