# 劳动用工合规调查报告（编排入口）

> **来源**：案例库 LWC-2026-0006（上市公司本部用工合规调查，116 份底稿，125 页报告）与 LWC-2026-0005 劳动章节的可复用经验。两案均为律师复核稿，人审待回填；本技能固化的是流程与检查清单，不是质量结论。
> 单题审查（一份劳动合同、一份竞业协议）仍用 `hiring-review` / `non-compete-review` 等技能；本技能面向**整家公司或一个用工群体**的调查报告。

---

## 目的

把「资料包 → 可复算的用工口径 → 分类定性 → 文本评析 → 报告 + 附录」做成可恢复、可溯源的流程：每个结论能回到底稿文件与页码，每个未核实事实以条件句进入正文并出现在附录清单。

---

## 前置条件：加载审查立场

读取 `employment-legal/CLAUDE.md`。配置缺失或含 `[PLACEHOLDER]` 时按 `hiring-review` 的「临时模式」规则处理，默认：风险偏好平衡型、立场为被调查公司合规视角、工作地点按资料确认。调查报告的立场由指令文件决定（公司自查 / 投资方 / 集团管理），不得从模板旧稿沿用。

## 动态事项确认（先读材料，后提问）

执行 `shared/legal-document-intake/SKILL.md`，并按 `../_shared/due-diligence-playbook.md` 第 1 节判定必答项：

- **受众与立场**：报告面向公司管理层自查，还是投资方 / 贷款人；决定措辞确定性与附录口径；
- **重点关注项**：指令文件列明的（如「假外包真派遣」「社保委托代缴」）优先；无则按本技能默认清单；
- **章节与资料夹对应**：指令文件通常规定「第三部分按资料夹分章、第二部分从正文归纳」，按其顺序执行；
- **可后置项**：尽调期间、出具日期、释义表简称、3 份以内文件的金额 / 日期识别不清 → `deferred_items`，进附录并在交付说明点名。

本类任务为正式对外报告，`execution_profile` 默认 `critical`。开工前必须输出 `INTAKE_DECISION`；指令文件 + 模板 + 资料包齐备时通常为 `ready` + `draft_mode: conditional`，不必澄清。

## 入口级护栏

- **司法解释二基准**：2025-09-01 之后的用工审查以法释〔2025〕12 号重判混同用工、变换主体续签、二倍工资、竞业限制范围与补偿、社保约定无效与补贴返还；旧结论不得沿用。
- **地方标准版本**：最低工资、社保基数、生育假天数按年度版本核对；客户文本中的旧数字是发现项，不是背景。
- **OCR 只定位**：扫描件 OCR 后台执行；识别不清的金额、日期、人名不得按推测填写，标【待核实】并进附录。
- **个人信息**：底稿含身份证号、住址时放内部目录；报告与附录只用工号或脱敏称谓；发送包做正则检查。
- **条件性表述**：代发薪人员是否构成派遣、外包人员此前是否已直接用工等推断性结论，正文用条件句并放附录前列。
- **覆盖审计**：装配前核对资料包每个文件是否被引用（playbook 第 4 节）。

## 详细步骤

### 步骤 1：资料清点与提取路径

| 文件类型 | 提取方式 | 说明 |
|---|---|---|
| xlsx / csv | 本地脚本直接读取 | 保留原列名，另建标准化列 |
| docx / doc | 文本提取 | doc 先转 docx |
| 有文本层 PDF | pdftotext 直取 | — |
| 扫描 PDF / 图片 | OCR，**后台任务** | 结果只用于定位；金额、日期、人名识别不清 → 【待核实】 |

每份文件登记 `file_id`、`sha256`、`extraction`、`chapter`（按指令文件的资料夹对应），`contains_pii` 为 true 的进内部目录。

### 步骤 2：识别三张基础表并固化口径

| 表 | 常见来源 | 关键字段 | 口径决定 |
|---|---|---|---|
| 花名册 / 劳动合同台账 | 人事系统导出、合同登记表 | 工号、姓名、用工类型、合同主体、合同期限、签订日期、工作地点、岗位 | **人员总数与用工类型的基准** |
| 社保公积金缴费表 | 当月社保 / 公积金明细 | 参保单位（自管户 / 代缴机构）、缴费基数、险种、公积金金额 | **参保主体与基数分布的基准** |
| 考勤表 | 月度考勤导出 | 工号、姓名、用工类型（如有）、出勤天数 | **实际用工在岗的基准** |
| 工资表（如有） | 薪酬导出 | 应发、实发、发放主体 | 代发薪识别、社保基数合理性 |

固化口径：

- 统计日：三表尽量取同一月份；不同月份时写明并解释差异；
- 人员键：优先工号；无工号用姓名 + 入职日期；**不以身份证号为键输出**；
- 用工类型标准化：`直签-固定 / 直签-无固定 / 直签-完成任务 / 派遣 / 外包 / 劳务 / 实习 / 返聘 / 代缴 / 代发薪 / 未知`，原始表述保留在旁列；
- 合同主体标准化：被调查公司 / 关联公司 A、B… / 人力资源机构 X、Y… / 未知。

### 步骤 3：差异矩阵

| 比对 | 发现类型 | 候选定性（交给下一步） | 需补资料 |
|---|---|---|---|
| 在社保表、不在花名册 | 代发薪 / 代缴人员不在用人单位名册 | 劳动合同主体不明 → 派遣或委托代缴 | 劳动合同样本、机构服务协议附件 |
| 在花名册、不在社保表 | 未参保、异地参保、劳务 / 实习 | 未参保风险 / 劳务关系定性 | 异地参保凭证、劳务协议 |
| 在考勤表、不在花名册 | 外包 / 派遣人员受用工方考勤 | 「名为外包实为派遣」线索 | 外包合同及补充协议 |
| 花名册类型 ≠ 考勤类型 | 劳务 vs 劳动合同记载冲突 | 事实劳动关系风险 | 两份原件 |
| 实习人数两表不一致 | 实习生口径不同 | 实习协议与学籍 | 实习协议、在校证明 |
| 合同主体 ≠ 参保主体 | 关联公司交叉用工 / 代缴 | 混同用工、变换主体续签 | 签订日期批次、调动文件 |
| 签订日期成批次 | 关联公司集中转签 | 变换主体连续订立固定期限合同 | 原合同、工龄承继约定 |
| 基数 = 下限 / 上限人数、中位数 | 基数偏低或集中下限 | 社保基数合规 | 工资表 |
| 公积金为零 | 未缴或法定例外 | 公积金合规 | 例外证明（残疾、退休返聘等） |

每条差异记录：人数、人员键清单（内部）、来源 `file_id`、候选定性、需补资料。

### 步骤 4：可复算输出

```markdown
## 用工口径表（统计日：YYYY-MM）
| 口径 | 人数 | 来源 |
|---|---|---|
| 花名册劳动合同记录 | 252（直签 248 / 派遣 4） | F-0012 |
| 劳务 / 实习 | 15 / 1 | F-0012 |
| 社保自管户 / 代缴 / 代发薪 / 派遣 | 175 / 26 / 54 / 3 | F-0031 |

| # | 差异 | 人数 | 候选定性 | 需补资料 | 来源 |
```

## 目的

把每个用工群体落到一个法律定性和一个风险等级，并说明证据来自哪份文件、还缺什么证据。定性错误会让后面所有比例、补缴和补偿结论失真，因此本步骤的每个结论都带置信度。

---

## 详细步骤

### 步骤 1：按形态逐类审查

| 形态 | 定性要件 | 典型风险 | 法源（见引用库） | 需补证据 |
|---|---|---|---|---|
| 直签-固定期限 | 合同主体 = 用工主体；期限、续签次数 | 连续两次固定期限后未签无固定（第 14 条）；满 10 年仍签固定 | 《劳动合同法》第 14 条（已核实） | 历次合同 |
| 直签-无固定 | — | 解除程序 | — | — |
| 关联公司交叉用工 | 合同主体与实际用工 / 参保主体不一致；签订日期成批次 | 混同用工责任；变换主体规避连续订立；工龄承继；二倍工资 | 法释〔2025〕12 号相关条文（G 节）；第 82 条（已核实） | 原合同、调动 / 转签文件、工龄约定 |
| 派遣 | 派遣协议 + 许可证 + 三性岗位 | 超 10% 比例；无许可；连带责任 | H 节 | 派遣协议、许可证 |
| 外包 | 对照表 12 要素 | 名为外包实为派遣；事实劳动关系 | H 节；对照表 | 商业合同、补充协议、结算单、考勤 |
| 超龄 / 退休返聘 | 是否已享受养老保险待遇（法释〔2025〕12号第 16 条）；2026-07-01 起须签书面「用工协议」、不低于最低工资、单位缴工伤保险（人社部等令第 56 号第 6、11、15 条，I 节） | 未签用工协议、未缴工伤保险；按旧 60 周岁直接终止；延迟退休到龄人员误按退休处理 | I 节 | 退休证明 / 养老金领取证明、用工协议、工伤保险缴费记录 |
| 劳务（兼职、非全日制） | 是否受考勤 / 制度管理；工时是否超非全日制上限 | 被认定全日制劳动关系 | 《劳动合同法》第 68–72 条 `[待验证]` | 劳务协议、考勤 |
| 实习 | 在校身份、实习协议、三方协议 | 毕业后继续用工 → 劳动关系 | — | 实习协议、学籍 |
| 异地委托代缴 | 劳动合同主体 = 用人单位，社保以机构名义参保 | 参保主体不一致；待遇申领与工伤认定；约定效力 | 法释〔2025〕12 号第 19 条口径（条号已核实） | 机构服务协议、员工同意书 |
| 代发薪 | **先查劳动合同主体** | 与机构签约 → 按派遣；否则回代缴 | 对照表第三节 | 劳动合同样本、机构协议附件 |
| 挂靠 | 无劳动关系却参保 | 骗取待遇风险 | 《社会保险法》第 88 条 `[待验证]` | 考勤、费用承担 |

### 步骤 2：「名为外包实为派遣」判定

按对照表逐项填「本案证据」列。LWC-2026-0006 的典型组合：商业合同名为《服务外包合同》，补充协议按人头计费、用工方决定工资与社保基数、考勤与加班费、退回机制；用工方还直接与人员签《派遣补充协议》约定试用期与工资；三方主体错位（外包合同对方为省外关联公司，劳动合同用工单位为北京机构，解除协议用上海机构）。

判定：计价 / 选人 / 指挥管理三项中两项以上呈派遣特征 → 高置信度；否则条件句。定性为派遣的人数计入派遣比例，并检查许可证与派遣协议是否提供。

### 步骤 3：关联公司交叉用工

- 从签订日期批次（如同一日成批转签）识别集中转签；
- 对连续订立固定期限合同、满 10 年工龄仍签固定期限的人员逐个列出；
- 检查工龄是否书面承继、原主体是否支付经济补偿；
- 以法释〔2025〕12 号关于变换签约主体 / 混同用工的条文为基准（条号见 G 节），不沿用 2025-09-01 前的裁判口径。

### 步骤 4：协商解除协议审查

对调查期间内（通常近 12 个月）的协商解除协议逐份列表：补偿金额与基数、是否含奖金、是否含「社保公积金补偿款」、是否含「不投诉承诺 + 违约金」、是否涉及董事 / 高管。

- 「不投诉承诺 + 违约金」与「社保补偿款」条款的效力对照法释〔2025〕12 号第 19 条口径 `[待律师复核]`；
- 这类条款与同期公积金投诉、社保稽核通知相互印证时，合并写入重大问题；
- 金额或日期识别不清（扫描件）→ 【待核实】，不填推测值。

### 步骤 5：输出

```markdown
## 用工形态分类汇总
| 形态 | 人数 | 定性 | 置信度 | 风险 | 证据 | 待核实 |
|---|---|---|---|---|---|---|
| 代发薪（异地研发 / 测试 / 销售） | 54 | 若由机构签约则为派遣（比例≈18%） | 中（条件句） | 🔴 | F-0031 | 劳动合同主体 |
| 司机「外包」 | 4 | 名为外包实为派遣 | 高 | 🔴 | F-0062、F-0063 | 派遣协议、许可证 |
```

每个条件句结论同时写入附录「待核实事项」前列。

## 目的

调查报告中的文本评析价值在于：客户文本沿用了哪些已废止的规则和旧数字，制度之间、制度与合同之间哪里冲突，哪些制度缺民主程序与公示证据。这些发现不依赖访谈，直接可核。

## 详细步骤

### 步骤 1：建立文本清单

| 类别 | 文件 | 重点 |
|---|---|---|
| 合同范本 | 固定 / 无固定期限劳动合同、完成任务合同 | 必备条款、期限、工作地点与调岗、解除条款、仲裁时效表述 |
| 专项协议 | 保密、竞业限制、培训服务期、派遣补充协议、医疗期协议、协商解除协议、实习协议、劳务协议 | 适用人员范围、补偿、违约金、旧最低工资数字 |
| 机构协议 | 派遣协议、外包合同及补充协议、代缴 / 代发薪服务协议 | 与 `workforce-classification` 对照表联动 |
| 规章制度 | 员工手册、考勤与休假、薪酬与绩效、奖惩、外包服务管理、保密与信息安全、差旅等 | 民主程序、公示签收、与合同冲突 |

### 步骤 2：以司法解释二为基准的逐条检查

| 检查项 | 常见文本问题 | 现行规则（锚点见引用库） |
|---|---|---|
| 仲裁时效 | 仍写「六十日内申请仲裁」 | 《劳动争议调解仲裁法》第 27 条：1 年（已核实） |
| 社保转移 | 写「三十日内办理转移」等废止规则 | 按现行社保转移接续办法 `[待验证]` |
| 社保约定 | 「自愿放弃」「社保补贴代缴」「异地参保视为已履行」 | 法释〔2025〕12 号第 19 条：约定无效；补缴后可请求返还补贴（条号已核实） |
| 竞业限制 | 全员竞业、无补偿、范围 / 期限超法定 | 法释〔2025〕12 号关于不负保密义务人员竞业条款、补偿与范围的条文（G 节）；《劳动合同法》第 23–24 条（已核实） |
| 连续订立 / 无固定 | 变换关联主体续签、第三次仍固定 | 《劳动合同法》第 14 条（已核实）；法释〔2025〕12 号关于变换主体的条文（G 节） |
| 二倍工资 | 未签合同期间补签倒签 | 《劳动合同法》第 82 条（已核实）；法释〔2025〕12 号关于二倍工资计算的条文（G 节） |
| 最低工资 / 病假工资 | 医疗期协议、病假制度沿用旧年度数字 | `local-rules-beijing.md` 第一、二节 |
| 生育假 | 制度写 128 天 | 现行 158 天（北京）`[管辖 flagged]` |
| 工时 | 销售 / 高管按不定时工时但无审批；综合工时批复过期 | 审批办法 + 地方规定 `[待验证]`；批复文号与有效期入附录 |
| 加班费基数 | 以基本工资为基数 | 《劳动法》加班费三档（规则已核实） |
| 解除条款 | 把「不能胜任」「严重违纪」写成单方即时解除且无程序 | 《劳动合同法》第 39–41、43 条 `[待验证]`；工会通知 |
| 违约金 | 服务期 / 竞业之外约定违约金 | 《劳动合同法》第 25 条（规则已核实） |
| 民主程序 | 制度无职工代表大会 / 工会讨论、无公示签收 | 《劳动合同法》第 4 条 `[待验证]` |
| 超龄用工 | 退休返聘仍用劳动合同范本或无书面协议；无工伤保险安排 | 人社部等令第 56 号第 6、15 条（2026-07-01，I 节） |
| 服务期 | 以学历教育为由约定服务期 / 违约金 | 法释〔2026〕14号（2026-07-30）：不得仅以第 22、25 条主张无效，超出合理比例部分综合判断（G 节配套） |
| 制度冲突 | 考勤制度与合同工时约定不一致；外包管理制度体现用工方选人 / 考勤 | 以合同优先并写入评析；后者作为派遣定性证据 |

## 目的

让律师拿到的是一份结构与版式和律所既有报告一致、每个结论可回溯、每个缺口有去处的复核稿，而不是一篇需要重排的长文。

## 详细步骤

### 步骤 1：正文（第三部分）

按指令文件章节顺序写，通常：

1. **组织架构与用工概况**：主体、关联公司、人数口径表、组织架构图（整页，留白为已知代价）；
2. **劳动人事**：用工分类汇总表 → 劳动合同与专项协议评析 → 规章制度评析 → 社保公积金（参保主体、基数分布、公积金、稽核与投诉）→ 工时与休假（审批、年休假、产假）→ 离职（协商解除协议表）；
3. **诉讼、仲裁与行政处罚**：案件表、稽核 / 处罚通知、信用报告交叉。

规则：

- 事实以底稿为准，每条可回到 `file_id`；
- 推断性结论用条件句并标【待核实】；
- 法条与地方数字只写已核实或 `[待验证]` 的版本；
- 释义表新增的简称与正文一致。

### 步骤 2：重大问题汇总（第二部分）

从正文倒推，不新增正文没有的结论。每项：

```markdown
| # | 重大问题 | 风险 | 正文位置 | 待核实 / 待补 |
|---|---|---|---|---|
| 1 | 54 名代发薪人员劳动合同主体不明，若由机构签约则派遣比例约 18% | 🔴 | 第三部分 2.1 | 附录 1、2 |
```

排序：🔴 → 🟠 → 🟡；同级按涉及人数。LWC-2026-0006 为 13 项，全部可回溯。

### 步骤 3：附录

「待核实事项及待补充资料」一表：序号 / 待核实事项 / 需提供的资料或说明。

- 来自 `deferred_items`、各子技能的【待核实】与「需补资料」；
- 「需律师决定」项在事项列以「【律师决定】」开头，保持可识别；
- 条件句结论对应的核实项放前列；
- 与正文【待核实】计数核对一致。

### 步骤 4：模板包成稿

按 `document-delivery-qa.md` 第 2 节：以模板 DOCX 为包，删除旧正文（另一客户旧稿不得残留），克隆标题 / 编号 / 表格样式，用标记语言生成正文；释义表补充简称；日期留【 】占位；目录域设 `updateFields`；表格不用固定行高、三列表按 38 / 62 等比例设宽。

### 步骤 5：QA 与覆盖审计

1. 覆盖审计（playbook 第 4 节）：资料包每个文件是否被引用，未引用者逐个解释；
2. LibreOffice 渲染逐页检查：表格截断、列宽、组织架构图、空白页、页眉页脚；
3. OOXML 校验；【待核实】计数与附录条目核对；
4. 发送包正则检查身份证号、手机号；含个人信息的底稿留内部目录。

### 步骤 6：交付说明与复核状态

交付说明列：占位符（出具日期、尽调期间、释义表待填）、目录域刷新、未执行事项（外部检索：企业信用 / 裁判文书 / 执行信息；独立模型复核）、结构指标（页数、表格数、待核实数，仅作解释）。

随后按 `shared/legal-document-intake/SKILL.md` 输出 `REVIEW_STATUS`；未做独立复核写 `skipped` 与原因。

### 步骤 7：案例库

律师反馈到达后，按 `shared/feedback-refinement/SKILL.md` 第 0 节在消费者项目 `docs/legal-ops/case-library/` 记录脱敏案例；本次成稿时先登记资料聚合指纹、覆盖率与结构指标。
