# 尽职调查 / 合规调查工作 Playbook

供 `commercial-legal/skills/equity-transaction-dd`、`employment-legal/skills/workforce-compliance-dd` 以及其他「资料室 → 分章底稿 → 报告 + 问题清单」形态的任务共用。本文件只规定**数据结构与闸门**，领域内容由各技能自带。

来源：案例库 LWC-2026-0005（股权交易法律尽调，354 份资料，125 页报告）与 LWC-2026-0006（劳动用工合规调查，116 份资料，125 页报告）的可复用经验。两案均为律师复核稿，人审结论待回填；本文件记录的是流程规则，不是质量结论。

## 1. 开工前必答与可后置

进入资料清点前执行 `shared/legal-document-intake/SKILL.md`，并把下列事项纳入 `material_missing` 判定：

| 事项 | 为何会改变成果 | 未答时的处理 |
|---|---|---|
| 委托方身份与报告受众（投资方 / 目标公司自查 / 贷款人 / 监管提交） | 决定立场、措辞确定性、问题清单口径 | 阻断，无法安全假设 |
| 交易结构（受让哪一方股权、比例、是否增资、是否取得控制权） | 决定国资程序、外资程序、经营者集中、优先购买权、控制权变更条款分析 | 可按「一般情形」继续，但每个受影响章节须注明；列为 `deferred_items` 首项 |
| 基准日 / 尽调期间 / 出具日期 | 决定资料截止、时效计算、占位符 | 可占位【 】，交付说明点名 |
| 联网外部检索许可（企业信用公示、裁判文书、执行信息、信用中国） | 决定能否做外部核验，否则须在报告中声明未执行 | 默认不联网并声明；律师可授权 |
| 参考稿 / 模板的使用规则（哪些段落不得参考、格式沿用范围） | 决定模板复刻与内容独立性 | 阻断，写错会污染成果 |
| 重点关注事项（如「假外包真派遣」「社保委托代缴」） | 决定资料优先级与章节深度 | 按指令文件；无则按领域技能默认清单 |

正式对外报告的默认执行档为 `critical`；`INTAKE_DECISION` 不得沉默跳过（LWC-2026-0005 读取了 intake skill 却未输出决策，属已记录缺口）。

## 2. 资料清单（schema）

每份文件一条，去重后形成清单。清单与指纹留在仓库外工作目录。

```yaml
- file_id: F-0001            # 稳定编号，底稿与报告只引用编号
  label: "章程-2019版"        # 脱敏标签，不含客户名
  chapter: "03-章程与治理"     # 映射到报告章节 / 资料夹
  type: pdf | doc | docx | xlsx | pptx | image | other
  sha256: "..."
  size: 123456
  pages: 24
  extraction: text | ocr | manual | unreadable   # 直取 / OCR / 人工转录 / 不可读
  status: read | pending | skipped               # skipped 必须写原因
  duplicates_of: null | F-0042                   # sha256 相同
  contains_pii: false | true                     # 身份证号、住址等；为 true 的底稿进「内部」目录
```

规则：

- 去重以 sha256 为准；文件名归一（去版本后缀、空格、全半角）只作提示。同名不同哈希是**两个版本**，不是重复——LWC-2026-0005 中同一编号的董事会决议实为两份不同落款日期、不同内容的文件。
- 扫描件 OCR 默认后台执行，不阻塞主线；OCR 结果只用于定位（见第 3 节）。
- OCR 工具（2026-10-15 调研，未在本仓实测）：本地 CPU 基线用 RapidOCR 3.10（ONNX，默认 PP-OCRv6，Apache-2.0）；复杂版面与表格用 MinerU 4（CPU 默认，Apache-2.0 附条件）或 PaddleOCR 3.7 的 PaddleOCR-VL；公章文字用 PP-OCRv6 印章模式；Rust 侧可用 oar-ocr。Marker / Surya 权重为 modified OpenRAIL-M，商业使用受限。各家均未公布中国法院文书的识别准确率，须用自有扫描案卷（案号、金额、日期）抽样评分；识别不清项仍按第 3 节规则处理。
- 资料聚合指纹 = 各文件 sha256 排序后清单的 sha256，供案例库记录。

## 3. 分章事实底稿（schema）

先写可溯源的底稿，再写报告。底稿按章节分文件落盘：两案都经历过一次上下文压缩，靠底稿文件续写。

```yaml
- fact_id: 03-017
  chapter: "03-章程与治理"
  statement: "现行章程第X条规定股权转让须经其他股东同意……"   # 脱敏陈述，不复制整段原文
  sources:
    - { file_id: F-0001, locator: "p.12 第X条" }              # 页码 / sheet!cell / 条号
  evidence_kind: original_viewed | ocr | summary | interview | public_record
  confidence: confirmed | inferred | assumed
  conflicts_with: [03-018]                                      # 与其他事实或文件矛盾
  verified_by_author: true | false                              # 主笔是否已回原件目视核对
  used_in: ["报告 3.2", "问题清单 待说明-04"]
```

硬规则：

- `evidence_kind` 为 `ocr` / `summary`（含子代理底稿）的事实，**凡影响结论、数字、条号、日期，必须由主笔回原件核对**并置 `verified_by_author: true`；未核对的只能以条件句进入报告。LWC-2026-0005 子代理底稿中四处可被原件推翻的错误（章程「缺句」误判、决议版本混同、委派函日期、文号笔误）均由此发现。
- 金额与数量尽量用两个以上独立来源勾稽（合同 / 征信 / 月报 / 审计报告 / 台账）；只有一个来源时写明；假设性测算列明假设与敏感性。
- 同一文件的多个版本须并列记录差异数量与位置，不得只取「最新」。
- 不复制员工身份证号、住址等个人信息；`contains_pii` 文件的底稿放在「内部」目录，发送包做正则检查。

## 4. 覆盖审计

报告初稿完成后、装配前执行：

1. 列出清单中 `status: read` 但未出现在任何 `sources` 的文件；
2. 逐个判定：无关（写原因）/ 漏读（补底稿）/ 需补章节（补报告）；
3. 把 `referenced / unique_files` 记入案例库。LWC-2026-0005 为 348 / 354，未引用的 6 份全部是资质证照，补写后发现许可证延续申请截止日早于报告出具日。

未做覆盖审计的报告不得写「资料已全部审阅」。

## 5. 问题清单三分类

问题清单单独成文，每项注明来源章节、影响和建议动作：

| 分类 | 含义 | 示例 |
|---|---|---|
| 补充资料 | 应当存在但资料室未提供 | 派遣协议与许可证；经营权合同后续期；租金支付凭证 |
| 待说明（事实矛盾） | 两份资料之间、或资料与访谈口径不一致 | 工商登记法定代表人与考勤表负责人不一致；花名册与考勤表用工类型不一致 |
| 需律师决定 / 复核 | 法律判断或信息不足以下结论 | 交易结构未知下的国资程序适用；按通行文本引用而未下载原文的条文 |

劳动用工类报告可以把前两类合并为「待核实事项及待补充资料」一表（序号 / 事项 / 需提供的资料或说明），但「需律师决定」项仍须可识别。

## 6. 报告装配

- **先正文后摘要**：重大问题汇总 / 管理层摘要从正文倒推，每项注明正文位置；摘要不得出现正文没有的结论。
- **确定性一致**：核心前提未核实时，正文、摘要与批注使用同一确定程度（条件句 + 【待核实】），不得出现「正文确定、批注待核实」（LWC-2026-0002）。
- **按一般情形**：交易结构等必答项未答时，受影响章节开头注明「以下按一般情形分析，待交易结构确认后更新」。
- **外部检索声明**：未执行企业信用、裁判文书、执行信息等外部核验时，在前言 / 方法说明中声明，并列入问题清单。
- **编制说明**（可选的第三件交付物）：工作流程、资料来源对照、计算方法、已纠正错误、法条核验表，律师据此快速判断可信度。
- **文档交付**：按 `shared/references/document-delivery-qa.md` 做模板复刻、渲染 QA 与发送包隐私检查。

## 7. 子代理与多模型分工

- 原始资料 OCR、分章摘录、覆盖审计比对适合子代理并行；结论性事实、法条与数字由主笔回原件和原文核对。
- 子代理统一规则文件：禁止联网、禁止修改原始资料、只补缺口、更正须在原处注明；并发上限由操作员设定。
- 正式对外报告在律师复核前应有一次不同模型的独立盲审，并按 `shared/legal-document-intake/SKILL.md` 输出 `REVIEW_STATUS`。两案均未执行，属已记录的流程缺口，不得因此省略状态输出。

## 8. 交付包检查

- 发送包不含身份证号、手机号等个人信息（正则检查）；内部底稿分目录；
- 占位符（出具日期、尽调期间、释义表简称）在交付说明中逐项点名；
- 目录域刷新提示；【待核实】/【待律师复核】计数；
- 案例库记录：资料聚合指纹、覆盖率、结构指标、未决事项（见消费者项目 `docs/legal-ops/case-library` 约定）。
