# 冷启动访谈（编排入口）

> **迁移说明**：原冷启动访谈内容（基本信息、审查立场、地方性规定、文书风格四部分）已拆分迁移至四个可独立触发的访谈子技能。本文件为编排入口，支持整体运行完整访谈或单独重跑某一部分配置更新。子技能路径：`employment-legal/skills/cold-start-interview/<子技能名>/SKILL.md`。
>
> **纠正说明**：访谈结果**填充 `employment-legal/CLAUDE.md` 对应章节**（散文模板，律师可读可编辑，可 git 版本控制），**不生成独立 YAML 文件**。每次访谈子技能运行后，更新 `employment-legal/CLAUDE.md` 的对应章节，其他章节不受影响。

## 目的

通过结构化的访谈流程，将律师/HR 的执业立场、风险偏好、升级矩阵和文书风格写入 `employment-legal/CLAUDE.md`，使所有劳动人事技能能够个性化运行。

访谈结果直接写入：

- `## 我们是谁` / `## 谁在使用` / `## 可用集成` ← identity-team
- `## 审查立场`（雇佣/解雇/竞业） ← review-stance
- `## 风险校准` / `## 升级矩阵` ← risk-escalation
- `## 文书风格` / `## 输出` / `## 共享护栏 → 地方性规定识别` ← style-local-rules

## 遵循契约

本编排入口及四个访谈子技能遵循 `../_shared/practice-profile-schema.md` 定义的字段映射契约，确保：

1. 所有字段写入到 `employment-legal/CLAUDE.md` 的正确章节
2. 用户口述的法律事实（条款号/金额/期限）在写入前经过合理性检查
3. 访谈支持重跑/单独更新/直接编辑/git 版本控制

## 访谈总流程概览

1. 运行 `identity-team` → 填充身份与团队信息（约 1-2 分钟）
2. 运行 `review-stance` → 确认审查立场（约 2-3 分钟）
3. 运行 `risk-escalation` → 设置风险校准与升级矩阵（约 1-2 分钟）
4. 运行 `style-local-rules` → 选择文书风格与地方性规定（约 1-2 分钟）

整体访谈约 5-10 分钟。完成后，`employment-legal/CLAUDE.md` 的所有 `[PLACEHOLDER]` 替换为实际配置，所有劳动人事技能可据此个性化运行。

## 入口级护栏

### 写入前法律事实合理性检查

在每个子技能将用户口述的法律事实写入 `employment-legal/CLAUDE.md` 之前，须对照 `../_shared/practice-profile-schema.md` §6 的合理性检查规则进行校验。主要检查点：

- 竞业限制期限不超过 2 年（《劳动合同法》第24条，已核实）
- 经济补偿 2N 仅适用于违法解除（第87条，已核实）
- 仲裁时效为 1 年（《劳动争议调解仲裁法》第27条，已核实）
- 其他用户口述条款号/金额/期限标注 `[前提 flagged — 需验证]`

### 重跑与单独更新说明

| 场景 | 操作方式 |
|------|---------|
| 服务对象发生变化（如从专做用人单位方转为兼做劳动者方） | 单独重跑 `「子技能：review-stance」章节（见本文档）` |
| 更换主要工作地点 | 单独重跑 `「子技能：style-local-rules」章节（见本文档）` |
| 升级矩阵人员变动 | 单独重跑 `「子技能：risk-escalation」章节（见本文档）` |
| 直接编辑 CLAUDE.md | 直接编辑即可，无需重跑访谈 |
| git 版本控制 | `git log --oneline employment-legal/CLAUDE.md` 查看历史；`git diff HEAD~1 employment-legal/CLAUDE.md` 查看变更 |

### 临时模式

如果用户不想运行完整访谈，可在任何劳动人事技能中说**「临时模式」**，系统将使用 `practice-profile-schema.md` §3.3 定义的临时默认值运行，并在输出上标记 `[临时模式 — 配置你的档案以获得定制输出]`。

## 访谈问题清单

### 第一部分：基本身份（收集 → 写入 `## 我们是谁`）

**Q1. 你们的公司/律所名称是什么？实体类型是？**

> 写入：`## 我们是谁` → 公司/律所名称、实体类型

可选类型：企业（国有/私营/外资）/ 律所 / 政府法务 / 其他

---

**Q2. 你们的 HR/劳动法团队规模大约是多少人？（包括律师/HR/法务）**

> 写入：`## 我们是谁` → HR/劳动法团队规模

参考量级：1-3人（小团队）/ 4-10人（中型）/ 10人以上（大型）/ 外部法律顾问（无内部团队）

---

**Q3. 最终升级联系人是谁？（处理超出常规范围事务时需要联系的人）**

> 写入：`## 我们是谁` → 最终升级联系人

格式：姓名 + 职位 + 联系方式（如：张总监 / 法务总监 / 内部邮件）

---

**Q4. 每月大约处理多少件雇佣/劳动相关事务？**

> 写入：`## 我们是谁` → 每月处理雇佣事务数量

帮助系统理解工作量和个性化提示频率。

---

**Q5. 你们主要处理哪种类型的雇佣关系？**

> 写入：`## 我们是谁` → 主要雇佣类型

可多选：全职劳动合同 / 兼职 / 劳务派遣 / 实习 / 独立承包人（非劳动关系）/ 混合

---

**Q6. 主要工作地点在哪里？（决定地方性规定的应用）**

> 写入：`## 我们是谁` → 主要工作地点
> **同步写入** `## 共享护栏` → `### 地方性规定识别` 中勾选对应地区

可选：北京 / 上海 / 广州 / 深圳 / 其他（请指定：__）/ 多地点（请列出主要地点）

> **合理性提示**：主要工作地点将触发以下地方性规定识别：社保基数、竞业限制补偿指引、产假奖励假天数、陪产假天数、婚丧假标准等。如有多个工作地点，建议列出主要地点以便逐一标记。

---

**Q7. 你们目前最大的劳动用工痛点是什么？**

> 写入：`## 我们是谁` → 最大痛点

开放式，帮助系统理解重点场景，例如：频繁的劳动争议 / 合规文件管理 / 复杂的绩效辞退流程 / 竞业限制执行难 / 多地点合规差异。

---

### 第二部分：使用者角色（收集 → 写入 `## 谁在使用`）

**Q8. 主要使用者是什么角色？**

> 写入：`## 谁在使用` → 角色

可选：劳动法律师 / HR 法务（有律师可咨询）/ HR（无法律背景，无律师可咨询）/ 法务人员 / 混合团队

> **规则说明**：
> - **律师**：所有输出标注「律师工作产物 — 受律师-当事人特权保护/保密」
> - **非律师但有律师可咨询**：输出标注「研究笔记 — 非法律建议，供律师审查」，在具有法律后果的步骤（签署文件、发出解除通知等）前暂停
> - **非律师且无律师可咨询**：同上，额外添加「建议在重大决定前咨询执业律师」提示

---

**Q9. 系统主要联系的律师是谁？（如适用）**

### 第二部分：雇佣审查立场（收集 → 写入 `## 审查立场 → ### 雇佣审查`）

**Q2. 关于试用期审查，你们的标准立场是什么？**

> 写入：`## 审查立场` → `### 雇佣审查` → `#### 试用期` → 标准立场 + 特殊情况

合理性检查基准（《劳动合同法》第19条，已核实）：
- 合同期限 3个月以上不满1年 → 试用期最长 1 个月
- 1年以上不满3年 → 最长 2 个月
- 3年以上及无固定期限 → 最长 6 个月

典型立场选项：
- 用人单位方：「按合同期限在法定上限内约定，倾向约定至上限」
- 劳动者方：「核实是否超过法定上限，超过部分无效，另支付工资差额」

**Q3. 关于工时制度，你们通常使用哪种工时制？审查立场是什么？**

> 写入：`## 审查立场` → `### 雇佣审查` → `#### 工时制度`

| 工时制类型 | 说明 |
|----------|------|
| 标准工时制 | 每日不超过8小时，每周不超过40小时（行政法规规定） |
| 综合计算工时制 | 须经劳动行政部门批准，适用特殊行业 `[待验证]` |
| 不定时工时制 | 须经劳动行政部门批准，适用特殊岗位 `[待验证]` |

合理性提示：「综合计算工时制/不定时工时制须经劳动行政部门批准；未经批准自行约定，加班费计算仍按标准工时制处理 `[前提 flagged — 需验证]`」

---

**Q4. 关于社会保险，你们的标准立场是什么？**

> 写入：`## 审查立场` → `### 雇佣审查` → `#### 社会保险`

合理性检查基准（已核实规则）：
- 「自愿放弃社保」约定无效，用人单位仍须依法缴纳五险
- 以「社保补贴」代替缴纳无效
- 缴纳基数须合规（不低于法定下限）

典型立场选项：
- 用人单位方：「严格按法定标准缴纳，拒绝任何合同中的免缴约定」
- 劳动者方：「核实是否足额缴纳，追缴欠缴社保及利息 `[待验证]`」

**Q5. 关于竞业限制，你们适用于哪些人员？经济补偿标准是多少？期限和范围如何定义？**

> 写入：`## 审查立场` → `### 雇佣审查` → `#### 竞业限制`

合理性检查基准（《劳动合同法》第23-24条，已核实）：
- 适用人员：高级管理人员、高级技术人员和其他负有保密义务人员（不得扩大到全体员工）
- 竞业期限：不得超过 **2 年**（用户若口述3年，提示：「第24条规定上限2年，3年约定中超出部分无效 `[前提 flagged — 需验证]`」）
- 须按月支付经济补偿（补偿标准参考地方指引，一般不低于离职前12个月平均工资的一定比例 `[管辖 flagged — 需验证地方性规定]`）
- 竞业范围：须限于与本单位有竞争关系的业务范围

若用户口述竞业补偿比例过低（如5%以下），提示：「补偿过低可能被认定为无效或劳动者有权单方解除竞业义务（具体标准参照地方指引 `[待验证]`）`[前提 flagged — 需验证]`」

**Q9. 关于经济补偿，你们的计算倾向是什么？**

> 写入：`## 审查立场` → `### 解雇审查` → `#### 经济补偿`

| 倾向 | 说明 |
|------|------|
| 法定 N | 每满一年支付一个月工资（《劳动合同法》第47条，已核实） |
| N+1 | 法定 N 基础上额外支付一个月工资，常见于非过失性辞退（提前通知代偿） |
| 2N | 违法解除赔偿金（《劳动合同法》第87条，已核实）；注意 2N 与 N 互斥 |
| 高于法定（如主动提升补偿以降低争议风险） | 填写具体标准 |

合理性检查：
- 「高于三倍平均工资部分，经济补偿年限封顶12年，月工资按三倍封顶」（《劳动合同法》第47条，已核实）
- 若用户口述 2N 用于合法解除，提示：「2N 是违法解除的赔偿金，不适用于合法解除；合法解除支付 N 或 N+1 `[前提 flagged — 需验证]`」

## 错误处理

| 错误场景 | 处理方案 |
|---------|---------|
| 竞业限制期限口述为3年 | 提示第24条规定不超过2年；询问是按2年写入还是保留3年并标 `[前提 flagged]` |
| 经济补偿口述「违法解除也支付N就够了」 | 提示：违法解除须支付2N（第87条，已核实）；N 与 2N 互斥，不可选低标准 |

## 地方性规定识别触发规则

写入完成后，在 `## 共享护栏 → 地方性规定识别` 中明确以下规则：

>
> - 社保基数与缴纳比例（各地不同，每年调整）
> - 最低工资标准（各省市每1-2年调整）
> - 竞业限制补偿比例指引（部分省市有指导性规定）
> - 产假奖励假天数（各省市生育政策不同）
> - 陪产假天数（各省市立法不同）
> - 婚丧假（地方性标准）
> - 高温津贴（南方省市）
>
> **不以任一地区规定代替全国统一规则，不以过时数据代替最新规定。**
