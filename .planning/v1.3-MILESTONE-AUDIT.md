## Critical Gaps

### Gap 1: Recall orchestration is not wired into ordinary WeCom/runtime flows

- **Requirements:** REC-01, REC-02, REC-05
- **Severity:** High
- **Evidence:** `packages/platform-runtime/src/platform_runtime/memory_orchestrator.py` provides a `MemoryOrchestrator`, but `services/wecom-service/src/wecom_service/session_runtime.py` and `services/wecom-service/src/wecom_service/ingress_runtime.py` still build `RunRequest` and call `runtime.create_run` without invoking memory recall before backend submission.
- **Impact:** The core user-facing v1.3 promise, automatic memory retrieval before ordinary WeCom backend submission, is not delivered end-to-end.
- **Recommended closure:** Add a closure phase to inject an optional memory orchestrator into WeCom/runtime host paths, call it before `create_run`, preserve interrupt/active-task behavior, and test continue/start flows.

### Gap 2: Feedback-to-memory is not wired from feedback callbacks to future context

- **Requirements:** FBL-01, FBL-02, FBL-03, FBL-04, REC-02
- **Severity:** High
- **Evidence:** `FeedbackLearningPolicy` and `MemoryCandidateReviewDecider` exist as library surfaces, but feedback-service code normalizes/classifies/queues feedback without invoking memory learning, review, or next context assembly.
- **Impact:** Feedback cannot safely affect future context through correction refs or human-reviewed memory candidates in the production service path.
- **Recommended closure:** Add service-level feedback-to-memory wiring with safe correction refs, candidate queue creation, explicit human review boundaries, and tests proving high-risk legal/route/skill outputs remain review-only.

### Gap 3: MemoryUse evidence recording is fail-open

- **Requirements:** REC-04
- **Severity:** Medium
- **Evidence:** `MemoryOrchestrator` catches and ignores all exceptions from `record_memory_use`.
- **Impact:** A broken evidence sink can still produce a context bundle without durable evidence, weakening auditability.
- **Recommended closure:** Change evidence failure policy to configurable fail-closed for legal production mode, or return structured degraded status that the WeCom/runtime host must handle.

### Gap 4: Formal verification artifacts are missing

- **Requirements:** All v1.3 requirements
- **Severity:** High for GSD lifecycle
- **Evidence:** No `*-VERIFICATION.md` exists for phases 20, 21, 22, 23, 24, or 25.
- **Impact:** The milestone cannot pass the three-source GSD audit even where code and tests exist.
- **Recommended closure:** Run `$gsd-verify-work` or reconstruct `VERIFICATION.md` for phases 20-25 after any code closure work is complete.
