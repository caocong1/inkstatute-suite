## Gap Closure

### Gap 1 (closed): Recall orchestration is now wired into ordinary WeCom/runtime flows

- **Requirements:** REC-01, REC-02, REC-05
- **Severity:** High → closed
- **Closure evidence:** `WeComSessionRuntime` accepts an optional `MemoryOrchestrator` and calls `recall_and_assemble` before `RunRuntime.create_run` for `CONTINUE_SESSION` and `START_NEW_SESSION` decisions. Interrupt resume and active-task follow-up paths bypass recall and preserve their existing behavior. `WeComRuntimeIngress` passes the orchestrator and a `FeedbackCorrectionRefProvider` into the session runtime. `test_session_memory_runtime.py` and `test_ingress_memory_runtime.py` cover these paths.

### Gap 2 (closed): Feedback-to-memory is now wired from feedback callbacks to future context

- **Requirements:** FBL-01, FBL-02, FBL-03, FBL-04, REC-02
- **Severity:** High → closed
- **Closure evidence:** `feedback_service.memory_wiring` provides `wire_feedback_to_memory`, `apply_memory_candidate_review`, and `InMemoryFeedbackMemoryContextStore`. `feedback_service.queue` exposes `ingest_feedback_callback_for_memory` which normalizes/dedupes/classifies callback feedback and delegates to the wiring helper. Same-session correction refs are persisted and retrievable for context assembly. Repeated negative feedback queues pending memory candidates; route/skill candidates remain review-only with `no_auto_modify`. `test_memory_wiring.py` covers ingestion, review actions, and high-risk guards.

### Gap 3 (closed): MemoryUse evidence failure is no longer silently fail-open

- **Requirements:** REC-04
- **Severity:** Medium → closed
- **Closure evidence:** `MemoryOrchestrator` carries an `evidence_failure_policy` that defaults to `fail_closed` for `record_memory_use` failures. A `MemoryUseEvidenceError` is raised on fail-closed, and a structured `degraded` status is returned when the policy is `degraded`. `test_memory_orchestrator.py` and `test_session_memory_runtime.py` cover both modes.

### Gap 4 (closed): Formal verification artifacts are now present

- **Requirements:** All v1.3 requirements
- **Severity:** High for GSD lifecycle → closed
- **Closure evidence:** `VERIFICATION.md` files exist for phases 20-25. `VALIDATION.md` files exist for phases 22-25 and 25.1. All artifacts include required sections and cite passing automated checks. `scripts/check_v1_3_verification_artifacts.py` deterministically verifies artifact presence, requirements traceability, and audit closure state.
