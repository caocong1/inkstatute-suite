# Milestone v1.1: Platform Foundation

**Status:** ✅ SHIPPED 2026-06-30
**Phases:** 09-13
**Total Plans:** 20

## Overview

v1.1 refactors the InkStatute codebase toward a reusable, backend-neutral, channel-neutral, industry-neutral agent platform. The four North Star contracts — `ChannelAdapter`, `BackendAdapter`, `SolutionLoader`, `RunRuntime` — become the stable seams for independently swappable channels, agent backends, and solutions. Hermes `lawfirm` is the first production backend; WeCom the first channel; the lawyer assistant the first solution. None of these defines the platform core. All new runtime lanes are default-OFF; live cutover remains a separate human gate.

**Architecture basis:** `.planning/drafts/agent-platform-north-star.md`
**Execution plan:** `.planning/drafts/agent-platformization-plan-v5.md`

**Depends on**: Phase 09
**Requirements**: REQ-platform-run-runtime, REQ-runtime-embeddability, REQ-runlane-output-boundary
**Plans**: 4 plans

Plans:

- [x] 10-02: Fake adapters and runtime lifecycle
- [x] 10-03: Streaming output boundary

**Details:**

Implemented `DefaultRunRuntime` as a library-only, dependency-injected runtime. Supports create/poll/stream/cancel/approve against `FakeBackendAdapter` and `FakeChannelAdapter`. **Depends on**: Phase 10 (runtime), Phase 11 (a real backend to exercise)
**Requirements**: REQ-channel-adapter-interface, REQ-multichannel-fixture, REQ-client-embedding-surface
**Plans**: 4 plans

Plans:

- [x] 12-01: WeCom channel wrapper
- [x] 12-02: Web/SSE channel adapter
- [x] 12-03: Platform API host + TypeScript SDK
- [x] 12-04: Embeddable web chat renderer

**Details:**

Wrapped existing WeCom primitives behind `ChannelAdapter` (behind a flag); existing WeCom tests pass with no production regression. Added `WebSseChannelAdapter` as a non-WeCom channel passing end-to-end against fakes. Channel adapters never call backend adapters directly — they submit through `RunRuntime`. `apps/platform_api` hosts `RunRuntime` via HTTP + SSE/WebSocket. `packages/platform-sdk-ts` generates deterministic TypeScript from OpenAPI. `apps/web_chat` renders `RunEvent` streaming via DOM-free `RenderRecord` objects (not HTML strings), embeddable by Tauri/Electron/Flutter webview. Secret refs isolated per `BotInstance`/`ChannelBinding`; no cross-channel payload sharing.

### Phase 13: SolutionLoader + Lawyer & Non-Legal Solutions

**Goal**: Prove the lawyer pack is a backend-portable solution (not platform core) and that a non-legal pack runs through the same contracts unchanged.
**Depends on**: Phase 11 (materialize-to-hermes), Phase 09 (manifest schema)
**Requirements**: REQ-solution-loader, REQ-solution-backend-portability, REQ-solution-privacy-gate, REQ-nonlegal-solution-composability
**Plans**: 4 plans

Plans:

- [x] 13-01: SolutionLoader library
- [x] 13-02: Lawfirm neutral solution pack + sanitizing Hermes materializer
- [x] 13-03: demo_non_legal solution pack
- [x] 13-04: Solution privacy scan + Phase 13 aggregate contract evidence

**Details:**

Implemented `SolutionLoader` in `packages/solution-loader` (not platform-runtime) with `validate`/`load`/`materialize_for` operations. Materializer registry keyed by `(backend_id, solution_id)` tuple; unknown backend returns `'no_materializer_registered'` Issue (not raise). `MaterializerSideEffects` frozen dataclass with `side_effect_kinds` subset of `{write_dir, read_dir, subprocess, network}`; callers assert no undeclared side effects. Lawfirm solution (`solution_id=lawfirm`) materializes via sanitizing Hermes materializer producing sanitized profile bundle. `demo_non_legal` solution pack reuses shared sanitize module; both packs register against `backend_id='hermes'`. Solution privacy scanner rejects secrets, logs, DBs, media, raw payloads, customer docs, and confidential artifacts. Composability gates prove platform core stays industry-neutral. `manifest.output_policy.allow_legal_conclusions` is explicitly false in the demo pack — first manifest to claim non-legal output scope.

## Milestone Summary

**Key Accomplishments:**

1. **Four-contract North Star architecture** — `ChannelAdapter`, `BackendAdapter`, `SolutionLoader`, `RunRuntime` as independently swappable seams with signature-only Protocol stubs, boundary allowlist, and privacy scan allowlist.
2. **Embeddable DefaultRunRuntime** — library-only, dependency-injected, fake backend, default-off feature flags, output boundary with allowlist policy.
3. **Hermes BackendAdapter** — subprocess one-shot adapter, non-mutating capability probe, fixture-based `/v1/runs` parity spike. Security-reviewed.
4. **Channel interface + multi-channel** — WeCom wrapper, Web/SSE channel, Platform API server, TypeScript SDK, embeddable web chat renderer — all default-off.
5. **SolutionLoader library + solutions** — lawfirm neutral manifest with sanitizing Hermes materializer, `demo_non_legal` pack, privacy scanner, aggregate contract evidence — proving backend portability and industry neutrality.

**Key Decisions:**

- Design to four neutral interface contracts: ChannelAdapter, BackendAdapter, SolutionLoader, RunRuntime
- Tech stack: JSON Schema contracts + Python 3.11 async core + TypeScript client SDK/chat component; Rust/Go deferred
- Solutions are backend-portable with per-backend materialization
- Clients default to remote/thin; runtime kept embeddable; no local runtime this milestone
- All new lanes default-OFF; live cutover remains a human gate
- Web chat renderer emits DOM-free RenderRecord objects, not HTML strings
