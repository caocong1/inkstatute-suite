# Plan 11-04 - Parity Fixtures, Report, And Contract Evidence

## Objective

Create sanitized one-shot vs `/v1/runs` parity fixtures, a deterministic parity report, and contract-test-suite evidence proving the API-run lane cannot be promoted unless parity passes.

## Threat Model

<threat_model>
<risk id="T-11-04-fixture-privacy" severity="high">Parity fixtures could commit raw legal prompts, transcripts, backend response bodies, secrets, or generated documents. Mitigation: fixtures use case IDs, refs, hashes, sanitized summaries, and `not_live_acceptance: true` only.</risk>
<risk id="T-11-04-false-promotion" severity="high">A partial parity report could be mistaken as permission to make `/v1/runs` default. Mitigation: report includes `promote_api_runs: false` whenever any case fails or any required dimension is missing.</risk>
<risk id="T-11-04-output-policy-gap" severity="high">Parity could compare raw backend text rather than user-visible policy output. Mitigation: fixture dimensions include `output_policy_action`, `visible_text_hash`, and absence of backend/meta leak summaries.</risk>
<risk id="T-11-04-contract-isolation" severity="medium">Contract-test-suite integration could introduce concrete Hermes coupling into neutral packages. Mitigation: tests import concrete backend code only from `packages/backends/hermes/src` through test-time `PYTHONPATH`, not from neutral runtime source.</risk>
</threat_model>
