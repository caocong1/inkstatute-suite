# Plan 11-01 - Hermes Backend Package And One-Shot Adapter

## Objective

Create the concrete Hermes backend package and implement the default subprocess one-shot `BackendAdapter` lane with reduced capabilities and protocol conformance tests.

## Threat Model

<threat_model>
<risk id="T-11-01-neutral-coupling" severity="high">Concrete Hermes code could leak into neutral runtime packages. Mitigation: create code under `packages/backends/hermes` only and add tests/source assertions that `packages/platform-runtime/src` remains free of Hermes/private path imports.</risk>
<risk id="T-11-01-channel-io" severity="high">The Hermes adapter could send directly to ordinary WeCom users. Mitigation: manifest and capabilities set `no_channel_io=True`, and adapter methods return platform objects only.</risk>
<risk id="T-11-01-raw-transcript" severity="high">One-shot results could store raw prompts, transcripts, or backend response bodies in committed fixtures/loggable metadata. Mitigation: use `raw_payload_ref`, content hashes, artifact refs, and sanitized summaries only.</risk>
<risk id="T-11-01-capability-overclaim" severity="medium">One-shot could claim cancel, streaming, approval, live update, or parallel support it does not have. Mitigation: one-shot manifest declares reduced capabilities and tests lock unsupported methods.</risk>
</threat_model>

- `submit_approval` does not auto-approve and records `approval_unsupported_by_oneshot` in metadata.
