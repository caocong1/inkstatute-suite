# Phase 13 Plan 03: Solutions/Demo_Non_Legal Neutral Pack

**Non-legal demo solution pack that runs through the same contracts unchanged, proving the platform core stays industry-neutral.**

## Objective

Build the second solution pack: `solutions/demo_non_legal/`. It uses the **same** `DefaultSolutionLoader`, **same** validator, **same** materializer-registry contract, **same** sanitize module — only the manifest JSON and a small materializer class change. No platform-code changes. This is the proof that the lawyer pack is a *solution*, not a hidden coupling.

## Read-First

- `.planning/drafts/agent-platform-north-star.md` §4.3 + §1 — "lawyer pack is one solution; other packs (IT-ops, etc.) ship through the same contracts".
- `solutions/lawfirm/manifest.json` — the structure this plan mirrors (kept identical except for industry_context and skill text).
- `solutions/lawfirm/src/inkstatute_solutions_lawfirm/sanitize.py` — the sanitize module this plan reuses.
- `solutions/lawfirm/src/inkstatute_solutions_lawfirm/hermes_materializer.py` — the materializer shape this plan follows.
- `.planning/REQUIREMENTS.md` §Solutions — REQ-nonlegal-solution-composability: "demo_non_legal passes composability gates".
- `packages/solution-loader/src/inkstatute_solution_loader/loader.py` — `DefaultSolutionLoader.materialize_for` (no `solution_id` branching).

## Acceptance Criteria

- `solutions/demo_non_legal/manifest.json` validates against `DefaultSolutionLoader.validate()` with **zero Issues** (same validator as lawfirm).
- `manifest.industry_context` contains key `education_domain` (NOT `legal_domain`); the JSON has zero legal-specific fields at any nesting level.
- `DemoNonLegalHermesMaterializer.materialize(solution, output_dir)` writes the same four-file bundle shape (SKILL.md.template, SAMPLE_PERSONA.md, tools.json, SANITIZATION_REPORT.md) under `output_dir/profiles/demo_non_legal/`.
- `DemoNonLegalHermesMaterializer.side_effects()` returns `MaterializerSideEffects(backend_id="hermes", declared_output_dir_relative="profiles/<solution_id>", side_effect_kinds=("write_dir",))`.
- Both packs (`lawfirm` and `demo_non_legal`) register into the same `MaterializerRegistry` without conflict.
- A test asserts that the SAME `DefaultSolutionLoader` instance handles BOTH solutions sequentially (no platform-code change between them).
- A test asserts `manifest.solution_id != "lawfirm"` and `manifest.industry_context` does not contain `legal_domain`.
- `solutions/demo_non_legal/tests/test_demo_non_legal_solution.py` contains ≥ 8 tests.

## Action

### 1. Create `solutions/demo_non_legal/manifest.json`

Mirror of `solutions/lawfirm/manifest.json` with:
- `solution_id = "demo_non_legal"`, `version = "1.0.0"`
- `persona_ref = "personas/demo_non_legal_persona.md"`
- `skills[]`: education-domain skills (`lesson_qa`, `homework_review`, `syllabus_lookup`, `quiz_generator`) with risk_level mapping
- `mcp[]`: education-domain tool refs (e.g., `curriculum_db`, `grading_service`) with secret_ref names only
- `output_policy`: same overlay shape but with `allow_legal_conclusions: false` (proves neutrality — the demo explicitly disallows legal conclusions)
- `eval[]`: `fixtures/lesson_qa_eval.json`
- `default_adapter_config`: `{ "backend_id": "hermes", "run_invocation_mode": "oneshot" }`
- `secret_templates[]`: `HERMES_API_KEY`, `CURRICULUM_DB_TOKEN`, `GRADING_SERVICE_TOKEN`
- `industry_context`: `{ "education_domain": { "level_scope": "K-12 and adult_learning", "high_risk_topics": ["academic_integrity", "student_privacy"] } }`

### 2. Create `solutions/demo_non_legal/MANIFEST.md`

Human-readable doc explaining: this pack exists to prove the contracts are industry-neutral; the structure is intentionally near-identical to `solutions/lawfirm/manifest.json`; switching between packs requires zero platform changes; future packs (IT-ops, finance, etc.) follow the same template.

### 3. Create `solutions/demo_non_legal/src/inkstatute_solutions_demo_non_legal/__init__.py`

Re-export `DemoNonLegalHermesMaterializer`, `DEMO_NON_LEGAL_SOLUTION_ID`, `DEMO_NON_LEGAL_VERSION`, `register_into(registry)`.

### 4. Create `solutions/demo_non_legal/src/inkstatute_solutions_demo_non_legal/hermes_materializer.py`

`DemoNonLegalHermesMaterializer` class with the same shape as `LawfirmHermesMaterializer`. **Imports** `inkstatute_solutions_lawfirm.sanitize` for the refuse-pattern scan (sharing one module = no duplicated pattern definitions). Writes the same 4 files under `output_dir/profiles/demo_non_legal/` with education-domain text content.

### 5. Create `solutions/demo_non_legal/tests/test_demo_non_legal_solution.py`

≥ 8 tests grouped into `TestNeutralManifest` (3), `TestHermesMaterializer` (3), `TestComposabilityWithLawfirm` (2). The two composability tests:
1. Register both `LawfirmHermesMaterializer` and `DemoNonLegalHermesMaterializer` into the same `MaterializerRegistry`; both `materialize_for` calls succeed (different solution_ids, same loader).
2. The SAME `DefaultSolutionLoader` instance handles lawfirm and demo_non_legal sequentially without any platform-code mutation between them (a `setUp` registers both; the test invokes materialize_for twice).

## must_haves

### truths

- `solutions/demo_non_legal/manifest.json` round-trips through `DefaultSolutionLoader.validate()` with **zero Issues**.
- `manifest.industry_context` contains key `education_domain` and contains no `legal_domain` key at any depth.
- `manifest.output_policy.allow_legal_conclusions` is `false` (explicit neutrality claim).
- `DemoNonLegalHermesMaterializer.materialize(clean_solution, tmp_path)` writes four files under `tmp_path/profiles/demo_non_legal/` and returns `bundle_ref == tmp_path/profiles/demo_non_legal`.
- Both `lawfirm` and `demo_non_legal` materializers can be registered into the same `MaterializerRegistry`; both `materialize_for` calls succeed without registry state mutation between them.
- The same `DefaultSolutionLoader` instance handles both solutions in sequence without reconfiguration.

### prohibitions

- MUST NOT add any legal-specific field at any nesting level in `manifest.json`.
- MUST NOT redefine `MaterializerSideEffects`, `MaterializerRegistry`, or the sanitize patterns; reuse from solution-loader and lawfirm packs.
- MUST NOT modify `platform_runtime`, `platform_contract`, `platform-runtime`, or `solution-loader` packages — composability requires zero platform-code change.

## Risks

- Sharing the sanitize module means the lawfirm sanitize changes affect the demo; this is intentional (single source of truth for refusal patterns) but the demo test must not depend on lawfirm-private regex details.
- The demo materializer uses education placeholder text that could read as trite — mitigated by including at least one realistic skill description (e.g., "Explain a quadratic equation step-by-step").
