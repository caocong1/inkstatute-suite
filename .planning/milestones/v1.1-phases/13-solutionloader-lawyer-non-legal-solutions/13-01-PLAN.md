# Phase 13 Plan 01: SolutionLoader Library + Side-Effect Contract

**Default-off `DefaultSolutionLoader` implementation with manifest validation, side-effect declaration, and materializer registry.**

## Objective

Build the concrete `SolutionLoader` package that implements the existing `platform_runtime.protocols.SolutionLoader` Protocol (`validate`/`load`/`materialize_for`), behind a default-OFF feature flag, with an explicit side-effect declaration contract so callers can assert "no undeclared side effects" per the north-star invariant.

## Read-First

- `.planning/drafts/agent-platform-north-star.md` §4.3 (SolutionLoader + neutral format) — author of the Protocol shape this implements.
- `.planning/drafts/agent-platformization-plan-v5.md` §3 (governing rules: default-OFF, raw_payload_ref-only, sanitized bundles only).
- `.planning/REQUIREMENTS.md` §Solutions — REQ-solution-loader wording for `validate`/`load`/`materialize_for` and the "no undeclared side effects" invariant.
- `packages/platform-runtime/src/platform_runtime/protocols.py` lines 175–248 — the `Issue`, `SolutionPackageManifest`, `Solution`, `BackendSolutionBundle`, and `SolutionLoader` Protocol shapes being implemented.
- `packages/platform-contract/src/platform_contract/events.py` lines 405–476 — the existing `SolutionPackageManifest` dataclass shape; this loader MUST NOT redefine the schema.
- `packages/backends/hermes/src/inkstatute_backends_hermes/__init__.py` — current Hermes backend package; this loader imports from it for the hermes materializer wiring.
- `packages/platform-runtime/src/platform_runtime/__init__.py` — public exports so we re-use `Issue`, `SolutionId`, `BackendId` types rather than redefining them.

## Acceptance Criteria

- `packages/solution-loader/pyproject.toml` exists with `name = "inkstatute-solution-loader"`, stdlib-only `requires-python = ">=3.11"`, no third-party deps.
- `inkstatute_solution_loader.config.SolutionLoaderFeatureFlags.require_enabled()` returns `False` unless `INKSTATUTE_SOLUTION_LOADER_ENABLED=true` (case-insensitive, value parsed defensively).
- `inkstatute_solution_loader.loader.DefaultSolutionLoader` implements the three Protocol methods and a `classify_side_effects(solution, backend_id) -> MaterializerSideEffects` method.
- `manifest_validator.validate(manifest)` returns empty `list[Issue]` for a neutral manifest and ≥1 Issue for each rejection: legal-only top-level key, raw_payload key, secret marker in any field, undeclared `materialize_for` target.
- `materializer_registry.register(backend_id, fn, side_effects)` records a materializer; `materializer_registry.get(backend_id)` returns the function or `None`; `materializer_registry.side_effects_for(backend_id)` returns its declared side-effects.
- `DefaultSolutionLoader.materialize_for(solution, "hermes")` dispatches to the registered hermes materializer (stub for Plan 13-02; this plan only wires the dispatch + side-effect assertion).
- `DefaultSolutionLoader.materialize_for(solution, "codex")` returns an empty `Issue` list added via the loader (NOT raising) — caller decides policy.
- `INKSTATUTE_SOLUTION_LOADER_ENABLED` absent ⇒ `require_enabled()` returns `False`; present and truthy ⇒ `True`; malformed value ⇒ `False` (no crash).
- All public functions/classes are exported via `__init__.py` for clean imports.
- `PYTHONPATH=packages/solution-loader/src:packages/platform-runtime/src:packages/platform-contract/src:packages/backends/hermes/src python -m unittest packages.solution_loader.tests.test_solution_loader_library -v` exits 0 with ≥ 15 tests covering each acceptance criterion.

## Action

### 1. Create `packages/solution-loader/pyproject.toml`

Stdlib-only package metadata, mirroring `packages/platform-runtime/pyproject.toml`:

```
[build-system]
requires = ["setuptools>=68"]
build-backend = "setuptools.build_meta"

[project]
name = "inkstatute-solution-loader"
version = "0.1.0"
description = "Default-off SolutionLoader implementing platform_runtime.protocols.SolutionLoader."
requires-python = ">=3.11"
dependencies = []
```

### 2. Create `packages/solution-loader/src/inkstatute_solution_loader/__init__.py`

Re-export `DefaultSolutionLoader`, `SolutionLoaderFeatureFlags`, `DefaultSolutionLoaderConfig`, `MaterializerSideEffects`, `ManifestValidator`, `MaterializerRegistry`.

### 3. Create `packages/solution-loader/src/inkstatute_solution_loader/config.py`

`SolutionLoaderFeatureFlags` frozen dataclass with `enabled: bool` and `require_enabled()` method. `load_solution_loader_feature_flags(env)` reads `INKSTATUTE_SOLUTION_LOADER_ENABLED` from env, accepting `"1"`, `"true"`, `"yes"`, `"on"` (case-insensitive). `DefaultSolutionLoaderConfig` frozen dataclass with `declared_output_root: Path | None`.

### 4. Create `packages/solution-loader/src/inkstatute_solution_loader/side_effects.py`

Frozen `MaterializerSideEffects` dataclass with `backend_id`, `declared_output_dir_relative`, `side_effect_kinds: tuple[str, ...]`, `notes`. Allowed `side_effect_kinds` values: `{"write_dir", "read_dir", "subprocess", "network"}`.

### 5. Create `packages/solution-loader/src/inkstatute_solution_loader/manifest_validator.py`

Validator with these rejection rules:

1. Reject top-level keys equal (case-insensitive) to any of: `lawyer`, `legal`, `lawfirm`, `attorney`, `counsel`, `law_firm`, `attorneys_at_law`. (industry_context only.)
2. Reject top-level keys equal (case-insensitive) to: `raw_payload`, `secret`, `token`, `password`, `api_key`, `private_key`. (raw_payload_ref allowed; secrets via secret_ref templates only.)
3. Reject any string field value matching a secret marker pattern (case-insensitive contains `"sk-"`, `"secret"`, `"password="`, `"bearer "` followed by ≥16 chars, hex blob ≥32 chars).
4. Reject `solution_id` values that contain `.`, `..`, `/`, `\\`, or whitespace.
5. Reject `version` not matching `^[0-9]+\.[0-9]+\.[0-9]+([+-][A-Za-z0-9.]+)?$`.
6. Reject `manifest.metadata["materialize_targets"]` items not in `{"hermes", "codex", "provider_model"}`.

### 6. Create `packages/solution-loader/src/inkstatute_solution_loader/materializer_registry.py`

`MaterializerRegistry` class with `register(backend_id, fn, side_effects)`, `get(backend_id) -> MaterializerFn | None`, `side_effects_for(backend_id)`, `known_backends() -> tuple[str, ...]`. `MaterializerFn = Callable[[Solution, Path], tuple[list[Issue], BackendSolutionBundle | None]]`.

### 7. Create `packages/solution-loader/src/inkstatute_solution_loader/loader.py`

`DefaultSolutionLoader` with `validate()`, `load()`, `materialize_for()` (returns `(issues, bundle_or_none)`), `classify_side_effects()`. Path-traversal guard: returned `bundle_ref` must resolve inside the caller-provided `output_dir`.

### 8. Create `packages/solution-loader/tests/test_solution_loader_library.py`

≥15 tests grouped into `TestFeatureFlags` (3), `TestManifestValidator` (8), `TestMaterializerRegistry` (3), `TestDefaultSolutionLoader` (4). At least one conformance test asserts the three required methods exist on `DefaultSolutionLoader`.

## must_haves

### truths

- A neutral `SolutionPackageManifest` (no legal-only top-level fields, no raw_payload, no secret markers, valid solution_id + version, materialize_targets ⊆ {hermes, codex, provider_model}) passes `DefaultSolutionLoader.validate()` with zero Issues.
- `INKSTATUTE_SOLUTION_LOADER_ENABLED` unset ⇒ `SolutionLoaderFeatureFlags.require_enabled()` returns `False`.
- A manifest with a top-level `lawyer` key produces an `Issue(path="lawyer", rule="legal_only_top_level_forbidden")`.
- A manifest with a `raw_payload` key produces an `Issue(path="raw_payload", rule="raw_payload_top_level_forbidden")`.
- `DefaultSolutionLoader.materialize_for(solution, "codex")` returns a non-empty Issue list and `None` bundle, never raises.
- `MaterializerRegistry.side_effects_for("hermes")` returns the side-effects declared at registration time.
- A conformance test asserts `DefaultSolutionLoader` exposes `validate`, `load`, `materialize_for` matching the Protocol signatures.

### prohibitions

- MUST NOT redefine `SolutionPackageManifest`, `Solution`, `BackendSolutionBundle`, or `Issue` shapes — the loader imports them.
- MUST NOT introduce any third-party Python dependency.
- MUST NOT write files outside the caller-provided `output_dir` argument.
- MUST NOT add a server, channel, or backend-adapter behavior to this package.
- MUST NOT enable the loader by default; `INKSTATUTE_SOLUTION_LOADER_ENABLED` is required.

## Risks

- The validator may reject legal-specific industry-context strings — mitigated by limiting legal-only checks to **top-level** keys (industry_context contents are not scanned here; solution-privacy scan in Plan 13-04 covers bundle content).
- Path-traversal guard could be too strict — `bundle_ref` is required to be relative to `output_dir`; if the materializer returns absolute paths, the loader raises (not silently coerces).
