# Plan 09-02 - Platform Contract Schema And Binding Extension

## Objective

Extend `packages/platform-contract` with the new neutral platform resource/run/channel schemas and Python dataclass bindings while preserving all existing V2 contract behavior and adapter manifest compatibility.

## Threat Model

<threat_model>
<risk id="T-09-02-breaking-v2" severity="high">Adding new schemas could break the existing five-event self-check or existing adapter manifests. Mitigation: make additions additive, keep existing dataclass fields/defaults, and run the existing self-check plus agent adapter tests.</risk>
<risk id="T-09-02-status-fork" severity="high">A new run status enum could drift from platform async task states. Mitigation: `Run.status` schema and binding use `AsyncTaskState` values exactly.</risk>
<risk id="T-09-02-artifact-confusion" severity="medium">`ArtifactRecord` could be used to replace nested `AgentResult.artifacts`. Mitigation: document and test that `ArtifactRecord` is a top-level reference object and `AgentResult.artifacts` remains unchanged.</risk>
<risk id="T-09-02-legal-coupling" severity="high">New schemas could add legal-only or lawfirm-only required top-level fields. Mitigation: reuse forbidden top-level field checks and place specific details in `industry_context` or `metadata`.</risk>
<risk id="T-09-02-secret-leak" severity="high">Tenant/channel/solution contracts could invite secret values into repo fixtures. Mitigation: require `secret_ref` or secret template names and forbid plaintext secret material.</risk>
</threat_model>
