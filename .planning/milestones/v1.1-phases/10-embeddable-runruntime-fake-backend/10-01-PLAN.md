# Plan 10-01 - Runtime Ports, Feature Flags, And Append-Only Store

## Objective

Create the neutral runtime support layer that later plans use: injected ports, default-off feature flags, and an append-only reference-first contract log store. This plan must not implement backend invocation or channel delivery.

## Threat Model

<threat_model>
<risk id="T-10-01-runtime-coupling" severity="high">Runtime support code could import concrete service, backend, or channel modules. Mitigation: keep `packages/platform-runtime/src` limited to platform-runtime and platform-contract imports, and verify boundary tests still pass.</risk>
<risk id="T-10-01-raw-payload-log" severity="high">Contract logs could store raw user payload text. Mitigation: store-level validation rejects `raw_payload` keys and requires refs, hashes, IDs, or sanitized summaries for payload evidence.</risk>
<risk id="T-10-01-default-on-lane" severity="high">New runtime lanes could become enabled without explicit opt-in. Mitigation: default every Phase 10 flag to `False` and add tests that fail if construction enables lanes by default.</risk>
<risk id="T-10-01-hidden-server" severity="medium">Runtime package support code could add server or filesystem behavior beyond injected stores. Mitigation: no HTTP framework, socket, database, queue, or background process code is introduced.</risk>
</threat_model>
