# Plan 10-03 - Streaming Output Boundary For Run Events

## Objective

Add a neutral output-boundary implementation and wire runtime streaming through it so fake backend deltas cannot leak backend/system/meta notices to ordinary users.

## Threat Model

<threat_model>
<risk id="T-10-03-stream-leak" severity="high">Backend-originated message deltas could bypass the output boundary during streaming. Mitigation: `DefaultRunRuntime.stream` applies the injected boundary to every event carrying visible text before yielding it.</risk>
<risk id="T-10-03-legal-rewrite" severity="high">The boundary could rewrite business/legal conclusions. Mitigation: allow decisions preserve visible text exactly, and tests assert conclusion text equality.</risk>
<risk id="T-10-03-secret-audit" severity="high">Audit metadata could store blocked original text. Mitigation: audit metadata includes hash and length only, never the original blocked/replaced text.</risk>
<risk id="T-10-03-neutral-scan" severity="medium">Neutral runtime source could contain concrete backend/channel names and fail boundary allowlist checks. Mitigation: source patterns are generic; concrete leak samples live in tests or fixtures.</risk>
</threat_model>
