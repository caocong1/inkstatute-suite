# Phase 35: V2 Acceptance Readiness Report & Traceability Update - Plan

**Planned:** 2026-07-03
**Phase:** 35
**Milestone:** v1.5 V2 Acceptance Closure
**Requirements:** DOC-01, DOC-02, DOC-03, DOC-04, DOC-05, DOC-06, DOC-07

## Goal

Operator can read a final V2 acceptance readiness report and updated PROJECT.md traceability that honestly distinguishes autonomous code closure from remaining human gates.

## Approach

This is the final phase of the v1.5 milestone. It synthesizes Phase 33 audit results and Phase 34 gap closure into the deliverable that triggers formal V2 acceptance. The work is primarily documentation generation:

1. **Build a stdlib-only report generator** (`scripts/generate_v2_readiness_report.py`) that reads the 3 JSON sidecars from Phase 33/34 and produces a Markdown readiness report mirroring PRD §10.1–10.4 with two-tier status model and §13 residual risk classification.
2. **Update PROJECT.md traceability** — move 9 satisfied requirements from Active `[ ]` to Validated with phase references; keep TRIAL-01 (human gate) unchecked.
3. **Generate the readiness report** — run the script to produce `.planning/milestones/v1.5-V2-ACCEPTANCE-READINESS.md`.
4. **Add the generator to the compileall gate** and write tests.
5. **Run full gate-suite regression** — verify all 9 gates pass green with no regressions.

No new services, no new dependencies, no new runtime components. Only a script, a generated report, a PROJECT.md edit, and tests.

### Task 1: Build V2 readiness report generator core (DOC-02, DOC-05)

**Files:**
- `scripts/generate_v2_readiness_report.py` (NEW)

**What:**
Create a stdlib-only script that reads the 3 JSON sidecars and generates a Markdown readiness report. The script uses triple-quoted f-strings for each section — no Jinja2, no external templating.

**Structure:**

```python
#!/usr/bin/env python3
"""Generate the V2 acceptance readiness report.

Reads Phase 33/34 JSON sidecars and produces a Markdown report
mirroring PRD §10.1–10.4 with two-tier status model and §13
residual risk classification.

Usage::

    python scripts/generate_v2_readiness_report.py
    python scripts/generate_v2_readiness_report.py --check

Output is deterministic: no timestamps, sorted where applicable.
Same codebase → byte-identical output across runs.
"""

from __future__ import annotations

import argparse
import json
import sys
from pathlib import Path
from typing import Any
```

**Key constants:**

```python
AUTONOMOUS_CLOSURE_STATUS = "READY"
V2_ACCEPTANCE_STATUS = "BLOCKED ON HUMAN GATES"

RESIDUAL_RISK_CLASSIFICATION: tuple[tuple[int, str, str, str], ...] = (
    # (risk_number, risk_short, tier, rationale)
    (1, "hook event ordering", "implementation-resolved",
     "Phase 3 source-confirmed hook ordering; occurred_at + ingested_at + seq + replay tests"),
    (2, "inbound event missing", "implementation-resolved",
     "agent:end reverse inference; fixtures prove AgentTurn reconstruction"),
    (3, "message_id stability", "implementation-resolved",
     "response_filter generates message_id; feedback loop fixtures prove stable mapping"),
    (4, "long-task state source", "implementation-resolved",
     "Async state machine implemented; fixtures cover queued/running/failed/succeeded"),
    (5, "response_filter + template card", "implementation-resolved",
     "feedback_target 1:1 mapping; fixtures prove single card per reply"),
    (6, "feedback dedup", "implementation-resolved",
     "Idempotency module + dedupe fixtures (repeated clicks, network retry)"),
    (7, "raw payload storage", "source-resolved",
     "PRD defines raw_payload_ref approach; implementation follows — no sensitive full text"),
    (8, "sensitive info redaction", "implementation-resolved",
     "privacy_scan.py + coverage ≥95%; privacy gates pass green"),
    (9, "route log gap", "implementation-resolved",
     "RouteDecision.mode=simple_qa implemented; fixtures cover skipped route"),
    (10, "CI fixture representativeness", "implementation-resolved",
     "Composability coverage 7/7 task types (route error, failure, dedup, non-legal)"),
    (11, "skill synthesis boundary", "source-resolved",
     "PRD defines skill_candidate only (no auto-modify); implementation records candidates"),
    (12, "lawyer trial sample size", "live-evidence-pending",
     "5 workdays / 15 tasks requires live human execution — Phase 8 human gate"),
    (13, "multi-hook same-event ordering", "implementation-resolved",
     "Phase 3 source-confirmed 3-hook ordering (admin_notice, response_filter, recorder)"),

    (17, "WeCom service protocol risk", "live-evidence-pending",
     "Fixture-satisfied (callback, ACK, 5s timeout, token); live UAT needed — Phase 5 gate"),
)
```

**Section builders** (each returns a string via triple-quoted f-string):

1. `_section_executive_summary(traceability, comp_coverage, ob_evidence)` — two-tier status model:
   - Autonomous Code Closure: **READY** (9/9 code requirements satisfied, 465 tests, 9 gates green)
   - V2 Acceptance: **BLOCKED ON HUMAN GATES** (Phase 5 live WeCom UAT + Phase 8 five-workday lawyer trial)

2. `_section_10_1(traceability)` — mirrors PRD §10.1 (4 criteria: README, PRD, .gitignore, git repo)

3. `_section_10_2(traceability, ob_evidence)` — mirrors PRD §10.2 (7 criteria: CI passing, WeCom contract tests, schema validation, fixture replay, relationship integrity, coverage ≥95%, output boundary)

4. `_section_10_3(comp_coverage)` — mirrors PRD §10.3 (7 synthetic task types, all covered)

5. `_section_10_4(traceability)` — mirrors PRD §10.4 (lawyer trial + live WeCom service; identifies human-gate criteria vs code-satisfied criteria)

6. `_section_13()` — §13 residual risk classification table (17 risks, 3 tiers)

7. `_section_phase5_uat()` — Phase 5 live WeCom UAT documentation (DOC-03)

8. `_section_phase8_trial()` — Phase 8 five-workday lawyer trial documentation (DOC-04)

**`main()` function:**
- argparse with `--check` flag
- Reads 3 JSON sidecars from `acceptance/`
- Calls each section builder, concatenates with `\n\n`
- Writes to `.planning/milestones/v1.5-V2-ACCEPTANCE-READINESS.md`
- `--check`: verifies report file exists, contains key section markers, exits non-zero if missing

**Determinism:**
- No `datetime.now()` — use fixed placeholder if any date is needed
- JSON sidecars are already deterministic (sorted keys)
- Section builders produce stable output from deterministic inputs
- Same codebase → byte-identical report

**Tests:**
- `test_v2_readiness_report.py`: test script runs, produces Markdown, all sections present, deterministic

- Gate: wecom-service (71 tests pass)
- Fixtures proving code readiness:
  - `phase55_wecom_service_agent_loop.json` — full agent loop

- Output boundary: 4/4 categories covered (gateway/rewrite, update/block, command/block, meta/block)

**2. Operator Checklist:**
```
- [ ] Deploy InkStatute WeCom service to a test server
- [ ] Configure WeCom callback URL, token, and encoding AES key (secrets outside repo)
- [ ] Verify callback signature verification and decryption
- [ ] Send a text message from WeCom → confirm InkStatute ACK within 5s
- [ ] Confirm message normalization (text → ChannelMessage)
- [ ] Send a task → confirm agent backend invocation (Hermes mode)
- [ ] Confirm reply text delivery via InkStatute WeCom service (not Hermes gateway)
- [ ] Confirm file delivery (if applicable)
- [ ] Confirm template card delivery with feedback_target
- [ ] Click feedback button → confirm FeedbackEvent normalization + idempotency
- [ ] Verify no Hermes/gateway/update/command/meta notices visible to user
- [ ] Verify output boundary: gateway/update/command/meta blocked or rewritten
- [ ] Confirm Hermes agent mode bootstrap evidence (version, profile, adapter callable)
- [ ] Confirm secrets not in repo / not in logs / not in contract logs
```

**3. Pass/Fail Criteria:**
- **PASS:** All checklist items confirmed by operator; no Hermes meta leaks; feedback loop complete; output boundary enforced
- **FAIL:** Any Hermes/gateway/update/command/meta notice visible to user; ACK timeout; feedback callback failure; secret leakage
