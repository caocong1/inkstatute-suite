### Privacy Gate Failure Details

`test_default_privacy_data_paths_are_clean` reports 10 false positives in Phase 13 planning files. These are planning/documentation files that reference `callback_body` and `secret_value` marker names in the context of describing privacy decisions — they are not actual raw callback bodies or real secrets.

| File | Line | Code | Context |
|------|------|------|---------|
| 13-01-SUMMARY.md | 86 | callback_body | Documentation reference |
| 13-02-PLAN.md | 82, 108 | callback_body | Documentation reference |
| 13-02-SUMMARY.md | 46, 91 | callback_body | Documentation reference |
| 13-03-SUMMARY.md | 74 | secret_value | Documentation reference |
| 13-VERIFICATION.md | 96, 100, 102 | callback_body | Phase 12 orphan diagnostic |
| deferred-items.md | 12 | callback_body | Phase 12 issue tracking |

**Root cause:** `default_privacy_data_paths()` scans `.planning/phases/**/*.md`. Phase 13 planning docs quote `callback_body` as a marker name (not as raw data). The regex scanner matches the literal word regardless of context.

**Recommended fix:** Sanitize the marker references in Phase 13 planning docs (e.g., `callback_body` → `callback body marker` or similar non-matching phrasing), similar to what Phase 12 did for 12-01/12-02 SUMMARY files in commit 583881f.
