# Plan 38-02 — SKILL Strategy, Mapper Injection, and None Fallback

## Objective

Complete the SKILL strategy in `RouterService` with full stateless Skill Registry lookup (search by name substring and intent category), then inject the `RouterPort` into `hermes-contract-layer/mapper.py` as an optional `router: RouterPort | None = None` parameter. When `None`, the mapper preserves inline inference exactly as today (zero regression). When injected, the mapper calls `router.decide(context)` and uses its output. On router exception, the mapper falls back to inline inference. This plan delivers the SKILL half of ROUTER-02 (stateless skill lookup from Skill Registry) and the ROUTER-01 injection/fallback behavior.

## Context

- Depends on Plan 38-01: `RouterService`, `RouterPort`, `RouterStrategy`, `classifier.py`, and `strategies.py` already exist in `packages/router-service/src/inkstatute_router_service/`.
- The SKILL strategy stub from Plan 38-01 handles `get_skill(skill_id)` but not `search()`. This plan completes the full SKILL strategy with `search(name_substring=...)` and `search(category=<intent>)` paths.
- The inline router in `mapper.py` produces a `route_decision` dict (lines 92-117) via `_route_mode()` (lines 230-238). The injected router must produce a dict with the same JSONL shape — the mapper converts the `RouteDecision` dataclass to a dict matching the inline shape.
- `SkillRegistryPort` from `packages/skill-registry/src/inkstatute_skill_registry/registry.py:16-28` provides `list_skills()`, `get_skill(skill_id)`, `search(tag, category, name_substring)`.
- Fallback policy (RESEARCH.md section 8): `router=None` → inline inference (as today). Router injected but raises → fall back to inline inference (NOT synthetic zero_match — preserves Hermes-derived decision which is more accurate).
- The `router` parameter is keyword-only with `None` default — all existing call sites (`test_mapper.py`, `test_hook.py`, `test_writer.py`) call `map_agent_end_context(context, now=...)` without the new parameter, so they are unaffected.
- `router-service` must NOT import `hermes-contract-layer` (one-directional dependency graph: `hermes-contract-layer → router-service → {platform-contract, skill-registry}`).
