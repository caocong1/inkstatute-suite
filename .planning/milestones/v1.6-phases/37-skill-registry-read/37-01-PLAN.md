# Plan 37-01 — Skill Registry Package, Mapper, and Registry Core

## Objective

Create the `packages/skill-registry/` package with the manifest-to-descriptor mapper and the read-only `SkillRegistry` class providing `list_skills`, `get_skill`, and `search` operations. This plan delivers the core SKILL-01 functionality: querying `NeutralSkillDescriptor` records derived from Hermes skill metadata in solution-pack manifests.

## Context

- `NeutralSkillDescriptor` already exists at `packages/platform-contract/src/platform_contract/events.py:104-112` — no schema changes needed (preserves SAFETY-06 contract freeze).
- Skill metadata source: `solutions/lawfirm/manifest.json` (4 skills, lines 12-41) and `solutions/demo_non_legal/manifest.json` (4 skills, lines 13-42). Manifest skills use `name` (not `skill_id`), `intent`, `required_tools`, and `risk_level`.
- Package pattern follows `packages/solution-loader/` — `pyproject.toml`, `src/inkstatute_skill_registry/`, `tests/`.
- The `skill_id` is derived as `{solution_id}/{skill_name}` for cross-pack uniqueness.

<action>
1. Create `packages/skill-registry/src/inkstatute_skill_registry/registry.py` with:
   - `SkillRegistryPort(Protocol)` with three methods: `list_skills() -> list[NeutralSkillDescriptor]`, `get_skill(skill_id: str) -> NeutralSkillDescriptor | None`, `search(tag: str | None = None, category: str | None = None, name_substring: str | None = None) -> list[NeutralSkillDescriptor]`. No write/update/delete methods in the Protocol.
   - `SkillRegistry` concrete class constructed with `__init__(self, skills: list[NeutralSkillDescriptor])` that stores `self._skills = list(skills)` and builds `self._by_id = {s.skill_id: s for s in self._skills}`.
   - `list_skills()` returns `list(self._skills)` (a copy, not the internal list).
   - `get_skill(skill_id)` returns `self._by_id.get(skill_id)`.
   - `search(tag, category, name_substring)` filters: `tag` matches `s.metadata.get("risk_level") == tag` or `tag in s.metadata.get("tags", [])`; `category` matches `s.metadata.get("intent") == category`; `name_substring` matches case-insensitive substring in `s.name`. Multiple filters apply AND logic. Returns `list(results)`.

2. Update `packages/skill-registry/src/inkstatute_skill_registry/__init__.py` to also re-export `SkillRegistry` and `SkillRegistryPort` from `.registry`. Add both to `__all__`.

3. Create `packages/skill-registry/tests/test_registry.py` with `unittest.TestCase` tests:
   - `test_list_skills_returns_all_descriptors`: Load from both manifests via `load_skills_from_manifests`, construct `SkillRegistry`, assert `list_skills()` returns 8 descriptors.
   - `test_get_skill_returns_descriptor_by_id`: `get_skill("lawfirm/case_qa")` returns a descriptor with `name="case_qa"`.
   - `test_get_skill_returns_none_for_unknown_id`: `get_skill("unknown/skill")` returns `None`.
   - `test_search_by_tag_risk_level`: `search(tag="high")` returns skills where `metadata["risk_level"] == "high"` (contract_draft, litigation_summary).
   - `test_search_by_category_intent`: `search(category="factual_qa")` returns skills where `metadata["intent"] == "factual_qa"` (case_qa, lesson_qa).
   - `test_search_by_name_substring`: `search(name_substring="case")` returns skills with "case" in name, case-insensitive (case_qa).
   - `test_search_with_no_filters_returns_all`: `search()` with no filters returns all 8 skills.
   - `test_search_with_multiple_filters`: `search(tag="medium", category="review")` applies AND logic — returns skills with both `risk_level=="medium"` AND `intent=="review"` (compliance_review).
   - `test_registry_is_read_only`: Assert no method on `SkillRegistry` (via `dir(SkillRegistry)`) starts with any of `add_`, `create_`, `update_`, `delete_`, `remove_`, `put_`, `post_`. Exclude dunder methods from the check.
   - `test_registry_does_not_mutate_internal_list`: Call `list_skills()`, append to the returned list, call `list_skills()` again — assert the second call still returns 8 items (internal list not affected).
   - Use `REPO_ROOT = Path(__file__).resolve().parents[3]` for manifest fixture paths.
</action>
