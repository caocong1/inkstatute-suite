# Plan 43-01 — Extract Channel-Generic Logic into channel-core + QQBot Channel Adapter Structure

## Goal

Extract the four channel-generic modules (idempotency, delivery_guard, active_task_router, output_policy) plus the owned_notices dependency from `wecom-service` into a new shared package `packages/channel-core/`. Convert the wecom-service modules into thin re-export shims so existing wecom-service tests pass unchanged (backward compatibility). Then create the `packages/channels/qqbot/` package with a `QQBotChannelAdapter` that implements all 6 `ChannelAdapter` Protocol methods, imports from `channel_core` (NOT from `wecom_service`), and handles receive (single mode), send (text), and callback verification.

This plan satisfies:
- QQBOT-01: channel-generic logic extracted into shared package; QQBot does not import from wecom_service.
- QQBOT-02: QQBot channel adapter implements ChannelAdapter Protocol (6 methods), handles receive, send, callback verification.

## Context

- The four channel-generic modules in `services/wecom-service/src/wecom_service/` are: `idempotency.py` (44 lines), `delivery_guard.py` (90 lines), `active_task_router.py` (195 lines), `output_policy.py` (102 lines). `output_policy.py` imports from `owned_notices.py` (129 lines) which is also channel-generic.
- `delivery_guard.py` and `owned_notices.py` are pure-extraction (no WeCom-specific aspects). `idempotency.py` has a WeCom-specific function name and key prefix. `active_task_router.py` has a WeCom-specific event name in `as_event()`. `output_policy.py` has a WeCom-specific policy name in audit metadata.
- The existing `packages/channels/wecom/` adapter imports from `wecom_service` — this is acceptable for WeCom. The existing `packages/channels/web_sse/` adapter is fully self-contained (no wecom_service imports) — this is the reference pattern for QQBot.
- `ChannelAdapter` Protocol (6 methods) is frozen: `channel_id`, `capabilities`, `verify_and_ack`, `normalize_inbound`, `deliver`, `health`. Defined in `packages/platform-runtime/src/platform_runtime/protocols.py:208-219`.
- `Channel.QQBOT = "qqbot"` already exists in `packages/platform-contract/src/platform_contract/enums.py:35`.
- `qqbot_channel_enabled` feature flag already exists with default `False` in `packages/platform-runtime/src/platform_runtime/feature_flags.py:23`.
- Contract freeze (SAFETY-02, SAFETY-06): No changes to `packages/platform-contract/` or `packages/platform-runtime/protocols.py` or `packages/platform-runtime/src/platform_runtime/feature_flags.py`.
- Privacy: No literal secrets in code or tests. Use `REDACTED` or short placeholders (< 12 chars).
