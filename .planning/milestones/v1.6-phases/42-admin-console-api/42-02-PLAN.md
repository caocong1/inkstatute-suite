# Plan 42-02 — Health/Status Views with Field Allowlist and Gate Status via Subprocess

## Goal

Add `/health` and `/gates` endpoints to the Admin Console API. The `/health` endpoint uses a **positive field allowlist** (`HEALTH_ALLOWED_FIELDS`) that excludes secret reference names, config paths, `secret_refs_configured` maps, and `api_base_url` values — only exposing `secrets_configured: true/false`. The `/gates` endpoint runs `run_v2_gates.py --json-summary` via `subprocess.run` — no gate internals are imported.

This plan satisfies:
- ADMIN-02: Operator can verify that Admin Console API health/status views use a field allowlist that excludes secret reference names, config paths, `secret_refs_configured` maps, and `api_base_url` values — only exposing `secrets_configured: true/false`.
- SC3 (gate subprocess portion): Operator can verify that the Admin Console API runs `run_v2_gates.py --json-summary` via subprocess for gate status views without importing gate internals.

## Context

- The Admin Console API service was created in Wave 1 (42-01) with `handle_admin_get` routing, auth gate, and data views (sessions, tasks, feedback). The `/health` and `/gates` routes currently return 501 placeholders.
- The field allowlist is a **positive filter** — only fields in `HEALTH_ALLOWED_FIELDS` are exposed. This is different from the `ALL_FORBIDDEN_KEYS` negative filter (which blocks known-bad keys). The allowlist approach prevents accidental exposure of new secret-like fields.
- `scripts/run_v2_gates.py` supports `--json-summary` (`run_v2_gates.py:25,40-46`) which outputs `{"passed": bool, "gates": [{"name": str, "exit_code": int}]}`. The Admin Console API runs this via `subprocess.run` — it does NOT import gate internals.
- The `run_v2_gates.py` script is at `scripts/run_v2_gates.py` relative to the repo root. The admin-console-api package is at `services/admin-console-api/src/admin_console_api/`. The repo root is 4 directories up from the package: `Path(__file__).resolve().parents[4]`.
- Contract freeze (SAFETY-02, SAFETY-06): No changes to `packages/platform-contract/` or `packages/platform-runtime/protocols.py`.
- Privacy: Health/status view tests use synthetic dicts with field names like `secret_refs_configured` and `api_base_url` — these are field names, not secret values.
