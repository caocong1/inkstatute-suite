# Plan 44-01 — Add Missing V2 Gates + Compileall Dirs + Meta-Test Gate Registration

## Goal

Modify `scripts/run_v2_gates.py` so the V2 gate suite covers every `packages/*/src` and
`services/*/src` directory. Concretely: add 3 new dedicated gates (`web-sse-channel`,
`wecom-channel`, `platform-sdk-ts`) for the 3 currently-uncovered package source dirs,
add the 4 missing source dirs to the `compileall` gate, and register the
`gate-coverage-meta-test` gate (created as a file in Plan 44-02) as a first-class gate
entry. This single plan owns ALL changes to `scripts/run_v2_gates.py` because the file is
modified in both the gate-addition and meta-test-registration steps.

This plan satisfies GATE-01 (success criteria #1 and #3): the 6 M2 package/service gates
already exist from Phases 37-43, and this plan closes the 3 remaining coverage gaps plus
registers the meta-test gate that enforces coverage going forward.

## Context

- `scripts/run_v2_gates.py` currently defines 15 gates in `_gates()` (lines 49-172). The
  `Gate` dataclass (lines 15-19) is `@dataclass(frozen=True)` with `name`, `command`,
  `pythonpath`. Source path variables are defined at the top of `_gates()` (lines 51-68).
  New gates are appended to the return tuple BEFORE the `compileall` gate.
- 3 package source dirs have passing tests but NO gate: `packages/channels/web_sse/src`
  (27 tests pass), `packages/channels/wecom/src` (12 tests pass ONLY when
  `services/wecom-service/src` is on PYTHONPATH — the test imports
  `wecom_service.protocol`), `packages/platform-sdk-ts/src` (9 tests pass; src holds only
  `index.ts` so compileall cannot validate it — coverage must come from the gate
  PYTHONPATH).
- 4 dirs are missing from the `compileall` gate command: `packages/backends/hermes/src`,
  `packages/solution-loader/src`, `solutions/lawfirm/src`, `solutions/demo_non_legal/src`.
- Verified (pre-planning): `python -m compileall packages/platform-sdk-ts/src` exits 0
  (a `.ts`-only dir compiles nothing and returns success — but it provides no real
  coverage, so the dir is covered via the dedicated gate's PYTHONPATH instead).
- Verified PYTHONPATH configs that make all 3 test suites pass:
  - web_sse: `packages/channels/web_sse/src:packages/channel-core/src:packages/platform-contract/src:packages/contract-test-suite/src:packages/platform-runtime/src` → 27 tests OK
  - wecom channel: `packages/channels/wecom/src:packages/channel-core/src:packages/platform-contract/src:packages/contract-test-suite/src:packages/platform-runtime/src:services/wecom-service/src` → 12 tests OK
  - platform-sdk-ts: `packages/platform-sdk-ts/src:packages/platform-contract/src:packages/contract-test-suite/src:packages/platform-runtime/src` → 9 tests OK
- Plan 44-02 creates `packages/contract-test-suite/tests/test_gate_coverage.py`. This plan
  registers the `gate-coverage-meta-test` gate that runs it. Because the file does not
  exist until Plan 44-02 is applied, this plan's verification does NOT run the full
  `python scripts/run_v2_gates.py` suite (the meta-test gate would fail on the missing
  file). Full-suite verification is deferred to Plan 44-03 (Wave 2, depends on 01 + 02).
