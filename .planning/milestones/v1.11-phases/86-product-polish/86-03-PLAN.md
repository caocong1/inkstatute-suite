  <action>
    1. Create `scripts/start-console.sh` with shebang `#!/usr/bin/env bash` and `set -euo pipefail` as the first two lines. Follow the pattern from scripts/start-hindsight.sh L18-19.

    2. Add a usage comment block after the set line: "Starts admin-web-ui + admin-console-api with env loading and PID tracking. Channel hosts (WeCom/QQBot) are started on-demand from the console UI, not by this script. Usage: ./scripts/start-console.sh [--dry-run]"

    3. Add `--dry-run` flag support: if `${1:-}` equals "--dry-run", print the commands that would be executed (env file path, PID file path, service commands) and exit 0. This enables CI testing without port binding.

    4. Env loading: set `ENV_FILE="${CONSOLE_ENV_FILE:-.env}"`. If the file exists, load it with `set -a; source "$ENV_FILE"; set +a` (following start-hindsight.sh L24-25 pattern). If the file does not exist, print a warning to stderr ("WARNING: $ENV_FILE not found, using current environment") and continue — do NOT exit with error, since the env vars may already be set in the shell.

    5. Create the runtime state directory: `mkdir -p "${HOME}/.inkstatute"`. This mirrors the ProcessSupervisor pattern (process_supervisor.py L52-56 uses `Path.home() / ".inkstatute"`).

    6. Launch the API server as a background subprocess: `python -m admin_console_api & API_PID=$!`. Launch the UI server as a background subprocess: `python -m admin_web_ui & UI_PID=$!`. These use the __main__.py entry points from Phase 79, which read ADMIN_CONSOLE_API_HOST/PORT and ADMIN_WEB_UI_HOST/PORT env vars with defaults 127.0.0.1:8081 and 127.0.0.1:8080.

    7. Write the PID file as JSON to `${HOME}/.inkstatute/console-pids.json`: `printf '{"api": %s, "ui": %s}\n' "$API_PID" "$UI_PID" > "${HOME}/.inkstatute/console-pids.json"`. Use JSON format (not .pid files) because .gitignore L14 ignores *.pid files. This mirrors the ProcessSupervisor JSON state pattern.

    8. Add trap cleanup: `trap 'kill ${API_PID} ${UI_PID} 2>/dev/null || true; rm -f "${HOME}/.inkstatute/console-pids.json"' EXIT`. This ensures both child processes are killed and the PID file is cleaned up when the script exits (normally or via signal).

    9. Print a success message with the service URLs: "Console UI: http://${ADMIN_WEB_UI_HOST:-127.0.0.1}:${ADMIN_WEB_UI_PORT:-8080}" and "Console API: http://${ADMIN_CONSOLE_API_HOST:-127.0.0.1}:${ADMIN_CONSOLE_API_PORT:-8081}" and "PID file: ${HOME}/.inkstatute/console-pids.json".

    10. End with `wait` to keep the script running until both child processes exit.

    11. Make the script executable: `chmod +x scripts/start-console.sh`.

    12. Create `services/admin-web-ui/tests/test_startup_script.py` with a `TestStartupScript` class. Use the Path resolution pattern: `_SCRIPT_PATH = Path(__file__).resolve().parents[3] / "scripts" / "start-console.sh"` (parents[0]=tests/, parents[1]=admin-web-ui/, parents[2]=services/, parents[3]=repo root). Read the script content in setUp. Test methods:

    - `test_script_sources_env`: assert "source" in content and "set -a" in content and "set +a" in content
    - `test_script_launches_both_services`: assert "admin_web_ui" in content and "admin_console_api" in content
    - `test_script_writes_pid_file`: assert "console-pids.json" in content and ".inkstatute" in content
    - `test_script_has_trap_cleanup`: assert "trap" in content and "kill" in content
