## Milestone Goal

Extend the platform beyond Hermes-only by proving agent-backend-neutral contracts (Codex + provider_model prototypes), normalizing routing as an independent service, exposing skill metadata and operational read views, completing conversation-read-view, and adding a second channel (QQBot) to prove ChannelAdapter portability — while keeping all existing V2 gates green and V2 human-gate evidence stable.

## Milestone Summary

The v1.6 milestone successfully extended the InkStatute platform from a Hermes-only backend to a multi-backend architecture with portable channel adapters. Key achievements:

1. **Multi-backend proof:** Codex and provider_model adapter prototypes prove the BackendAdapter Protocol is backend-neutral. Both pass capability probes and complete minimal `submit_run → AgentResult` flows. All M2 feature flags default to `False`, preventing prototype adapters from serving live WeCom turns during V2 human gates.

2. **Independent routing:** The Router Service is a standalone library injectable into `hermes-contract-layer/mapper.py`, producing `RouteDecision` events with the same JSONL shape as the inline implementation. Supports RULE and SKILL routing modes with stateless skill lookup from the Skill Registry.

3. **Skill Registry:** Read-only Skill Registry exposes Hermes skill metadata as `NeutralSkillDescriptor` records with list/get/search operations and a `/.well-known/agent-skills/index.json` discovery endpoint per the Cloudflare agent-skills-discovery convention.

4. **Conversation Read-View completion:** Cursor-based pagination, time-range and dimension filters, trace reconstruction by `trace_id`, and CSV/JSON export — with read-time privacy scrubbing applied to all new endpoints.

5. **Admin Console API:** Read-only Admin Console API with static token auth, sessions/tasks/feedback/gates/health views, and a field allowlist that excludes secret references.

6. **QQBot channel portability:** Channel-generic logic extracted from `wecom-service` into a shared `channel-core` package. QQBot ChannelAdapter implements the 6-method `ChannelAdapter` Protocol with a fixture-driven receive→ACK→adapter→reply→card→feedback loop proof.

7. **Gate coverage enforcement:** 19 V2 gates covering every `packages/*/src` and `services/*/src` directory. A meta-test (`gate-coverage-meta-test`) enforces coverage going forward — future uncovered directories automatically fail CI.

## Key Decisions

1. **BackendAdapter Protocol frozen** — No method count changes during M2. Codex and provider_model adapters implement the existing Protocol without modification.
2. **ChannelAdapter Protocol frozen** — 6 methods preserved. QQBot adapter implements the existing Protocol; channel-generic logic extracted to `channel-core` without Protocol changes.
3. **All M2 feature flags default False** — `router_service_enabled`, `skill_registry_enabled`, `admin_api_enabled`, `qqbot_channel_enabled`, `codex_backend_enabled`, `provider_model_backend_enabled` all default to `False` in `RuntimeFeatureFlags`.
4. **Contract freeze maintained** — `packages/platform-contract/` was not modified during M2. Baseline hash test prevents drift.
5. **Gate coverage meta-test** — Phase 44 added a meta-test that enforces every `packages/*/src` and `services/*/src` directory is covered by a gate, preventing future coverage gaps.
