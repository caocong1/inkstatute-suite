- [ ] `parse_mode_str(s: str) -> AgentMode | None` handles Chinese aliases: "文书"/"起草"/"文书起草" → Draft; "案情"/"案情分析"/"诉讼"/"证据" → Evidence; "咨询"/"问答"/"法律问答" → Chat; plus English: "draft"/"document"/"doc", "evidence"/"caseanalysis"/"case", "chat"/"qa"/"q&a"
- [ ] `fallback_classify(ctx: ClassifyContext, fallback_reason: str, diagnostic: str | None) -> ClassifyResult` — structural only: if `has_active_document` → use `current_mode` (parse via `parse_mode_str`, default Chat if unparseable); else → Chat; action always "continue"; source "fallback"; reason "AI 分类失败，已使用结构性安全默认模式"
- [ ] `LLMModeClassifier` accepts a host-injected LLM callable (Protocol, same pattern as `ModelClassifierPort`); system prompt and policy supplement are ported verbatim from Rust lines 125-196
- [ ] Action pinning: when `current_mode` is None (no committed task), action is always pinned to "continue" regardless of LLM output
- [ ] `parse_classifier_response()` parses JSON `{"mode":"...", "action":"...", "label":"...", "reason":"..."}`, normalizes action, parses mode, pins action when current_mode is None
- [ ] Error diagnostics: `classify_error_diagnostic()` categorizes errors as `auth_failed`, `model_not_found`, `timeout`, `response_parse_failed`, `network_error`, `request_failed` (same as Rust lines 281-298)
- [ ] Retry logic: `classify_with_retry()` tries fast provider first, retries with primary on fallback, returns second fallback result if both fail
- [ ] `fallback_classify()` does NOT read `ctx.user_message` for keyword matching (safety property — a broken LLM must not surprise-switch)

### Task 98-02-04: Integrate mode detection into `RouteDecision.metadata`

**Action**: Modify `packages/router-service/src/inkstatute_router_service/service.py` to optionally call `ModeClassifierPort.classify()` when a mode classifier is injected, and store the results in `RouteDecision.metadata`. The `RouterService.__init__` accepts an optional `mode_classifier: ModeClassifierPort | None = None` (same host-injection pattern as `model_classifier`). When a mode classifier is provided, `decide()` calls `classify()` with a `ClassifyContext` built from the routing context and stores: `metadata["agent_mode"]`, `metadata["mode_action"]`, `metadata["mode_label"]`, `metadata["mode_source"]`, `metadata["mode_fallback_reason"]`. When no mode classifier is injected, these metadata keys are absent (backward compatible).
