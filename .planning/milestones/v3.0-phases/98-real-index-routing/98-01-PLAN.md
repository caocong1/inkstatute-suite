### Task 98-01-03: Integrate strong-signal + soft matching into `RouterService.decide()`

**Action**: Modify `packages/router-service/src/inkstatute_router_service/service.py` to run strong-signal matching BEFORE the strategy cascade. The routing flow becomes: (1) empty/trivially short → None, confidence 0.9; (2) strong-signal rules → rule's primary_skill, confidence 0.95; (3) factual short-circuit → None, confidence 0.85, matched_rule="factual_short_circuit"; (4) soft trigger-phrase matching (threshold ≥0.4) → best match, gate_before=ask-user-enforcement (unless score ≥0.7 → skip), gate_after=legal-de-ai-polish; (5) fall through to existing strategy cascade (RULE/SKILL/HYBRID). The strong-signal and soft-match layers are pre-router — they run for ALL strategies, not just HYBRID. The existing `_build_decision()` method is extended to accept `gates_before` and `gates_after` computed by the router (not just from context).
