# Plan 88-02: RunEvent Respecification — ingested_at, Replay, and Seq-Based Resume

## Goal

Respecify `RunEvent` as the carrier for the unified event vocabulary by adding the `ingested_at` field and a `payload` field for typed event data. Implement and test out-of-order replay (events arrive non-monotonically by `seq` but replay correctly when sorted) and seq-based resume (from any `seq` breakpoint, replay produces no duplicates and no loss).

1. `sort_events_by_seq(events: list[dict]) -> list[dict]` — takes a list of RunEvent dicts (each with a `seq` integer field), returns them sorted by `seq` ascending. This enables out-of-order replay: events may arrive non-monotonically but replay correctly when sorted.

2. `resume_from_seq(events: list[dict], last_seen_seq: int) -> list[dict]` — takes a full ordered list of RunEvent dicts and a `last_seen_seq` breakpoint, returns only events with `seq > last_seen_seq`, preserving order. This enables seq-based resume: from any breakpoint, the client gets exactly the events it hasn't seen — no duplicates, no loss.

Both functions should be pure (no side effects, no mutation of input). Add type hints. Add docstrings explaining the replay/resume semantics.
</action>
