# Plan 88-04: Five-Phase Progress Contract and Event Mapping Table

## Goal

Define the five-phase progress contract (research → intake → retrieval → draft → review) as a Python enum with a mapping table from unified event types to phases and to UI concepts (thinking / tool / streaming / review). The `phase.changed` event carries this state. Tests verify that the mapping table covers all relevant event types and that phase transitions follow the defined order.

   - `THINKING = "thinking"`
   - `TOOL = "tool"`
   - `STREAMING = "streaming"`
   - `REVIEW = "review"`

3. `PHASE_ORDER: list[FivePhase]` — constant list `[FivePhase.RESEARCH, FivePhase.INTAKE, FivePhase.RETRIEVAL, FivePhase.DRAFT, FivePhase.REVIEW]` defining the canonical phase order.

4. `EVENT_TYPE_TO_PHASE: dict[str, FivePhase]` — mapping from unified event type string values to their primary phase:
   - `"thought.delta"` → `FivePhase.RESEARCH` (thinking/reasoning happens during research)
   - `"tool_call.started"` → `FivePhase.RETRIEVAL` (tool calls for retrieval)
   - `"tool_call.delta"` → `FivePhase.RETRIEVAL`
   - `"tool_call.completed"` → `FivePhase.RETRIEVAL`
   - `"message.delta"` → `FivePhase.DRAFT` (streaming the draft response)
   - `"message.completed"` → `FivePhase.DRAFT`
   - `"plan.updated"` → `FivePhase.INTAKE` (plan formation happens during intake)
   - `"phase.changed"` → not mapped (it IS the phase change event itself)
   - `"elicitation.requested"` → `FivePhase.INTAKE` (clarification questions during intake)
   - `"permission.requested"` → `FivePhase.RETRIEVAL` (permissions for tool execution)
   - `"artifact.created"` → `FivePhase.REVIEW` (artifact produced for review)
   - `"citation.recorded"` → `FivePhase.REVIEW` (citations verified during review)
   - `"session.started"` → `FivePhase.RESEARCH` (session start begins research)
   - `"run.state_changed"` → not mapped (lifecycle event, not phase-specific)
   - `"error"` → not mapped (can occur in any phase)

5. `PHASE_TO_UI_CONCEPT: dict[FivePhase, UiConcept]` — mapping from phases to UI concepts:
   - `FivePhase.RESEARCH` → `UiConcept.THINKING`
   - `FivePhase.INTAKE` → `UiConcept.THINKING`
   - `FivePhase.RETRIEVAL` → `UiConcept.TOOL`
   - `FivePhase.DRAFT` → `UiConcept.STREAMING`
   - `FivePhase.REVIEW` → `UiConcept.REVIEW`

6. `is_valid_transition(current: FivePhase, next_phase: FivePhase) -> bool` — returns True if `next_phase` is the same as `current` or comes after `current` in `PHASE_ORDER`. Phases can only advance or stay, not go backward (with one exception: intake can follow research, and research can follow intake if more research is needed — but for V3 MVP, enforce forward-only). Implementation: `PHASE_ORDER.index(next_phase) >= PHASE_ORDER.index(current)`.

7. `get_phase_for_event_type(event_type: str) -> FivePhase | None` — looks up `EVENT_TYPE_TO_PHASE`, returns `None` for unmapped event types.

8. `get_ui_concept_for_phase(phase: FivePhase) -> UiConcept` — looks up `PHASE_TO_UI_CONCEPT`.

Update `__init__.py`: add `from .five_phase import FivePhase, UiConcept, PHASE_ORDER, EVENT_TYPE_TO_PHASE, PHASE_TO_UI_CONCEPT, is_valid_transition, get_phase_for_event_type, get_ui_concept_for_phase`. Add all to `__all__`.
