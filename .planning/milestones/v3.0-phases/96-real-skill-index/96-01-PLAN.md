# Plan 96-01: Scanner Core — packages/skill-index scaffold + SKILL.md walker + frontmatter parser + token estimator + read-only enforcement

## Goal

Create the new `packages/skill-index` Python package from scratch. This plan builds the foundational scanner layer: a recursive directory walker that discovers all `SKILL.md` files in a repo (excluding `.qwen/`, `node_modules/`, `_shared/`), a YAML frontmatter parser that handles both the minimal ai-for-china-legal schema and the rich legal-skills schema, a CJK-aware token estimator (no external tokenizer dependency), and read-only enforcement tests that assert scanning never modifies source repo files (mtime + SHA-256 hash comparison).

This is the foundation for all subsequent plans (96-02 classification+metadata, 96-03 conflict model, 96-04 gate+e2e). No gate registration happens here — that is deferred to Plan 96-04 to avoid breaking the gate-coverage meta-test before tests exist.

## Reversibility Gate

**One-way-door:** Creating `packages/skill-index/` with `src/` and `tests/` directories. Once `packages/skill-index/src` exists on disk, the `gate-coverage` meta-test (`test_gate_coverage.py`) will discover it and fail unless it is covered by a gate. Strategy: this plan does NOT register the gate yet — the gate-coverage meta-test will fail until Plan 96-04 registers the `skill-index` gate. To avoid breaking CI during Wave 1, the package `src/` directory is created but the gate registration is done in 96-04. If the tracer needs to be reverted, remove the `packages/skill-index/` directory entirely — no existing file is modified in this plan.

**One-way-door:** The read-only enforcement contract (SAFE-05). Once `test_read_only.py` asserts mtime + hash immutability, the scanner must never write to source repos. Strategy: the scanner uses only `path.read_text(encoding="utf-8")` / `path.read_bytes()` — no write calls anywhere in the scanner module. The test is the enforcement mechanism.

This module extracts and parses YAML frontmatter from SKILL.md files. It must handle:
1. Standard frontmatter delimited by `---` at the start of the file
2. Folded scalar `>` for multi-line `description` fields (ai-for-china-legal pattern)

4. Both minimal schema (name, description, argument-hint) and rich schema (name, version, license, author, homepage, description)

Define the following:

1. A frozen slotted dataclass `FrontmatterResult` with fields:

   - `body: str` — the markdown body after frontmatter (full file content if no frontmatter)

   - Parse with `yaml.safe_load()` — handle `yaml.YAMLError` by returning `FrontmatterResult(frontmatter={}, body=text_after_first_delimiter, raw_text=text, warnings=["malformed_frontmatter"])`
   - If `name` field is missing from parsed frontmatter, add warning `"missing_name_field"` (caller can fall back to directory name)

Create `packages/skill-index/src/inkstatute_skill_index/token_estimator.py`.

This module provides a CJK-aware token estimation heuristic. No external tokenizer dependency (no tiktoken, no transformers). The formula:
```
token_estimate = (CJK_character_count × 1.0) + (non_CJK_character_count // 4)
```

Define the following:

1. A function `is_cjk(char: str) -> bool`:
   - Returns `True` if the character is in the CJK Unified Ideographs range: `\u4e00 <= char <= '\u9fff'`
   - Also returns `True` for CJK Extension A (`\u3400`–`\u4dbf`) and CJK Compatibility Ideographs (`\uf900`–`\ufaff`)
   - Returns `False` otherwise

2. A function `estimate_tokens(text: str) -> int`:
   - Counts CJK characters using `is_cjk()`
   - Counts non-CJK characters as `len(text) - cjk_count`
   - Returns `cjk_count + non_cjk_count // 4`
   - The estimate covers the full text (frontmatter + body)

3. A function `estimate_tokens_for_file(path: Path) -> int`:
   - Reads the file content via `path.read_text(encoding="utf-8")`
   - Returns `estimate_tokens(content)`
   - Must NOT modify the file (read-only)

Import `Path` from pathlib.

CRITICAL: No external tokenizer library. No `import tiktoken`, no `import transformers`. The heuristic is intentionally approximate — it is for routing and context budget purposes, not exact counts. The `estimate_tokens_for_file` function must use `read_text` only, never `write_text` or any write operation.
</action>

Create `packages/skill-index/src/inkstatute_skill_index/scanner.py`.

This module walks a repo directory tree recursively and discovers all `SKILL.md` files. It is the foundational scanner that produces raw `ScannedSkill` records — classification (orchestration vs leaf) and metadata enrichment happen in Plan 96-02.

Define the following:

1. A frozen slotted dataclass `ScannedSkill` with fields:
   - `skill_id: str` — namespace-prefixed ID (e.g., `commercial-legal:contract-review` or `legal-court-sms`)
   - `name: str` — skill name from frontmatter or directory name fallback
   - `source_repo: str` — `"ai-for-china-legal"` or `"legal-skills"` (passed by caller)
   - `plugin: str | None` — plugin name for ai-for-china-legal (e.g., `"commercial-legal"`), `None` for legal-skills flat structure
   - `relative_path: str` — path relative to repo root (e.g., `"commercial-legal/skills/contract-review/SKILL.md"`)
   - `absolute_path: str` — absolute path to the SKILL.md file
   - `frontmatter: dict[str, Any]` — parsed frontmatter dict
   - `body: str` — markdown body text
   - `raw_text: str` — full file content
   - `token_estimate: int` — estimated token count
   - `warnings: list[str]` — warnings from frontmatter parsing + scanner
   - `depth: int` — nesting depth (0 = direct child of skills/, 1 = nested under a parent)

2. A frozen slotted dataclass `ScanResult` with fields:
   - `repo_name: str` — `"ai-for-china-legal"` or `"legal-skills"`
   - `repo_path: str` — absolute path to the repo root
   - `skills: list[ScannedSkill]` — all discovered skills
   - `warnings: list[str]` — repo-level warnings (e.g., `"missing_plugin_json"`)

3. A set `EXCLUDED_DIRS` containing: `{".qwen", "node_modules", ".git", "__pycache__", ".claude-plugin"}` — directories to skip during traversal. Note: `.claude-plugin` is skipped because it contains plugin.json/marketplace.json, not SKILL.md files.

4. A function `scan_repo(repo_path: str | Path, repo_name: str) -> ScanResult`:
   - Walks `repo_path` recursively using `pathlib.Path.rglob("SKILL.md")`
   - Skips any path component in `EXCLUDED_DIRS`
   - Skips `_shared/` directories (they contain reference .md files, not SKILL.md — but since we glob for `SKILL.md` specifically, `_shared/` won't match unless it contains a SKILL.md, which it doesn't per research)
   - For each discovered `SKILL.md`:
     - Read content via `path.read_text(encoding="utf-8")` — READ ONLY
     - Parse frontmatter via `parse_frontmatter(text)`
     - Extract name via `extract_name(frontmatter, fallback=directory_name)`
     - Estimate tokens via `estimate_tokens(text)`
     - Compute `relative_path` relative to `repo_path`
     - Compute `depth` = count of path components between `skills/` and the SKILL.md file, minus 1 (0 = direct child, 1 = nested)
     - Determine `plugin` from the path: for ai-for-china-legal, the first path component is the plugin name (e.g., `commercial-legal`); for legal-skills, plugin is `None`
     - Compute `skill_id`: for ai-for-china-legal, `f"{plugin}:{name}"`; for legal-skills, `f"legal-{name}"`; for shared skills (path starts with `shared/`), `f"shared:{name}"`
   - Returns `ScanResult(repo_name=repo_name, repo_path=str(repo_path), skills=skills, warnings=repo_warnings)`

5. A helper function `_compute_depth(relative_path: str) -> int`:
   - Splits the path by `/`
   - Finds the index of `skills` component
   - Returns the number of path components between `skills/` and `SKILL.md`, minus 2 (0 = `skills/<name>/SKILL.md`, 1 = `skills/<parent>/<name>/SKILL.md`)
   - For legal-skills flat structure (`skills/<name>/SKILL.md`), returns 0
   - For paths not containing `skills/` (e.g., `shared/research-gate/SKILL.md`), returns 0

6. A helper function `_determine_plugin(relative_path: str, repo_name: str) -> str | None`:
   - For `ai-for-china-legal`: returns the first path component if it's not `shared`, else returns `"shared"`
   - For `legal-skills`: returns `None`

7. A helper function `_compute_skill_id(name: str, plugin: str | None, repo_name: str) -> str`:
   - If `repo_name == "legal-skills"`: returns `f"legal-{name}"`
   - If `plugin == "shared"`: returns `f"shared:{name}"`
   - If `plugin is not None`: returns `f"{plugin}:{name}"`
   - Fallback: returns `name`

Import `Path` from pathlib, `Any` from typing, `dataclass`, `field` from dataclasses. Import `parse_frontmatter`, `extract_name` from `.frontmatter_parser`. Import `estimate_tokens` from `.token_estimator`.

CRITICAL: The scanner must NEVER call any write operation — no `path.write_text()`, no `path.touch()`, no `os.rename()`, no `shutil` operations. It reads files only. The `scan_repo` function must not create any temp files in the source repo. All file reads use `path.read_text(encoding="utf-8")`. The scanner must handle `PermissionError` and `UnicodeDecodeError` gracefully by producing a warning record instead of crashing.
