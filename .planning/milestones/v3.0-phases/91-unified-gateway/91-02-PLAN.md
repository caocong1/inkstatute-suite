# Plan 91-02: SSE Last-Event-ID Replay — In-Memory Event Buffer, Seq-Based Reconnection, Integration Tests

## Goal

Implement SSE Last-Event-ID reconnection for the Gateway: when a client disconnects from a `GET /v1/runs/{id}/events` SSE stream and reconnects with a `Last-Event-ID` header, the Gateway replays all events with `seq > last_event_id` from an in-memory per-run event buffer, then continues streaming new events. The replay must be seq-based (not timestamp-based), must not duplicate events, and must not lose events. This satisfies GW-02: "SSE 流式传输统一事件，支持 `Last-Event-ID` 按 `seq` 断线续传，不重复不丢失".

The in-memory event buffer stores events per `run_id` with their `seq` numbers. On reconnection, the Gateway finds events with `seq > last_seq`, replays them in seq order, then continues streaming. Buffer size is capped at 1000 events per run (sufficient for single-firm scale ≤50 lawyers). Terminal-state runs keep their buffer for 5 minutes then clean up.

## Reversibility Gate

**One-way-door:** The Last-Event-ID replay contract — once the Gateway supports `Last-Event-ID` reconnection, clients will depend on it for connection resilience. Removing it would break reconnection behavior. Strategy: the replay logic is isolated in `event_buffer.py` (a separate module) so it can be tested independently. The `seq`-based replay protocol is dictated by the existing `RunEvent.seq` field (Phase 88), not a new design choice — it is stable by definition. The buffer is in-memory only (no persistent storage), so the contract is "best-effort replay for events still in buffer" — if the buffer has been cleaned up, the client gets a fresh stream from the current position.

**One-way-door:** Modifying `services/gateway/src/gateway/app.py` (shared with Plan 91-03). Strategy: this plan modifies `app.py` only in the `handle_stream_run` handler and the `stream` method to integrate the event buffer. The changes are additive — the existing tracer slice behavior (from Plan 91-01) is preserved. Plan 91-03 depends on this plan to avoid conflicting edits to `app.py`.

<action>
Create `services/gateway/src/gateway/event_buffer.py`. This module provides the in-memory event buffer for SSE Last-Event-ID reconnection.

Define the following:

1. A dataclass `BufferedEvent` with fields: `event: RunEvent`, `buffered_at: float` (timestamp when the event was added to the buffer). This wraps a `RunEvent` with buffer metadata.

2. A class `RunEventBuffer` with:
   - `__init__(self, *, max_events_per_run: int = 1000, terminal_retention_seconds: float = 300.0)` — stores config. `max_events_per_run` caps the buffer size per run (default 1000). `terminal_retention_seconds` is how long to keep the buffer after a run reaches terminal state (default 300 = 5 minutes).
   - `def append(self, run_id: str, event: RunEvent) -> None` — appends an event to the buffer for `run_id`. If the buffer exceeds `max_events_per_run`, the oldest events are evicted (FIFO). If the event's `event_type` indicates a terminal state (`run.state_changed` with status `succeeded`, `failed`, or `cancelled`), marks the run as terminal with a timestamp.
   - `def replay(self, run_id: str, last_seq: int) -> list[RunEvent]` — returns events for `run_id` with `seq > last_seq`, ordered by `seq` ascending. Returns an empty list if no events match or the buffer has been cleaned up.
   - `def get_buffered_events(self, run_id: str) -> list[RunEvent]` — returns all buffered events for `run_id` (for testing/debugging).
   - `def is_terminal(self, run_id: str) -> bool` — returns `True` if the run has reached terminal state.
   - `def cleanup_expired(self, now: float | None = None) -> int` — removes buffers for terminal runs whose retention period has expired. Returns the count of removed run buffers.
   - `def clear_run(self, run_id: str) -> None` — removes the buffer for a specific run (used when a run is cancelled or explicitly cleaned up).

3. Terminal state detection: a helper function `_is_terminal_event(event: RunEvent) -> bool` that checks if the event's `event_type == "run.state_changed"` and the payload contains a status of `succeeded`, `failed`, or `cancelled`. Import `RunEventType` from `platform_contract.enums` for the event type constant.

4. The buffer must be thread-safe (use `threading.Lock`) since the Gateway may serve multiple concurrent SSE connections.

Import `RunEvent` from `platform_runtime.protocols`. Import `RunEventType` from `platform_contract.enums`. Import `threading`, `time` from stdlib. Import `dataclass`, `field` from `dataclasses`.

The buffer is purely in-memory — no persistent storage, no external dependencies. This is sufficient for single-firm scale (≤50 lawyers) per Key Decision #4.
</action>

<action>
Modify `services/gateway/src/gateway/app.py` to integrate the `RunEventBuffer` into the SSE streaming flow.

1. Add `event_buffer: RunEventBuffer` as a constructor parameter to `GatewayApp.__init__`. Store it as `self._event_buffer`.

2. Modify the `stream` method to:
   - Extract the `Last-Event-ID` header using `parse_last_event_id(headers)`.
   - When `Last-Event-ID` is present (not `None`), call `self._event_buffer.replay(run_id, last_seq)` to get buffered events with `seq > last_seq`.
   - Yield the replayed events as SSE frames first (via `GatewaySseStream.encode_event`), in seq order.
   - Then continue streaming new events from `runtime.stream(run_id)`, appending each event to the event buffer via `self._event_buffer.append(run_id, event)`.
   - When `Last-Event-ID` is absent, stream from the beginning (current behavior from Plan 91-01), appending each event to the buffer.

3. Modify `handle_stream_run` to:
   - Accept an optional `last_seq: int | None` parameter.
   - When `last_seq` is not `None`, first yield replayed events from the buffer, then continue with live events.
   - Append every streamed event to the event buffer (both replayed and live events are already in the buffer, but live events need to be appended as they arrive).

4. The replay events must be encoded through `GatewaySseStream.encode_event()` with the output boundary applied — replayed events go through the same boundary as live events. Events blocked by the boundary are skipped during replay.

5. After the stream completes (run reaches terminal state), the event buffer's `is_terminal` flag is set by the terminal event's `append` call. The buffer retains the events for `terminal_retention_seconds` (5 minutes) before cleanup.

CRITICAL: The replay must not duplicate events. If a client received events up to seq=5, disconnects, and reconnects with `Last-Event-ID: 5`, the replay returns only events with seq > 5. If the client reconnects with `Last-Event-ID: 3`, the replay returns events with seq > 3 (which may include events the client already saw — this is the client's responsibility to deduplicate by `event_id`). The Gateway guarantees no events with seq <= last_seq are replayed.

CRITICAL: This modification to `app.py` must not break the tracer slice from Plan 91-01. The existing `test_end_to_end_tracer_slice` test must still pass.
</action>
