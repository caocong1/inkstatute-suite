# Plan 93-02: Wave 2 — Workspace ChatPanel + EventStreamStore wiring + SSE reconnection + send/clarify/feedback actions

## Goal

Wire the ui-core `ChatPanel` to live Gateway SSE via `createEventStream()` + `PlatformApiClient`, proving the core lawyer interaction: send a message → see streaming reply → see five-phase progress → see events rendered. This plan replaces the tracer workspace shell (from Plan 93-01) with a fully functional workspace page that creates runs, streams events, and renders all ui-core chat components driven by `RenderState` from the event reducer.

The plan also implements the `SessionContext` — a per-workspace-page context that manages the active run's `EventStreamStore`, handles message sending (via `gateway.createRun()`), and provides the reactive `RenderState` signal to `ChatPanel`, `DocPreview`, `CitationPanel`, and `DraftingProgressSteps`. The SSE reconnection with Last-Event-ID is already implemented in ui-core's `EventStreamStore` (exponential backoff 1s→30s, idempotent reducer) — this plan verifies it works end-to-end through the Vite dev proxy.

This plan does NOT implement the remaining Gateway stubs (`submit_elicitation`, `submit_approval`, `get_session`, `list_session_runs`, `get_run`) — those are Plan 93-03. However, the workspace page must handle the case where these endpoints return 501 gracefully (show appropriate UI states). The `createRun` and `streamRun` endpoints are already fully implemented in the Gateway from Phase 91.

## Reversibility Gate

**One-way-door: EventStreamStore as the sole run state source in the workspace.** Once the workspace page creates an `EventStreamStore` per active run and feeds its `state()` signal to all ui-core components, there is no parallel state path for run data. Strategy: the `SessionContext` owns the `EventStreamStore` lifecycle (create on run start, stop on unmount), and all components receive `RenderState` via props from `stream.state()`. No component subscribes to SSE directly.

**One-way-door: createRun body shape.** The `PlatformApiClient.createRun(body)` accepts an `unknown` body. The web client must construct the `AgentTurn` + `SolutionBinding` payload matching the Gateway's `_build_agent_turn()` and `_build_solution_binding()` expectations (see `app.py` lines 488-613). Once this shape is locked, changing it requires coordinated Gateway + SDK changes. Strategy: create a `runBuilder.ts` utility that constructs the run body from a simple `{ conversationId, prompt, attachments? }` input, centralizing the shape in one module.

Create `apps/web/src/hooks/useEventStream.ts` — a SolidJS hook that wraps `createEventStream()` with reactive lifecycle management.

```typescript
import { createEffect, onCleanup, onMount } from "solid-js";
import { createEventStream, type EventStreamStore, type RenderState } from "@inkstatute/ui-core";
import { gateway } from "../config/gateway";

export function useEventStream(runId: () => string | null): {
  state: () => RenderState;
  isStreaming: () => boolean;
  error: () => Error | null;
  reconnect: () => void;
} {
  const [isStreaming, setIsStreaming] = createSignal(false);
  const [error, setError] = createSignal<Error | null>(null);
  let store: EventStreamStore | null = null;

  createEffect(() => {
    const id = runId();
    // Cleanup previous stream
    if (store) {
      store.stop();
      store = null;
      setIsStreaming(false);
    }
    if (!id) return;

    store = createEventStream({
      client: gateway,
      runId: id,
      onError: (err) => setError(err),
    });
    setIsStreaming(true);
    store.streamEvents().then(() => {
      setIsStreaming(false);
    }).catch((err) => {
      setError(err);
      setIsStreaming(false);
    });
  });

  onCleanup(() => {
    store?.stop();
  });

  function reconnect() {
    if (store) {
      setError(null);
      store.streamEvents();
    }
  }

  return {
    state: () => store?.state() ?? initialState(),
    isStreaming,
    error,
    reconnect,
  };
}
```

Key behaviors:
- When `runId()` changes (new run started), the effect cleans up the old stream and creates a new one
- `state()` returns the current `RenderState` from the store, or `initialState()` if no store exists
- `isStreaming()` tracks whether the SSE connection is active
- `error()` captures any stream errors for UI display
- `reconnect()` manually triggers a reconnection attempt
- `onCleanup()` stops the stream when the component unmounts (prevents memory leaks and orphaned SSE connections)
