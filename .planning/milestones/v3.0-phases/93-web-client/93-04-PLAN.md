# Plan 93-04: Wave 3 — Responsive mobile layout + Playwright E2E tests + gate registration + phase completion

## Goal

Add the responsive mobile layout (768px breakpoint, drawer navigation, tab toggle workspace), set up Playwright E2E tests covering the full lawyer flow on both desktop and mobile viewports, verify all 6 success criteria from the ROADMAP, and complete Phase 93.

This plan addresses the remaining success criteria not yet covered: #3 (mobile browser responsive layout — no horizontal scroll, touch targets, clarification card usable) and #6 (E2E tests cover the main flow with fixture backend, no real LLM). Success criteria #1 (app builds, uses ui-core, zero chat UI code), #2 (desktop full flow), #4 (reconnection), and #5 (multi-device) are proven by Plans 93-01 through 93-03 — this plan verifies them in the E2E context.

The responsive layout is CSS-first: media queries at 768px breakpoint, drawer overlay on mobile, tab toggle for workspace (chat / document / citations), 44px minimum touch targets, 16px font on inputs (prevents iOS auto-zoom), safe-area insets for notched devices. No custom gestures — the drawer opens via hamburger button tap, document preview uses native browser scroll/zoom.

The Playwright E2E tests use a fixture Gateway mock (Playwright route interception for non-streaming endpoints + a lightweight Node HTTP server for SSE streaming) that replays the fixture event sequence from ui-core's test fixtures. Tests cover: login, new session, send task, streaming reply, five-phase progress, clarification card, artifact download, feedback, reconnection, and mobile viewport.

## Reversibility Gate

**One-way-door: 768px breakpoint as the single responsive breakpoint.** Once the CSS media queries at `@media (max-width: 767px)` and `@media (min-width: 768px)` are in `app-shell.css`, all responsive behavior is anchored to this single breakpoint. Strategy: the breakpoint matches the UI-SPEC contract and is CSS-only — no JS-based device detection. The layout switches between sidebar (desktop) and drawer (mobile) purely via CSS.

**One-way-door: Playwright as the E2E framework.** Adding `@playwright/test` as a devDependency and creating `playwright.config.ts` commits the project to Playwright for E2E testing. Strategy: Playwright is the standard choice for web E2E, supports Chromium/Firefox/WebKit, and can test responsive layouts via viewport configuration. The fixture Gateway mock uses Playwright's `page.route()` for non-streaming endpoints and a lightweight HTTP server for SSE.
