**Wave**: 2
**Depends on**: 99-01 (requires `PracticeProfile`, `PracticeProfileStore`, `InMemoryPracticeProfileStore`, `create_temporary_profile`, `TEMPORARY_MODE_TAG`)

### Task 99-02-01: Create `injector.py` — PracticeProfileInjector

**Action**: Create `packages/practice-profile/src/inkstatute_practice_profile/injector.py` defining `PracticeProfileInjector`. The injector takes a `PracticeProfileStore` and an optional `skill_index_path` (path to `skill-index.json`). Its primary method is `inject(skill_id: str, tenant_id: str, plugin: str | None = None) -> ProfileInjectionResult`. The flow: (1) Check if the skill has `practice_profile_dependency=True` in the index — if False, return a result with `profile_injected=False` and empty context; (2) If True, determine the plugin (from the skill's index record `plugin` field, or from the `plugin` parameter); (3) Fetch the tenant's profile from the store via `store.get(tenant_id, plugin)`; (4) If no profile exists, generate a temporary profile via `create_temporary_profile(tenant_id, plugin)`; (5) Render the profile as a markdown context section starting with `## 执业配置` — if temporary mode, prepend the `[临时模式]` tag; (6) Return a `ProfileInjectionResult` with `context_section: str`, `profile_injected: bool`, `temporary_mode: bool`, `plugin: str | None`. The context section format: `## 执业配置\n\n### 身份信息\n...\n### 审查立场\n...\n### 升级矩阵\n...\n### 文书风格\n...\n### 管辖识别\n...` (only sections that have non-empty data are included). In temporary mode, the section starts with `[临时模式 — 配置你的档案以获得定制输出]\n\n## 执业配置\n\n...`.

### Task 99-02-02: Create `interview.py` — ColdStartInterviewOrchestrator

**Action**: Create `packages/practice-profile/src/inkstatute_practice_profile/interview.py` defining `ColdStartInterviewOrchestrator`. The orchestrator manages the 5-step cold-start interview, emitting `ElicitationRequestedPayload` events in sequence. Each step maps to one `elicitation.requested` event with 2-4 questions (enforced by `validate_question_count`). The 5 steps for commercial-legal (reference implementation): (1) `identity-team` — identity, practice environment, team structure, integrations; (2) `review-stance` — risk appetite, 甲方/乙方 stance; (3) `escalation-rules` — amount thresholds, auto-escalation triggers; (4) `document-style` — output format, tone, citation preferences; (5) `jurisdiction-profile` — governing law, local regulations. The orchestrator exports: `InterviewStep` (frozen dataclass with `step_id`, `intro`, `questions: list[ElicitationQuestion]`), `InterviewState` (frozen dataclass with `tenant_id`, `plugin`, `current_step_index`, `completed_steps: list[str]`, `answers: dict[str, dict[str, str]]`), `ColdStartInterviewOrchestrator` (class with `start(tenant_id, plugin) -> InterviewState`, `get_current_elicitation(state) -> ElicitationRequestedPayload`, `submit_answers(state, answers: dict[str, str]) -> InterviewState`, `is_complete(state) -> bool`, `finalize(state) -> PracticeProfile`). The `submit_answers` method writes answers to the state and advances to the next step. The `finalize` method constructs a `PracticeProfile` from the collected answers and writes it to the `PracticeProfileStore` via `store.upsert`. The question definitions for commercial-legal are defined as a module-level constant `COMMERCIAL_LEGAL_INTERVIEW_STEPS: list[InterviewStep]`. Each step has exactly 2-4 `ElicitationQuestion` objects with `id`, `question`, `allow_multiple`, and `options` (where applicable).
