### Task 99-01-02: Create `model.py` — PracticeProfile dataclass with plugin-specific sections

**Action**: Create `packages/practice-profile/src/inkstatute_practice_profile/model.py` defining the `PracticeProfile` frozen dataclass. The model has a common header (identity, role, integrations) plus a `plugin_configs: dict[str, JsonObject]` map where each key is a plugin name (e.g., `"commercial-legal"`, `"litigation-legal"`) and the value is that plugin's practice profile data as a `JsonObject` (from `platform_contract.events`). The common header fields are: `tenant_id: str`, `plugin: str` (which plugin this profile is for — a profile is per-plugin per-tenant), `identity: JsonObject` (org_name, entity_type, team_size, escalation_contact, monthly_volume, counterparty_type, practice_environment), `user_role: JsonObject` (role, lawyer_contact), `integrations: JsonObject` (contract_mgmt, e_signature, doc_storage, wecom_dingtalk), `escalation_matrix: JsonObject` (approval_table, amount_thresholds, auto_escalation_triggers), `document_style: JsonObject` (revision_tone, stakeholder_summary, work_product_location, renewal_reminder_recipient), `shared_guardrails: JsonObject` (no_silent_fill, timeliness_trigger, legal_fact_verification, source_labels, destination_check, dual_severity, jurisdiction_identification), `plugin_configs: dict[str, JsonObject]` (domain-specific sections like 审查立场 for commercial-legal, 风险校准 for litigation-legal), `temporary_mode: bool = False`, `updated_at: str | None = None`. The dataclass is frozen with `slots=True`. Include a `to_json() -> JsonObject` and `from_json(data: JsonObject) -> PracticeProfile` round-trip serialization pair.

### Task 99-01-04: Create `secret_guard.py` — secret detection on profile write

**Action**: Create `packages/practice-profile/src/inkstatute_practice_profile/secret_guard.py` that validates practice profile data on write, rejecting fields that match secret patterns. Reuse the pattern philosophy from `packages/acp-event-bridge/src/inkstatute_acp_event_bridge/privacy_scan.py` (11 compiled regex patterns) but define a focused subset for practice profile fields. The module exports `validate_no_secrets(data: JsonObject) -> None` which raises `SecretDetectedError(field_path: str, pattern_name: str)` if any field value matches a secret pattern. The error message must NEVER include the matched secret text — only the field path and pattern name. Patterns to check: `api_key`/`access_token`/`secret_key` assignments, PEM private key blocks (`-----BEGIN ... PRIVATE KEY-----`), `password`/`passwd`/`pwd` assignments, `aes_key`/`encoding_aes_key` references, and `HERMES_HOME`/`ACP_*`/`AGENT_*` env secret assignments. The validator recursively traverses nested dicts and lists, checking all string values.

### Task 99-01-05: Create `store.py` — PracticeProfileStore Protocol + InMemoryPracticeProfileStore

**Action**: Create `packages/practice-profile/src/inkstatute_practice_profile/store.py` defining the `PracticeProfileStore` Protocol and `InMemoryPracticeProfileStore` implementation, following the `SessionStore` / `InMemorySessionStore` pattern from `packages/rbac/src/rbac/session.py`. The Protocol has methods: `get(tenant_id: str, plugin: str) -> PracticeProfile | None`, `upsert(tenant_id: str, profile: PracticeProfile) -> None` (validates no secrets before storing, calls `validate_no_secrets(profile.to_json())`), `delete(tenant_id: str, plugin: str) -> None`, and `list_plugins(tenant_id: str) -> list[str]`. The `InMemoryPracticeProfileStore` is thread-safe via `threading.Lock`, stores profiles in a `dict[tuple[str, str], PracticeProfile]` keyed by `(tenant_id, plugin)`. The `upsert` method enforces that `profile.tenant_id == tenant_id` and `profile.plugin == plugin` (raises `ValueError` on mismatch). The `upsert` method calls `validate_no_secrets` before storing — if secrets are detected, the write is rejected and the error propagates. Cross-tenant access is enforced at the Gateway layer (Plan 99-03), not in the store itself — the store trusts the caller has already verified tenant access.
