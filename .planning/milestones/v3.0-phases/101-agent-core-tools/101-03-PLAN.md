### Task 101-03-02: Implement document_generate tool

**Action**: Create `packages/agent-core/src/inkstatute_agent_core/tools/document_generate.py` with the document generation tool handler. This tool imports `TrackChangesBuilder` (not a rewrite per CORE-03) and produces a `.docx` with native Word track changes.

The document_generate tool:
1. Receives arguments: `input_docx_path` (str), `review_items` (list of dicts), `output_path` (str), `reviewer` (str, optional — defaults to "乙方律师审查")
2. Validates input and output paths via `PathSandbox` (both must be within allowed roots)
3. Lazy-imports `TrackChangesBuilder` via `importlib.import_module()` (matching the provider_model lazy-import pattern) — the import path is configurable, defaulting to the lawfirm-profile scripts location. If the import fails (e.g., lxml not installed), returns an error `ToolResult` (not a crash).
4. Constructs `TrackChangesBuilder(input_docx_path)`
5. Calls `builder.process(review_items=review_items)` (using the adapted method from Task 101-03-01)
6. Calls `builder.save(output_path)`
7. Constructs `Artifact(artifact_id=str(uuid4()), kind=ArtifactKind.TRACKCHANGES_DOCX, name=<filename>, uri=f"file://{output_path}", mime_type="application/vnd.openxmlformats-officedocument.wordprocessingml.document")`
8. Emits `artifact.created` event via `emitter.emit_artifact_created(artifact)` — **requires an EventEmitter**, so the tool is created via a factory: `create_document_generate_tool(sandbox: PathSandbox, emitter: EventEmitter, script_path: str | None = None) -> ToolHandler`
9. Returns `ToolResult(content=f"修订版已生成: {output_path}", metadata={"artifact_id": artifact.artifact_id, "output_path": output_path, "review_results": results_summary})`

The `script_path` parameter defaults to `/home/sorawatcher/workspace/lawfirm-profile/scripts/contract_review_trackchanges.py`. The lazy import uses `importlib.util.spec_from_file_location()` to load the module from the file path (since it's not on the Python path).

### Task 101-03-03: Verify generated docx has native Word track changes markers

**Action**: Create a verification test that checks the generated docx contains native Word track changes OOXML elements. The test:
1. Creates a minimal input docx fixture (a simple docx with a few paragraphs of text)
2. Defines 2-3 review items that match text in the fixture
3. Calls the document_generate tool
4. Unzips the output docx and parses `word/document.xml`
5. Asserts the presence of:
   - `<w:ins>` elements (insertions) with `w:author` and `w:date` attributes
   - `<w:del>` elements (deletions) with `w:author` and `w:date` attributes
   - `<w:delText>` elements (deleted text, converted from `<w:t>`)
   - `word/comments.xml` part exists in the zip
   - `<w:comment>` elements in `comments.xml`
   - `<w:commentRangeStart>` / `<w:commentRangeEnd>` / `<w:commentReference>` in `document.xml`
   - `[Content_Types].xml` has an `Override` for `comments.xml`
   - `word/_rels/document.xml.rels` has a `Relationship` targeting `comments.xml`

This test verifies CORE-03's requirement that "产出的 docx 在 Word 中显示为原生修订标记" — the OOXML elements that Word interprets as native track changes are present.
