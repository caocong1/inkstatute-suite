### Task 101-02-01: Implement PathSandbox for file reading security

**Action**: Create `packages/agent-core/src/inkstatute_agent_core/tools/path_sandbox.py` with a `PathSandbox` class that validates file paths against an allowlist of root directories. This is a port of the Rust `PathSandbox` from `lawyer-desktop/src-tauri/src/security/path_sandbox.rs`.

`PathSandbox`:
- `__init__(allowed_roots: list[str | Path])` — stores canonicalized root paths
- `validate(path: str | Path) -> Path` — validates and returns the canonical path:
  1. Reject paths with `..` components (path traversal prevention) — check `Path(path).parts` for `".."` 
  2. Canonicalize the path via `Path(path).resolve()` (resolves symlinks)
  3. Check the canonical path starts with at least one allowed root (also canonicalized)
  4. If not within any root, raise `PermissionError("access denied: outside allowed directories")`
  5. Return the canonical path
- `is_allowed(path: str | Path) -> bool` — returns True/False instead of raising

### Task 101-02-02: Implement file_read tool

**Action**: Create `packages/agent-core/src/inkstatute_agent_core/tools/file_read.py` with the file reading tool handler. The tool:
1. Receives arguments: `path` (str — file path to read), `max_chars` (int, optional, default 50000)
2. Validates the path via `PathSandbox.validate()`
3. Reads the file as text (try UTF-8, fall back to latin-1 for encoding resilience)
4. Truncates to `max_chars` if exceeded (appends `"...[truncated]"` indicator)
5. Binary files (detected by null bytes in first 8KB) are rejected with a clear error message
6. Returns `ToolResult(content=file_text)` on success, `ToolResult(content=..., error=ErrorInfo(...))` on failure

The `create_file_read_tool(sandbox: PathSandbox) -> ToolHandler` factory function captures the sandbox. Also define the OpenAI tool definition:

```python

    "type": "function",
    "function": {
        "name": "read_file",
        "description": "读取指定路径的文件内容（仅限工作区/上传目录，只读，最大50000字符）",
        "parameters": {
            "type": "object",
            "properties": {
                "path": {"type": "string", "description": "文件路径（相对于工作区根目录或绝对路径）"},
                "max_chars": {"type": "integer", "description": "最大读取字符数（默认50000）"}
            },
            "required": ["path"]
        }
    }
}
```

### Task 101-02-03: Implement MCP client (JSON-RPC 2.0 over stdio)

**Action**: Create `packages/agent-core/src/inkstatute_agent_core/tools/mcp_client.py` with a `McpClient` class that implements the MCP protocol (JSON-RPC 2.0 over stdio) for communicating with Node.js connector subprocesses.

`McpClient`:
- `__init__(connector_path: str, env: dict[str, str] | None = None, timeout: float = 40.0)` — stores connector path, environment, and timeout. The connector path is **configured** (not user-supplied) — this is a controlled subprocess, not arbitrary shell execution.
- `async def start() -> None` — spawns the Node.js connector as a subprocess (`asyncio.create_subprocess_exec("node", connector_path, stdin=PIPE, stdout=PIPE, stderr=PIPE)`), performs `initialize` handshake (protocol version "2024-11-05"), sends `notifications/initialized`
- `async def list_tools() -> list[dict]` — calls `tools/list` and returns the list of tool descriptors (`{name, description, inputSchema}`)
- `async def call_tool(name: str, arguments: dict) -> str` — calls `tools/call` with `{name, arguments}`, parses response (`{content: [{type: "text", text}], isError}`), returns the text content. If `isError` is true, raises an exception with the error text.
- `async def close() -> None` — terminates the subprocess, cleans up
- `async def __aenter__()` / `async def __aexit__()` — async context manager support

JSON-RPC protocol implementation:
- One JSON object per line on stdin, exactly one JSON object per line on stdout
- Request: `{"jsonrpc": "2.0", "id": <int>, "method": "...", "params": {...}}`
- Response: `{"jsonrpc": "2.0", "id": <int>, "result": {...}}` or `{"jsonrpc": "2.0", "id": <int>, "error": {"code": ..., "message": ...}}`
- Notification (no id, no response): `{"jsonrpc": "2.0", "method": "notifications/initialized"}`
- Auto-incrementing request ID counter starting from 1
- `asyncio.Queue` for matching responses to requests by ID (read stdout line by line in a background task)

Also implement `mcp_input_schema_to_openai_parameters(input_schema: dict) -> dict` — converts MCP `inputSchema` to OpenAI `parameters` format (direct passthrough — both are JSON Schema `{"type": "object", "properties": ..., "required": ...}`).

And `mcp_tool_to_openai_definition(tool: dict) -> dict` — wraps an MCP tool descriptor into OpenAI function-calling format: `{"type": "function", "function": {"name": tool["name"], "description": tool["description"], "parameters": tool["inputSchema"]}}`.

### Task 101-02-04: Implement regulation search tool via MCP client

**Action**: Create `packages/agent-core/src/inkstatute_agent_core/tools/regulation_search.py` with the regulation search tool handler. This tool is a thin wrapper that calls the `law-database` MCP connector via the MCP client.

The regulation search tool:
1. Receives arguments: `keyword` (str), `law_type` (str, optional), `issuing_authority` (str, optional), `status` (str, optional)
2. Uses the `McpClient` to call `search_laws` on the `law-database` connector
3. Returns the search results text as `ToolResult(content=results_text)`

The `create_regulation_search_tool(mcp_client: McpClient) -> ToolHandler` factory function captures the MCP client. Also define the OpenAI tool definition for `search_laws`.

Additionally, implement a **fixture mode** for testing: when `LAW_DB_FIXTURES=1` environment variable is set, the tool returns canned responses (matching the law-database connector's own fixture mode). This enables testing without network or Node.js. The fixture mode can be implemented as an alternative handler: `create_fixture_regulation_search_tool(fixture_responses: dict[str, str]) -> ToolHandler` that returns canned responses based on the keyword.
