# Plan 95-01: Bot Tracer — Gateway Client + Event Consumer + WeCom Degradation Tracer

## Goal

Create the two new modules that form the bot-to-Gateway consumption path: `gateway_client.py` (thin stdlib HTTP client for Gateway API) and `event_consumer.py` (SSE consumer + degradation aggregator + delivery mapper). This plan implements the end-to-end tracer slice for WeCom: a normalized inbound callback → `GatewayClient.create_run()` → `GatewayClient.stream_events()` (SSE) → collect events → `aggregate_events()` → map `BotDelivery` to `adapter.deliver()` calls.

This is the minimal vertical slice that proves:
1. A bot service can create a Gateway run via HTTP POST with Bearer token auth
2. A bot service can consume the Gateway SSE stream and collect events
3. The pure-function `aggregate_events()` from Phase 88 produces a correct `BotDelivery` from collected events
4. The `BotDelivery` maps correctly to WeCom `ChannelDelivery` calls (text, card, file)
5. Intermediate prompts ("正在检索法规…", "仍在处理") are delivered during the stream, not after

No existing files are modified in this plan — `webhook.py` and `wiring.py` are changed in Plan 95-02. This plan only adds new modules and tests, proving the consumption path works before wiring it into the live webhook flow.

## Reversibility Gate

**One-way-door:** Creating `gateway_client.py` and `event_consumer.py` in `services/wecom-service/src/wecom_service/`. These new files are automatically covered by the existing `wecom-service` gate (#2) which runs `unittest discover -s services/wecom-service/tests`. Once the tests pass, removing these modules would break the gate. Strategy: the modules are purely additive — no existing source file is modified. The `__init__.py` is updated only to export the new symbols. If the tracer doesn't work, the modules can be removed without affecting any existing test.

**One-way-door:** The Gateway consumption pattern — bot services talk to Gateway via HTTP, not via direct runtime imports. Once `gateway_client.py` exists, the architectural direction is set: bots are Gateway consumers, not direct agent callers. Strategy: this plan does NOT modify `webhook.py` or `wiring.py` — the old direct-agent-call path remains functional in parallel. The tracer proves the new path works; Plan 95-02 does the switchover.

Create `services/wecom-service/src/wecom_service/gateway_client.py`. This module provides a thin HTTP client for the Gateway API using only stdlib (`urllib.request`, `http.client`, `json`). No external dependencies.

Define the following:

1. A frozen slotted dataclass `GatewayClientConfig` with fields:
   - `base_url: str` — Gateway base URL (e.g., `http://127.0.0.1:8081`)
   - `bearer_token: str` — pre-resolved Bearer token for auth
   - `tenant_id: str = "default-tenant"` — tenant ID for run creation
   - `timeout_seconds: float = 30.0` — HTTP request timeout

2. A class `GatewayClient` with:
   - `__init__(self, config: GatewayClientConfig)` — stores config. No network connection at construction time.
   - `def create_session(self, *, conversation_id: str) -> dict[str, Any]` — POST `/v1/sessions` with `{"conversation_id": conversation_id, "tenant_id": config.tenant_id}`. Returns `{"session_id": ..., "tenant_id": ...}`. Uses `urllib.request.Request` with `Authorization: Bearer {token}` header.
   - `def create_run(self, *, turn: dict[str, Any], solution: dict[str, Any], session_id: str | None = None) -> dict[str, Any]` — POST `/v1/runs` with `{"turn": turn, "solution": solution, "session_id": session_id}`. Returns `{"run_id": ..., "status": ...}`.
   - `def stream_events(self, run_id: str, *, last_event_id: int | None = None) -> Iterator[dict[str, Any]]` — GET `/v1/runs/{run_id}/events` with `Accept: text/event-stream`. If `last_event_id` is provided, sends `Last-Event-ID: {last_event_id}` header. Reads the HTTP response line-by-line, parses SSE frames (`id:`, `event:`, `data:` lines), and yields each event as a parsed dict. The iterator ends when the HTTP connection closes (terminal state). Uses `http.client.HTTPConnection` for streaming reads.
   - `def submit_elicitation(self, run_id: str, *, interrupt_id: str, answers: dict[str, Any]) -> dict[str, Any]` — POST `/v1/runs/{run_id}/elicitation` with `{"interrupt_id": interrupt_id, "answers": answers}`. Returns response dict.
   - `def submit_approval(self, run_id: str, *, permission_id: str, decision: str) -> dict[str, Any]` — POST `/v1/runs/{run_id}/approvals` with `{"permission_id": permission_id, "decision": decision}`. Returns response dict.
   - `def download_artifact(self, artifact_id: str) -> bytes` — GET `/v1/artifacts/{artifact_id}`. Returns the raw artifact bytes.
   - `def submit_feedback(self, *, run_id: str, feedback_data: dict[str, Any]) -> dict[str, Any]` — POST `/v1/feedback` with feedback payload. Returns response dict.

3. A helper function `_parse_sse_frame(lines: list[str]) -> dict[str, Any] | None` — parses a group of SSE lines (separated by blank line) into an event dict. Extracts `id` (event_id), `event` (event_type), and `data` (JSON-parsed payload). Returns `None` for incomplete frames.

4. A helper function `_build_headers(config: GatewayClientConfig, *, extra: dict[str, str] | None = None) -> dict[str, str]` — builds the standard headers dict with `Authorization: Bearer {token}`, `Content-Type: application/json`, plus any extra headers.

5. A custom exception `GatewayClientError(Exception)` with fields `status: int`, `code: str`, `message: str`. Raised on non-2xx HTTP responses.

Import `urllib.request`, `http.client`, `json`, `time` from stdlib. Import `Iterator`, `Any`, `Mapping` from typing/collections.abc. No imports from the gateway package itself — this is an HTTP client, not an in-process caller.

CRITICAL: All methods must include the `Authorization: Bearer {token}` header. No method bypasses auth. The `stream_events` method must handle SSE frame parsing correctly: `id:` line sets event_id, `event:` line sets event_type, `data:` line(s) are concatenated and JSON-parsed. Frames are separated by blank lines. The iterator must yield events as they arrive (not buffer the entire stream), but for single-firm scale a blocking read is acceptable.

     1. Create or reuse a Gateway session (if `session_id` is None, call `gateway_client.create_session(conversation_id=conversation_id)`)

     3. Consume the SSE stream via `gateway_client.stream_events(run_id)`, collecting events into a list
     4. During streaming: when `tool_call.*` events arrive (first one only), send "正在检索法规…" via `adapter.deliver()` with `delivery_type="text"`. When `plan.updated`/`phase.changed` events arrive (first one only), send "仍在处理" via `adapter.deliver()`.      5. When the stream ends (terminal state), call `aggregate_events(collected_events)` to get `BotDelivery`
     6. Map `BotDelivery` to `adapter.deliver()` calls:

        - `error_prompt` → `ChannelDelivery(delivery_type="text", content=error_prompt, to_user=to_user)`
     7. Return an evidence dict: `{"status": "completed", "run_id": run_id, "delivery_count": N, "delivered": bot_delivery.delivered}`

   - `def _map_card_to_delivery(self, card: dict[str, Any], *, to_user: str, run_id: str) -> ChannelDelivery` — maps an elicitation/permission card payload to a WeCom `ChannelDelivery` with `delivery_type="card"`.    - `def _map_file_to_delivery(self, file_payload: dict[str, Any], *, to_user: str, run_id: str) -> ChannelDelivery | None` — maps an artifact payload to a WeCom `ChannelDelivery` with `delivery_type="file"`.    - `def _should_send_intermediate(self, event: dict[str, Any], state: dict[str, Any]) -> bool` — determines if an intermediate prompt should be sent for this event based on degradation rules (FOLD for first tool_call, FIRST_THEN_SILENT for first plan/phase, time-based for subsequent "仍在处理").
