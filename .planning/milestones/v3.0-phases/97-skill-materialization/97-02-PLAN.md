# Plan 97-02: Context Budget Injector — Section-Priority Deterministic Trim

**Wave**: 2
**Depends on**: 97-01 (uses materializer's output structure and IndexRecord format)
**Requirements**: SKILL-06
**Scope**: Implement the `SkillBodyInjector` with section-priority deterministic budget trimming. Given a token budget and a skill body (2K–20K tokens), the injector parses SKILL.md into sections, assigns priorities, trims from lowest priority, and produces a `SkillBodyInjectionResult` with a trim report. This plan can run in parallel with 97-03 (no file conflicts).

## Tasks

### Task 97-02-01: Implement SkillBodyInjector with section-priority deterministic trim

**Action**: Implement `body_injector.py` with the `SkillBodyInjector` class and `SkillBodyInjectionResult` dataclass. Parse SKILL.md into sections using markdown headers (`##`). Assign priorities: (1) Protected (never trimmed): frontmatter + description + first section, (2) High: gate sections (research-gate, ask-user-enforcement), (3) Medium: core instructions, orchestration tables, (4) Low: examples, appendices, references. Trim from lowest priority until under budget. Use the CJK-aware token estimation heuristic from Phase 96: `token_estimate = (CJK_chars × 1.0) + (non_CJK_chars / 4)`.

**Files to create/modify**:
- `packages/skill-materializer/src/inkstatute_skill_materializer/body_injector.py` (full implementation)
- `packages/skill-materializer/tests/test_body_injector.py`
- `packages/skill-materializer/tests/fixtures/body_injector_fixtures.py` (SKILL.md samples of varying lengths)

**Read first**:
- `packages/platform-runtime/src/platform_runtime/context_assembler.py` (lines 17, 82-100, 237-276 — budget enforcement pattern: `ContextAssemblyPolicy`, `ContextAssemblyBudgetError`, trim algorithm)
- `packages/skill-index/src/inkstatute_skill_index/index_builder.py` (IndexRecord.token_estimate field)
- `.planning/phases/97-skill-materialization/97-CONTEXT.md` §6 (context budget injection decision, section-priority trim)
- `.planning/phases/97-skill-materialization/97-RESEARCH.md` §7 (existing budget logic, Phase 97 adaptation, token range verification, CJK-aware heuristic)

**Acceptance criteria**:
- [ ] `SkillBodyInjector(budget_tokens=N, chars_per_token=4)` constructs an injector with the given budget
- [ ] `injector.inject(skill_body_text)` returns a `SkillBodyInjectionResult`
- [ ] `SkillBodyInjectionResult` contains: `injected_text`, `original_token_estimate`, `injected_token_estimate`, `trimmed_sections` (list of `{section_name, priority, original_tokens, reason}`), `budget_used`, `budget_tokens`
- [ ] Section parsing: SKILL.md is split by `## ` headers; frontmatter (YAML between `---` fences) is always protected
- [ ] Priority assignment: frontmatter + description + first `##` section = protected; sections containing "research-gate" or "ask-user" in header = high; sections with "example"/"appendix"/"reference" in header = low; all others = medium
- [ ] Trim algorithm: while `injected_token_estimate > budget_tokens`, remove the lowest-priority section with the most tokens; record in `trimmed_sections`; re-estimate
- [ ] If protected sections alone exceed budget, raise `SkillBodyBudgetError` (mirrors `ContextAssemblyBudgetError` pattern)
- [ ] Deterministic: same input + same budget → same output (no random, no LLM)
- [ ] Token estimation uses CJK-aware heuristic: `CJK_chars × 1.0 + non_CJK_chars / 4`
- [ ] Unit tests with fixture SKILL.md bodies of ~2K, ~5K, ~10K, ~20K tokens pass
- [ ] Test: budget=10000 on a 20000-token body → result has `injected_token_estimate <= 10000` and `trimmed_sections` is non-empty
- [ ] Test: budget=100000 on a 2000-token body → result has `injected_text == original_text` and `trimmed_sections` is empty
- [ ] Test: budget=100 on a body with 500-token protected sections → raises `SkillBodyBudgetError`
