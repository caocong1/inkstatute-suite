# Plan 90-02: ACP Output Filter — Backend Noise Blocking, Business Rewrite, Integration with Existing Output Boundary

## Goal

Implement ACP-specific output boundary rules in `output_filter.py` that block or rewrite backend noise categories (meta, gateway, system, update, command, help, `available_commands_update`, terminal) before they reach the unified event stream. This is the first enforcement point of the "output boundary enforced twice" requirement (AGENTS.md: bridge + gateway). The filter integrates with the existing `DefaultAssistantOutputBoundary` from `platform-runtime` by adding ACP-specific pre-filtering for notification types and content patterns that are pure backend noise.

The filter produces a `FilterDecision` (ALLOW / REWRITE / BLOCK) for each event passing through the bridge, with audit metadata using reference-first logging (hash prefix + length, no original text stored).

## Reversibility Gate

**One-way-door:** The set of blocked content categories (meta, gateway, system, update, command, help, `available_commands_update`, terminal) defines what backend noise is invisible to users. Once these are blocked, removing a category from the block list would make previously-invisible backend noise visible — a user-facing behavior change. Strategy: the blocked categories are derived directly from requirement ACP-05 (not a design choice), so they are stable by definition. The filter uses a default-deny policy for unknown ACP notification types (explicit allowlist for known types), which means new notification types are blocked by default until explicitly allowed — this is a safe default that requires conscious action to relax.

**One-way-door:** The filter integrates with the existing `DefaultAssistantOutputBoundary.apply()` method. The integration pattern (ACP-specific pre-filter → existing boundary → final decision) establishes the processing order. Strategy: the ACP pre-filter runs first (cheapest check — type-based, no text scanning), then the existing boundary runs for content that passes the pre-filter. This order is documented in `output_filter.py` and tested.

Define:

1. A `StrEnum` `FilterAction` with values `ALLOW = "allow"`, `REWRITE = "rewrite"`, `BLOCK = "block"` (reuse `BoundaryAction` from `platform_runtime.output_boundary` if importable, otherwise define locally).

2. A frozen slotted dataclass `FilterDecision` with fields: `action: str`, `visible_content: str | None`, `audit_metadata: dict`, `reason: str`. The `audit_metadata` must use reference-first logging: `input_hash_prefix` (SHA-256 first 16 hex chars), `input_length`, `privacy: "no_original_text_stored"`, `rule_id`. No original text is stored in the decision.

3. A constant `ACP_BLOCKED_CONTENT_CATEGORIES: frozenset[str]` containing the 8 blocked category prefixes: `"meta:"`, `"gateway:"`, `"system:"`, `"update:"`, `"command:"`, `"help:"`, `"available_commands_update:"`, `"terminal:"`.

4. A constant `ACP_ALLOWED_EVENT_TYPES: frozenset[str]` — explicit allowlist of unified event types that may pass through the filter: `"message.delta"`, `"message.completed"`, `"thought.delta"`, `"tool_call.started"`, `"tool_call.delta"`, `"tool_call.completed"`, `"plan.updated"`, `"phase.changed"`, `"elicitation.requested"`, `"permission.requested"`, `"artifact.created"`, `"citation.recorded"`, `"run.state_changed"`, `"error"`, `"session.started"`. Any event type NOT in this set is blocked by default (default-deny).

5. A constant `_ACP_BLOCK_PATTERNS: tuple[tuple[str, re.Pattern[str]], ...]` — regex patterns for ACP-specific blocked content. Patterns (case-insensitive, matching the blocked categories):
   - `"meta_notice"`: `r"\bmeta\s*:"` — blocks "meta:" prefixed content
   - `"gateway_notice"`: `r"\bgateway\s*:"` — blocks "gateway:" prefixed content
   - `"system_notice"`: `r"\bsystem\s*:"` — blocks "system:" prefixed content
   - `"update_notice"`: `r"\bupdate\s*:"` — blocks "update:" prefixed content (but NOT "update" in normal legal text like "更新" — only the English "update:" prefix)
   - `"command_notice"`: `r"\bcommand\s*:"` — blocks "command:" prefixed content
   - `"help_notice"`: `r"\bhelp\s*:"` — blocks "help:" prefixed content
   - `"available_commands_update"`: `r"\bavailable_commands_update\b"` — blocks available_commands_update content
   - `"terminal_notice"`: `r"\bterminal\s*:"` — blocks "terminal:" prefixed content

6. A constant `_ACP_REWRITE_PATTERNS: tuple[tuple[str, re.Pattern[str]], ...]` — regex patterns for content that should be rewritten to a business-friendly notice instead of blocked:
   - `"backend_lifecycle"`: `r"\b(?:reconnect(?:ed)?|disconnect(?:ed)?|shutting down|restart(?:ed)?)\b"` — rewrite to a business notice

7. A constant `_BUSINESS_REWRITE_NOTICE = "InkStatute 正在处理您的请求，请等待下一条更新。"` — the business-friendly replacement text for rewritten content.

8. A function `_audit(text: str, *, rule_id: str) -> dict` — returns `{"rule_id": rule_id, "input_hash_prefix": hashlib.sha256(text.encode("utf-8")).hexdigest()[:16], "input_length": len(text), "privacy": "no_original_text_stored"}`. This is reference-first logging — no original text stored.

9. A class `ACPOutputFilter` with method:
   - `def filter_event(self, event_type: str, content: str | None, event_metadata: dict | None = None) -> FilterDecision` — the main filtering method. Logic:
     (a) If `event_type` is not in `ACP_ALLOWED_EVENT_TYPES`, return BLOCK with reason `"event_type_not_allowed"` and audit metadata. This is the default-deny policy.
     (b) If `content` is None or empty, return ALLOW (no content to filter).
     (c) Normalize content to lowercase for pattern matching.
     (d) Check `_ACP_BLOCK_PATTERNS` — if any matches, return BLOCK with the matching `rule_id` and audit metadata (reference-first, no original text).
     (e) Check `_ACP_REWRITE_PATTERNS` — if any matches, return REWRITE with `visible_content = _BUSINESS_REWRITE_NOTICE` and audit metadata.
     (f) If no patterns match, return ALLOW with `visible_content = content` and audit metadata with `rule_id = "business_output"`.

   - `def filter_notification(self, notification: dict) -> FilterDecision` — convenience method that extracts the event type and content from a raw ACP notification dict (using `_extract_update` logic similar to `event_mapping.py`) and delegates to `filter_event`. For `elicitation/create` and `session/request_permission` notifications, always returns ALLOW (these are user-facing interactive events that must reach the user).

   - `def apply_with_existing_boundary(self, event_type: str, content: str | None, existing_boundary: DefaultAssistantOutputBoundary) -> FilterDecision` — applies the ACP pre-filter first, then if the pre-filter returns ALLOW, delegates to the existing `DefaultAssistantOutputBoundary.apply()` method for the second layer of filtering. Returns the combined decision. If the ACP pre-filter blocks or rewrites, the existing boundary is not called (short-circuit). Import `DefaultAssistantOutputBoundary` from `platform_runtime.output_boundary`.

Import `re`, `hashlib` from stdlib. Import `RunEventType` from `platform_contract.enums`. Import `DefaultAssistantOutputBoundary` from `platform_runtime.output_boundary` (for the `apply_with_existing_boundary` method).

The filter must NOT store original text in any decision or audit metadata — all audit metadata is reference-first (hash prefix + length only).
