# 18-01 Plan: Adapter Contract and Capability Manifest

## Objective

Add a provider-neutral `MemoryStore` adapter contract and capability manifest so Mem0, Zep, or another store can be evaluated later without changing RunRuntime or channel contracts.

## Constraints

- No SDK dependency.
- No network calls.
- No provider secrets.
- No legal production default for external memory in Phase 18.

## Tasks

### 18-01-T1: Add manifest and adapter protocol

Create `packages/platform-runtime/src/platform_runtime/memory_adapters.py` with:

- `MemoryStoreAdapter` Protocol for the minimal memory surface: manifest, upsert, search, delete/tombstone, and export support hooks.
- `MemoryStoreCapabilityManifest` frozen dataclass.
- `MemoryAdapterEvaluation` frozen dataclass.
- `evaluate_memory_adapter_manifest(...)`.

Export symbols from `platform_runtime.__init__`.

### 18-01-T2: Add manifest evaluation tests

Create `packages/platform-runtime/tests/test_memory_adapter_contract.py` with tests proving:

- Platform-native manifest can be accepted for current legal use.
- Mem0-style and Zep-style manifests can be accepted for sanitized spikes but remain deferred for legal production.
- Manifests fail if they store raw payloads by default, lack tenant isolation, lack deletion/export, or try to become legal default without approval.
- Secret-like refs and raw payload metadata are rejected.
