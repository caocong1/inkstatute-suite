<objective>
Build a repeatable in-process evaluation harness that drives the native memory stack through six canonical scenarios and produces a scored, gate-checked report.

All fixture data is synthetic and ref-only. No live inference or external network calls.
</objective>

<constraints>
- Do NOT add external eval frameworks (no deepeval, evals, etc.)
- All scenarios use InMemoryMemoryStore or SQLiteMemoryStore with synthetic data
- MemoryEvalGateError is raised from assert_gates(), not during run()
- Baseline score is deterministic given same inputs
- No raw legal/customer text in any scenario setup
</constraints>

## Task 24-01-01: Create memory_eval.py with MemoryEvalScenario and MemoryEvalReport

**MemoryEvalScenario** (enum or dataclass): `multi_turn_recall`, `cross_session_continuity`, `deletion_and_export`, `tenant_isolation`, `feedback_learning_integration`, `false_recall_rejection`

**MemoryEvalResult** (`@dataclass(frozen=True, slots=True)`):
- `scenario: str`
- `passed: bool`
- `relevance_score: float` — 0.0–1.0
- `source_traceability: bool` — all returned records have source_refs as URIs
- `deletion_correctness: bool` — deleted records not recalled
- `privacy_passed: bool` — no raw payload keys in any record metadata
- `cross_tenant_leaked: bool` — True if cross-tenant record was returned
- `latency_ms: float | None = None`
- `context_size_tokens: int | None = None`
- `notes: str = ""`

**MemoryEvalReport** (`@dataclass(frozen=True, slots=True)`):
- `results: tuple[MemoryEvalResult, ...]`
- `baseline_score: float` — weighted average of passed scenarios
- `hard_gate_failures: tuple[str, ...]` — descriptions of hard failures

```python
def assert_gates(self) -> None:
    """Raise MemoryEvalGateError if any hard gate fails."""

@staticmethod
def compute_baseline(results: Iterable[MemoryEvalResult]) -> float:
    """Simple pass-rate: passed scenarios / total scenarios."""
```

**MemoryEvalGateError**: subclass `AssertionError`; message lists all gate failures

## Task 24-01-02: Add MemoryEvalRunner with six scenarios

```python
class MemoryEvalRunner:
    def __init__(
        self,
        *,
        memory_store_factory: Callable[[], Any] | None = None,
        clock: Any | None = None,
        id_factory: Any | None = None,
    ) -> None: ...

    def run(self) -> MemoryEvalReport: ...
```

**Scenario implementations** (all synthetic, no external I/O):

1. **multi_turn_recall**: Insert 3 records for session A. Query with session scope. Pass if all 3 returned with source_ref URIs.

2. **cross_session_continuity**: Insert 1 user-scoped record. Query from a different session but same user. Pass if record recalled (user scope crosses sessions).

3. **deletion_and_export**: Insert 1 record, delete it, query. Pass if deleted record is NOT returned (`deletion_correctness=True`).

4. **tenant_isolation**: Insert record for tenant-A. Query with tenant-B scope. Pass if nothing returned (`cross_tenant_leaked=False`).

5. **feedback_learning_integration**: Run `FeedbackLearningPolicy.learn()` with 2 repeated negative events, queue candidates, approve via `MemoryCandidateReviewDecider`, query. Pass if promoted record recalled.

6. **false_recall_rejection**: Insert record for session A. Query with session B. Pass if nothing returned (scope isolation).

**Hard gate conditions**:
- `cross_tenant_leaked = True` on any result
- `privacy_passed = False` on any result
- `deletion_correctness = False` on the deletion_and_export scenario
- `false_recall_rejection` scenario fails (record was recalled for wrong session)
