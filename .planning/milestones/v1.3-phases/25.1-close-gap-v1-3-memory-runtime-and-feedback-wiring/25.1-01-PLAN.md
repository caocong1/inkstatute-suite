<objective>
Close the REC runtime gap by wiring existing platform memory recall into ordinary WeCom runtime submissions and hardening MemoryUse evidence behavior.

Purpose: Phase 22 produced a library orchestrator, but the v1.3 audit found no ordinary WeCom/runtime production path invokes recall before backend submission and MemoryUse failures are silently ignored. This plan makes the already-built memory path reachable through InkStatute-owned WeCom runtime flows while preserving interrupt resume, active-task fast paths, and reference-first privacy.

Output: A production-safe optional memory orchestrator injection path, fail-closed/degraded MemoryUse evidence policy, and focused service/runtime tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| WeCom callback -> ingress/session runtime | Sanitized callback metadata enters InkStatute-owned runtime orchestration. |
| Session runtime -> feedback correction ref provider | Resolved tenant/workspace/user/session scope is used to retrieve same-session feedback correction refs. |
| Session runtime -> MemoryOrchestrator | Resolved tenant/workspace/user/session scope plus feedback correction refs are used for recall and context assembly. |
| MemoryOrchestrator -> MemoryStoreAdapter | Memory search and MemoryUse evidence writes cross into a storage implementation. |
| Session runtime -> RunRuntime.create_run | Bounded context metadata is passed to backend submission. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25.1-01 | Information Disclosure | `WeComSessionRuntime` memory recall | mitigate | Build recall arguments from resolved `SessionScope` and decision session id; tests assert cross-branch bypass and scope-safe refs. |
| T-25.1-02 | Information Disclosure | create-run metadata | mitigate | Merge only `ContextBundle` refs, feedback correction refs, ids, counts, statuses, hashes, lengths, and policy refs through `_safe_json`; tests reject forbidden raw/full-text keys. |
| T-25.1-03 | Repudiation | `MemoryOrchestrator.record_memory_use` | mitigate | Replace silent exception swallowing with `MemoryUseEvidenceFailureMode`; legal runtime uses fail-closed behavior per D-01. |
| T-25.1-04 | Denial of Service | memory recall before backend submission | accept | Optional host injection limits blast radius; no background service or external network dependency is added. |
| T-25.1-SC | Tampering | npm/pip/cargo installs | mitigate | No package install is planned; package legitimacy audit in research states no external packages are required. |
</threat_model>
