<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller to MemoryStore | Host-supplied dataclasses and query metadata enter the persistence boundary. |
| MemoryStore to SQLite file | Validated contract objects become durable rows and JSON payloads. |
| SQLite file to caller | Durable rows are reconstructed into returned dataclasses. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-20-01 | Information Disclosure | `SQLiteMemoryStore.upsert`, `upsert_candidate`, `record_memory_use` | high | mitigate | Call `_validate_record`, `_validate_candidate`, and `_validate_use` before serialization; tests must prove forbidden raw/full-text/secret metadata raises `MemoryPrivacyError` and leaves no row behind. |
| T-20-02 | Information Disclosure | JSON payload serialization | high | mitigate | Persist contract-shaped refs, hashes, lengths, statuses, scopes, TTL/deletion metadata, confidence, and safe summaries only; test fixture data must remain synthetic. |
| T-20-03 | Tampering | SQLite writes | medium | mitigate | Use transactions for record JSON and side-table index updates so payload and indexes cannot diverge after partial writes. |
| T-20-04 | Repudiation | Candidate/use evidence | medium | mitigate | Persist `MemoryCandidate` and `MemoryUse` with source refs and copied dataclass fields so review and context-use evidence survives restart. |
| T-20-SC | Tampering | Package supply chain | low | mitigate | No npm/pip/cargo install is permitted in this plan; use Python stdlib `sqlite3` only. |
</threat_model>
