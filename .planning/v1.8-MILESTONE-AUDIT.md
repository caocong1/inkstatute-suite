### Gaps (host-level)

1. **No production host** composing `verify_and_ack` → `QQBotRuntimeIngress` / `handle_feedback_callback` → session/deliver in one webhook service.
2. **Runtime registration** of `QQBotChannelAdapter` into `DefaultRunRuntime.channels` / flag→config mapping not implemented as a host service.
3. **Smoke dry-run** skips adapter Protocol + session runtime (leaf helpers only).

These gaps do **not** invalidate phase success criteria as written (phases delivered composable package modules + toolkit). They block claiming a **deployed live QQBot webhook host** is complete. Live promotion remains an intentional human gate.
