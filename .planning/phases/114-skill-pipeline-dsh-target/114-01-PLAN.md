# Plan 114-01: convert-skills.js dsh target

## Goal

Extend `ai-for-china-legal/scripts/convert-skills.js` with a new `dsh` target that materializes skills from the 4 whitelisted domains into DSH-compatible flat structure (`dist/dsh/<domain>/<skill-name>/SKILL.md`), promotes sub-skills to top-level with `<parent>-<child>` naming, and applies two semantic rewrites (slash commands → skill tool guidance, CLAUDE.md write instructions → practice-profile.md). Existing kimi/opencode/standalone targets remain untouched.

## Files to create/modify

- `ai-for-china-legal/scripts/convert-skills.js` — add `"dsh"` to `VALID_PLATFORMS`, add `convertToDSH()` function, add domain whitelist `DOMAIN_MAP`, add sub-skill promotion logic, add two semantic rewrite functions, add `dsh` dispatch branch in `main()`
- `ai-for-china-legal/test/fixtures/dsh-synthetic/` — synthetic fixture corpus (NOT real corpus content) with 2 domains, 1 top-level skill + 1 sub-skill each, slash command references, CLAUDE.md write references
- `ai-for-china-legal/test/dsh-convert.test.js` — unit tests for `convertToDSH()`, sub-skill promotion, slash command rewrite, CLAUDE.md rewrite, domain whitelist filtering, flat structure output

## Tasks

### Task 1: Add dsh target scaffold + domain whitelist + flat structure + sub-skill promotion

**Files:** `ai-for-china-legal/scripts/convert-skills.js`

**Action:**

1. Add `"dsh"` to `VALID_PLATFORMS` array (line 47). Do NOT remove or reorder existing entries.
2. Add a `DOMAIN_MAP` constant near the top (after imports, before argument parsing):
   ```javascript
   const DOMAIN_MAP = {
     'commercial-legal': 'legal-commercial',
     'litigation-legal': 'legal-litigation',
     'family-legal': 'legal-family',
     'employment-legal': 'legal-employment',
   };
   ```
3. Add a `convertToDSH(skill, relPath, sourceDomain)` function after `convertToStandalone()` (after line 216). This function must:
   - Accept the parsed skill (metadata + body) and the source domain name.
   - Map source domain to output domain via `DOMAIN_MAP` (skip if not in map — return null to signal "not whitelisted").
   - Determine the flat skill name: if `relPath` contains a sub-directory (i.e., `parent/child/SKILL.md` where parent is a top-level skill), use `<parent>-<child>` naming. If `relPath` is just `parent/SKILL.md`, use `parent`.
   - Preserve frontmatter `name` field as-is (original name, not hyphenated). The directory name uses the hyphenated form for uniqueness; frontmatter `name` retains original.
   - Output a single file: `<domain>/<flat-skill-name>/SKILL.md` with frontmatter (`name`, `description`, `argument-hint` if present) + body.
   - Return `{ files: [{path, content}], domain: <output-domain>, skillName: <flat-name> }`.
4. The `dsh` target does NOT use the shared `processSkills()` dispatcher as-is because it needs domain-aware routing and sub-skill promotion. Instead, add a dedicated `processDSH(skillFiles, inputBase, outputBase)` function that:
   - Iterates skill files, determines source domain from the input path (the top-level directory name under inputBase).
   - Calls `convertToDSH()` for each.
   - Skips files whose source domain is not in `DOMAIN_MAP` (whitelist filter).
   - Skips auto-product directories (`.qwen/`, `managed-agent-cookbooks/`, `_shared/` — any path segment starting with `.` or `_`).
   - Writes output files to `dist/dsh/<output-domain>/<flat-skill-name>/SKILL.md`.
   - Returns a summary object: `{ domains: { <domain>: [<skillName>, ...] }, totalSkills: N }`.
5. In `main()`, add an `else if (platform === "dsh")` branch (after the standalone branch, before the closing brace) that calls `processDSH()`. The `dsh` target should NOT be included in the `"all"` platform expansion (line 260 — keep `["kimi", "opencode", "standalone"]` unchanged).
6. Update the usage/help text (lines 38-43) to include `dsh` in the platforms list and add a dsh example.

### Task 2: Implement two semantic rewrites (slash commands + CLAUDE.md writes)

**Files:** `ai-for-china-legal/scripts/convert-skills.js`

**Action:**

Add two rewrite functions and wire them into `convertToDSH()` body processing (apply to the body text before writing):

1. **Slash command rewrite** — `rewriteSlashCommands(text)`:
   - Regex: `/\/([a-z-]+):([a-z-]+)/g` (matches `/commercial-legal:contract-review` etc.)
   - Replacement: `用 skill 工具按名加载 $2 技能` (uses the skill name part, drops the plugin prefix).
   - Example: `运行 /commercial-legal:contract-review 进行审查` → `运行 用 skill 工具按名加载 contract-review 技能 进行审查`
   - Apply globally (all occurrences in body).

2. **CLAUDE.md write instruction rewrite** — `rewriteClaudeMdWrites(text)`:
   - Match patterns where CLAUDE.md is referenced as a write target. Patterns to match (Chinese):
     - `写入.*CLAUDE\.md` (e.g., "写入 commercial-legal/CLAUDE.md")
     - `CLAUDE\.md.*写入` (reversed order)
     - References to `commercial-legal/CLAUDE.md` or `<plugin>/CLAUDE.md` as a read target for "实践配置文件" should also be rewritten to `practice-profile.md` since the DSH app uses a single profile file.
   - Replacement strategy: Replace any `<plugin-name>/CLAUDE.md` path reference with `practice-profile.md`. Replace "写入 ... CLAUDE.md" with "写入 practice-profile.md". Replace "读取 ... CLAUDE.md（实践配置文件）" with "读取 practice-profile.md（实践配置文件）".
   - Regex for path replacement: `/[a-z-]+\/CLAUDE\.md/g` → `practice-profile.md`
   - Regex for bare `CLAUDE\.md` (when not part of a path, e.g., "写入 CLAUDE.md") → `practice-profile.md`
   - Be careful NOT to rewrite references to `CLAUDE.md` that are part of migration notes or historical context (lines starting with `>` blockquote migration notes). Only rewrite actionable instructions (write/read targets). A pragmatic approach: rewrite all `CLAUDE.md` references to `practice-profile.md` except those inside `> **迁移说明**` blockquote lines.

3. Wire both rewrites into `convertToDSH()`: after extracting body, apply `rewriteSlashCommands(rewriteClaudeMdWrites(body))` before composing the output file content.

