## Tasks

### Task 1: End-to-end demo script (test_dsh_materialization.sh)

**Files:** `ai-for-china-legal/scripts/test_dsh_materialization.sh`

**Action:**

Create `scripts/test_dsh_materialization.sh` (bash, `set -euo pipefail`). This script follows the pattern of `inkstatute-suite/scripts/test_materialize_presets.sh` (Phase 113). The script:

1. **Setup:** Clean any previous `dist/dsh/` directory. Create fresh `dist/dsh/`.

2. **Step 1 — Convert (4 domains):** Run `convert-skills.js --to dsh` for each whitelisted domain:
   ```bash
   DOMAINS=("commercial-legal:legal-commercial" "litigation-legal:legal-litigation" "family-legal:legal-family" "employment-legal:legal-employment")
   for entry in "${DOMAINS[@]}"; do
     source="${entry%%:*}"
     target="${entry##*:}"
     node scripts/convert-skills.js --to dsh \
       --input "./${source}/skills" \
       --output "./dist/dsh/${target}"
   done
   ```
   Note: the `--output` flag sets the base output dir. The `convertToDSH` function (from Plan 114-01) writes to `<output>/<domain>/<skill-name>/SKILL.md`. Since we pass `--output ./dist/dsh/legal-commercial` for the commercial-legal source, the converter should write directly to that path. Verify the output structure matches `dist/dsh/<domain>/<skill-name>/SKILL.md`.

   Alternative (if the converter design from 114-01 routes by domain internally): run a single conversion with `--input .` (repo root) and `--output ./dist/dsh`, letting the converter's domain whitelist filter handle routing. The script should use whichever approach the implemented converter supports — document the chosen approach in script comments.

3. **Step 2 — Generate manifest:**
   ```bash
   node scripts/generate-dsh-manifest.js \
     --input ./dist/dsh \
     --output ./dist/dsh/content-manifest.json \
     --release-version 1.0.0
   ```

4. **Step 3 — Create zip:**
   ```bash
   cd dist/dsh
   zip -r "../legal-skills-content-1.0.0.zip" .
   cd ../..
   sha256sum dist/legal-skills-content-1.0.0.zip > dist/legal-skills-content-1.0.0.zip.sha256
   ```

5. **Step 4 — Unpack to temp and verify:**
   ```bash
   UNPACK_DIR=$(mktemp -d)
   unzip -q dist/legal-skills-content-1.0.0.zip -d "$UNPACK_DIR"
   ```
   Verifications:
   - `content-manifest.json` exists in unpacked dir and is valid JSON.
   - Manifest `min_engine_version` === `47f943859b`.
   - Manifest has 4 domain keys.
   - For each skill in manifest: the SKILL.md file exists at `<domain>/<skill-name>/SKILL.md` in unpacked dir.
   - For each skill: sha256 of unpacked SKILL.md matches manifest hash.
   - No slash command residue: `grep -rn '/[a-z-]*:[a-z-]*' "$UNPACK_DIR" | wc -l` === 0.
   - No CLAUDE.md write residue: `grep -rn 'CLAUDE\.md' "$UNPACK_DIR" | grep -v '迁移说明' | wc -l` === 0.
   - Run content gate: `node scripts/test-dsh-output.js --input "$UNPACK_DIR"` — all pass.

6. **Cleanup:** Remove temp dir. Print summary: domains, total skills, zip path, zip sha256, all verifications passed.

7. **Exit:** 0 if all verifications pass, 1 if any fail.

8. Make script executable: `chmod +x scripts/test_dsh_materialization.sh`.

**Verify:**
```xml

```

**Done:** `bash scripts/test_dsh_materialization.sh` runs the full pipeline (convert → manifest → zip → unpack → verify) with zero manual steps, exits 0, and prints a summary with domain count, skill count, and hash verification results.
