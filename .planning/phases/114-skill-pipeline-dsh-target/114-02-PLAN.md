# Plan 114-02: content-manifest.json generator + zip publish script + manifest schema

## Goal

Create a manifest generator (`generate-dsh-manifest.js`) that scans `dist/dsh/<domain>/` directories, computes sha256 for each SKILL.md, and emits `content-manifest.json` with the required schema. Create a zip publish script (`publish-dsh-content.sh`) that packages the manifest + content into a zip. Define the manifest schema as a Dart model in the InkStatute suite for Phase 115 consumption.

## Files to create/modify

- `ai-for-china-legal/scripts/generate-dsh-manifest.js` — manifest generator (Node.js, uses `node:crypto` for sha256, `node:fs` for scanning)
- `ai-for-china-legal/scripts/publish-dsh-content.sh` — zip packaging script (bash, cross-platform compatible)
- `ai-for-china-legal/test/dsh-manifest.test.js` — unit tests for manifest generator
- `ai-for-china-legal/test/fixtures/dsh-manifest-sample/` — synthetic sample dist directory for manifest tests
- `inkstatute-suite/apps/flutter_app/lib/content/manifest_schema.dart` — Dart model class for content-manifest.json (for Phase 115 updater consumption)
- `inkstatute-suite/apps/flutter_app/test/content/manifest_schema_test.dart` — Dart tests for manifest schema parsing

## Tasks

### Task 1: Manifest generator (generate-dsh-manifest.js)

**Files:** `ai-for-china-legal/scripts/generate-dsh-manifest.js`

**Action:**

Create `scripts/generate-dsh-manifest.js` (ES module, same style as `convert-skills.js`). The script:

1. Accepts CLI args: `--input <dist-dsh-dir>` (default `./dist/dsh`), `--output <manifest-path>` (default `./dist/dsh/content-manifest.json`), `--release-version <semver>` (default `1.0.0`), `--min-engine-version <commit>` (default reads from `engines/dsh-pin.txt` if available, else `47f943859b`).

2. Scans `<input>/<domain>/` directories (one level — each domain dir contains `<skill-name>/SKILL.md`).

3. For each domain, iterates skill subdirectories, finds `SKILL.md`, computes sha256 hash using `node:crypto` (`createHash('sha256')`).

4. Builds manifest object with this exact schema:
   ```json
   {
     "schema_version": "1.0.0",
     "release_version": "<from --release-version>",
     "released_at": "<ISO 8601 timestamp at generation time>",
     "min_engine_version": "47f943859b",
     "domains": {
       "legal-commercial": {
         "skills": [
           { "name": "contract-review", "sha256": "<hex hash>" },
           { "name": "contract-review-risk-identification", "sha256": "<hex hash>" }
         ]
       },
       "legal-litigation": { "skills": [...] },
       "legal-family": { "skills": [...] },
       "legal-employment": { "skills": [...] }
     }
   }
   ```

5. Writes manifest as JSON (2-space indent) to the output path.

6. Prints a summary: total domains, total skills, manifest path.

7. Validates: if no domains found in input, exit with error code 1 and message. If a domain directory has no skill subdirectories, skip it (don't emit empty domain entries).

**Verify:**
```xml
<automated>cd /home/sorawatcher/workspace/ai-for-china-legal && node scripts/generate-dsh-manifest.js --input ./dist/dsh-test --output ./dist/dsh-test/content-manifest.json --release-version 1.0.0 && node -e "const m = JSON.parse(require('fs').readFileSync('./dist/dsh-test/content-manifest.json','utf-8')); console.log(m.schema_version, m.min_engine_version, Object.keys(m.domains))"</automated>
```

**Done:** `generate-dsh-manifest.js` produces valid JSON with schema_version, release_version, released_at, min_engine_version, and domains with skills arrays containing name + sha256 for each SKILL.md.

### Task 2: Zip publish script (publish-dsh-content.sh)

**Files:** `ai-for-china-legal/scripts/publish-dsh-content.sh`

**Action:**

Create `scripts/publish-dsh-content.sh` (bash, `set -euo pipefail`). The script:

1. Accepts environment variables:
   - `CONTENT_RELEASE_URL` — target release URL (optional; if unset, prints a message that GitHub Release is the default target and proceeds with local zip generation only).
   - `RELEASE_VERSION` — semver (default `1.0.0`, can be overridden by first positional arg `$1`).
   - `DIST_DIR` — dist directory (default `./dist/dsh`).

2. Steps:
   - Verify `DIST_DIR/content-manifest.json` exists (exit 1 if missing — manifest must be generated first).
   - Create zip: `zip -r "../legal-skills-content-${RELEASE_VERSION}.zip" .` from within `DIST_DIR` (includes manifest + all domain/skill directories).
   - Compute sha256 of the zip file itself: `sha256sum legal-skills-content-${RELEASE_VERSION}.zip > legal-skills-content-${RELEASE_VERSION}.zip.sha256`.
   - Print summary: zip path, zip sha256, manifest path.
   - If `CONTENT_RELEASE_URL` is set, print instructions for upload (do NOT actually upload — no GH token in this phase). If unset, print "GitHub Release is the default target. Set CONTENT_RELEASE_URL to use a custom source."

3. Cross-platform note: use `zip` command (available on Linux CI and WSL). Add a check: `command -v zip || { echo "Error: zip not found"; exit 1; }`.

4. Make the script executable: `chmod +x scripts/publish-dsh-content.sh`.

**Verify:**
```xml
<automated>cd /home/sorawatcher/workspace/ai-for-china-legal && bash scripts/publish-dsh-content.sh 1.0.0 && ls -la dist/legal-skills-content-1.0.0.zip dist/legal-skills-content-1.0.0.zip.sha256</automated>
```

**Done:** `publish-dsh-content.sh` produces `dist/legal-skills-content-<version>.zip` containing all domain directories + content-manifest.json, plus a `.sha256` sidecar file.

### Task 3: Manifest generator tests + Dart manifest schema

**Files:** `ai-for-china-legal/test/dsh-manifest.test.js`, `ai-for-china-legal/test/fixtures/dsh-manifest-sample/`, `inkstatute-suite/apps/flutter_app/lib/content/manifest_schema.dart`, `inkstatute-suite/apps/flutter_app/test/content/manifest_schema_test.dart`

**Action:**

   - `legal-commercial/contract-review/SKILL.md` (synthetic content)
   - `legal-commercial/contract-review-risk-identification/SKILL.md` (synthetic)
   - `legal-litigation/cold-start-interview/SKILL.md` (synthetic)

2. Create `test/dsh-manifest.test.js` (Node.js built-in test runner). Tests:
   - **Schema fields:** manifest has `schema_version`, `release_version`, `released_at`, `min_engine_version`, `domains`.
   - **Domain structure:** `domains.legal-commercial.skills` is an array of `{name, sha256}` objects.
   - **sha256 correctness:** hash matches manually computed sha256 of the fixture SKILL.md file.
   - **min_engine_version:** defaults to `47f943859b` when not specified.
   - **released_at:** is a valid ISO 8601 string.
   - **Empty input:** exits with code 1 when no domains found.
   - **Skill count:** total skills across domains matches number of SKILL.md files in fixtures.

3. Add `"test:dsh-manifest": "node --test test/dsh-manifest.test.js"` to `ai-for-china-legal/package.json` scripts.

4. Create `inkstatute-suite/apps/flutter_app/lib/content/manifest_schema.dart` — Dart model for the manifest (for Phase 115 updater):
   - `ContentManifest` class with fields: `schemaVersion`, `releaseVersion`, `releasedAt` (DateTime), `minEngineVersion`, `domains` (Map<String, DomainEntry>).
   - `DomainEntry` class with `skills` (List<SkillEntry>).
   - `SkillEntry` class with `name` (String) and `sha256` (String).
   - `ContentManifest.fromJson(Map<String, dynamic>)` factory constructor.
   - `toJson()` method for round-trip serialization.
   - No external dependencies — pure Dart classes with manual JSON parsing.

5. Create `inkstatute-suite/apps/flutter_app/test/content/manifest_schema_test.dart` — Dart tests:
   - Parse a sample manifest JSON → verify all fields populated correctly.
   - Round-trip: `fromJson` → `toJson` → equals original JSON structure.
   - Edge case: empty skills array in a domain.
   - Edge case: manifest with 4 domains.
