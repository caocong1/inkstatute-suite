## Tasks

### Task 1: Content gate validator (test-dsh-output.js)

**Files:** `ai-for-china-legal/scripts/test-dsh-output.js`, `ai-for-china-legal/test/fixtures/dsh-gate-sample/`

**Action:**

Create `scripts/test-dsh-output.js` (ES module). The script:

1. Accepts CLI args: `--input <dist-dsh-dir>` (default `./dist/dsh`). Scans all `<domain>/<skill-name>/SKILL.md` files recursively (one level of skill subdirectories per domain).

2. For each SKILL.md file, runs these validations (collect all failures, don't stop on first):
   - **Parseable:** file can be read and YAML frontmatter extracted (regex `^---\n([\s\S]*?)\n---\n`). If no frontmatter found → FAIL "missing frontmatter".
   - **Valid frontmatter:** frontmatter parses as YAML (using `yaml` package) and contains `name` (non-empty string) and `description` (non-empty string). Missing either → FAIL.
   - **No slash command residue:** body text contains no `/<plugin>:<skill>` patterns. Regex: `/\/[a-z-]+:[a-z-]+/`. If found → FAIL "slash command residue: <matched pattern>".
   - **No CLAUDE.md write residue:** body text contains no `CLAUDE.md` references outside `> **迁移说明**` blockquote lines. Regex: search for `CLAUDE\.md` in lines NOT starting with `>`. If found → FAIL "CLAUDE.md write residue".
   - **Directory name = skill name:** the directory containing SKILL.md must match the frontmatter `name` field OR the hyphenated `<parent>-<child>` form. For top-level skills: `dirname === frontmatter.name`. For promoted sub-skills: `dirname === <parent>-<child>` (frontmatter `name` may be just `<child>` — this is expected per GA-3). If mismatch → FAIL "directory name mismatch: dir=<dir> name=<fm-name>".

3. Output format: print `[PASS] <path>` for each valid file, `[FAIL] <path>: <reason>` for each failure. At the end, print summary: `X passed, Y failed`. Exit code 0 if all pass, 1 if any fail.

4. Create synthetic fixtures under `test/fixtures/dsh-gate-sample/`:
   - `legal-commercial/contract-review/SKILL.md` — valid (correct frontmatter, no residue, dir=name).
   - `legal-commercial/contract-review-risk-identification/SKILL.md` — valid sub-skill (dir=hyphenated, name=child).
   - `legal-bad/no-frontmatter/SKILL.md` — invalid (no frontmatter).
   - `legal-bad/missing-description/SKILL.md` — invalid (frontmatter missing `description`).
   - `legal-bad/slash-residue/SKILL.md` — invalid (contains `/commercial-legal:review` in body).
   - `legal-bad/claude-md-residue/SKILL.md` — invalid (contains "写入 CLAUDE.md" in body, not in migration blockquote).
   - `legal-bad/name-mismatch/SKILL.md` — invalid (dir=`wrong-name`, frontmatter name=`different-name`).

5. The script should have a `--self-test` mode that runs against `test/fixtures/dsh-gate-sample/` and asserts: 2 pass, 5 fail (with specific failure reasons). This enables the gate to test itself.

**Verify:**
```xml
<automated>cd /home/sorawatcher/workspace/ai-for-china-legal && node scripts/test-dsh-output.js --self-test 2>&1 | tail -5</automated>
```

**Done:** `node scripts/test-dsh-output.js --self-test` reports 2 passed, 5 failed, exit code 1. Running against real `dist/dsh/` output (from Plan 114-01) reports all passed, exit code 0.

### Task 2: Extend test:compatibility + add npm scripts

**Files:** `ai-for-china-legal/package.json`

**Action:**

1. Add `"test:dsh": "node scripts/test-dsh-output.js"` to `scripts` section.
2. Add `"test:dsh-convert": "node --test test/dsh-convert.test.js"` (from Plan 114-01).
3. Add `"test:dsh-manifest": "node --test test/dsh-manifest.test.js"` (from Plan 114-02).
4. Extend `test:compatibility` to chain the dsh gate. Change from:
   ```json
   "test:compatibility": "node scripts/convert-skills.js --to all --input ./commercial-legal/skills --output ./dist/test"
   ```
   to:
   ```json
   "test:compatibility": "node scripts/convert-skills.js --to all --input ./commercial-legal/skills --output ./dist/test && npm run test:dsh"
   ```
   This preserves the existing kimi/opencode/standalone test and appends the dsh gate. The dsh gate runs against `./dist/dsh` (default), so a `test:dsh:full` convenience script should also be added that runs convert → manifest → gate in sequence:
   ```json
   "test:dsh:full": "node scripts/convert-skills.js --to dsh --input ./commercial-legal/skills --output ./dist/dsh/legal-commercial && node scripts/convert-skills.js --to dsh --input ./litigation-legal/skills --output ./dist/dsh/legal-litigation && node scripts/convert-skills.js --to dsh --input ./family-legal/skills --output ./dist/dsh/legal-family && node scripts/convert-skills.js --to dsh --input ./employment-legal/skills --output ./dist/dsh/legal-employment && node scripts/generate-dsh-manifest.js && node scripts/test-dsh-output.js"
   ```
   Note: the `test:dsh:full` script runs dsh conversion for each of the 4 domains separately (since `convert-skills.js --to dsh` takes a single `--input` dir). The output goes to `dist/dsh/<domain>/` for each. Then generates manifest and runs gate.

5. Do NOT modify the existing `convert`, `publish:all`, or other scripts — only add new scripts and extend `test:compatibility`.

**Verify:**
```xml

```

**Done:** `npm run test:compatibility` runs the existing all-target conversion AND the dsh gate. `npm run test:dsh:full` runs the complete dsh pipeline (convert 4 domains → manifest → gate). Both exit 0 on success.

### Task 3: CI workflow (GitHub Actions)

**Files:** `ai-for-china-legal/.github/workflows/dsh-materialization.yml`

**Action:**

Create `.github/workflows/dsh-materialization.yml`. The corpus repo currently has NO CI (verified in research — no `.github/workflows/` directory exists). This is the first CI workflow. The workflow:

1. **Triggers:** `push` to `main` and `pull_request` to `main`. Paths filter: `scripts/**`, `*/skills/**`, `shared/**`, `package.json`, `.github/workflows/dsh-materialization.yml`.

2. **Job: `dsh-materialization`** (runs on `ubuntu-latest`):
   - Checkout code.
   - Setup Node.js (version `^22.19.0 || >=24.0.0` per `engines` field — use `node-version: '22'` as minimum).
   - `npm ci` (install dependencies — `yaml` package).
   - Run the full dsh pipeline:
     ```yaml
     - run: npm run test:dsh:full
     ```
   - Upload artifact: `dist/dsh/` directory + `dist/dsh/content-manifest.json` as `dsh-content-${{ github.sha }}` artifact (retention 7 days).

3. **Job: `compatibility`** (runs on `ubuntu-latest`, in parallel with dsh-materialization):
   - Same setup.
   - `npm run test:compatibility` (existing all-target conversion + dsh gate).

4. Both jobs must pass for the workflow to be green. No deployment/upload step (upload is Phase 115 concern).

5. Add a `.github/workflows/` directory if it doesn't exist (it doesn't — verified).
