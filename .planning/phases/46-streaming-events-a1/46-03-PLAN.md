# Plan 03: Runtime Stream Cancellation Propagation + Output Boundary Event-Type Allowlist

## Objective

Wire cancellation propagation through the runtime's `stream()` method by wrapping `backend.stream_events()` in `try/finally` with `aclose()` cleanup, ensuring client cancellation propagates `GeneratorExit` to the adapter and provider with no zombie runs (STREAM-02). Additionally, extend `DefaultAssistantOutputBoundary` with an event-type allowlist that filters out `ERROR`, `TOOL_CALL_STARTED`, and `TOOL_CALL_COMPLETED` event types before they reach channels (Success Criterion 3). This plan depends on Plans 01 and 02 because the cancellation integration test uses real adapter streaming implementations.

    - When the client stops iterating (breaks out of `async for event in runtime.stream(run_id)`), aclose() is called on the backend's async generator, propagating GeneratorExit into the adapter
    - The backend's stream_events() generator receives GeneratorExit and can clean up provider connections

  <action>
    1. In runtime.py, replace the `stream` method (lines 264-270) with a try/finally + aclose() pattern:
       ```
       async def stream(self, run_id: str) -> AsyncIterator[RunEvent]:
           self.feature_flags.require_enabled("run_runtime_enabled")
           self.feature_flags.require_enabled("streaming_lane_enabled")
           gen = self.backend.stream_events(run_id)
           try:
               async for event in gen:
                   bounded_event = self._apply_output_boundary(event)
                   if bounded_event is not None:
                       yield bounded_event
           finally:
               await gen.aclose()
       ```
       The key change: instead of `async for event in self.backend.stream_events(run_id):`, we create the generator object `gen`, iterate it in a try block, and call `await gen.aclose()` in the finally block. This ensures cleanup runs on both normal completion and cancellation.
