<objective>
以**只读**方式接入引擎自动维护的 `session-query.db`，提供会话列表与全文搜索。这是 ConversationDrawer 与搜索面板的数据源——app 侧不再自建会话库。
</objective>

<context>
引擎自动生成 `<sessionsRoot>/session-query.db`（实测 schema）：

```sql
CREATE TABLE persisted_sessions (
  id TEXT PRIMARY KEY, version INTEGER NOT NULL, created_at INTEGER NOT NULL,
  cwd TEXT, parent_session TEXT, seed_length INTEGER, delegation_depth INTEGER,
  agent_preset TEXT, revision TEXT NOT NULL, generation INTEGER NOT NULL
) STRICT;

CREATE VIRTUAL TABLE persisted_docs USING fts5(
  text, session_id UNINDEXED, seq UNINDEXED, type UNINDEXED, time UNINDEXED,
  surface UNINDEXED, codepoint_length UNINDEXED, tokenize='unicode61'
);
```

**该库归引擎所有。app 侧只读，永不写入。** 写入会破坏引擎的 generation/revision 一致性。

`sqlx` 已在 Cargo.toml（`features = ["sqlite","runtime-tokio"]`）。
</context>

### Task 1: src/engine/history.rs — 只读查询

- **type:** code
- **files:** apps/desktop/src-tauri/src/engine/history.rs
- **action:** 实现：

```rust
pub struct HistoryStore { /* 私有：SqlitePool */ }

#[derive(Debug, Clone, Serialize)]
pub struct SessionSummary {
    pub id: String,
    pub created_at: i64,
    pub cwd: Option<String>,
    pub agent_preset: Option<String>,
    /// 从 persisted_docs 取该会话第一条 type='session/title' 的文本；无则取首条用户消息前 40 字
    pub title: Option<String>,
}

#[derive(Debug, Clone, Serialize)]
pub struct SearchHit {
    pub session_id: String,
    pub seq: i64,
    pub time: i64,
    pub doc_type: String,
    /// FTS5 snippet()，命中处用 <mark> 包裹
    pub snippet: String,
}

impl HistoryStore {
    /// 只读打开。库不存在时返回 Ok(None)（首次运行、引擎尚未产出）。
    pub async fn open(sessions_root: &Path) -> Result<Option<Self>, EngineError>;

    /// 按 created_at 倒序，分页
    pub async fn list_sessions(&self, limit: i64, offset: i64) -> Result<Vec<SessionSummary>, EngineError>;

    pub async fn session_count(&self) -> Result<i64, EngineError>;

    /// FTS5 全文搜索。query 需转义 FTS5 特殊字符。
    pub async fn search(&self, query: &str, limit: i64) -> Result<Vec<SearchHit>, EngineError>;

    /// 某会话的全部文档行，按 seq 升序 —— 供回灌(RTM-07)取历史往来
    pub async fn session_docs(&self, session_id: &str) -> Result<Vec<SearchHit>, EngineError>;
}
```

**实现要点：**

1. **必须只读打开**：连接串用
   `sqlite:file:<path>?mode=ro&immutable=0`
   （`mode=ro` 拒绝一切写；`immutable=0` 因为引擎在并发写，不能声明不可变）。
   `SqliteConnectOptions` 里显式 `.read_only(true)` 与 `.create_if_missing(false)`。

2. **FTS5 查询转义**：用户输入可能含 `"`、`*`、`^`、`AND`/`OR`/`NOT` 等。
   做法：把输入按空白切词，每个词用双引号包裹并把内部 `"` 转义为 `""`，词间用空格（隐式 AND）。
   例：`合同 "第三条"` → `"合同" "第三条"""`。
   **不要把原始输入直接拼进 MATCH**——会导致语法错误或注入式行为。

3. **snippet**：用 `snippet(persisted_docs, 0, '<mark>', '</mark>', '…', 24)`。

4. **title 解析**：`session/title` 事件的文本在 `persisted_docs.text`，`type = 'session/title'`。
   取该会话 seq 最小的一条。无则回退首条 `type='user/message'` 的前 40 字符。

5. **库不存在** → `open` 返回 `Ok(None)`，调用方渲染空列表，**不报错**。

6. **并发安全**：引擎在写，app 在读。SQLite WAL 模式下并发读安全。
   遇到 `SQLITE_BUSY` 重试 3 次（每次退避 50ms）后返回错误。

- **verify:**
  - 单元测试：构造一个含上述 schema 的临时库并插入样本，验证 `list_sessions` / `search` / `session_docs`
  - 单元测试：**尝试写入被拒**（执行 `INSERT` 断言返回 Err）——这是只读保证的关键测试
  - 单元测试：库不存在 → `open` 返回 `Ok(None)`
  - 单元测试：`search("合同 \"第三条\"")` 不 panic 且返回结果（转义生效）
  - 单元测试：`search("*")` 之类的特殊输入不导致 SQL 错误
- **acceptance_criteria:**
  - 只读保证有测试固化
  - FTS5 转义覆盖特殊字符
