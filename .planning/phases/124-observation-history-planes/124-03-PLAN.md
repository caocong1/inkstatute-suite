### Task 1: src/engine/mapper.rs — 事件映射

- **type:** code
- **files:** apps/desktop/src-tauri/src/engine/mapper.rs
- **action:** 实现有状态映射器（有状态是因为 tool-call-delta 需要按 index 累积、turn/step 需要跟踪）：

```rust
pub struct EventMapper { /* 私有：run_id, seq 计数, 工具调用累积表, 当前 turn/step */ }

impl EventMapper {
    pub fn new(run_id: String) -> Self;

    /// 输入一条 DSH 事件，输出 0..N 条统一信封。
    pub fn map(&mut self, ev: &SessionEvent) -> Vec<RunEventEnvelope>;

    /// 输入日志头
    pub fn map_header(&mut self, h: &SessionHeader) -> Vec<RunEventEnvelope>;

    /// ACP 权限请求 → permission.requested
    pub fn map_permission(&mut self, req: &PermissionRequest) -> RunEventEnvelope;
}
```

**映射表，逐条落实：**

| DSH 输入 | 输出 `event_type` | payload 要点 |
|---|---|---|
| `SessionHeader` | `session.started` | `session_id`, `created_at`, `cwd` |
| `assistant/chunk` · `text-delta` | `message.delta` | `message_id`（用 `turn:step:index` 合成）, `delta` |
| `assistant/message` | `message.completed` | `message_id`, `content`（拼接 `data.message.content[].text`） |
| `assistant/chunk` · `reasoning-delta` | `thought.delta` | `delta` |
| `tool/call` | `tool_call.started` | `tool_call_id`, `tool_name`, `arguments` |
| `assistant/chunk` · `tool-call-delta` | `tool_call.delta` | `tool_call_id`, `arguments_delta` |
| `tool/result` | `tool_call.completed` | `tool_call_id`, `result`, `is_error` |
| `step/start` | `plan.updated` | 追加一个 `WorkflowStep{kind:"tool", state:"run"}` |
| `step/end` | `plan.updated` | 把对应 step 标 `state:"done"` |
| `turn/start` | `run.state_changed` | `status: "running"` |
| `turn/end`（reason.kind ≠ error） | `run.state_changed` | `status: "completed"` |
| `turn/end`（reason.kind == error） | `error` | `code`, `message`（**用户可读中文**） |
| ACP `session/request_permission` | `permission.requested` | `tool_call_id`, `options` |
| `session/title` | 不产事件 | 作为 metadata 附在下一条信封的 `metadata.title` |

**不映射**（丢弃）：`agent/inbox/spliced`、`request/header`、`request/context`、
`session/flush`、`session/end-seed`、`user/message`、`Other(_)`。

> `user/message` 不映射的原因：用户消息由前端本地即时上屏（用户自己刚输入的），
> 不需要经引擎回环。若未来要做多端同步再改。
> 但**`is_real_user_message()` 的过滤逻辑仍必须保留**——历史回放（Phase 125 从历史面加载旧会话）会用到它。

**实现细节：**

1. `event_id`：`format!("{}-{}", run_id, envelope_seq)`，`envelope_seq` 从 0 单调递增。
2. `occurred_at`：由 DSH 的 `time`（epoch millis）转 ISO8601 UTC。
3. `seq`：用映射器自己的 `envelope_seq`，**不是 DSH 的 seq**（一条 DSH 事件可能产出多条信封）。
   DSH 原 seq 放进 `metadata.dsh_seq`。
4. **工具调用累积**：`tool-call-delta` 按 `index` 累积 `arguments_delta`；
   `block-end` 时若 block 是 tool-call，则补发一条完整的 `tool_call.started`（若之前没发过）。
5. **错误文案映射**（`turn/end` reason.kind == error），按 `error.code`：
   - `AUTH` → "API 密钥无效，请在设置中重新填写"
   - `RATE_LIMIT` → "请求过于频繁，请稍后再试"
   - `TIMEOUT` → "模型响应超时"
   - 含 `ECONNREFUSED`/`ENOTFOUND`/`network` → "网络连接失败，请检查网络"
   - 其它 → "任务执行失败"
   **原始 message 只放进 `metadata.raw_error`，供本地日志，不作为用户文案。**

- **verify:**
  - 单元测试：每条映射规则各一个用例（14 条）
  - 单元测试：`envelope_seq` 严格单调递增且无跳号
  - 单元测试：`tool-call-delta` 累积后 `block-end` 补发完整 started
  - 单元测试：5 类错误码各映射到正确中文
  - 单元测试：被丢弃的事件类型产出空 vec
- **acceptance_criteria:** 15 种 event_type 全覆盖；错误文案不泄漏技术细节

### Task 2: src/engine/runtime.rs — 运行时编排

- **type:** code
- **files:** apps/desktop/src-tauri/src/engine/runtime.rs
- **action:** 把 supervisor + acp + tailer + mapper 编排成一个可被 Tauri 命令驱动的运行时：

```rust
pub struct EngineRuntime { /* 私有 */ }

impl EngineRuntime {
    /// 启动：读 current 指针 → 定位引擎目录 → spawn → initialize
    pub async fn start(app: AppHandle) -> Result<Self, EngineError>;

    /// 发消息：ensure 会话 → 启动该会话的尾随器（若未启动）→ 构造回灌 → prompt
    pub async fn send(&self, conversation_id: &str, text: &str) -> Result<(), EngineError>;

    pub async fn cancel(&self, conversation_id: &str) -> Result<(), EngineError>;
    pub async fn respond_permission(&self, request_id: i64, d: PermissionDecision) -> Result<(), EngineError>;
    pub async fn shutdown(&mut self) -> Result<(), EngineError>;
}
```

**推送到前端**：每条 `RunEventEnvelope` 用
```rust
app.emit("inkstatute://run-event", &envelope)?;
```
事件名固定为 `inkstatute://run-event`，前端 Phase 125 用 `listen()` 订阅。

**双通道去重**：ACP 的 `agent_message_chunk` 与日志的 `assistant/message` 都携带已提交文本。
**以日志为准**：ACP 侧的 chunk 不产 envelope，只用于
(a) 断连兜底：若尾随器 30s 未产出而 ACP 有文本，则降级用 ACP 文本产 `message.completed`；
(b) 记一条 debug 日志用于交叉校验。

**Tauri 命令**（本 plan 注册）：
```rust
#[tauri::command] pub async fn engine_start(...) -> Result<EngineStatus, String>;
#[tauri::command] pub async fn engine_send(conversation_id: String, text: String) -> Result<(), String>;
#[tauri::command] pub async fn engine_cancel(conversation_id: String) -> Result<(), String>;
#[tauri::command] pub async fn engine_respond_permission(request_id: i64, allow: bool) -> Result<(), String>;
#[tauri::command] pub async fn engine_status() -> Result<EngineStatus, String>;
```

- **verify:** `cargo check` 通过；`cargo test runtime` 通过（用 mock server）
- **acceptance_criteria:** 运行时可启动、可发消息、可取消、可关停；事件经统一通道推出
