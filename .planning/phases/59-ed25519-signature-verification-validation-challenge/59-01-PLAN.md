| Boundary | Description |
|----------|-------------|
| QQ Bot platform → webhook callback | Untrusted network input crosses here — attacker can send forged callbacks |
| Raw HTTP body → signature verification | Untrusted payload — attacker can tamper with body in transit |
| BotSecret → key derivation | Secret material — if leaked, attacker can forge valid signatures |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-59-01 | Spoofing | _ed25519.verify / signature.verify_callback_signature | mitigate | Ed25519 signature verification over timestamp+request_body rejects forged callbacks without valid signature |
| T-59-02 | Tampering | signature.verify_callback_signature | mitigate | Signature covers exact request_body bytes — any modification invalidates signature; request_body passed as bytes, never re-serialized |
| T-59-03 | Tampering | _ed25519.py vendored code | mitigate | Copy RFC 8032 reference verbatim; test_ed25519_vectors.py with official demo vectors detects any algorithm modification |
| T-59-04 | Information Disclosure | signature.derive_keypair / derive_seed | mitigate | BotSecret is passed as parameter, never stored in module-level state; config stores reference only (bot_secret_ref in Plan 02) |
| T-59-05 | Elevation of Privilege | signature.verify_callback_signature | mitigate | Returns False (not exception) on invalid input — caller can safely reject without crash; no path to bypass verification |
