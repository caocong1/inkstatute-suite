<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| QQ Bot platform → webhook callback | Untrusted network input — attacker can send forged callbacks with arbitrary headers and body |
| RawInbound.metadata → verify_and_ack | Untrusted metadata channel — signature headers and raw_body flow through here |
| AckResponse.metadata → webhook response | Trusted output — validation challenge response body returned to QQ platform |
| bot_secret_ref → runtime secret resolution | Secret reference → raw BotSecret injection at runtime (never in config or code) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-59-07 | Spoofing | adapter.verify_and_ack | mitigate | Ed25519 signature verification via verify_callback_signature before accepting any callback; reject with 401 on missing/invalid signature |
| T-59-08 | Tampering | adapter.verify_and_ack raw_body handling | mitigate | raw_body passed as bytes from RawInbound.metadata to verify_callback_signature — never re-serialized; signature covers exact bytes |
| T-59-09 | Elevation of Privilege | adapter.verify_and_ack | mitigate | 401 returned before any payload processing when signature is missing or invalid — no path to normalize_inbound or deliver without verified signature |
| T-59-10 | Information Disclosure | config.py bot_secret_ref | mitigate | bot_secret_ref stores reference only (e.g., "secret://qqbot/bot-secret"), never raw BotSecret; raw secret injected at runtime via metadata, never persisted in config |
| T-59-11 | Tampering | adapter.verify_and_ack op=13 handling | mitigate | op=13 challenge response signed with Ed25519 private key — QQ platform verifies signature to confirm webhook ownership |
| T-59-12 | Repudiation | adapter.verify_and_ack | accept | Replay window handling (timestamp freshness check) is out of scope for this phase; QQ platform manages replay protection at the network layer. Timestamp is included in signature message for future replay protection. |
| T-59-SC | Tampering | pip/cargo installs | accept | No package installs in this phase — dependencies = [] invariant holds, stdlib only |
</threat_model>
