<objective>
Close the FBL service wiring gap by connecting feedback-service callbacks to the existing platform feedback learning and human review surfaces without adding a new service, database, queue, provider, or Hermes dependency.

Purpose: Phase 23 produced feedback learning and review primitives, but the v1.3 audit found feedback-service code does not invoke them and same-session corrections do not feed future context. This plan creates an injected helper surface that feedback-service callers can use to create correction refs, queue pending candidates, persist candidate rows when a durable store is already injected, and apply explicit review actions safely.

Output: `feedback_service.memory_wiring` helper module, public exports, and tests proving correction refs, pending candidates, explicit review promotion, rejection/defer behavior, and no-auto-modify route/skill safety.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Feedback callback/event input -> feedback-service helper | Untrusted feedback event mappings enter normalization, dedupe, classification, and learning. |
| Feedback-service helper -> platform-runtime learning policy | Sanitized event metadata becomes correction refs and pending candidates. |
| Feedback-service helper -> review store/durable candidate store | Pending candidates are queued or persisted as candidates only. |
| Explicit review action -> memory store | Human review decisions can promote approved candidates to MemoryRecord entries. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25.1-05 | Tampering | `wire_feedback_to_memory` | mitigate | Callback ingestion queues candidates and returns refs; it never calls `memory_store.upsert()` or promotes recall-visible memory. |
| T-25.1-06 | Elevation of Privilege | route/skill candidate review | mitigate | Preserve `proposed_action="review_route_or_skill_candidate"` guard; tests assert only defer is allowed and no-auto-modify remains true. |
| T-25.1-07 | Information Disclosure | feedback event metadata | mitigate | Reuse feedback queue clone/privacy checks and platform memory safe metadata; reject raw payload/full-text keys. |
| T-25.1-08 | Repudiation | duplicate feedback callbacks | mitigate | Use existing dedupe/idempotency metadata and return queued candidate ids plus persisted candidate ids in result metadata. |
| T-25.1-SC | Tampering | npm/pip/cargo installs | mitigate | No package install is planned; all code uses existing stdlib/local packages. |
</threat_model>
