## Shared Patterns

### Reference-First Privacy

**Sources:** `ingress_runtime.py` lines 205-229; `queue.py` lines 193-201; `memory.py` lines 207-235

Apply to all runtime metadata, feedback events, candidates, MemoryUse evidence, eval fixtures, and planning artifacts. Do not store `raw_payload`, full legal/customer text, document text, callback bodies, or secrets.

### Optional Host Injection

**Sources:** `ingress_runtime.py` lines 34-62; `memory_eval.py` lines 81-90

Use optional constructor parameters and injected factories/stores. Do not add a daemon, provider SDK, global runtime service, new DB, or Hermes core dependency.

### Human Review Boundary

**Sources:** `memory_review.py` lines 110-121, 177-185

Route/skill candidates use `proposed_action="review_route_or_skill_candidate"` and may only be deferred by this decider; approval/edit/reject/tombstone should raise for those high-risk candidates.

### Planning Verification Artifact Shape

**Source:** `.planning/phases/19-close-gap-v1-2-wecom-session-runtime-e2e-wiring/19-VERIFICATION.md` lines 1-46

Copy frontmatter fields `phase`, `status`, `verified_at`, `score`, `human_verification`, `review_status`, then sections `Goal`, `Must-Haves`, `Evidence`, `Automated Checks`, `Notes`, and `Result`. Keep live WeCom/lawyer trial as manual carried gates unless actual human evidence exists.
