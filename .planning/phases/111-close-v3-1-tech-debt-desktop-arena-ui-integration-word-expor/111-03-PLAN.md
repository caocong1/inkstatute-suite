<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Desktop app → arena-service | HTTP calls from the desktop app to arena-service (127.0.0.1:8001) cross a trust boundary — the arena client must send the bearer token for authentication. |
| SSE stream → desktop app | SSE events from arena-service are consumed by createArenaStream — the store must not execute arbitrary code from event payloads. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-111-03-01 | Spoofing | arena-service client (config/arena.ts) | mitigate | Send `Authorization: Bearer ${VITE_ARENA_SERVICE_TOKEN}` header on all arena client requests; arena-service rejects missing/wrong tokens with 401. |
| T-111-03-02 | Tampering | SSE event consumption (createArenaStream) | accept | createArenaStream store is an existing tested component from Phase 110; it parses SSE frames as data, not code — no eval or dynamic code execution. |
| T-111-03-03 | Information Disclosure | Arena page error states | mitigate | Arena page should not display raw backend error details to the lawyer; show user-friendly error messages (existing output boundary in arena-service filters backend noise). |
| T-111-03-SC | Tampering | npm/pip/cargo installs | accept | No package installs — all dependencies already in workspace. |
</threat_model>
