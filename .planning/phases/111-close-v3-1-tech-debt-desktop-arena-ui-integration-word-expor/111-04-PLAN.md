Add the `POST /v1/arena/{arena_id}/export` endpoint to arena-service. The endpoint is a thin caller — it NEVER re-implements docx generation.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Desktop app → arena-service export endpoint | HTTP call crosses trust boundary — must be behind localhost check + bearer token auth. |
| arena-service → filesystem (output_path) | The export endpoint writes a docx to a user-chosen path — path injection could write to arbitrary locations. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-111-04-01 | Spoofing | Export endpoint auth | mitigate | Existing `auth.require_localhost` + `auth.require_auth` middleware applied BEFORE routing to export handler (app.py:121,143) — no bypass possible. |
| T-111-04-02 | Tampering | output_path validation | mitigate | Validate `output_path` is non-empty; consider validating it is within an expected directory (e.g., user home or temp). The path comes from the desktop's native save dialog (trusted local source), but server-side validation is defense-in-depth. |
| T-111-04-03 | Information Disclosure | Export error messages | mitigate | Do not leak backend error details (stack traces, internal paths) to the client; return structured error dicts with safe messages. |
| T-111-04-04 | Elevation | Export endpoint permission | accept | Export endpoint only generates docx files — no command execution, no permission escalation path. |
| T-111-04-SC | Tampering | npm/pip/cargo installs | accept | No package installs — all dependencies already in workspace. |
</threat_model>
