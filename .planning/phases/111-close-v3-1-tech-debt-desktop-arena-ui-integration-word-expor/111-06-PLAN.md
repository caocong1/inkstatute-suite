## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Desktop app → arena-service export endpoint | onExport triggers an HTTP call to the export endpoint — must be behind existing auth + localhost middleware. |
| arena-service → filesystem (output_path) | The export endpoint writes docx to the user-chosen path — path comes from native save dialog (trusted local source). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-111-06-01 | Spoofing | onExport → export endpoint call | mitigate | arenaClient sends `Authorization: Bearer ${VITE_ARENA_SERVICE_TOKEN}` header; arena-service rejects missing/wrong tokens with 401. |
| T-111-06-02 | Information Disclosure | Export error display in ArenaPage | mitigate | Show user-friendly error messages ("导出失败"); do NOT display raw backend error details, stack traces, or internal file paths to the lawyer. |
| T-111-06-03 | Tampering | output_path from native save dialog | accept | Path comes from the OS native save dialog (trusted local source); server-side validation in the export endpoint (Plan 04) provides defense-in-depth. |
| T-111-06-04 | Tampering | E2E test track-changes mock | accept | Test mock is confined to the test environment; production uses the real TrackChangesBuilder from agent-core. |
| T-111-06-SC | Tampering | npm/pip/cargo installs | accept | No package installs — pure wiring + test addition. |
</threat_model>
