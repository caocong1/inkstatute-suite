# Plan 06-03 - Read API And Contract Fixture Integration

## Objective

Expose the Phase 6 minimum GET surfaces through pure route handlers and add cross-service fixtures/tests proving the conversation read model and feedback queue work together from contract-log-derived data.

## Threat Model

<threat_model>
<risk id="T-06-03-api-privacy" severity="high">API responses may expose raw payloads, secrets, runtime database paths, customer documents, media bytes, or backend notices. Mitigation: handlers return scrubbed read-view dictionaries and tests scan for exact raw payload keys and secret-like text.</risk>
<risk id="T-06-03-route-scope" severity="medium">The API layer may grow beyond the Phase 6 minimum surface. Mitigation: implement only the three specified GET surfaces and return 404/400 for unsupported paths/statuses.</risk>
<risk id="T-06-03-relationships" severity="high">Conversation/task/feedback views may break result-to-feedback or trace relationships. Mitigation: contract-test-suite fixtures validate schema/relationships and handler tests assert association fields.</risk>
<risk id="T-06-03-feedback-route" severity="high">Pending feedback route could hide human-review requirements or imply automatic skill changes. Mitigation: route-mismatch queue items expose skill_candidate evidence, requires_human_review, and no_auto_modify.</risk>
</threat_model>
