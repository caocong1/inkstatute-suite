### Task 1: Offline degradation + UpdateStatus

**Files:** `lib/content/update_status.dart`, `lib/content/content_updater.dart`, `test/content/offline_test.dart`

**Action:**

1. Create `lib/content/update_status.dart`:
   - `UpdateStatus` class (immutable) with:
     - `isUpToDate` (bool) — true if current version matches latest checked
     - `currentVersion` (String?) — current release version
     - `latestCheckedVersion` (String?) — latest version from last check
     - `lastCheckedAt` (DateTime?) — timestamp of last check
     - `isOffline` (bool) — true if last check failed due to network
     - `errorMessage` (String?) — error message if last check failed
     - `displayMessage` (String) — human-readable status message in Chinese:
       - Up to date: "技能内容已是最新版本 (v<version>)"
       - Update available: "发现新版本 v<version>，正在更新..."
       - Update failed: "技能更新失败，已回退到 v<version>"
       - Offline: "技能更新不可用（离线模式），当前版本 v<version>"
       - No content: "未安装技能内容包"

2. Add offline degradation to `ContentUpdater`:
   - `Future<UpdateResult> checkAndUpdateOfflineSafe()` — Wraps `checkAndUpdate()`. On `UpdateException(networkError)`:
     - If current release exists, return `UpdateResultFailure` with `rolledBackTo=currentVersion` and a flag indicating offline mode
     - If no current release but last-good exists, rollback to last-good and return failure
     - If neither exists, return failure with message "no content available"
   - `UpdateStatus currentStatus()` — Returns current `UpdateStatus` based on last check result and local state.

3. Create `test/content/offline_test.dart`:
   - Test offline with current release: returns failure with rolledBackTo=currentVersion, status.isOffline=true
   - Test offline with no current but last-good exists: rollback to last-good, return failure
   - Test offline with no content at all: return failure with "no content available"
   - Test `currentStatus()` returns correct display message for each state
   - Test `currentStatus()` for up-to-date state
   - Test `currentStatus()` for no-content state

**Verify:**
```xml

```

**Done:** Offline degradation works correctly. UpdateStatus provides UI-ready messages.

### Task 3: Zero-restart validation test

**Files:** `test/content/zero_restart_test.dart`

**Action:**

Create `test/content/zero_restart_test.dart`:
- This test validates that DSH skill watcher detects new skill directories without engine restart.
- Since we can't run a real DSH engine in unit tests, this test validates the **contract**:
  1. Create a temp directory representing `customSkillDirs`
  2. Create initial skill structure: `<dir>/legal-commercial/contract-review/SKILL.md`
  3. Simulate "before update" skill catalog snapshot (list of skill names)
  4. Simulate content update: create new release dir with additional skills
  5. Update `current` pointer to new release
  6. Simulate "after update" skill catalog snapshot (list of skill names from new release dir)
  7. Assert that the new skills appear in the "after" snapshot
  8. Assert that the directory structure is compatible with DSH's depth:1 scan (one level of skill dirs per domain)
- This is a structural validation test, not a live engine test. The live engine validation is part of Phase 120 lawyer trial.
