# Plan 11-02 - Non-Mutating Capability Probe And Fallback Audit

## Objective

Add a safe Hermes capability probe that inspects only non-mutating endpoints, maps results into adapter capabilities, and falls back to the one-shot manifest with sanitized audit reasons when probing fails.

## Threat Model

<threat_model>
<risk id="T-11-02-mutating-probe" severity="high">Startup capability detection could create or read run-specific state. Mitigation: hard-code the probe request set to `/health`, `/v1/capabilities`, and `/v1/models`, and test that `/v1/runs` never appears in transport calls.</risk>
<risk id="T-11-02-response-leak" severity="high">Probe fallback audit could store raw response bodies, hostnames, tokens, or private paths. Mitigation: fallback reports use bounded reason codes and sanitized endpoint names only.</risk>
<risk id="T-11-02-no-channel-io" severity="high">Probe-derived capabilities could omit or downgrade `no_channel_io=True`. Mitigation: mapping always sets ordinary-user Hermes backend manifests to `no_channel_io=True` or returns a blocking issue.</risk>
<risk id="T-11-02-version-drift" severity="medium">Hermes endpoint shape can drift by version. Mitigation: probe parser tolerates missing fields and falls back to reduced one-shot capabilities.</risk>
</threat_model>
