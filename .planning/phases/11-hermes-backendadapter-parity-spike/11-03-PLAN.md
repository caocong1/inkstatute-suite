# Plan 11-03 - Default-Off Runs Lane And Approval Safety

## Objective

Add a testable Hermes `/v1/runs` adapter seam behind `INKSTATUTE_HERMES_API_RUNS_ENABLED`, while preserving one-shot as default and enforcing the high-risk legal approval boundary.

## Threat Model

<threat_model>
<risk id="T-11-03-default-on-runs" severity="high">The API-run lane could become default before parity is proven. Mitigation: config defaults `api_runs_enabled=False`, env parsing requires exact true value, and tests assert API-run submission is refused when disabled.</risk>
<risk id="T-11-03-unfiltered-events" severity="high">Run events could expose backend meta/tool/gateway text before output boundary handling. Mitigation: API-run event mapping records refs/sanitized summaries and leaves ordinary-user visibility to `DefaultRunRuntime.stream` output-boundary enforcement.</risk>
<risk id="T-11-03-approval-safety" severity="high">Approval could auto-approve high-risk legal conclusions or skill changes. Mitigation: guard rejects approvals with high-risk legal metadata and returns/preserves pending or failed state with human-review metadata.</risk>
<risk id="T-11-03-state-drift" severity="medium">Hermes API statuses could drift from platform AsyncTaskState. Mitigation: status mapper only emits known `AsyncTaskState` values and maps unknowns to `failed` with sanitized error metadata.</risk>
</threat_model>
