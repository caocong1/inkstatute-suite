# Plan 42-01 — Admin Console API Service Structure, Static Token Auth, and Sessions/Tasks/Feedback Views

## Goal

Create the `services/admin-console-api/` service with static token authentication from env (`ADMIN_API_TOKEN`) and three read-only data views (sessions, tasks, feedback) that reuse `ContractLogReadModel` and cursor pagination from `services/conversation-read-view/`. The service is strictly read-only — no mutations, no writes, no POST/PUT/DELETE handlers.

This plan satisfies ADMIN-01 (data views portion):
- SC1: Operator can authenticate to the Admin Console API via a static token from env and query sessions, tasks, and feedback views with filtering and pagination, receiving read-only responses.

## Context

- The Admin Console API is a **new service** following the existing `services/conversation-read-view/` pattern: `src/{package}/`, `tests/`, `pyproject.toml` with `dependencies = []`, `README.md`. Pure Python, stdlib only, no server process.
- `ContractLogReadModel` (`services/conversation-read-view/src/conversation_read_view/read_model.py:28-288`) provides `get_conversation()`, `get_task()`, `get_task_by_trace_id()`, `list_conversations()`, `list_tasks()`. The Admin Console API imports and delegates to these methods — it does not subclass or duplicate.
- Cursor pagination (`services/conversation-read-view/src/conversation_read_view/pagination.py:1-133`) provides `clamp_limit()`, `encode_cursor()`, `decode_cursor()`, `slice_page()`. The Admin Console API reuses these directly.
- Privacy scrubbing (`services/conversation-read-view/src/conversation_read_view/privacy.py:51-62`) provides `scrub_contract_payload()` which raises `ValueError` on forbidden keys. The Admin Console API routes all data-view responses through this scrub.
- The `admin_api_enabled` feature flag already exists in `RuntimeFeatureFlags` (`packages/platform-runtime/src/platform_runtime/feature_flags.py:22`) with default `False`. Wave 1 wires a basic flag check; Wave 3 (42-03) adds comprehensive flag gating tests.
- The API entry point pattern is `handle_get(path, query, read_model, ...) -> tuple[int, dict]` from `conversation_read_view/api.py:18-82`. The Admin Console API follows the same pattern but adds an auth gate.
- Contract freeze (SAFETY-02, SAFETY-06): No changes to `packages/platform-contract/` or `packages/platform-runtime/protocols.py`.
- Privacy: Tests use short placeholder tokens (e.g., `test-token`) — never real secret-like values. Plan files use `REDACTED` or short placeholders (< 12 chars).
