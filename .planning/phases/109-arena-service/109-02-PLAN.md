# Plan 02: SSE Multiplexing + Event Buffer for Reconnection

## Objective

Create `ArenaSseStream` (SSE encoding with N-agent multiplexing on a single connection, each event tagged with `metadata.agent_slot`) and `ArenaEventBuffer` (in-memory per-arena event buffer with seq-based replay for SSE reconnection). The multiplexing reuses the Gateway's `encode_sse_event` pattern but adds arena-specific event framing. The buffer mirrors `RunEventBuffer` but is keyed by `arena_id` instead of `run_id`.

## must_haves

truths:
  - N agents' events are multiplexed on a single SSE connection with `metadata.agent_slot` preserved in every frame
  - Client can demultiplex by filtering on `metadata.agent_slot` in the SSE JSON data
  - `ArenaEventBuffer` is keyed by `arena_id` (not `run_id`) — supports arena-level reconnection
  - `replay(arena_id, last_seq)` returns exactly events with `seq > last_seq` — NO duplication, NO loss
  - FIFO eviction caps memory at `max_events_per_arena` per arena

  - `ArenaSseStream` accepts an optional output filter (wired in Plan 03) for two-layer boundary enforcement
  - `parse_last_event_id` extracts the `Last-Event-ID` header for reconnection breakpoint
