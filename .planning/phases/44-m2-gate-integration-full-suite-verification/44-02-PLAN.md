# Plan 44-02 — Create Gate-Coverage Meta-Test

## Goal

Create `packages/contract-test-suite/tests/test_gate_coverage.py` — a meta-test that
asserts every `packages/*/src` and `services/*/src` directory on disk is covered by at
least one V2 gate, and that the gate count meets the Phase 44 baseline. Coverage is
determined by runtime inspection of `scripts/run_v2_gates._gates()`: a directory is
"covered" if it appears in any gate's `pythonpath` tuple OR in the `compileall` gate's
command path arguments. This is the concrete artifact that satisfies GATE-01 success
criterion #3 (a meta-test asserting every `packages/*/src` and `services/*/src`
directory is covered by a gate, failing if any directory is uncovered).

This plan creates the file only. It runs in parallel with Plan 44-01 (different file, no
merge conflict). The meta-test's behavioral PASS requires Plan 44-01's gate changes to be
applied (the 3 new gates + 4 compileall dirs make all directories covered); that
end-to-end pass is verified by Plan 44-03's full-suite run.

## Context

- The meta-test uses runtime inspection (importing `_gates` from `run_v2_gates.py`) rather
  than static parsing — this stays in sync with the gate runner automatically and avoids
  regex fragility. Pattern source: `44-PATTERNS.md` lines 82-148 and `44-RESEARCH.md`
  lines 184-243.
- `REPO_ROOT = Path(__file__).resolve().parents[3]` — contract-test-suite tests are 3
  dirs below repo root (matches `test_audit_v2_requirements.py:25`).
- Import convention: `sys.path.insert(0, str(REPO_ROOT / "scripts"))` then
  `from run_v2_gates import _gates`. `_gates(repo_root)` returns a tuple of `Gate`
  objects; each `Gate` has `.name` (str), `.command` (tuple[str, ...]),
  `.pythonpath` (tuple[str, ...] defaulting to ()).
- The `compileall` gate is identifiable by the string `"compileall"` appearing in its
  `.command` tuple. Its path arguments are relative strings ending in `/src`.
- The meta-test module imports only stdlib (`sys`, `unittest`, `pathlib.Path`) at module
  level, so the gate's PYTHONPATH does not affect import resolution; it sets its own
  `sys.path` entry for the `scripts` dir.
- After Plan 44-01 + 44-02 are both applied, all 14 `packages/*/src` + 5 `services/*/src`
  = 19 directories are covered. Before 44-01, 3 dirs are uncovered, so the meta-test
  would FAIL if run in isolation prior to 44-01 — this is expected and is why the
  full-suite verification lives in Plan 44-03.
- This file is discovered by the existing `contract-test-suite` gate (which runs
  `unittest discover -s packages/contract-test-suite/tests`) AND by the new
  `gate-coverage-meta-test` gate registered in Plan 44-01 — both run the same file; this
  redundancy is harmless (the test is fast).

<action>
1. Create `packages/contract-test-suite/tests/test_gate_coverage.py` with module docstring:
   "Meta-test: assert every packages/*/src and services/*/src directory is covered by a V2
   gate. A directory is covered if it appears in any gate's PYTHONPATH tuple or in the
   compileall gate's command path arguments. Uses runtime inspection of
   scripts/run_v2_gates._gates() — no static parsing."

2. Module-level imports: `from __future__ import annotations`, `import sys`,
   `import unittest`, `from pathlib import Path`. Define
   `REPO_ROOT = Path(__file__).resolve().parents[3]`.

3. Define a module-level helper `def _gates():` that does
   `sys.path.insert(0, str(REPO_ROOT / "scripts"))`, then
   `from run_v2_gates import _gates as _build_gates`, and returns `_build_gates(REPO_ROOT)`.
   (The `sys.path.insert` is idempotent enough for a single test-process use; this matches
   the pattern in 44-PATTERNS.md lines 119-131.)

4. Define `class TestGateCoverage(unittest.TestCase):` with:

   a. `def _all_covered_src_paths(self):` — returns a `set` of resolved `Path` objects.
      Iterate `for gate in _gates():`; for each `p` in `gate.pythonpath` add
      `Path(p).resolve()`. Then detect the compileall gate via
      `if "compileall" in gate.command:` and for each `arg` in `gate.command`, if
      `isinstance(arg, str) and arg.endswith("/src")`, add `(REPO_ROOT / arg).resolve()`.
      Return the set.

   b. `def test_all_packages_src_covered(self):` —
      `on_disk = {p.resolve() for p in (REPO_ROOT / "packages").glob("*/src")}`;
      `covered = self._all_covered_src_paths()`;
      `uncovered = on_disk - covered`;
      `self.assertEqual(uncovered, set(), f"Uncovered packages/*/src: {sorted(str(p) for p in uncovered)}")`.

   c. `def test_all_services_src_covered(self):` —
      `on_disk = {p.resolve() for p in (REPO_ROOT / "services").glob("*/src")}`;
      `covered = self._all_covered_src_paths()`;
      `uncovered = on_disk - covered`;
      `self.assertEqual(uncovered, set(), f"Uncovered services/*/src: {sorted(str(p) for p in uncovered)}")`.

   d. `def test_gate_count_meets_baseline(self):` —
      `self.assertGreaterEqual(len(_gates()), 19)`.
      Use `assertGreaterEqual` (a regression FLOOR), NOT an exact count, so future phases
      that add gates do not break this meta-test. The exact-count assertion (== 19) lives
      in `test_audit_v2_requirements.py` (Plan 44-03).

5. End the file with `if __name__ == "__main__":` → `unittest.main()`.

6. Do NOT import `platform_contract`, `contract_test_suite`, or any source package at
   module level — the test only needs stdlib + the `run_v2_gates` module via `sys.path`.
   Do NOT use subprocess to call `--list` (runtime inspection of `_gates()` is the
   chosen approach per RESEARCH). Do NOT hardcode directory names — enumerate on disk via
   `glob("*/src")` so new directories automatically become coverage requirements.
</action>
