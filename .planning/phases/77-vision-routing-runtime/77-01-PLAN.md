<objective>
Establish the operator-config vision routing mode validation and policy schema as the shared, server-enforced authority for vision routing configuration.

Purpose: VIS-01 requires operators to configure a vision routing mode (`auto` | `always_preprocess` | `main_only`) plus an optional dedicated vision provider/model. Phase 76 created `VisionPolicyDoc` as a draft-tolerant stub with `allow_partial=True` vision validation. Phase 77 must add `routing_mode` enum validation and enforce vision pair completeness when the routing mode requires a vision step, while preserving the Phase 76 contract that `main_only` allows absent/partial/complete vision drafts. This plan preserves the CONTEXT locks: no secret resolution in operator-config, no Hermes filesystem authority, and no runtime routing logic (that lives in `vision_router.py`).

Output: `routing_mode` enum validation, vision completeness enforcement gated by routing mode, public export updates, and focused package tests.
</objective>
