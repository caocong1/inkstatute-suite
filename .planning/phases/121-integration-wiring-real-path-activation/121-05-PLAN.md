### Task 1: Create real-API smoke test — prompt → streaming → committed text

- **type:** test
- **files:** apps/flutter_app/test/e2e/real_api_smoke_test.dart
- **action:**
  1. Add `@Tags(['realApi'])` annotation at the top of the file.
  2. Write a test that:
     - Loads the DeepSeek API key from the OS credential store via `CredentialStore().loadApiKey()`.
     - If no key is found, call `print('Skipping: no API key in credential store')` and `return` (self-skip, not a failure).
     - Creates a `DshProcessManager` with `DshConfig.forEngine(engineDir)` pointing at the built engine from 121-01.
     - Calls `manager.spawn(config, apiKey)`.
     - Calls `manager.healthProbe()` — assert `Healthy`.
     - Gets `acpClient` from `manager.acpClient`.
     - Calls `acpClient.newSession(absoluteCwd)` — assert non-empty session ID.
     - Creates a `SessionDatabase.inMemory()`, `SessionRepository`, and `ChatController`.
     - Calls `controller.sendPrompt("你好，请简单介绍一下中国合同法的基本原则。")`.
     - Awaits completion.
     - Asserts `controller.messages` contains at least one `UserMessage` and one `AssistantMessage`.
     - Asserts the `AssistantMessage.text` is non-empty.
     - Asserts `controller.status == MessageStatus.completed`.
     - Calls `manager.dispose()` — assert `CleanExit` or `ForceKilled`.
     - Calls `manager.assertNoOrphans()` — assert `true`.
  3. Add a timeout of 60 seconds for the real API call.
  4. Use `testWidgets` or `group`/`test` as appropriate. Since this is an integration test (not a widget test), use `test` from `package:test/test.dart`.
- **verify:**
  - With a real API key in the credential store: `flutter test test/e2e/real_api_smoke_test.dart` passes.
  - Without an API key: the test self-skips (prints skip message, returns early, passes).
  - The test never prints or logs the API key.
- **acceptance_criteria:**
  - Test spawns a real DSH engine, creates a real session, sends a real prompt, and receives committed text
  - Test self-skips without an API key (no failure in CI)
  - Engine is properly shut down (zero orphans)
  - No API key is logged or printed

### Task 2: Create real-API approval card test

- **type:** test
- **files:** apps/flutter_app/test/e2e/real_api_approval_test.dart
- **action:**
  1. Add `@Tags(['realApi'])` annotation.
  2. Write a test that:
     - Loads the API key (self-skip if absent).
     - Spawns the real engine, creates a session.
     - Sets up the `ChatController` with permission policy wiring (from 121-01).
     - Sends a prompt that is likely to trigger a tool request (e.g., "请执行 `ls` 命令查看当前目录" or a prompt that requires bash execution).
     - Awaits the response.
     - Asserts that an `ApprovalMessage` appears in `controller.messages` (the permission policy creates an approval card when the engine requests permission for terminal/bash).
     - Note: the approval card is created with `pending` status and the policy returns `reject-once` — the tool is denied but the card is displayed.
     - Asserts the approval card has a `toolCallId` and `toolName`.
     - Calls `controller.handleApproval(toolCallId, false)` — verify the card status updates to `rejected`.
     - Shuts down the engine, asserts zero orphans.
  3. Add a timeout of 60 seconds.
  4. Note: the approval card may not appear if the engine doesn't request permission for the given prompt. The test should handle this gracefully — if no approval card appears, the test still passes but logs a note that the approval path was not exercised. A more reliable trigger prompt may be needed based on the engine's actual behavior.
- **verify:**
  - With a real API key: test passes (either approval card appears and is verified, or test notes the path wasn't triggered).
  - Without a key: self-skips.
- **acceptance_criteria:**
  - Test verifies the approval card creation path on the real engine
  - Test handles the case where no permission request is triggered
  - Engine is properly shut down
