<objective>
Wire `GuardrailIntegrator.runAllChecks()` into `ChatController`'s assistant message processing path so every assistant message passes through all 6 guardrail checks before being rendered. Add negative regression tests on the integrated path that verify guardrail bypass attempts fail. This closes INT-01 — the critical gap where guardrails exist as standalone modules but are never enforced in the chat flow.
</objective>

### Task 2: Wire GuardrailIntegrator into ChatController.sendPrompt()

- **type:** code
- **files:** apps/flutter_app/lib/chat/chat_controller.dart
- **action:**
  1. Add `import 'package:flutter_app/guardrails/guardrail_integrator.dart'` and `import 'package:flutter_app/guardrails/guardrail_models.dart'` to `chat_controller.dart`.
  2. In `sendPrompt()`, after the assistant message is parsed (line ~86-93 in current code), before adding it to `_messages`:
     - Call `GuardrailIntegrator.runAllChecks(assistantMsg)` to get guardrail results.
     - Compute `blocked = GuardrailIntegrator.shouldBlock(results)`.
     - Compute `warnings = GuardrailIntegrator.warnings(results)`.
     - Recreate the `AssistantMessage` with the guardrail results, warnings, and blocked flag attached:
       ```dart
       final checkedMsg = AssistantMessage(
         text: parsed.cleanText,
         timestamp: DateTime.now(),
         citations: parsed.citations,
         humanReviewMarkers: parsed.humanReviewMarkers,
         clarifyRequests: parsed.clarifyRequests,
         guardrailResults: results,
         guardrailWarnings: warnings,
         guardrailBlocked: blocked,
       );
       ```
     - Add `checkedMsg` to `_messages` instead of the unchecked `assistantMsg`.
     - Persist `checkedMsg` to the repository.
  3. If `blocked` is true:
     - Add a `SystemErrorMessage` after the assistant message indicating the guardrail block (e.g., "护栏拦截：${GuardrailIntegrator.blocks(results).join('; ')}").
     - Set `_status = MessageStatus.completed` (not error — the guardrail block is a policy decision, not a system error).
  4. If there are warnings but no block:
     - The assistant message is rendered with warning indicators (the UI layer in `ChatMessageWidget` will show warnings based on `guardrailWarnings`).
  5. Add a `GuardrailIntegrator` instance field to `ChatController` (optional injection for testing):
     ```dart
     final GuardrailIntegrator? _guardrailIntegrator;
     ```
     In the constructor, accept an optional `GuardrailIntegrator? guardrailIntegrator` parameter. If null, use the static `GuardrailIntegrator.runAllChecks()` method.
- **verify:**
  - `flutter analyze` passes
  - New test `test/chat/chat_controller_guardrail_integration_test.dart`:
    - Test 1: Send a prompt with a mock ACP client that returns assistant text with no citations → `ResearchGateChecker` should flag it (warn or block) → `AssistantMessage.guardrailResults` is non-empty.
    - Test 2: Send a prompt with assistant text containing `[HUMAN_REVIEW: ...]` → `HumanReviewEnforcer` should pass → `guardrailBlocked` is false.
    - Test 3: Send a prompt with assistant text that has no `[POLISHED]` marker → `PolishChecker` should flag it.
  - Existing `test/chat/chat_controller_test.dart` still passes (guardrails add results but don't break existing behavior for passing messages).
- **acceptance_criteria:**
  - `ChatController.sendPrompt()` calls `GuardrailIntegrator.runAllChecks()` on every assistant message
  - Guardrail results are attached to the `AssistantMessage` before it's added to `_messages`
  - Blocked messages produce a `SystemErrorMessage` with the block reason
  - Warning messages carry warning text for UI rendering
  - Guardrail integrator is injectable for testing

### Task 3: Add negative regression tests on the integrated path

- **type:** test
- **files:** apps/flutter_app/test/guardrails/guardrail_bypass_regression_integrated_test.dart
- **action:**
  1. Write integration-level tests that verify guardrail bypass attempts fail when going through the full `ChatController.sendPrompt()` path (not just standalone checker tests):
     - **Test: Research-gate bypass attempt** — assistant text with a conclusion but zero citations → `guardrailResults` contains a non-pass `ResearchGateChecker` result → message is not rendered as a clean conclusion.
     - **Test: Citation audit bypass** — assistant text with unverified citations → `guardrailResults` contains a `CitationAuditEnforcer` warning → `guardrailWarnings` is non-empty.
     - **Test: Human review removal attempt** — assistant text with `[HUMAN_REVIEW: ...]` marker → the marker is parsed and preserved in `humanReviewMarkers` → `HumanReviewEnforcer` passes (marker present) → if marker is absent on a high-risk task, the enforcer blocks.
     - **Test: Polish bypass** — assistant text without `[POLISHED]` marker → `PolishChecker` flags it → warning is attached.
  2. Each test uses a mock `AcpClient` that streams a specific assistant text, then asserts the `ChatController.messages` list contains an `AssistantMessage` with the expected guardrail results.
  3. Verify that `guardrailBlocked` is `true` when any check returns `block` severity.
  4. Verify that a `SystemErrorMessage` follows the blocked assistant message.
- **verify:**
  - `flutter test test/guardrails/guardrail_bypass_regression_integrated_test.dart` passes
  - `flutter test` (full suite) still passes
- **acceptance_criteria:**
  - 4+ negative regression tests on the integrated `ChatController` path
