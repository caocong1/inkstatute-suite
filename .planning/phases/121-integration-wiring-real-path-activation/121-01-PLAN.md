Note: since the policy returns `reject-once` immediately, `handleApproval()` is a UI-state update (the ACP response was already sent). ### Task 3: Enhance AppStartup with engine spawn coordination

- **files:** apps/flutter_app/lib/app/app_startup.dart
- **action:**

     - Calls `loadEngineConfig()` to get the `EngineStartupConfig`.

     - Creates a `DshProcessManager`.
     - Calls `manager.spawn(dshConfig, config.apiKey)`.
     - Calls `manager.healthProbe()`.
     - Returns `EngineLaunchResult(manager, healthResult)` on success, or `EngineLaunchResult(manager, Unhealthy(reason))` on probe failure.
  2. Add a class `EngineLaunchResult` that holds the `DshProcessManager` and `HealthResult`.
  3. Add a method `Future<String> resolveEngineDir()` that:
     - Checks `engines/releases/` for the built engine zip.
     - Extracts (or locates) the engine directory at the expected path.
     - Returns the absolute path to the engine directory (e.g., `engines/releases/engine-0.1.0-47f943859b/`).
  4. Update `EngineStartupConfig.validatePaths()` to only require `enginePath` to exist (Python and script paths are optional at startup — they're only needed for export, which is Wave 2).
- **verify:**
  - `flutter analyze` passes
  - New test `test/app/app_startup_integration_test.dart`: mock the engine directory, verify `launchEngine()` calls `DshProcessManager.spawn()` and `healthProbe()`.
  - Existing `test/app/app_startup_test.dart` still passes.
- **acceptance_criteria:**
  - `AppStartup.launchEngine()` creates a `DshProcessManager`, spawns the engine, and runs the health probe

  - `resolveEngineDir()` finds the built engine directory

### Task 4: Rewrite main.dart with AppStartup-driven startup flow

- **type:** code
- **files:** apps/flutter_app/lib/main.dart
- **action:**
  1. Replace the current minimal shell with a stateful `InkStatuteApp` that drives the startup flow.
  2. Create a `_AppState` with an `AppStartup` instance initialized with the platform-appropriate app data directory (use `DshPaths.resolveDshHome()` parent or `Platform.environment` to determine the app data dir).
  3. In `initState()`, call `_appStartup.shouldShowWizard()`:
     - If true: set state to show `FirstRunWizard`.
     - If false: proceed to `_startEngineAndChat()`.
  4. `FirstRunWizard.onComplete` callback:
     - Call `_appStartup.completeWizard()` with the wizard state (practice area, API key, model config).
     - Proceed to `_startEngineAndChat()`.
  5. `_startEngineAndChat()`:
     - Call `_appStartup.launchEngine()`.
     - If result is null (no config): show error screen ("请先完成首启向导").
     - If health result is `Unhealthy`: show error screen with the reason (user-readable Chinese via `ErrorMapper`).
     - If health result is `Healthy`:
       - Get `acpClient` from `manager.acpClient`.
       - Create `SessionDatabase.forPath()` at the app data dir.
       - Call `db.init()`.
       - Create `SessionRepository(db)`.
       - Call `acpClient.newSession()` with an absolute cwd to create a new session.
       - Create `ChatController` with the `acpClient`, repository, session ID, and practice area from wizard settings.
       - Set state to show `ChatScreen` with the `ChatController`.
  6. Create a `ChatScreen` widget that wraps `ChatView` with:
     - An `AppBar` with the app title and practice area.
     - The `ChatView` connected to the `ChatController` (messages, status, callbacks).
     - `onSendPrompt` → `controller.sendPrompt()`.
     - `onCancel` → `controller.cancelInFlight()`.
     - `onAllowApproval` → `controller.handleApproval(id, true)`.
     - `onRejectApproval` → `controller.handleApproval(id, false)`.
     - `onClarifySubmit` → `controller.handleClarifyResponse()`.
  7. In `dispose()`, call `manager.dispose()` to gracefully shut down the engine.
  8. Show a loading indicator during engine spawn and health probe.
- **verify:**
  - `flutter analyze` passes
  - New test `test/main_startup_flow_test.dart`: widget test that verifies the app shows the wizard on first run (no settings file) and shows a loading state during engine startup.
  - The app can be launched with `flutter run -d linux` (or Windows) and reaches the chat UI when the engine is available.
- **acceptance_criteria:**
  - `main.dart` imports `AppStartup`, `FirstRunWizard`, `DshProcessManager`, `ChatController`, `SessionDatabase`, `SessionRepository`
  - First run shows `FirstRunWizard`; subsequent runs skip to engine spawn
  - Engine is spawned via `DshProcessManager.spawn()` with real `DshConfig.forEngine()`
  - Health probe runs before chat UI is shown
  - `ChatView` is connected to a real `ChatController` with a real `AcpClient`
  - Engine is shut down on app dispose
