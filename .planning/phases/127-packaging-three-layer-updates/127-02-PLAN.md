实现引擎半自动更新的七步流程与 UI，并用 GATE-13 固化最重要的不变式：**冒烟通过之前，`current` 指针一次都不动；坏包必须被拦下且用户无感。**
</objective>

### Task 1: src/engine/updater.rs — 七步编排

- **type:** code
- **files:** apps/desktop/src-tauri/src/engine/updater.rs
- **action:** 实现：

```rust
#[derive(Serialize)]
pub struct UpdateCheck {
    pub available: bool,
    pub current_version: Option<String>,
    pub latest_version: Option<String>,
    /// 不兼容时的中文说明；兼容则为 None
    pub blocked_reason: Option<String>,
    pub download_size_mb: Option<f64>,
}

#[derive(Serialize, Clone)]
pub enum UpdateStage {
    Checking, Downloading { done: usize, total: usize },
    Assembling, SmokeTesting, Switching, Done, Failed { reason: String },
}

#[derive(Serialize)]
pub enum UpdateOutcome {
    Updated { from: Option<String>, to: String },
    UpToDate,
    Blocked { reason: String },
    Failed { reason: String, current_intact: bool },
}

pub struct EngineUpdater { /* 私有 */ }

impl EngineUpdater {
    /// 步骤 1-2：拉 engine-lock.json，比对版本，检查兼容闸
    pub async fn check(&self, app_version: &str) -> Result<UpdateCheck, EngineError>;

    /// 步骤 3-6：下载 → 铺树 → 冒烟 → 切指针。进度经回调上报。
    pub async fn apply<F>(&self, app_version: &str, on_stage: F) -> UpdateOutcome
    where F: Fn(UpdateStage) + Send + Sync;

    /// 步骤 7：回滚到上一版本
    pub async fn rollback(&self) -> Result<String, EngineError>;

    /// 列出已安装的引擎版本（供设置面板"回退到上一版本"）
    pub fn installed_versions(&self) -> Result<Vec<String>, EngineError>;
}
```

**七步的实现，逐条落实：**

1. **取版本**：GET `<update_base>/engine-lock.json`（源可配，默认业主托管地址，10s 超时）。
   网络失败 → `UpdateCheck { available: false, blocked_reason: Some("无法连接更新服务器") }`，
   **不报错、不阻塞**。

2. **兼容闸**：`app_version` 是否满足 `lock.compatible_app_range`（semver range）。
   不满足 → `Blocked { reason: "需要先升级应用程序" }`，**不下载**。

3-4. **下载与铺树**：调 `assemble(&lock, cordis_yml, &engine_dir(new_version), &opts, on_progress)`。
   `engine_dir` 已存在 → 说明上次装过（可能是冒烟失败残留），先 `remove_dir_all` 再装。

5. **冒烟**：调 `smoke_test(&engine_dir(new_version), &node_binary(), Duration::from_secs(60))`。
   - **失败 → `remove_dir_all(engine_dir(new_version))`，`current` 不动，
     返回 `Failed { reason: <冒烟的中文 failure>, current_intact: true }`。**
   - 这是整个更新机制最重要的一步。

6. **切指针**：`paths::write_current(new_version)`。**只有走到这一步才动指针。**

7. **保留一代**：切换成功后，删除除「新版本」与「上一版本」之外的所有 `engine/<version>/` 目录。

**`rollback()`**：读 `installed_versions()`，找到当前版本之外最新的一个，
先对它跑冒烟，通过才 `write_current`。**回滚也要过冒烟。**

**不变式（写进模块顶部注释）：**
```
//! 不变式：engine/current 指针只在冒烟通过后被写入。
//! 任何下载、校验、铺树、冒烟失败的路径都不得触碰该指针。
//! GATE-13 会用坏包验证这一点。
```

- **verify:**
  - 单元测试：mock 一个 sha512 不符的 lock → `Failed`，`current` 未变，新目录被删
  - 单元测试：mock 冒烟失败 → `Failed { current_intact: true }`，`current` 未变，新目录被删
  - 单元测试：兼容闸不通过 → `Blocked`，**未发生任何下载**（断言下载函数未被调用）
  - 单元测试：成功路径 → `current` 变为新版本，保留两代目录，第三代被删
  - 单元测试：`rollback` 在冒烟失败时不切指针
- **acceptance_criteria:** 五条路径均有测试；不变式被测试固化

### Task 5: GATE-13 —— 坏包必须被拦下

- **type:** code
- **files:** scripts/gates/v5/update-rollback.mjs, scripts/gates/v5/run-gates.mjs
- **action:** 门禁用**真实坏包**验证不变式。步骤：

  1. 准备：装配一个正常引擎到临时 `app_root/engine/<v1>/`，写 `current = v1`。
  2. **坏包 A（完整性失败）**：复制 `engine-lock.json`，把其中一个包的 `integrity`
     改成一个合法格式但错误的 sha512，版本号改为 `v2-bad-integrity`。
     跑更新 → 断言：
     - 返回 `Failed`
     - `current` **仍是 v1**
     - `engine/v2-bad-integrity/` 目录**不存在**
     - `engine/v1/` 完好（跑一次冒烟应通过）
  3. **坏包 B（冒烟失败）**：正常装配到 `v2-bad-smoke`，然后**故意破坏**它
     （删掉 `node_modules/@deepseek-ai/dsh-acp-demo/lib/bin.js`），再触发冒烟步骤。
     断言：
     - 冒烟返回失败
     - `current` **仍是 v1**
     - 破坏的目录被清理
  4. **成功路径**：正常装配 `v2` 并走完七步 → 断言 `current == v2` 且 `v1` 目录仍在（保留一代）。
  5. **回滚路径**：调 `rollback()` → 断言 `current == v1`。

  实现方式：这些断言用 Rust 集成测试写（`apps/desktop/src-tauri/tests/update_rollback_test.rs`），
  门禁脚本负责调用 `cargo test -- --ignored update_rollback` 并解释结果。

  注册进 `run-gates.mjs`，名为 `update-rollback`。

- **verify:**
  - `cargo test -- --ignored update_rollback` 全绿
  - `node scripts/gates/v5/update-rollback.mjs` 绿灯
  - `node scripts/gates/v5/run-gates.mjs` 输出 `6 passed, 0 failed`
- **acceptance_criteria:**
  - 两种坏包都被拦下且 `current` 未动
  - 成功路径保留一代
  - 回滚可用
