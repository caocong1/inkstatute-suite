<objective>
Implement the v4 gates runner (GATE-01, GATE-02) that enforces code quality and test coverage for all V4 product code.

The runner: (1) `dart analyze apps/flutter_app` — zero analysis issues, (2) `flutter test apps/flutter_app` — all tests pass, (3) engine manifest validation — all 5 fields present if manifest exists, (4) mock E2E — acp_client tests with mock fixtures pass, (5) meta-test — every new Dart `lib/` directory has a corresponding `test/` directory with at least one `_test.dart` file. CI integration via `.github/workflows/v4-gates.yml`.

Purpose: Establish the gate system that every subsequent V4 phase must pass. The meta-test (GATE-02) ensures no Dart library code ships without test coverage — this is a binding coding rule from AGENTS.md.
Output: `scripts/run_v4_gates.py` + self-tests + CI workflow.
</objective>

Assert at least one `_test.dart` file exists in the test/ dir. If any lib/ dir lacks coverage, print `FAIL: <lib_dir> has no test coverage` and exit 1.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Gate runner → CI | Gate runner output determines CI pass/fail; a bypassed or faked gate would allow broken code to merge |
| Meta-test → codebase | Meta-test scans the codebase for lib/ dirs; it must not be bypassable or skippable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-112-19 | Elevation of Privilege | Gate bypass | mitigate | Every gate runs the real command and checks exit code; no auto-pass; --check runs individual gates but full run is the CI default |
| T-112-20 | Tampering | Meta-test coverage | mitigate | Meta-test walks actual filesystem; cannot be faked by adding empty test dirs (asserts at least one _test.dart file with content) |
| T-112-21 | Denial of Service | Gate runner crash | mitigate | Gate runner uses try/except per gate; a crashing gate reports FAIL, not silent pass |
</threat_model>
