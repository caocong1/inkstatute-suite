<objective>
Implement the engine release pipeline (DSH-03): pin the DSH commit, create the product ACP composition config with terminal-default-deny approval stack, and build the script that produces `engine-<version>.zip` + `engine-manifest.json`.

The pipeline: (1) `engines/dsh-pin.txt` pins commit `47f943859b`, (2) `engines/acp.cordis.yml` configures the ACP composition with `approval.policy: ask` + `sandbox-policy.mode: workspace-write` (terminal/execute_code default deny → escalate to user card), (3) `scripts/build_dsh_release.sh` checks out the pin → `pnpm install` → `pnpm build` → assembles engine directory (bin.js + workspace deps + cordis.yml) → zips → generates manifest with sha256.

Purpose: Establish the immutable engine artifact pipeline. Every engine upgrade goes through this script — change pin → rebuild → real-machine regression → app version release. No auto-upgrade.
Output: `engines/dsh-pin.txt` + `engines/acp.cordis.yml` + `scripts/build_dsh_release.sh` + smoke test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DSH repo → engine zip | Source code crosses from the DSH repo into the build artifact; the pin ensures reproducibility |
| Engine zip → end user | The zip is distributed with the app; tampering with it must be detectable via sha256 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-112-15 | Tampering | Engine zip integrity | mitigate | sha256 in manifest; no auto-upgrade; zip is immutable artifact |
| T-112-16 | Information Disclosure | Secrets in engine zip | mitigate | No API keys baked into build; DEEPSEEK_API_KEY is runtime-injected; grep assertion in test_build_dsh_release.sh |
| T-112-17 | Tampering | DSH commit pin | mitigate | Pin file is version-controlled; upgrade requires explicit edit + rebuild + regression |
| T-112-18 | Denial of Service | Build script failure | accept | Build script fails loud (set -euo pipefail); no silent partial builds |
</threat_model>
