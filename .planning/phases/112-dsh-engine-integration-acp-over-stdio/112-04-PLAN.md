<objective>
Implement the DSH subprocess manager (DSH-02) that spawns, monitors, and cleanly shuts down the DSH ACP engine process.

The manager: (1) spawns `node <engine>/lib/bin.js --config <engine>/acp.cordis.yml` from a bundled engine directory, (2) sets `DSH_HOME` to the platform-appropriate runtime path, (3) injects `DEEPSEEK_API_KEY` via environment (never to disk), (4) runs an initialize health probe via AcpClient, (5) on app exit closes stdin → waits for clean exit → kills on timeout → asserts zero orphan processes.

Purpose: The subprocess manager is the lifecycle owner of the DSH engine. It must guarantee no orphan processes remain after app exit — this is a critical reliability requirement for a desktop app.
Output: `dsh_process.dart` + `dsh_config.dart` + `engine_health.dart` + integration tests with PID assertions.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App → DSH subprocess | App spawns and controls the DSH engine process; environment variables (including API key) cross this boundary |
| DSH stderr → app logs | Engine diagnostic output crosses into app logging; must be reference-first (no customer data) |
| DSH subprocess → OS process table | Orphan processes can persist after app exit; PID assertion is the mitigation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-112-11 | Information Disclosure | API key in environment | mitigate | API key injected via Process.start environment map only; never logged, never written to disk; grep assertion for zero plaintext keys in logs |
| T-112-12 | Denial of Service | Orphan processes after exit | mitigate | stdin close → DSH quiesce → clean exit; 10s timeout → force kill; PID assertion confirms no orphans |
| T-112-13 | Information Disclosure | stderr logging | mitigate | stderr logged as warnings only; reference-first policy; no raw customer payloads or model output in app logs |
| T-112-14 | Tampering | Engine process spawn | mitigate | Engine spawned from fixed bundled directory (engine\<version>\); no user-controlled path in spawn arguments |
</threat_model>
