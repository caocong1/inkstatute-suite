- `test_agent_turn_required_fields_unchanged`: load `agent_turn.schema.json`, assert `required` == `V2_SCHEMA_REQUIRED_FIELDS["agent_turn"]`.

- `test_agent_result_required_fields_unchanged`: same for agent_result.

- `test_route_decision_required_fields_unchanged`: same.
- `test_route_decision_properties_unchanged`: same.
- `test_no_fields_removed_from_v2_schemas`: for each of the 5 schemas, assert every property in the V2 baseline still exists in the current schema (superset is OK, subset is not).

- `test_v2_python_dataclasses_unchanged`: import `AgentTurn`, `AgentResult`, `ExecutionTrace`, `FeedbackEvent`, `RouteDecision` from `platform_contract`, assert each has the expected field names via `dataclasses.fields()`. Create `packages/contract-test-suite/tests/test_unified_event_composability.py` with unittest tests that verify the 13 new event-type schemas are industry-neutral (no legal-specific top-level fields).

Test methods:
1. `test_new_event_schemas_have_no_forbidden_top_level_fields`: iterate all 13 new schema files (`session_started` through `error_event`), for each, assert no property name is in `FORBIDDEN_TOP_LEVEL_FIELDS` (which includes `jurisdiction`, `lawyer`, `legal`, `lawfirm`, `attorney`, `counsel`, `case_type`, `statute`, `cause_of_action`, `liability`, `client_name`, `id_number`, `phone`, `bank_account`, `address`, `raw_payload`).

2. `test_new_event_schemas_have_no_forbidden_required_fields`: iterate all 13 new schemas, assert no required field name is in `FORBIDDEN_TOP_LEVEL_FIELDS`.

3. `test_new_event_schemas_have_industry_context_in_metadata_only`: verify that legal-specific data can only go in `metadata` or nested objects, not at top level. For each new schema, assert there is no top-level `industry_context` property that is required (it should be optional if present, or absent — legal data goes in `metadata`).

4. `test_non_legal_fixture_validates_with_new_event_types`: create a synthetic non-legal event fixture (e.g., an engineering task) using `session.started` and `message.completed` event types with non-legal payloads. Validate it against the new schemas. Assert no validation error.

5. `test_legal_data_in_metadata_not_top_level`: create a `session.started` event payload with `metadata.industry_context.jurisdiction = "CN"`. Assert this validates (legal data in metadata is allowed). Then create the same event with `jurisdiction` as a top-level property. Assert validation fails (additionalProperties: false blocks it, and the forbidden field check catches it).

6. `test_all_new_schemas_are_additional_properties_false`: iterate all 13 new schemas, assert `additionalProperties` is `false` (prevents injecting legal-specific fields at top level).

7. `test_elicitation_schema_neutral_for_non_legal_use`: create an elicitation request with non-legal questions (e.g., engineering questions). Assert it validates against `elicitation_requested.schema.json`.

8. `test_permission_schema_neutral_for_non_legal_use`: create a permission request for a non-legal tool. Assert it validates against `permission_requested.schema.json`.
</action>
