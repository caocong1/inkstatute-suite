## Implementation Details

### Equivalence Testing Methodology
1. Create a fixed input (prompt, fixture provider with deterministic responses)
2. Run via in-process adapter → collect event types and payloads
3. Run via ACP server (driven by ACPClient) → collect event types and payloads
4. Assert event type sequences match
5. Assert message content matches (allowing for ACP transport serialization differences)

### Backend Interchangeability Test
- Use `FakeBackendAdapter` (from platform-runtime fakes) configured to produce the same event sequence as the agent-core
- Run the same `RunRequest` through both `FakeBackendAdapter` (simulating hermes) and `InProcessAgentCoreAdapter`
- Assert event type sequences match
- This proves the Gateway can swap `backend_id` without code changes

### Operator Config Schema
```python
@dataclass(frozen=True, slots=True)
class BackendSelectionDoc:
    default_backend_id: str = "inkstatute"
    backend_overrides: dict[str, str] = field(default_factory=dict)
```

The resolver:
```python
def resolve_backend_id(
    tenant_id: str | None,
    selection: BackendSelectionDoc | None,
) -> str:
    if selection is None:
        return "inkstatute"  # default
    if tenant_id and tenant_id in selection.backend_overrides:
        return selection.backend_overrides[tenant_id]
    return selection.default_backend_id
```
