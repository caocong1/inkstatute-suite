<objective>
让主代理知道**何时**、**如何**调用复核与对抗工具，如何在多轮后早停，以及如何把分歧综合成一份不掩盖分歧的终稿。编排写在人设里而非代码里——DSH 拥有执行核心。
</objective>

<context>
本 plan 只有一处 Rust 代码（`review.rs`），职责是**解析**复核产物的结构化文本、
判定分歧是否消解、生成 `[HUMAN_REVIEW:]` 标记。编排本身由主代理人设驱动。

这与 Phase 126 的护栏解析器（`guardrails.rs`）同构：模型按约定格式输出，Rust 侧解析并强制呈现。
</context>

```
[GUARDRAIL:CROSS_REVIEW]
以下情形，在给出最终结论之前**必须**先调用复核工具：
- 你即将标注 [HUMAN_REVIEW:] 的任何结论
- 诉讼时效认定、合同效力认定、刑事责任判断
- 涉案金额或条款金额超过 100 万元
- 行政处罚幅度的判断
- 任何由 [unverified] 依据支撑的结论

   并附上复核者提出的【分歧】清单。

绝不把复核工具的原始输出直接抄给用户。你要做的是综合（见下）。
```

### Task 2: 主代理人设 —— 综合与早停

- **type:** config
- **files:** presets/legal-core/preset.yml
- **action:** 追加第八段，锚点 `[GUARDRAIL:SYNTHESIS]`：

```
[GUARDRAIL:SYNTHESIS]
综合复核与对抗结果时：

**分歧不得抹平。** 复核者与你意见不一致的每一条，都要在终稿中显式呈现，
格式固定：
[分歧] <争点> ｜ 本意见：<你的立场与依据> ｜ 复核意见：<对方立场与依据> ｜ <是否已消解>

消解的标准是**有一方拿出了对方无法反驳的现行法依据**，而不是"看起来更合理"。
不确定是否消解，就按未消解处理。

**未消解的分歧必须升级人审**，在结论处标注：
[HUMAN_REVIEW: 模型间存在未消解分歧 —— <争点摘要>]

**对抗质询的【致命问题】未被你正面回应的**，同样升级人审。

**早停规则**：对抗质询最多两轮。若第二轮未提出任何新的【致命问题】或【可被攻击】项，
立即停止，不要再发起第三轮。若第一轮即返回「无实质可攻击点」，不要发起第二轮。

**复核不放宽引用审查**：复核者引入的法律依据，你同样要按 [verified]/[retrieved]/[unverified]
标注后才能写进终稿；不要因为"复核者说的"就当作已核实。
```

- **verify:**
  - `grep -c '\[GUARDRAIL:' presets/legal-core/preset.yml` 返回 8
  - `grep -c '\[分歧\]' presets/legal-core/preset.yml` ≥ 1
- **acceptance_criteria:** 分歧呈现、人审升级、早停三条规则齐全

### Task 3: src/engine/review.rs —— 复核产物解析

- **type:** code
- **files:** apps/desktop/src-tauri/src/engine/review.rs
- **action:** 实现（与 `guardrails.rs::scan` 同构的纯解析）：

```rust
pub struct ReviewScan {
    pub disagreements: Vec<Disagreement>,
    pub unresolved_count: usize,
    pub fatal_challenges: Vec<String>,
    /// 从 [HUMAN_REVIEW: 模型间存在未消解分歧 …] 中抽出的条目
    pub escalations: Vec<String>,
}

pub struct Disagreement {
    pub issue: String,
    pub own_position: String,
    pub reviewer_position: String,
    pub resolved: bool,
    pub offset: usize,
}

/// 从终稿文本中扫出分歧与对抗结论。
pub fn scan_review(text: &str) -> ReviewScan;

/// 复核轮次追踪：判断是否应当早停。
pub struct RoundTracker { /* 私有 */ }
impl RoundTracker {
    pub fn new(max_rounds: usize) -> Self;   // 默认 2
    /// 记录一轮对抗结果，返回是否应当继续
    pub fn record(&mut self, fatal: usize, attackable: usize) -> bool;
    pub fn rounds_used(&self) -> usize;
    pub fn stopped_early(&self) -> bool;
}
```

**解析规则：**
1. 分歧行：`\[分歧\]\s*(.+?)\s*｜\s*本意见：(.+?)\s*｜\s*复核意见：(.+?)\s*｜\s*(.+)`
   —— 全角竖线 `｜` 为分隔符。最后一段含「已消解」判 `resolved = true`，否则 false。
   **末段缺失或无法判定时按未消解处理**（保守方向）。
2. 致命问题：从对抗输出的 `【致命问题】` 段落逐条抽取（到下一个 `【` 或文末为止）。
3. `escalations`：复用 `guardrails::scan` 的 `[HUMAN_REVIEW:]` 抽取，筛出含「分歧」的条目。
4. **早停**：`record(fatal, attackable)` 在 `fatal == 0 && attackable == 0` 时返回 false；
   `rounds_used >= max_rounds` 时返回 false。

**不变式（写进模块注释并由测试固化）：**
```
//! 未消解分歧数 > 0 时，终稿必须带对应的 [HUMAN_REVIEW:] 标记。
//! 若解析出未消解分歧却找不到对应标记，视为模型未遵守人设 —— 由调用方补一条，
//! 绝不因为"模型没标"就当作没有分歧。
```
配套：`pub fn ensure_escalated(scan: &ReviewScan, text: &str) -> Option<String>`
返回需要**由 app 侧补上**的人审标记文案（模型漏标时的兜底）。

- **verify:**
  - 单元测试：标准三段分歧行正确解析，`resolved` 判定正确
  - 单元测试：末段缺失 → `resolved == false`（保守）
  - 单元测试：`【致命问题】` 多条抽取正确，遇下一个 `【` 停止
  - 单元测试：`record(0,0)` → false；`record(2,1)` 两次后达上限 → false
  - 单元测试：**未消解分歧但无 `[HUMAN_REVIEW:]` → `ensure_escalated` 返回 Some**（兜底不变式）
  - 单元测试：正文里出现字面量「[分歧]」但格式不完整 → 不误识别
- **acceptance_criteria:** 解析保守、早停正确、漏标有兜底
