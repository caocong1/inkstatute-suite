### Task 2: 映射到 Arena 统一事件

- **type:** code
- **files:** apps/desktop/src-tauri/src/engine/mapper.rs
- **action:** 在 `EventMapper` 中扩展映射表：

| DSH 输入 | 统一 `event_type` | payload 要点 |
|---|---|---|
| `subagent/start`（toolName 为复核类） | `arena.workflow_started` | `mode: "arena_review"`, `agent_slots: [toolName]` |
| `subagent/descriptor` | `arena.workflow_started` 的 metadata 补充 | `provider` / `model`，供 UI 显示模型名 |
| `subagent/end`（复核类） | `arena.review_completed` | `slot`, 复核意见摘要 |
| `subagent/start`（toolName == adversarial_challenge） | `arena.adversarial_challenge_completed` 的前导 | 标记进入对抗轮 |
| `subagent/end`（对抗类） | `arena.adversarial_challenge_completed` | `round`, `fatal_count` |
| 主代理 `message.completed` 且 `scan_review` 有分歧 | `arena.synthesis_completed` | `disagreements`, `unresolved_count` |
| `RoundTracker::stopped_early()` | `arena.early_stop_triggered` | `rounds_used`, `reason` |

**实现要点：**
1. 映射器需持有一个 `toolName → 角色` 映射（复核 / 对抗），从配置读或硬编码三个已知名字。
   **未知 toolName 的子代理不产 Arena 事件**（可能是未来别的用途），只记 debug 日志。
2. `arena.*` 事件的确切 `event_type` 字符串必须与
   `packages/ui-core/src/reducers/arenaEventReducer.ts` 的 `case` 分支逐字对齐——
   实现前先 `grep -oE 'case "[a-z_.]+"' packages/ui-core/src/reducers/arenaEventReducer.ts` 取准确清单。
3. 沿用 Phase 124 的 `envelope_seq` 单调递增，不另起计数。

- **verify:**
  - 单元测试：七条映射各一个用例
  - 单元测试：未知 toolName → 空 vec
  - 单元测试：`event_type` 字符串与 reducer 的 case 清单完全一致（读文件比对，防漂移）
- **acceptance_criteria:** 子代理活动经既有 Arena 词汇到达前端，reducer 零改动

### Task 3: 触发入口 —— 深度复核按钮

- **type:** code
- **files:** apps/desktop/src/components/DeepReviewButton.tsx, apps/desktop/src/components/Workspace.tsx
- **action:**
  1. 新建 `DeepReviewButton`：会话界面工具条上一个按钮「深度复核」。
     - 点击 → 对**当前最后一条 assistant 成稿**追加一轮互评 + 对抗
       （实现为发一条约定提示："请对上一条意见执行交叉复核与对抗质询"）
     - 复核进行中禁用，显示进度
     - **能力降级**：调 `review_capability()`
       - `None` → 按钮禁用，提示「请先在设置中配置至少一个模型服务商」
       - `SingleVendor` → 按钮可用，旁边小字「单厂商复核，效力有限」并在结果页重复该提示
       - `CrossVendor` → 正常
  2. `Workspace.tsx` 接入按钮，并在收到 `arena.*` 事件时渲染
     `ParallelStreamPanel`（进行中）→ `ReviewSummary`（复核结论）→ `SynthesisViewer`（综合稿）。
  3. **不做模式选择器**——按钮只有一个，模式由人设决定。
     `ArenaWorkflowCreator` 改造为纯展示的「复核配置概览」（显示将请哪几个模型），去掉模式选择 UI。
- **verify:**
  - 测试：`None` 能力时按钮 `disabled` 且有中文提示
  - 测试：`SingleVendor` 时显示效力提示
  - 测试：推入 `arena.review_completed` 事件后 `ReviewSummary` 出现在 DOM
  - 测试：界面上**不存在模式选择控件**（`grep` 断言无 mode picker）
- **acceptance_criteria:** 一个按钮、能力自适应、无模式选择
