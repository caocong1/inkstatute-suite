### Task 3: acp.cordis.yml 注册子代理传输与复核工具

- **type:** config
- **files:** engines/acp.cordis.yml
- **action:** 在 `approval` 块之后、`acp-agent` 块之前插入：

```yaml
# ── 多模型互评（Phase 128）────────────────────────────────────────────
# 子代理传输：spawn = 全新会话，不继承父历史。
# 刻意不装 fork-in-process —— 复核者若看见起草者的推理会被锚定，
# 原 v3.1 设计以 AST 门禁强制新鲜上下文，此处沿用该立场。
- id: subagent-runtime
  name: '@deepseek-ai/dsh-subagent'

- id: subagent-spawn
  name: '@deepseek-ai/dsh-subagent-spawn-in-process'
  config:
    providerName: spawn

# 复核者 A —— 与主模型不同厂商，避免同源盲区。
- id: reviewer-a
  name: '@deepseek-ai/dsh-tool-subagent'
  config:
    provider: spawn
    toolName: legal_review_a
    maxDepth: 1              # 复核者不得再起复核者
    agentOptions:
      provider: openai
      model: gpt-5
    toolFilter:
      allow: ['read', 'grep', 'glob', 'skill']   # 只读检索；禁 bash、禁写文件
    persona: |
      你是独立复核律师，不参与起草。你**没有**看到起草过程，只拿到案情与初稿。
      逐条核查：事实认定是否有据、法律适用是否准确、引用是否现行有效、
      是否遗漏对当事人不利的情形、结论与理由是否自洽。
      按固定结构输出：
      【同意】…
      【分歧】<逐条列出，每条写明分歧点、你的理由、依据>
      【遗漏】…
      【风险】…
      你自己的每处法律依据同样必须标注 [verified] / [retrieved] / [unverified]。
      不要改写初稿，只出复核意见。没有分歧就明说没有，不要为凑数造分歧。

# 复核者 B —— 第三家厂商，与 A 独立。
- id: reviewer-b
  name: '@deepseek-ai/dsh-tool-subagent'
  config:
    provider: spawn
    toolName: legal_review_b
    maxDepth: 1
    agentOptions:
      provider: anthropic
      model: claude-sonnet-4-5
    toolFilter:
      allow: ['read', 'grep', 'glob', 'skill']
    persona: |
      （与 reviewer-a 相同的复核人设，逐字复制）

# 对抗质询者 —— 对方律师视角，专找漏洞。
- id: challenger
  name: '@deepseek-ai/dsh-tool-subagent'
  config:
    provider: spawn
    toolName: adversarial_challenge
    maxDepth: 1
    agentOptions:
      provider: openai
      model: gpt-5
    toolFilter:
      allow: ['read', 'grep', 'glob', 'skill']
    persona: |
      你是对方当事人的代理律师。目标是**推翻或削弱**这份意见。
      找：事实认定的薄弱环节、可被质疑的证据链、对方可主张的抗辩与反诉、
      程序性瑕疵（管辖、时效、主体资格、举证责任分配）、
      以及该意见回避或轻描淡写的不利事实。
      按固定结构输出：
      【致命问题】<会导致结论不成立的>
      【可被攻击】<会削弱但不推翻的>
      【建议补强】…
      若确实找不出实质问题，明确输出「无实质可攻击点」，不要制造无关质疑。
```

**注意**：`agentOptions.provider` 的取值必须是 `acp.cordis.yml` 里 `llm` 块下已声明的 pi-ai 路由名
（`deepseek` / `openai` / `anthropic` / `google` / `groq` / `xai` / `zhipu` / `qwen-token-plan-cn`）。
模型名必须存在于该路由的目录中，否则请求期才报错。

### Task 4: 缺密钥时的优雅降级

- **type:** code
- **files:** apps/desktop/src-tauri/src/engine/credentials.rs
- **action:** 复核厂商的密钥可能没配（律师只填了 DeepSeek）。实现：

```rust
/// 返回已配置密钥的供应商列表，供引擎启动时决定注入哪些环境变量，
/// 以及供 UI 提示复核能力的可用程度。
pub fn configured_providers() -> Vec<Provider>;

/// 复核能力等级：按已配置的**不同厂商**数量判定。
pub enum ReviewCapability {
    /// 仅 1 家厂商 —— 可用同厂商不同模型复核，效力有限
    SingleVendor { provider: Provider },
    /// ≥2 家厂商 —— 完整交叉互评
    CrossVendor { providers: Vec<Provider> },
    /// 无任何密钥
    None,
}
pub fn review_capability() -> ReviewCapability;
```

`build_engine_env` 改为注入**全部已配置**供应商的环境变量（而非只注入当前活动供应商），
这样子代理才能用别家厂商。仍然：不落盘、不进日志、不进命令行参数。

- **verify:**
  - 单元测试：0 / 1 / 3 家已配置时 `review_capability()` 返回正确变体
  - 单元测试：`build_engine_env` 注入了全部已配置厂商的变量，且未配置的厂商不出现
  - 单元测试：返回值经 `Debug` 不泄漏密钥
- **acceptance_criteria:** 单厂商可降级运行；多厂商自动启用交叉互评
