# Plan 02: Client Capabilities + Inbound Request Routing + fs Handler

## Objective

Wire the fs security primitives from Plan 01 into the ACP client lifecycle: (1) `ACPClient` advertises `clientCapabilities.fs.readTextFile: true` at `initialize` when configured, (2) inbound `fs/read_text_file` JSON-RPC requests from agents are routed to registered handlers (not crashed on when unregistered), (3) a concrete `FSReadHandler` combines `FSSandbox` + `ReferenceSanitizer` to safely read and sanitize reference files, (4) `ACPBackendConfig` gains an optional `client_capabilities` field that defaults to `None` so the Gateway path is zero-change backward compatible.

**Scope note:** Only `fs/read_text_file` is implemented for v1; `fs/write`, `fs/list` are deferred to future phases. This is the first time inbound requests (messages with both `id` and `method`) are handled — previously only responses (has `id`, no `method`) and notifications (has `method`, no `id`) were handled by `StdioACPTransport.receive()`.
