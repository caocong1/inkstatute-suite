# Plan 01: Admin Web UI + Lawyer Web Chat (C3 + C4)

## Objective

Implement two new opt-in Python services that render browser-facing surfaces while enforcing the output boundary:

1. **`services/admin-web-ui/`** — a server-side rendered operator dashboard built on Python stdlib `http.server`. It proxies read-only requests to the existing `admin-console-api` `handle_admin_get` handler, renders session/task inspection, feedback review queue, gate status, and health monitoring as escaped plaintext HTML (never `innerHTML`), and sets a strict Content-Security-Policy. Access is gated by the `admin_web_ui_enabled` feature flag (default `False`) and RBAC (Phase 51).

2. **`services/lawyer-web-chat/`** — a server-side rendered lawyer web chat built on Python stdlib `http.server` with real Server-Sent Events streaming. It provides session authentication (RBAC `lawyer` role tokens), message history, file upload (reference-only), feedback submission, and multi-device sync via server-side session state. It is gated by the `lawyer_web_chat_enabled` feature flag (default `False`) and enforces the same output boundary as WeCom.

## Risks And Mitigations

| Risk | Mitigation |
|------|-----------|
| XSS via backend content | html.escape on all dynamic content; never innerHTML; strict CSP header |
| Session token leakage | HttpOnly + Secure + SameSite=Strict cookies; HMAC-signed RBAC tokens with expiry |
| Raw legal payloads in browser | File upload stores references only; no localStorage/sessionStorage of payloads |
| Feature flag bypass | Both services gate on flag before any rendering; disabled returns 503 |
| Stray untracked files | Only git add explicit phase-57 paths; never git add -A |
