# Plan 01 Summary: Wire TenantGuard into Web UIs and admin-console-api views

## Objective

Close the HIGH-severity gap identified in the v1.7 milestone audit: tenant isolation
primitives (Phase 56) existed in `platform-runtime` but were not wired into the Web UI
data access paths (Phase 57). This plan integrated `TenantScopeResolver` and
`TenantGuard` into `admin-console-api` and `lawyer-web-chat`, created a
`TenantScopedContractLogReadModel` wrapper for tenant-filtered read-model queries, and
added comprehensive tenant isolation tests across all affected services.

## Changes Made

### Task 1: TenantScopedContractLogReadModel (conversation-read-view)

**New file:** `services/conversation-read-view/src/conversation_read_view/tenant_read_model.py`
- `TenantScopedContractLogReadModel` class wrapping `ContractLogReadModel`
- Filters `get_conversation`, `get_task`, `get_task_by_trace_id`, `list_conversations`,
  `list_tasks` by `tenant_id` when `ScopedQueryFilter` is active
- When filter is None or inactive, delegates directly (zero regression)
- Helper functions `_extract_tenant_id_from_conversation` and `_extract_tenant_id_from_task`
  extract `tenant_id` from the event dicts (injected by `TenantScopedContractLogStore`)

**Updated:** `services/conversation-read-view/src/conversation_read_view/__init__.py`
- Exported `TenantScopedContractLogReadModel` in `__all__`

**New test file:** `services/conversation-read-view/tests/test_tenant_scoped_read_model.py`
- 11 tests covering disabled filter, active filter, no filter, wrong tenant, issues delegation

### Task 2: Wire TenantGuard into admin-console-api

**Updated:** `services/admin-console-api/src/admin_console_api/api.py`
- Imported `TenantScopeResolver`, `TenantGuard`, `TenantScopeRequestContext` from `platform_runtime`
- Added Step 2c: tenant scope resolution + guard enforcement after auth
- Synthetic `Identity(role=Role.ADMIN, tenant_id="default")` for static-token path
- Passes `tenant_filter` to `handle_sessions`, `handle_tasks`, `handle_feedback`

**Updated:** `services/admin-console-api/src/admin_console_api/views.py`
- Imported `TenantScopedContractLogReadModel` from `conversation_read_view`
- Added `tenant_filter` keyword param to `handle_sessions`, `handle_tasks`, `handle_feedback`
- `_wrap_scoped` helper wraps read_model in `TenantScopedContractLogReadModel`
- `handle_feedback` filters by `item.get("tenant_id")` when filter active (fail-safe: no tenant_id = excluded)

**Updated tests:**
- `test_views.py`: Added `TenantScopedSessionsViewTests`, `TenantScopedTasksViewTests`, `TenantScopedFeedbackViewTests` (16 tests)
- `test_api.py`: Added `TenantGuardIntegrationTests` (4 tests: disabled, enabled, unresolved raises, static token)

### Task 3: admin-web-ui tenant isolation tests (no code changes)

**Updated:** `services/admin-web-ui/tests/test_server.py`
- Added `TenantIsolationTests` class with 4 E2E tests through admin-web-ui → admin-console-api
- Tests use real `handle_admin_get` as proxy target with tenant-tagged read model
- Verifies: disabled mode shows all, enabled mode filters by identity, cross-tenant isolation, feedback filtering

### Task 4: Wire TenantGuard into lawyer-web-chat

**Updated:** `services/lawyer-web-chat/src/lawyer_web_chat/server.py`
- Imported `TenantScopeResolver`, `TenantGuard`, `TenantScopeRequestContext` from `platform_runtime`
- Added tenant scope resolution + guard enforcement after `_authenticate()`
- Passes `tenant_filter` to `_handle_history`, `_handle_stream`, `_handle_upload`, `_handle_feedback`

**Updated:** `services/lawyer-web-chat/src/lawyer_web_chat/history.py`
- Added `tenant_filter` keyword param to `get_history`
- When active, filters messages by `msg.metadata.get("tenant_id") == tenant_filter.tenant_id`

**Updated:** `services/lawyer-web-chat/src/lawyer_web_chat/upload.py`
- Added `tenant_filter` keyword param to `get_upload` and `list_uploads`
- When active, filters by `metadata.get("tenant_id") == tenant_filter.tenant_id`

**Updated:** `services/lawyer-web-chat/src/lawyer_web_chat/feedback.py`
- Added `tenant_filter` keyword param to `submit_feedback` (API consistency; write path already uses tenant_id)

**Updated tests:**
- `test_server.py`: Added `TenantIsolationTests` (6 tests: disabled, enabled history filter, uploads, feedback, unresolved raises, cross-tenant sessions)
- `test_history.py`: Added 4 tenant filter tests (active, disabled, no filter, exclude without tenant_id)
- `test_upload.py`: Added 4 tenant filter tests (list active, list disabled, get wrong tenant, get matching tenant)
- `test_session.py`: Added 1 session listing tenant isolation test
