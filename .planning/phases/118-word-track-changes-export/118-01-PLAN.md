# Plan 118-01: Change list JSON schema + Dart models + parser

## Goal

Define the structured change list JSON schema that the model produces, create Dart models for it, and implement a parser that extracts change lists from assistant messages.

## Tasks

### Task 1: Change list JSON schema

Create `lib/export/change_list_schema.dart`:
- `ChangeItem` — Single change item:
  - `id` (int)
  - `clauseLocation` (String) — Clause location/identifier
  - `originalText` (String) — Original text to find
  - `revisedText` (String?) — Replacement text (null = comment only)
  - `reason` (String) — Revision reason
  - `riskLevel` (RiskLevel) — P0/P1/P2
  - `comment` (String) — Comment to attach
- `RiskLevel` — Enum: p0 (must fix), p1 (negotiate), p2 (optimize)
- `ChangeList` — Container:
  - `items` (List<ChangeItem>)
  - `sourceDocument` (String) — Source docx path or identifier
  - `createdAt` (DateTime)
  - `toJson()` / `fromJson()` serialization
- Schema validation: `ChangeList.validate()` returns list of validation errors

### Task 2: Change list parser

Create `lib/export/change_list_parser.dart`:
- `ChangeListParser` class:
  - `static ChangeList? extractFromMessage(AssistantMessage message)` — Extracts JSON change list from assistant text
  - The JSON is expected in a `[CHANGE_LIST: ...]` block or as a fenced ```json block
  - `static String? extractJsonBlock(String text)` — Extracts the JSON block from text
  - `static ChangeList? parseJson(String json)` — Parses JSON string to ChangeList
  - Returns null if no valid change list is found

### Task 3: Model-never-writes-docx assertion

Create a test that asserts the export path never passes raw model text to the docx writer. The only input to the docx writer is a validated `ChangeList` object.
