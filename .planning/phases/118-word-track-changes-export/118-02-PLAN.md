# Plan 118-02: Python script refactor + docx golden test infrastructure

## Goal

Refactor the track-changes Python script to accept JSON input, create the Dart docx exporter that invokes portable Python, and set up golden test fixtures.

## Tasks

### Task 1: Python script refactor

Create `apps/flutter_app/assets/scripts/contract_review_trackchanges_v4.py`:
- Based on `lawfirm-profile/scripts/contract_review_trackchanges.py` (41,185 bytes)
- Refactored to accept JSON change list as input (via stdin or file path argument)
- CLI interface: `python contract_review_trackchanges_v4.py --input <docx> --changes <json> --output <docx>`
- The `REVIEW_ITEMS` list is replaced by JSON-parsed `ChangeItem` objects
- `TrackChangesBuilder` class retained with same OOXML manipulation logic
- lxml dependency preserved (embeddable Python includes lxml)

### Task 2: Dart docx exporter

Create `lib/export/docx_exporter.dart`:
- `DocxExporter` class:
  - `Future<ExportResult> export(ChangeList changeList, String inputDocxPath, String outputDocxPath)` — Invokes portable Python with the track-changes script
  - Uses `Process.run` to call Python with arguments
  - Returns `ExportResult.success(path)` or `ExportResult.failure(error)`
  - **Never passes raw model text to the script** — only the validated ChangeList JSON
  - Error handling: Python not found, script not found, invalid input docx, etc.
- `ExportResult` — Sealed class: `ExportSuccess(path)` / `ExportFailure(error)`

### Task 3: Golden test fixtures

Create test fixtures:
- `test/fixtures/export/sample_change_list.json` — A small change list with 2-3 items
- `test/fixtures/export/sample_input.docx` — A minimal docx for testing
- `test/export/docx_exporter_test.dart` — Tests that:
  - Validate the change list schema
  - Assert the exporter only passes ChangeList JSON to Python (not raw model text)
  - Test export success and failure paths
  - Golden test: compare output docx structure against expected

- `dart analyze` has no issues
