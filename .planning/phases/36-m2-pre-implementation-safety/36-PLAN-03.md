# Plan 03: Privacy Scrub Unification + Generic Output Boundary Rules

## Goal

Unify the forbidden full-text keys into a single shared module (`privacy_keys.py`) referenced by all store-time and read-time scrub paths, add 4 new backend field names to the forbidden set, ensure every API response path applies `scrub_contract_payload`, and add generic output boundary patterns that block or rewrite provider/model noise (model name leakage, API errors, function call traces, rate-limit notices, context-window warnings) without false-positive on legal business text.

- `("api_error", r"\b(?:api key invalid|quota exceeded|rate limit retry|context window exceeded|insufficient quota)\b")`

Step 2 — Add new rewrite rules to `_REWRITE_RULES` (after the existing `debug_trace` rule at line 106):
- `("rate_limit_notice", r"\b(?:rate[_ ]?limit(?:ed|ing)?|too many requests|retrying(?: after)? \d+)\b")`
- `("context_window", r"\b(?:context (?:window|length) (?:exceeded|limit)|maximum context|token limit)\b")`
