# Plan 07-02 - Privacy, Composability, And Thin-Layer Gates

## Objective

Add reusable contract-suite helpers and tests that enforce privacy minimization, industry-neutral composability, and the V2 thin-layer boundary. These gates must fail committed unsafe data and platform-core coupling while allowing source-code guard strings and reference-first evidence.

## Threat Model

<threat_model>
<risk id="T-07-02-privacy" severity="high">Committed fixtures, docs, or bundle manifests may accidentally include raw callback bodies, secrets, customer material, or full sensitive values. Mitigation: strict data scan with exact-key JSON/YAML detection and common pattern checks.</risk>
<risk id="T-07-02-false-positive" severity="medium">A global string ban could fail legitimate validator/test code. Mitigation: split source scan from data scan and explicitly allow guard strings in source files.</risk>
<risk id="T-07-02-boundary" severity="high">Platform contracts could import Hermes or service runtime modules and stop being backend-neutral. Mitigation: AST import scan over `packages/platform-contract/src`.</risk>
<risk id="T-07-02-auto-skill" severity="high">Feedback fixtures could imply automatic legal skill modification. Mitigation: gate route_mismatch and skill_candidate evidence for `requires_human_review` and `no_auto_modify` semantics.</risk>
</threat_model>
