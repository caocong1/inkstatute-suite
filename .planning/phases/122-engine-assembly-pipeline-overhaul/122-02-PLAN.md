<objective>
在 Tauri Rust 侧实现 lockfile 装配器：读 `engine-lock.json` → 并发下载 tarball → 逐包校验 sha512 → 解包铺平到目标目录 → 裁剪非目标平台预编译 → 写入 `acp.cordis.yml`。**运行时不依赖 npm/pnpm/yarn。**
</objective>

<context>
装配器的可行性依据（`.planning/research/V5-SELECTION.md` E11）：lockfile 树**零嵌套 `node_modules`**，
每个包直接落在 `<engineDir>/node_modules/<name>/`。因此不需要实现依赖解析，只需按 lock 的 key 铺文件。

npm tarball 的内部结构固定：所有文件都在 `package/` 前缀下。解包时**剥掉这一层前缀**。
</context>

### Task 2: src/engine/paths.rs — 路径解析

- **type:** code
- **files:** apps/desktop/src-tauri/src/engine/paths.rs
- **action:** 实现所有运行时路径的**单一来源**。函数签名：

```rust
/// %LOCALAPPDATA%\InkStatute （Windows）/ ~/.local/share/InkStatute（Linux 开发用）
pub fn app_root() -> Result<PathBuf, EngineError>;

/// <app_root>/engine
pub fn engine_base() -> Result<PathBuf, EngineError>;

/// <app_root>/engine/<version>
pub fn engine_dir(version: &str) -> Result<PathBuf, EngineError>;

/// <app_root>/engine/current —— 单行文本，内容是版本号
pub fn current_pointer() -> Result<PathBuf, EngineError>;

/// 读 current 指针；文件不存在或为空返回 Ok(None)
pub fn read_current() -> Result<Option<String>, EngineError>;

/// 原子写 current：先写 current.tmp，再 rename
pub fn write_current(version: &str) -> Result<(), EngineError>;

/// <app_root>/runtime/.dsh —— DSH_HOME
pub fn dsh_home() -> Result<PathBuf, EngineError>;

/// <dsh_home>/sessions —— 与 acp.cordis.yml 的 persistenceRoot 一致
pub fn sessions_root() -> Result<PathBuf, EngineError>;

/// <app_root>/node/node.exe（Windows）/ <app_root>/node/bin/node（其他）
pub fn node_binary() -> Result<PathBuf, EngineError>;
```

规则：
- Windows 用 `%LOCALAPPDATA%`；缺失时回退 `%USERPROFILE%\AppData\Local`。
- 非 Windows 用 `$HOME/.local/share`（仅供开发机测试）。
- 允许环境变量 `INKSTATUTE_APP_ROOT` 覆盖 `app_root()`，**仅供测试使用**，在文档注释中注明。
- `write_current` 必须先写临时文件再 `fs::rename`（同目录内 rename 在 Windows 与 POSIX 均为原子）。

- **verify:** 单元测试覆盖：设 `INKSTATUTE_APP_ROOT` 到 tempdir → `write_current("1.0")` → `read_current()` 返回 `Some("1.0")`；未写时返回 `None`
- **acceptance_criteria:** 全部路径经此模块解析，其它模块不得自行拼路径

### Task 3: src/engine/lock.rs — lock 文件模型

- **type:** code
- **files:** apps/desktop/src-tauri/src/engine/lock.rs
- **action:** 定义与 `engines/engine-lock.json` 对应的 serde 结构：

```rust
#[derive(Debug, Clone, Deserialize, Serialize)]
pub struct EngineLock {
    pub schema_version: String,
    pub engine_version: String,
    pub node_version: String,
    pub target_platform: String,
    pub compatible_app_range: String,
    pub cordis_config_sha256: String,
    pub generated_at: String,
    #[serde(default)]
    pub prune: HashMap<String, Vec<String>>,
    pub packages: HashMap<String, LockedPackage>,
}

#[derive(Debug, Clone, Deserialize, Serialize)]
pub struct LockedPackage {
    pub name: String,
    pub version: String,
    pub integrity: String,      // "sha512-<base64>"
    pub tarball_path: String,   // "/@scope/name/-/name-version.tgz"
}
```

另实现：
- `EngineLock::from_json(&str) -> Result<Self, EngineError>`，解析后校验：
  - `schema_version == "1.0.0"`，否则 `EngineError::UnsupportedLockSchema`
  - `packages` 非空
  - 每个 key 的 `node_modules` 出现次数恰为 1，否则 `EngineError::NestedDependency(key)`
  - 每个 `integrity` 以 `"sha512-"` 开头，否则 `EngineError::BadIntegrity(key)`
- `LockedPackage::verify_sha512(&self, bytes: &[u8]) -> Result<(), EngineError>`：
  对 `bytes` 求 sha512，base64 标准编码（含 padding），与 `integrity["sha512-".len()..]` 比较。
  **不匹配时错误信息不得包含实际哈希以外的内容，且不得输出包内容。**

- **verify:** 单元测试：合法 lock 解析成功；嵌套 key 被拒；`sha512-` 前缀缺失被拒；`verify_sha512` 对已知字节串正确判定
- **acceptance_criteria:** 结构与 122-01 产出的 JSON 完全对应，反序列化零报错

### Task 4: src/engine/assemble.rs — 装配器

- **type:** code
- **files:** apps/desktop/src-tauri/src/engine/assemble.rs
- **action:** 实现：

```rust
pub struct AssembleOptions {
    pub registry: String,           // 默认 https://registry.npmmirror.com
    pub registry_fallback: String,  // https://registry.npmjs.org
    pub concurrency: usize,         // 默认 8
}

pub struct AssembleProgress {
    pub total: usize,
    pub done: usize,
    pub current: String,
}

/// 把 lock 描述的依赖树铺到 dest（dest 必须不存在或为空）。
/// 成功后 dest 下有 node_modules/**、acp.cordis.yml、engine-lock.json。
pub async fn assemble<F>(
    lock: &EngineLock,
    cordis_yml: &str,
    dest: &Path,
    opts: &AssembleOptions,
    on_progress: F,
) -> Result<(), EngineError>
where F: Fn(AssembleProgress) + Send + Sync;
```

实现要点，逐条落实：

1. **目标目录必须干净**：`dest` 已存在且非空 → `EngineError::DestNotEmpty`。装配到 `dest.with_extension("partial")` 这样的临时兄弟目录，全部成功后再 `fs::rename` 到 `dest`；任何步骤失败则 `fs::remove_dir_all` 临时目录并返回错误。**绝不留半成品在 `dest`。**

2. **下载**：URL = `format!("{}{}", registry.trim_end_matches('/'), pkg.tarball_path)`。
   主 registry 失败（网络错误或非 2xx）→ 用 `registry_fallback` 重试一次。两者都失败才报错。

3. **校验先于落盘**：下载到内存 `Vec<u8>` → `verify_sha512` → 才解包。**校验失败立即整体失败**，不重试（哈希不符是完整性问题，不是网络问题）。

4. **解包**：`flate2::read::GzDecoder` + `tar::Archive`。对每个 entry：
   - 取 entry 路径，**剥掉第一层 `package/` 前缀**；若不以 `package/` 开头则跳过该 entry。
   - 目标路径 = `partial_dir.join(lock_key).join(剥离后的相对路径)`，其中 `lock_key` 就是 packages 的 key（形如 `node_modules/@deepseek-ai/dsh-acp-demo`）。
   - **路径穿越防护**：规范化后必须仍在 `partial_dir` 之内，否则 `EngineError::PathTraversal`。拒绝任何含 `..` 的 entry。
   - 保留可执行位（Unix）；Windows 忽略权限位。

5. **并发**：用 `futures::stream::iter(...).buffer_unordered(opts.concurrency)`。每完成一个包调用一次 `on_progress`。

6. **裁剪**：解包全部完成后，对 `lock.prune` 的每一项 `(rel_dir, names)`：
   删除 `partial_dir/node_modules/<rel_dir>/<name>` 各目录。
   例：`node-pty/prebuilds` + `["darwin-arm64","darwin-x64","win32-arm64"]`
   → 删 `node_modules/node-pty/prebuilds/darwin-arm64` 等三个。
   目录不存在时**跳过而非报错**（上游可能改布局）。

7. **写配置**：把 `cordis_yml` 写到 `partial_dir/acp.cordis.yml`；
   校验其 sha256 等于 `lock.cordis_config_sha256`，不等则 `EngineError::CordisConfigMismatch`。
   同时把 lock 本身序列化写到 `partial_dir/engine-lock.json`（供后续校验与回滚参考）。

8. **入口存在性断言**：
   `partial_dir/node_modules/@deepseek-ai/dsh-acp-demo/lib/bin.js` 必须存在，否则 `EngineError::MissingEntrypoint`。

9. **rename 到 dest**。

**禁止事项**（在代码注释中写明）：
- 禁止调用 npm/pnpm/yarn 或任何外部包管理器
- 禁止信任 lock 中的域名（`tarball_path` 不含域名，registry 由配置提供）
- 禁止在错误信息、日志中输出下载内容

- **verify:**
  - 单元测试用本地构造的 tar.gz（含 `package/` 前缀）验证解包与前缀剥离
  - 单元测试验证路径穿越被拒（构造含 `package/../evil` 的 tar）
  - 单元测试验证 sha512 不符时整体失败且 `dest` 不存在
- **acceptance_criteria:** 装配器纯 Rust 实现，无外部进程调用
