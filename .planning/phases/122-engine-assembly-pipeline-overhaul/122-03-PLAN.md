### Task 1: src/engine/smoke.rs — 冒烟探针

- **type:** code
- **files:** apps/desktop/src-tauri/src/engine/smoke.rs
- **action:** 实现：

```rust
pub struct SmokeResult {
    pub ok: bool,
    pub protocol_version: Option<u32>,
    pub agent_name: Option<String>,
    pub session_id: Option<String>,
    pub elapsed_ms: u128,
    pub failure: Option<String>,   // 用户可读的中文原因
    pub stderr_tail: Vec<String>,  // 最多 20 行，仅进本地日志
}

/// 对一个已装配的引擎目录跑冒烟。不需要真实 API key。
/// 全程有超时保护，结束时保证进程已退出（无孤儿）。
pub async fn smoke_test(engine_dir: &Path, node_bin: &Path, timeout: Duration) -> SmokeResult;
```

实现步骤，逐条落实：

1. 建临时 `DSH_HOME`（tempdir）与临时工作区目录（tempdir），**不碰真实用户数据**。
2. spawn：
   ```
   <node_bin> <engine_dir>/node_modules/@deepseek-ai/dsh-acp-demo/lib/bin.js
              --config <engine_dir>/acp.cordis.yml
   ```
   - 工作目录：`engine_dir`
   - 环境：继承 + `DSH_HOME=<临时>` + `DEEPSEEK_API_KEY=sk-smoke-probe`
   - stdio：三管道
3. 收 stderr 到环形缓冲（最多 20 行），**永不回显到 UI**。
4. 按行读 stdout，逐行 `serde_json` 解析（**非 JSON 行必须忽略而非报错**）。
5. 发 `initialize`：
   ```json
   {"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":1,"clientCapabilities":{"fs":{"readTextFile":false,"writeTextFile":false},"terminal":false}}}
   ```
   断言响应 `result.protocolVersion == 1`，记录 `result.agentInfo.name`（期望 `deepseek-harness-acp`）。
6. 发 `session/new`：
   ```json
   {"jsonrpc":"2.0","id":2,"method":"session/new","params":{"cwd":"<临时工作区绝对路径>","mcpServers":[]}}
   ```
   断言响应含 `result.sessionId`。
   **`cwd` 必须是绝对路径**，相对路径会被拒。
7. 关 stdin → 等退出（超时 5s）→ 超时 kill。
8. **断言会话日志落位**：在 `<临时 DSH_HOME>/sessions/` 下应出现目录结构
   `--<规范化 cwd>--/<sessionId>/`。
   注意：DSH 是**惰性物化**——`session/new` 后若无 append 则不写文件。
   因此本步只断言 `<临时 DSH_HOME>/sessions/` 目录**存在**（`session-query.db` 会被创建），
   **不断言 `session.jsonl` 存在**。日志内容的验证在 Phase 124。
9. **断言无字面量目录**：`<engine_dir>/${DSH_HOME}` 必须不存在（缺陷 D1 的回归防护）。
10. 任一步失败 → `ok: false` + 中文 `failure`，且保证进程已终止。

`failure` 文案映射（面向用户，不含技术堆栈）：
- 进程启动失败 → "引擎无法启动，安装可能不完整"
- initialize 超时 → "引擎无响应"
- protocolVersion 不为 1 → "引擎版本不兼容"
- session/new 失败 → "引擎会话创建失败"
- 字面量目录出现 → "引擎配置异常：会话目录位置错误"

- **verify:**
  - 单元测试：用一个假的 node 脚本（回放固定 JSON 响应）验证成功路径与各失败路径
  - 单元测试：验证非 JSON 行被忽略
- **acceptance_criteria:**
  - 冒烟不写任何真实用户目录
  - 任何返回路径上进程均已退出
  - stderr 不进入 `failure` 文案

     `git ls-files -z | xargs -0 grep -lI 'sk-[A-Za-z0-9]\{16,\}'` 无命中
