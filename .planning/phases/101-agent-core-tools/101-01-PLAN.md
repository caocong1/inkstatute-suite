### Task 101-01-01: Implement ToolRegistry and dispatching ToolExecutor

**Action**: Create `packages/agent-core/src/inkstatute_agent_core/tools/registry.py` with a `ToolRegistry` class that maps tool names to callable handlers and stores tool definitions (OpenAI function-calling format). Define `ToolHandler = Callable[[dict], Awaitable[ToolResult]]` — the per-tool handler signature (receives parsed arguments dict, returns `ToolResult`). The `ToolRegistry` holds:
- `register(name: str, handler: ToolHandler, description: str, parameters: dict)` — registers a tool with its OpenAI-format definition
- `register_definition(name: str, handler: ToolHandler, definition: dict)` — registers with a pre-built OpenAI function-calling definition dict
- `get_handler(name: str) -> ToolHandler | None` — looks up a handler by name
- `get_tool_definitions() -> list[dict]` — returns the list of OpenAI-format tool definitions for the `ChatRequest.tools` parameter
- `has_tool(name: str) -> bool` — checks if a tool is registered

Also create `packages/agent-core/src/inkstatute_agent_core/tools/executor.py` with a `create_dispatching_executor(registry: ToolRegistry) -> ToolExecutor` factory function. The dispatching executor:
1. Receives `(tool_call_id, tool_name, arguments)` 
2. Looks up the handler in the registry via `get_handler(tool_name)`
3. If not found, returns `ToolResult(content=f"Unknown tool: {tool_name}", error=ErrorInfo(...))`
4. If found, calls `await handler(arguments)` and returns the `ToolResult`
5. Catches exceptions and returns `ToolResult(content=str(exc), error=ErrorInfo(...))` — but the turn loop already has its own try/except, so this is a secondary safety net

### Task 101-01-03: Implement clarification (ask_user) tool

**Action**: Create `packages/agent-core/src/inkstatute_agent_core/tools/clarification.py` with the clarification tool handler. This tool is special — it terminates the current turn (matching Rust `finish_ask_user_turn()`).

The clarification tool handler:
1. Receives arguments dict from the LLM with keys: `intro` (str), `questions` (list of dicts with `id`, `question`, `allow_multiple`, `options`)
2. Parses questions into `ElicitationQuestion` objects (each option is `ElicitationOption(label, value)`)
3. Validates 2-4 questions (using `validate_question_count()` from `platform_contract.elicitation`)
4. Auto-assigns `q1`, `q2`, etc. if `id` is empty (matching Rust `parse_ask_user_args()`)
5. Auto-fills `value` from `label` if empty
6. If no options on a question, it's free-text (empty options list)
7. Generates `interrupt_id` (UUID)
8. **Requires an `EventEmitter`** — the handler needs to emit `elicitation.requested`. Since `ToolHandler` signature is `Callable[[dict], Awaitable[ToolResult]]` (no emitter access), the clarification tool is constructed as a **closure** or a **factory function** that captures the emitter: `create_clarification_tool(emitter: EventEmitter) -> ToolHandler`
9. Emits `elicitation.requested` via `emitter.emit_elicitation_requested(interrupt_id, intro, questions)`
10. Returns `ToolResult(content=f"已向用户提出澄清问题 (interrupt_id={interrupt_id})", metadata={"terminate_turn": True, "elicitation_id": interrupt_id})`

### Task 101-01-04: Enhance turn loop to check terminate_turn metadata

**Action**: Modify `packages/agent-core/src/inkstatute_agent_core/turn_loop.py` to check `result.metadata.get("terminate_turn")` after each tool execution. When a tool returns `ToolResult` with `terminate_turn=True` in metadata:
1. The tool result is still appended to `current_messages` (so the conversation history is complete)
2. The `tool_call.completed` event is emitted normally (status="succeeded")
3. After processing all tool calls in the current batch, check if any tool returned `terminate_turn=True`
4. If so, emit `run.state_changed` with status `"waiting_for_user"` and `return` from the generator (do not continue to the next round)

This is a minimal, backward-compatible change. When no tool returns `terminate_turn`, behavior is unchanged (loop continues to next round). The clarification tool is the only tool that uses this mechanism in Phase 101.
