### Task 99-03-01: Create Gateway practice-profile handler module

**Action**: Create `services/gateway/src/gateway/practice_profile.py` defining `GatewayPracticeProfileHandler` — the handler class for the 3 practice profile endpoints. The handler takes a `PracticeProfileStore` (from `packages/practice-profile`) and a `ColdStartInterviewOrchestrator`. Methods: `handle_get_profile(ctx: AuthContext, plugin: str | None) -> JsonObject` — returns the tenant's profile (all plugins or filtered by `?plugin=X`); `handle_put_profile(ctx: AuthContext, body: JsonObject) -> JsonObject` — updates the tenant's profile (validates no secrets via `validate_no_secrets`, enforces ADMIN/OPERATOR role, constructs `PracticeProfile.from_json`, calls `store.upsert`); `handle_start_interview(ctx: AuthContext, body: JsonObject) -> JsonObject` — starts a cold-start interview (enforces ADMIN/OPERATOR role, calls `orchestrator.start(tenant_id, plugin)`, returns the initial `ElicitationRequestedPayload` as JSON for the client to render). The handler uses `check_read_access`/`check_write_access`/`check_tenant_access` from `rbac_check.py` and raises `GatewayAuthError` (403) when unauthorized. The handler uses `ctx.tenant_id` for all operations — cross-tenant access is structurally impossible because the tenant_id comes from the auth context, not the request body.
