# Plan 91-01: Gateway Tracer — Move platform_api to services/gateway, Scaffold 12 Endpoints, Auth Middleware, SSE via encode_sse_event, Gate Registration

## Goal

Create the `services/gateway/` service by upgrading `apps/platform_api/` into a unified multi-tenant HTTP+SSE Gateway. This plan implements the end-to-end tracer slice: `POST /v1/sessions` → `POST /v1/runs` → `GET /v1/runs/{id}/events` (SSE) → `DELETE /v1/runs/{id}`. The Gateway is framework-free (stdlib pattern, zero external dependencies), uses `encode_sse_event` from the `web_sse` package for SSE encoding (replacing platform_api's custom SSE constants), and uses `rbac.identity.resolve_identity()` for auth (Bearer token first, session cookie fallback). The 12-endpoint surface is scaffolded with the tracer-critical endpoints fully implemented and the remaining endpoints stubbed with correct routing and 501 responses. Gate registration in `scripts/run_v2_gates.py` ensures the new service is CI-covered from the start.

This is the minimal vertical slice that proves the Gateway can create sessions, create runs, stream events via the unified SSE encoder with output boundary enforcement, and cancel runs — all behind RBAC auth — before expanding into Last-Event-ID replay, uploads, artifacts, feedback, skills, and full OpenAPI.

## Reversibility Gate

**One-way-door:** Creating a new `services/gateway/` service and registering its gate in `scripts/run_v2_gates.py`. Once the gate is registered, the `gate-coverage` meta-test will fail if the gate is removed, and the service becomes a permanent CI requirement. Strategy: the gate addition is purely additive — no existing gate entry is modified. The `apps/platform_api/` directory is NOT removed in this plan (it stays as a reference during transition; removal happens in Phase 104). Task 01-01 is a checkpoint to verify the service scaffolds, compiles, and the gate registration is additive before building the handlers on top.

**One-way-door:** The SSE encoder convergence — replacing platform_api's custom `SSE_EVENT_RUN` / `SSE_EVENT_RUN_COMPLETED` constants with `encode_sse_event` from the `web_sse` package. Once the Gateway emits SSE frames via `encode_sse_event`, any downstream client that parsed the old custom format would break. Strategy: the old `apps/platform_api/` is kept during transition (not removed until Phase 104), so no existing consumer is broken. The new Gateway uses the proven `encode_sse_event` format that `lawyer-web-chat` already uses successfully.

**One-way-door:** The auth middleware pattern — every Gateway endpoint goes through `resolve_identity()`. Once this is locked, removing auth from any endpoint would be a security regression. Strategy: the auth middleware is applied centrally in `app.py` dispatch, not per-handler, so individual handlers cannot accidentally bypass it. The `rbac_enabled=False` static-token fallback is preserved for self-hosted single-tenant deployments.

Define the following:

1. A frozen slotted dataclass `AuthContext` with fields: `identity: Identity | None`, `authenticated: bool`, `tenant_id: str`, `error: str | None`. The `tenant_id` is `identity.tenant_id` when authenticated, or the `default_tenant_id` from config when unauthenticated (for self-hosted single-tenant mode where auth may be disabled). 2. A class `GatewayAuth` with:
   - `__init__(self, *, rbac_secret: str | None = None, static_token: str | None = None, rbac_enabled: bool = False, session_store: SessionStore | None = None, default_tenant_id: str = "default")` — stores all auth config.    - `def authenticate(self, headers: Mapping[str, str]) -> AuthContext` — extracts the `Authorization` header and the session cookie from headers, calls `resolve_identity()` from `rbac.identity`. The session cookie is extracted using `parse_cookie_header(headers.get("Cookie"), SESSION_COOKIE_NAME)` from `rbac.session`.
   - `def require_auth(self, headers: Mapping[str, str]) -> AuthContext` — like `authenticate` but raises `GatewayAuthError` (status 401) when authentication fails. Used by endpoints that require auth.
   - `def require_role(self, headers: Mapping[str, str], allowed_roles: tuple[Role, ...]) -> AuthContext` — like `require_auth` but also raises `GatewayAuthError` (status 403) when the identity's role is not in `allowed_roles`.
   - `def check_tenant(self, ctx: AuthContext, resource_tenant_id: str | None) -> None` — raises `GatewayAuthError` (status 403) when `ctx.tenant_id` does not match `resource_tenant_id` (cross-tenant access denied). When `resource_tenant_id` is `None`, no check is performed (resource is not tenant-scoped).

3. A custom exception `GatewayAuthError(Exception)` with fields `status: int`, `code: str`, `message: str`.

Import `resolve_identity`, `Identity` from `rbac.identity`. Import `SessionStore`, `parse_cookie_header`, `SESSION_COOKIE_NAME` from `rbac.session`. Import `Role` from `rbac.roles`. All imports are via PYTHONPATH. The module must be stdlib-only at the top level (rbac imports are internal packages).

CRITICAL: The auth middleware must NEVER auto-approve any permission. It only resolves identity — permission decisions are made by the user through elicitation/approval endpoints, not by the auth layer.
