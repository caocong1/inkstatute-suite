# Plan 91-03: Upload, Artifact, and Feedback Endpoints — Reference-First Upload, Auth+Tenant Artifact Download, Feedback Normalization

## Goal

Implement three Gateway endpoints that absorb capabilities from `services/lawyer-web-chat`: `POST /v1/uploads` (reference-first file upload), `GET /v1/artifacts/{artifact_id}` (artifact download with auth + tenant check), and `POST /v1/feedback` (feedback normalization). These endpoints replace the 501 stubs from Plan 91-01 with full implementations. This satisfies GW-04: "附件上传与产物下载 reference-first（返回 `attachment_ref` / `artifact_id`，不落敏感全文），下载需鉴权 + 租户校验".

The upload handler stores references only (`payload_ref`, `content_ref`, `content_hash`) — never raw legal content — following the same pattern as `lawyer-web-chat`'s `FileUploadHandler`. The artifact download handler requires auth and tenant validation — cross-tenant access is rejected with 403. The feedback handler normalizes feedback actions (up/down/needs_fix/route_wrong) using the same pattern as `lawyer-web-chat`'s `FeedbackHandler`, producing `FeedbackEvent` records with `skill_candidate.requires_human_review=True` for route mismatches.

## Reversibility Gate

**One-way-door:** The reference-first upload contract — once the Gateway returns `attachment_ref` / `artifact_id` instead of raw content, clients will depend on this reference pattern. Strategy: the reference-first pattern is already proven by `lawyer-web-chat`'s `FileUploadHandler` (which has been in production). The Gateway ports the same pattern, so it is stable by definition. Raw content is never stored — only hashes and references — satisfying AGENTS.md: "Never commit secrets, tokens, runtime databases, logs, customer documents, or raw legal payloads."

**One-way-door:** Modifying `services/gateway/src/gateway/app.py` (shared with Plan 91-02). Strategy: this plan depends on Plan 91-02 (which already modified `app.py` for Last-Event-ID replay). The changes in this plan are additive — replacing 501 stubs with real handlers. The `handle_upload`, `handle_get_artifact`, and `handle_submit_feedback` stubs from Plan 91-01 are replaced with full implementations. No existing handler is modified.

**One-way-door:** Cross-tenant artifact access denial — once the Gateway enforces tenant isolation on artifact downloads, removing it would be a security regression. Strategy: tenant isolation is enforced via `GatewayAuth.check_tenant()` (from Plan 91-01), which is already tested. The artifact handler delegates to `check_tenant` — it does not implement its own tenant check logic.

Create `services/gateway/src/gateway/upload.py`. Port the `FileUploadHandler` from `lawyer-web-chat/src/lawyer_web_chat/upload.py` into the Gateway, adapting it to the Gateway's auth + tenant pattern.

Define the following:

1. A dataclass `UploadResult` (porting from `lawyer-web-chat`) with fields: `upload_id: str`, `payload_ref: str`, `content_ref: str`, `content_hash: str`, `filename: str`, `size_bytes: int`, `mime_type: str`, `tenant_id: str`, `metadata: dict[str, Any]`. Add `tenant_id` as an explicit field (in `lawyer-web-chat` it was in metadata — in the Gateway it is a first-class field for tenant isolation).

2. A class `GatewayUploadHandler` with:
   - `__init__(self) -> None` — initializes an in-memory upload store (`dict[str, UploadResult]`) and a counter.
   - `def handle_upload(self, *, filename: str, content_bytes: bytes, mime_type: str, tenant_id: str, conversation_id: str) -> UploadResult` — processes a file upload, storing references only. Computes SHA-256 content hash, generates `payload_ref` and `content_ref` in the format `ref://{tenant_id}/{conversation_id}/{upload_id}/payload` and `ref://{tenant_id}/{conversation_id}/{upload_id}/content`. Sanitizes the filename (strips path components). Never stores raw content — only the hash and references. Stores the `UploadResult` in the internal store.
   - `def get_upload(self, upload_id: str, *, tenant_id: str) -> UploadResult | None` — retrieves an upload by ID. Returns `None` if the upload does not exist OR if the upload's `tenant_id` does not match the requesting `tenant_id` (cross-tenant access denied, fail-safe: invisible to other tenants).
   - `def list_uploads(self, conversation_id: str, *, tenant_id: str) -> list[UploadResult]` — lists uploads for a conversation, filtered by tenant_id.

3. A function `handle_upload_request(handler: GatewayUploadHandler, auth_ctx: AuthContext, body: Mapping[str, object]) -> JsonObject` — the Gateway endpoint handler for `POST /v1/uploads`. Parses the request body (filename, content as base64, mime_type, conversation_id), calls `handler.handle_upload()` with the auth context's `tenant_id`, and returns the upload result as a JSON dict. The response includes `upload_id`, `payload_ref`, `content_ref`, `content_hash`, `filename`, `size_bytes`, `mime_type`, `tenant_id`, and `reference_only: True`.

CRITICAL: Raw content is never stored. Only the SHA-256 hash and references are kept. The `content_bytes` are hashed and immediately discarded. This satisfies AGENTS.md safety constraints.
</action>
