# Plan 91-05: Full OpenAPI Document, Integration Tests, Gate Suite Green, and Phase 91 Verification

## Goal

Complete Phase 91 with three final deliverables:

1. **Full OpenAPI 3.1 document** — expand the initial OpenAPI builder from Plan 91-01 with complete schemas, examples, security schemes, and the `Last-Event-ID` header parameter for all 12 endpoints. The document must be deterministic, byte-stable, and valid OpenAPI 3.1.

2. **End-to-end integration tests** — comprehensive tests that exercise the full Gateway surface: create session → create run → stream events with Last-Event-ID reconnection → submit elicitation → submit approval → upload → download artifact → submit feedback → list skills. These tests verify all 6 Phase 91 success criteria end-to-end.

3. **Phase 91 verification** — run the full gate suite, verify all gates green (31 gates), verify all 6 success criteria from the ROADMAP are met, and confirm all 6 requirements (GW-01..06) are satisfied. This is the final gate before Phase 91 is marked complete.

## Reversibility Gate

**One-way-door:** The full OpenAPI document is the contract surface for all Gateway clients. Once published, changing endpoint schemas or response shapes would break SDK generation and client integrations. Strategy: the OpenAPI document is generated deterministically (sort_keys, fixed indent) so it is byte-stable for diffing. Schema changes require a version bump. The document is tested for validity (parseable, all paths have operations, all schemas referenced).

**One-way-door:** The integration tests lock in the end-to-end behavior of the Gateway. Once they pass, any change that breaks them is a regression. Strategy: the integration tests use a `FakeRunRuntime` and fixture data (no network, no external agents), so they are deterministic and repeatable. They cover the full success criteria but do not test implementation details (those are covered by unit tests in previous plans).
