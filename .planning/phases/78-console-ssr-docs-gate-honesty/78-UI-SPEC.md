Declared values (multiples of 4), inherited from Phase 75 / 76 / 77 / existing dashboard (`1rem ≈ 16px`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Badge padding, inline status text padding, gate-honesty banner icon gap |
| sm | 8px | Compact field gaps, table cell padding (`0.4–0.6rem`), dual-knob row gap |
| md | 16px | Default field stack gap, card padding (`1rem`), section padding |
| lg | 24px | Section padding (`1.5rem`), section bottom margin, notice banner margin |
| xl | 32px | Page main padding (`2rem`), header/nav horizontal padding |
| 2xl | 48px | Break between config cards/panels |
| 3xl | 64px | Page-level break between major sections (e.g. Gate Status vs config links) |

Exceptions:
- Touch/click targets for checkboxes, submit, probe, and select controls: minimum 44×44px hit area (padding around control), even if visual control is smaller.

## Typography

Exactly four sizes, two weights — aligned to existing admin dashboard and carrying the Phase 75 UI-REVIEW fixes:

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px (`1rem`) | 400 | 1.5 | Form help text, probe results, empty/error body, gate-honesty body text, notice copy |
| Label | 14px (`0.875rem`) | 600 | 1.4 | Field labels, table keys, nav links, identity bar, badge text, gate-honesty heading |
| Heading | 18px (`1.125rem`) | 600 | 1.2 | Section titles (`h2`), card panel titles (`h3`) |
| Display | 20px (`1.25rem`) | 600 | 1.2 | Page brand header only (`InkStatute Admin Dashboard`) |

Do not introduce additional sizes or weights. Monospace for secret-ref values, API base URLs, model IDs, and provider IDs: inherit size from Body/Label; use `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`.

**Phase 78 chrome fixes (from Phase 75 UI-REVIEW):**
- `.header h1` is exactly `1.25rem` / weight 600 (not browser-default 700).
- `.section h2` and all card panel `h3` are exactly `1.125rem` / weight 600 / line-height 1.2.
- `.identity` is `0.875rem` / weight 600 (Label role) instead of `0.8rem`.
- `.nav-link` remains `0.875rem` / weight 600 (Label role).
- `.data-table` uses `0.875rem` (Label size) when used; no extra 0.85rem size.

## Color

Preserve existing InkStatute Admin palette (60/30/10), inherited from Phase 75 / 76 / 77:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f5f5f5` | Page background |
| Secondary (30%) | `#ffffff` sections / `#fafafa` cards / `#1a1a2e` header / `#16213e` nav / `#0f3460` identity bar | Panels, nav chrome |
| Accent (10%) | `#aaccff` | Nav links, identity text, `:focus-visible` outline on interactive controls, gate-honesty banner border |
| Destructive | `#c0392b` | Error messages, invalid-config/CSRF banners, probe-fail status, `status-err` only |
| Success | `#27ae60` | Probe-success status, `status-ok`, "ref configured" / "vision configured" only |
| Text | `#222222` | Body copy |
| Muted | `#888888` | Empty states, help captions, "not set" / "not configured" / "not required" |
| Key muted | `#555555` | Field labels / table keys |

Accent reserved for:
1. Top nav link color (and hover → `#ffffff`).
2. Identity bar secondary text.
3. `:focus-visible` outline on all form controls (2px solid `#aaccff`).
4. Gate-honesty banner border (1px solid `#aaccff`) and background tint (`#f5f8ff`).

Accent is **not** for primary submit fill, probe button fill, or gate-honesty body text. Primary submit and probe buttons use header navy `#1a1a2e` background + `#ffffff` text. Gate-honesty body text uses standard Text `#222222`.

**Carried fix from Phase 75 / 76 UI-REVIEW:** routine OFF / "not configured" / "not required" states use muted `#888888` (`.empty`), not destructive `#c0392b`. Reserve `status-err` red for actual errors, CSRF failures, validation errors, and probe failures.

## CSRF Contract (ADM-02)

All mutating config routes (`/config/channels`, `/config/providers`, `/config/catalog`, `/config/vision`, `/config/providers/probe`) use the same signed CSRF pattern as Phase 76/77:

- GET handlers issue a route-bound token with `issue_csrf_token(identity, route, signing_key=rbac_secret)`.
- The token is rendered as a hidden `<input type="hidden" name="csrf_token" value="...">` inside the relevant form.
- POST handlers parse the form and call `validate_csrf_token(token, identity, route, signing_key=rbac_secret)` before proxying the request.
- On missing, malformed, or mismatched token, the handler returns 403 and renders the page with the exact error copy: "Request could not be verified. Refresh the page and try again."
- The channel route (`/config/channels`) is updated from the Phase 75 placeholder random token to the signed, route-bound token pattern.
- Probe tokens are bound to `/config/providers/probe`, not to the save route.
- No token is reused across routes; cross-route tokens fail validation.

Display requirements:
- CSRF token is never logged, echoed, or rendered outside the hidden input.
- The error message is shown as a `.error` flash at the top of the relevant section.
- The form is still rendered so the operator can refresh the page and resubmit.

## Gate Honesty Contract (DOC-02)

Every config page and the `/gates` page displays a gate-honesty notice:

```
[gate-honesty card .notice-honesty]
  Heading: "This console does not close live acceptance gates"
  Body: "Saving config or running a probe does not claim Phase 5 WeCom UAT, Phase 8 lawyer trial, or QQ live acceptance. Smoke and probe evidence remains `not_live_acceptance`."
```

Rules:
- The banner appears **above** the form, below the section title and any flash messages.
- It uses the `notice-honesty` class: `background: #f5f8ff`, `border: 1px solid #aaccff`, `border-radius: 6px`, `padding: 16px`, `margin-bottom: 16px`.
- Heading text uses Label role (`0.875rem` / weight 600 / `#222222`).
- Body text uses Body role (`1rem` / weight 400 / `#222222`).
- The `code` segment (`not_live_acceptance`) is rendered in monospace with the same Body size.
- The banner is never dismissible and never hidden by feature flags.
- The Gate Status page (`/gates`) also adds a "Carried human gates" subsection after the automated gate list with the same text.

Forbidden text in any config response, smoke output, or documentation: "lawyer trial acceptance complete", "live wecom uat passed", "live qq openapi acceptance", "live provider reachability".

## Accessibility & Safety

- Every form control has a visible `<label for="…">` with human text (not raw snake_case) or is wrapped in a `<label>` (radio/checkbox rows).
- The gate-honesty banner has `role="note"` and an `aria-label="Gate honesty notice"` so screen readers announce it once.
- CSRF failure messages are associated with the form via a `<p class="error" role="status">` at the top of the section.
- Status uses words ("configured", "not configured", "not required", "succeeded", "failed") plus color class — never color alone.
- CSP remains strict (`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'`); no inline scripts; no `innerHTML` of untrusted data — all dynamic strings through `html.escape`.
- Output boundary (`AdminUiBoundary`) applies to any free-text API messages before render.
- Never render resolved secrets, `.env` file contents, store filesystem paths, probe response bodies, `Authorization` headers, or `api_key_ref` values.
- Do not claim live WeCom/QQ acceptance or live provider reachability from saving config or running a probe.
- Preserve `packages/operator-config` refs-only policy: no raw secrets in form bodies or responses.
