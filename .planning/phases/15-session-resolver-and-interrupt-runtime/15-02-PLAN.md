<constraints>
- Use the existing Phase 14 `RunInterrupt` contract and existing enum values; do not introduce a competing interrupt schema or state machine.
- Keep runtime support dependency-free and embedded; no server, DB, queue, scheduler, new service, or external package.
- Do not make `BackendAdapter` implementations rebuild Hermes core or call Hermes gateway. Resume handoff must stay backend-neutral and no-channel-IO.
- Do not store clarification answers, legal facts, prompt text, callback bodies, or backend debug output in interrupt records. Store `prompt_ref`, `resume_state_ref`, `expected_response_schema_ref`, hashes, lengths, IDs, and idempotency keys.
</constraints>

<must_haves>
Truths:
- INT-01: A run/result that indicates clarification maps to `AsyncTaskState.WAITING_FOR_USER`, `AgentResultStatus.NEEDS_CLARIFICATION`, and a persisted `RunInterrupt(status=waiting_for_user)`.
- INT-02: The next scoped answer turn resolves the interrupt and submits a resume handoff through `DefaultRunRuntime` without ordinary users knowing command syntax.
- INT-03: Multiple-choice/freeform metadata survives as refs and metadata such as `expected_response_schema_ref`, `question_kind`, and `choice_refs`; user-visible wording is not stored inside the interrupt record.
- INT-04: Duplicate answers do not submit a second backend run, expired interrupts do not resume, and cancelled interrupts remain cancelled.

Required artifacts:
- `packages/platform-runtime/src/platform_runtime/interrupts.py`
- `packages/platform-runtime/tests/test_interrupt_runtime.py`
- Runtime and fake backend support in `runtime.py` and `fakes.py`

Key links:
- Runtime `create_run` records waiting-for-user interruption evidence when fake/backend output reports clarification.
- Runtime resume handoff submits a `RunRequest` with `metadata.interrupt_id`, `metadata.resume_state_ref`, `metadata.resuming_run_id`, and sanitized answer evidence.
- Interrupt lifecycle records append `run_interrupt` and `run_event` evidence through the existing `ContractLogStore` when enabled.
</must_haves>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| backend result -> interrupt runtime | Backend output may request clarification and must be normalized into platform states without leaking backend internals. |
| user answer -> resume handoff | Untrusted answer text is used transiently to resume but persisted only as refs/hashes/lengths. |
| interrupt store -> backend adapter | Resume metadata controls which paused run continues. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-15-02-01 | Spoofing/Elevation of Privilege | `InMemoryInterruptStore.pending_for_scope` | mitigate | Scope interrupts by tenant/workspace/channel/user/bot/session and add mismatch tests. |
| T-15-02-02 | Replay/Tampering | `resume_interrupt` | mitigate | Store resolved turn/idempotency key and return duplicate decisions without a second backend call. |
| T-15-02-03 | Information Disclosure | interrupt lifecycle events | mitigate | Persist prompt/resume refs and answer hashes/lengths only; assert raw answer text is absent. |
| T-15-02-04 | Denial of Service | stale waiting interrupts | mitigate | Implement deterministic expire/cancel paths and tests. |
| T-15-02-SC | Tampering | package installs | mitigate | No package-manager install tasks; stdlib-only implementation. |
</threat_model>
