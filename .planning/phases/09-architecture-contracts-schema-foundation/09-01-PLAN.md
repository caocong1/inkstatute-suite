# Plan 09-01 - North Star Architecture Docs And Protocol Stubs

## Objective

Promote the North Star platform architecture into `docs/architecture/`, record the seven ADR drafts, and create importable signature-only Protocol stubs for the four stable platform contracts without implementing runtime behavior.

## Threat Model

<threat_model>
<risk id="T-09-01-runtime-creep" severity="high">Protocol scaffolding could accidentally implement orchestration behavior that belongs to Phase 10. Mitigation: keep `packages/platform-runtime/src/platform_runtime/protocols.py` limited to `Protocol` signatures, type aliases, dataclasses for request/result shapes only when needed, and no service logic.</risk>
<risk id="T-09-01-boundary-confusion" severity="high">Architecture docs could imply Hermes gateway or WeCom protocol internals are the platform boundary. Mitigation: docs and ADRs state that InkStatute owns the channel boundary and Hermes is only the first backend adapter.</risk>
<risk id="T-09-01-secret-docs" severity="high">Architecture docs could capture runtime paths, secrets, logs, or customer payloads. Mitigation: use only sanitized architecture descriptions and secret reference terminology.</risk>
<risk id="T-09-01-adr-drift" severity="medium">ADRs could contradict the active North Star draft or V2 PRD safety constraints. Mitigation: read `.planning/drafts/agent-platform-north-star.md`, `.planning/drafts/agent-platformization-plan-v5.md`, `docs/requirements/V2-PRD.md`, and `AGENTS.md` before authoring.</risk>
</threat_model>
