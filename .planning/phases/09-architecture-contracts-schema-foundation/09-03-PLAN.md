# Plan 09-03 - Platform Relationship Fixtures And Replay Gates

## Objective

Add sanitized platform-foundation fixtures and replay checks proving the new channel/run/artifact/delivery contracts compose with the existing five V2 events, including a non-legal scenario with no legal top-level fields.

## Threat Model

<threat_model>
<risk id="T-09-03-fixture-privacy" severity="high">Fixture authors could accidentally include raw callback bodies, customer content, or secret values. Mitigation: use synthetic non-legal data, `fixture://` refs, and `secret_ref` names only.</risk>
<risk id="T-09-03-relationship-gap" severity="high">New schemas could validate individually while the end-to-end relationship chain is broken. Mitigation: add explicit relationship checks across channel, run, artifact, delivery, and feedback IDs.</risk>
<risk id="T-09-03-legal-leak" severity="high">Non-legal fixture could still depend on lawfirm-only schema fields. Mitigation: assert no forbidden legal fields appear at top level and validate without lawfirm assumptions.</risk>
<risk id="T-09-03-existing-regression" severity="medium">Extending replay helpers could break existing Phase 1-7 fixtures. Mitigation: keep existing replay behavior as default and add optional platform-extension checks only when fixture objects exist.</risk>
</threat_model>
