# Plan 96-04: Gate Registration + End-to-End Index Generation + Read-Only Verification + Phase Completion

## Goal

This is the final plan of Phase 96. It assembles all components from Plans 96-01, 96-02, and 96-03 into a complete end-to-end index generation pipeline, registers the new `skill-index` gate (34 → 35 gates), runs the full gate suite, and verifies all 6 success criteria from ROADMAP.md.

This plan implements:

1. **index_builder.py** — assembles the complete `skill-index.json` from scanned skills + classification + metadata + merge report. Produces the final JSON with top-level metadata, `repos`, `skills` array, and `merge_report`.

2. **cli.py** — CLI entry point: `python -m inkstatute_skill_index scan --repo <path> --output <path>`. Enables running the scanner from the command line.

3. **Gate registration** — adds `skill_index_src` path variable, `Gate("skill-index", ...)` entry, and `"packages/skill-index/src"` to the compileall gate in `scripts/run_v2_gates.py`. Gate count goes from 34 to 35.

4. **End-to-end tests** — `test_index_builder.py` (full index assembly + schema validation), `test_cli.py` (CLI invocation), `test_e2e_read_only.py` (end-to-end scan of real repos with read-only verification).

5. **Phase completion** — run full gate suite, verify all 6 success criteria, update STATE.md.

## Reversibility Gate

**One-way-door:** Registering the `skill-index` gate in `scripts/run_v2_gates.py`. Once registered, the gate-coverage meta-test will enforce that `packages/skill-index/src` is covered. Removing the gate would break the meta-test. Strategy: all tests from Plans 96-01, 96-02, 96-03 must be passing before this plan registers the gate. If the gate fails, fix the tests before proceeding.

**One-way-door:** The `skill-index.json` output format. Once the index builder produces JSON with a specific schema, downstream consumers (Phase 97 materializer, Phase 98 router) will depend on it. Strategy: the schema is defined in 96-CONTEXT.md §Key Decisions #7 and 96-RESEARCH.md §12. The index builder follows this schema exactly.

   - `scanner_version: str`
   - `repos: dict[str, dict[str, Any]]` — per-repo metadata (path, commit, skill_count)
   - `skills: list[IndexRecord]`
   - `merge_report: dict[str, Any]` — serialized MergeReport
   - `warnings: list[str]` — top-level warnings

3. A function `build_index(repo_configs: list[dict[str, str]], previous_index_path: str | Path | None = None) -> SkillIndex`:
   - `repo_configs` is a list of dicts, each with `{"name": "ai-for-china-legal", "path": "/home/sorawatcher/workspace/ai-for-china-legal"}` or `{"name": "legal-skills", "path": "/home/sorawatcher/workspace/legal-skills"}`
   - For each repo config:
     - Call `scan_repo(path, name)` to get `ScanResult`
     - Load plugin.json files for each plugin (for classification signal 2) — read `.claude-plugin/plugin.json` from each plugin directory
     - Call `classify_all_skills(scan_result.skills, plugin_json_skills)` to get classification results
     - For each skill, call `extract_metadata(skill, skill_dir)` to get metadata
     - For each skill, compute `content_hash` via `compute_content_hash(skill.raw_text)`
     - For each skill, detect local modification via `_detect_local_modification(skill)`
     - Assemble `IndexRecord` from scanner + classification + metadata + hash
   - After all repos are scanned, call `build_merge_report(all_skills, previous_index)` to get merge report
   - Assemble `SkillIndex` with `generated_at` (current UTC time), `scanner_version` (from `__init__.SCANNER_VERSION`), `repos` metadata, `skills` list, `merge_report` (serialized), `warnings`
   - Returns `SkillIndex`

4. A function `serialize_index(index: SkillIndex) -> dict[str, Any]`:
   - Converts `SkillIndex` to a JSON-serializable dict
   - Converts dataclass fields to dicts/lists
   - Returns the complete dict matching the schema in 96-RESEARCH.md §12

5. A function `write_index(index: SkillIndex, output_path: str | Path) -> None`:
   - Calls `serialize_index(index)` to get the dict
   - Writes JSON to `output_path` with `indent=2` and `ensure_ascii=False`
   - CRITICAL: `output_path` must be OUTSIDE the source repos (enforced by caller / CLI)

6. A helper function `_load_plugin_json_skills(repo_path: Path, repo_name: str) -> dict[str, list[dict]] | None`:
   - For ai-for-china-legal: reads each `<plugin>/.claude-plugin/plugin.json` and extracts the `skills` array
   - Returns a dict mapping `plugin_name → skills[]` list
   - For legal-skills: returns `None` (no skills[] array in plugin.json)
   - Handles missing plugin.json gracefully (returns `None` for that plugin, adds warning)

7. A helper function `_get_repo_commit(repo_path: Path) -> str | None`:
   - Tries to get the git commit SHA via `subprocess.run(["git", "rev-parse", "HEAD"], cwd=repo_path)`
   - Returns the SHA string if successful, `None` if not a git repo or git is unavailable
   - Read-only — does not modify the repo

Import all components from sibling modules. Import `json`, `datetime` from stdlib. Import `Path` from pathlib. Import `subprocess` from stdlib. Import `Any` from typing. Import `dataclass`, `field` from dataclasses.

CRITICAL: The index builder must NOT write to source repos. The `write_index` function writes to `output_path` which must be outside the source repos. The `_load_plugin_json_skills` and `_get_repo_commit` functions are read-only. The builder assembles data in memory and writes only to the specified output path.
