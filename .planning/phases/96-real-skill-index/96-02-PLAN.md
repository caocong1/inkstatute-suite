# Plan 96-02: Orchestration/Leaf Classification + Metadata Enrichment

## Goal

Build the classification and metadata enrichment layer on top of the scanner core from Plan 96-01. This plan implements:

1. **Three-way cross-validation orchestration/leaf classifier** — classifies each scanned skill as `"orchestration"` or `"leaf"` using directory structure + plugin.json + body text heuristics. Extracts parent-child relationships.

2. **Metadata extractor** — enriches each skill record with the 8 metadata fields required by SKILL-03: `token_estimate` (already from scanner), `declared_gates`, `referenced_resources`, `practice_profile_dependency`, `host_assumptions`, `required_scripts`, `source_repo`, `license`.

This plan depends on Plan 96-01 (scanner core produces `ScannedSkill` records). It can run in parallel with Plan 96-03 (conflict model) since they touch different new files.

## Reversibility Gate

**One-way-door:** Adding `orchestration_classifier.py` and `metadata_extractor.py` to the `inkstatute_skill_index` package. These are new modules — purely additive. If classification logic is wrong, the modules can be modified without affecting the scanner core. No existing file is modified except `__init__.py` (additive exports).

<action>
Create `packages/skill-index/src/inkstatute_skill_index/orchestration_classifier.py`.

This module classifies each `ScannedSkill` as `"orchestration"` or `"leaf"` using three-way cross-validation and extracts parent-child relationships.

Define the following:

1. A frozen slotted dataclass `ClassificationResult` with fields:
   - `skill_type: str` — `"orchestration"` or `"leaf"`
   - `parent_skill: str | None` — skill_id of parent (for leaf skills nested under an orchestration entry), `None` for orchestration entries and flat skills
   - `child_skills: list[str]` — list of child skill_ids (for orchestration entries), empty list for leaf skills
   - `classification_signals: list[str]` — which signals triggered the classification (e.g., `["directory_has_children", "body_text_orchestration"]`)
   - `warnings: list[str]` — classification warnings

2. A function `classify_skill(skill: ScannedSkill, all_skills: list[ScannedSkill], plugin_json_skills: dict[str, list[dict]] | None = None) -> ClassificationResult`:
   - Performs three-way cross-validation:
     - **Signal 1 — Directory structure:** Check if the skill's directory contains sub-directories with their own SKILL.md files. If `skill.depth == 0` and there exist other skills in `all_skills` with `depth == 1` whose `relative_path` starts with the same parent path, this skill has children → orchestration signal.
     - **Signal 2 — plugin.json:** If `plugin_json_skills` is provided and the skill's path appears as a parent of other paths in the `skills[]` array, → orchestration signal. Also, if the skill's path is nested under another skill's path in plugin.json, → leaf signal with parent identified.
     - **Signal 3 — Body text heuristic:** Check if `skill.body` contains `"编排入口"` (orchestration entry) or `"子技能编排顺序"` (sub-skill orchestration order) or a markdown table with sub-skill paths → orchestration signal. Check if body contains `"迁移说明"` (migration note) → leaf signal.
   - Classification logic:
     - If ANY orchestration signal is triggered → `skill_type = "orchestration"`
     - If `skill.depth >= 1` (nested under a parent) → `skill_type = "leaf"`, `parent_skill` = skill_id of the parent (derived from path)
     - If no signals and `skill.depth == 0` → `skill_type = "leaf"` (standalone leaf, no parent)
     - For legal-skills (all flat, `depth == 0`, no nesting) → always `"leaf"`, `parent_skill = None`
   - Child skills extraction: for orchestration entries, find all skills in `all_skills` whose `relative_path` starts with the orchestration entry's directory path + `/` and have `depth == 1`. Collect their `skill_id`s into `child_skills`.
   - Parent skill extraction: for leaf skills with `depth >= 1`, derive parent from the path component above the skill's directory. Find the parent skill in `all_skills` by matching the path prefix.

3. A function `classify_all_skills(skills: list[ScannedSkill], plugin_json_skills: dict[str, list[dict]] | None = None) -> dict[str, ClassificationResult]`:
   - Classifies all skills and returns a dict mapping `skill_id → ClassificationResult`
   - Handles the case where a skill is both a leaf (has a parent) and has children (orchestration) — in this case, classify as orchestration (orchestration takes precedence)

4. A helper function `_check_directory_has_children(skill: ScannedSkill, all_skills: list[ScannedSkill]) -> bool`:
   - Returns True if any other skill in `all_skills` has a `relative_path` that starts with the skill's directory path (minus `SKILL.md`) followed by `/`

5. A helper function `_check_body_text_orchestration(body: str) -> bool`:
   - Returns True if body contains any of: `"编排入口"`, `"子技能编排顺序"`, `"子技能"` in a markdown table context

6. A helper function `_check_body_text_leaf(body: str) -> bool`:
   - Returns True if body contains `"迁移说明"` (migration note pattern)

7. A helper function `_extract_parent_from_path(relative_path: str, all_skills: list[ScannedSkill]) -> str | None`:
   - For a path like `commercial-legal/skills/contract-review/risk-identification/SKILL.md`, the parent directory is `commercial-legal/skills/contract-review/`
   - Find the skill in `all_skills` whose `relative_path` is `commercial-legal/skills/contract-review/SKILL.md`
   - Return that skill's `skill_id`

8. A helper function `_extract_children_from_path(skill: ScannedSkill, all_skills: list[ScannedSkill]) -> list[str]`:
   - For an orchestration skill at `commercial-legal/skills/contract-review/SKILL.md`, find all skills whose path starts with `commercial-legal/skills/contract-review/` and have exactly one more path component before `SKILL.md`
   - Return their `skill_id`s

Import `ScannedSkill` from `.scanner`. Import `dataclass`, `field` from dataclasses. Import `Any` from typing.

CRITICAL: The classifier must be tolerant of edge cases:
- A skill with `depth == 0` but no children in the directory and no body text signals → classified as `"leaf"` (standalone)
- The ai-governance name collision (`filing-material-preparation` under two parents) — the classifier uses `path` not `name` to determine parent-child, so both instances are correctly classified as leaf skills with different parents
- Missing plugin.json (`plugin_json_skills = None`) → classification falls back to directory structure + body text only
</action>

     - `"de-ai-polish"` or `"去AI化"` or `"de-AI"` → add `"de-ai-polish"`
   - Returns sorted unique list (no duplicates)

4. A function `_extract_referenced_resources(body: str) -> list[str]`:
   - Extracts file paths matching patterns:
     - `shared/references/...` paths
     - `shared/research-gate/...` paths
     - `_shared/...` paths
     - `references/...` paths (relative to skill directory)
   - Uses regex to find paths in markdown links, code blocks, and plain text
   - Returns sorted unique list

5. A function `_check_practice_profile_dependency(body: str) -> bool`:
   - Returns `True` if body contains any of: `"CLAUDE.md"`, `"实践配置"`, `"practice profile"`, `"审查立场"`, `"执业配置"`
   - Returns `False` otherwise

6. A function `_extract_host_assumptions(body: str, frontmatter: dict[str, Any]) -> list[str]`:
   - Extracts trigger patterns: regex for `/<plugin>:<skill>` patterns (e.g., `/commercial-legal:contract-review`)
   - Extracts `argument-hint` from frontmatter if present
   - Returns list of strings (trigger patterns + argument hints)

7. A function `_extract_required_scripts(body: str, skill_file_path: str, skill_dir: Path | None = None) -> list[str]`:
   - Scans body text for `scripts/` path references (e.g., `scripts/script.py`)
   - If `skill_dir` is provided, also checks if a `scripts/` directory exists next to the SKILL.md and lists `.py` files in it
   - Returns sorted unique list of script paths (relative to skill directory)

8. A function `_extract_license(frontmatter: dict[str, Any], source_repo: str) -> str | None`:
   - If `frontmatter` has a `license` field, return it as string
   - If `source_repo == "legal-skills"` and no frontmatter license, return `None` (should not happen per research, but handle gracefully)
   - If `source_repo == "ai-for-china-legal"`, return `None` (license is project-level, not per-skill)

Import `ScannedSkill` from `.scanner`. Import `re` from stdlib. Import `Path` from pathlib. Import `Any` from typing. Import `dataclass`, `field` from dataclasses.

CRITICAL: The metadata extractor must be read-only — it reads body text and optionally lists files in a directory, but never writes. The `_extract_required_scripts` function uses `skill_dir.glob("scripts/*.py")` to list files, which is a read-only operation.
