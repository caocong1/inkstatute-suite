# Plan 02: Arena Dataclasses (Config/Handle/Status/UserAction) + Cross-Language Round-Trip

## Objective

Define the 4 Arena contract dataclasses (`ArenaWorkflowConfig`, `ArenaHandle`, `ArenaStatus`, `ArenaUserAction`) in both Python and TypeScript, with JSON Schemas and a cross-language round-trip test proving Python → JSON → TypeScript-shape-conformance → JSON → Python is lossless. This is CONTRACT-02.

## Context

- @packages/platform-contract/src/platform_contract/events.py — existing contract dataclasses (`Run`, `RunHandle`, `Session`) are the pattern to follow for non-event-payload dataclasses
- @packages/platform-contract/src/platform_contract/unified_events.py — `serialize_payload`/`deserialize_payload` pattern and `_NESTED_TYPE_MAP` for nested dataclass coercion
- @packages/platform-contract/src/platform_contract/__init__.py — re-export pattern for public symbols
- @packages/platform-contract/src/platform_contract/schemas/run.schema.json — schema template for non-event contract dataclasses
- @packages/platform-sdk-ts/src/events.ts — TS interface definitions, hand-written
- @packages/platform-sdk-ts/tests/test_event_types.py — TS text-inspection test pattern
- @.planning/phases/105-arena-contract-extension/105-RESEARCH.md — Assumption Log items 2/3, Open Question 3 (dataclass schemas recommended), Common Pitfall #4 (nested dataclass registration)
