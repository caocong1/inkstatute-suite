# Plan 01: Create packages/model-gateway/ with ModelProviderGateway Composite BackendAdapter

## Objective

Create the `packages/model-gateway/` package with `ModelProviderGateway` — a composite `BackendAdapter` that wraps multiple `provider_model` sub-adapters in a `dict[str, BackendAdapter]` keyed by `backend_id`. The gateway implements all 9 frozen `BackendAdapter` Protocol methods, delegating `submit_run` by `solution.backend_id` and routing `get_run`/`stream_events`/`cancel_run`/`submit_approval`/`collect_artifacts` via an internal `run_id → backend_id` mapping. When `model_gateway_enabled` is `False` (default), the gateway is transparent — pass-through to the matching sub-adapter with no rate limiting, circuit breaking, fallback, or cost tracking.
