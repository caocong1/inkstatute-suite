### Task 1: src/content/manifest.rs — 内容包清单模型

- **type:** code
- **files:** apps/desktop/src-tauri/src/content/manifest.rs
- **action:** 按 v4.0 已定的 `content-manifest.json` schema 实现 serde 模型
  （行为参照 `apps/flutter_app/lib/content/manifest_schema.dart`，**只读参照**）：

```rust
pub struct ContentManifest {
    pub schema_version: String,
    pub release_version: String,     // semver
    pub released_at: String,         // ISO8601
    pub min_engine_version: String,  // semver 或 semver range
    pub domains: HashMap<String, DomainEntry>,
}
pub struct DomainEntry { pub skills: Vec<SkillEntry> }
pub struct SkillEntry { pub name: String, pub sha256: String }

impl ContentManifest {
    pub fn total_skill_count(&self) -> usize;
    /// v4 是字符串相等；v5 改 semver 范围比较
    pub fn is_compatible_with(&self, engine_version: &str) -> bool;
}
```

**`is_compatible_with` 的实现要点**（这是 v5 相对 v4 的唯一语义变化）：
- 用 `semver` crate（Cargo.toml 增 `semver = "1"`）
- `min_engine_version` 可以是精确版本（`0.1.0-rc.6`）或范围（`>=0.1.0-rc.6`）
- **预发布版本比较要正确**：`0.1.0-rc.6 >= 0.1.0-rc.5` 为真，`0.1.0-rc.6 >= 0.1.0` 为假。
  `semver` crate 的 `VersionReq` 默认**不匹配预发布版**，必须显式处理：
  若待比较版本含预发布标识，用 `Version` 直接比较而非 `VersionReq::matches`。
- 解析失败 → 返回 `false`（保守拒绝），不 panic

- **verify:**
  - 单元测试：`0.1.0-rc.6` vs `min=0.1.0-rc.5` → true
  - 单元测试：`0.1.0-rc.5` vs `min=0.1.0-rc.6` → false
  - 单元测试：`0.1.0-rc.6` vs `min=0.2.0` → false
  - 单元测试：非法版本串 → false（不 panic）
- **acceptance_criteria:** semver 比较正确处理预发布版

### Task 2: src/content/updater.rs — 内容包更新器

- **type:** code
- **files:** apps/desktop/src-tauri/src/content/updater.rs, apps/desktop/src-tauri/src/commands/content.rs
- **action:** 行为参照 `apps/flutter_app/lib/content/content_updater.dart`。实现：

```rust
pub struct ContentUpdater { /* 私有 */ }

pub enum UpdateOutcome {
    UpToDate { version: String },
    Updated { from: Option<String>, to: String },
    Skipped { reason: String },        // 不兼容 / 离线
    RolledBack { to: String, reason: String },
}

impl ContentUpdater {
    /// 启动时调用。失败绝不阻塞启动。
    pub async fn check_and_update(&self, engine_version: &str) -> UpdateOutcome;
    pub fn current_release(&self) -> Option<String>;
    pub fn skills_dir(&self) -> PathBuf;   // <app_root>/skills/<current>
}
```

**流程（每步失败都保持 last-good 且不阻塞启动）：**
1. 拉远端 `content-manifest.json`（源可配，默认 GitHub Release；超时 10s）。网络失败 → `Skipped{离线}`。
2. `is_compatible_with(engine_version)` 为假 → `Skipped{不兼容}`，记日志。
3. 与本地 `<app_root>/skills/current` 指向的版本比较，相同 → `UpToDate`。
4. 下载内容包 zip 到临时目录，解压到 `<app_root>/skills/<release_version>.partial/`。
5. **逐技能校验 sha256**（manifest 的 `domains[].skills[].sha256` 对应各 `SKILL.md`）。
   任一不符 → 删 partial 目录 → `RolledBack{保持旧版}`。
6. 全部通过 → `rename` partial 到正式目录 → **原子写 `skills/current` 指针**。
7. 旧版本保留一代，更早的删除。

**Tauri 命令：**
```rust
#[tauri::command] pub async fn check_content_update() -> Result<UpdateOutcome, String>;
#[tauri::command] pub fn get_content_status() -> Result<ContentStatus, String>;
```
`ContentStatus { current_release, skill_count, last_check, last_outcome }`——供设置面板"技能"页签显示。

- **verify:**
  - 单元测试：sha256 不符 → partial 被删、current 未变
  - 单元测试：不兼容 → Skipped 且不下载
  - 单元测试：网络失败 → Skipped 且不 panic
  - 单元测试：成功路径 → current 指向新版本，旧版本目录仍在
- **acceptance_criteria:** 任何失败路径都保持 last-good 可用

### Task 4: SKL-13 token 预算门禁

- **type:** code
- **files:** scripts/gates/v5/token-budget.mjs, scripts/gates/v5/run-gates.mjs
- **action:** 门禁脚本计算「技能目录清单渲染进模型前缀的长度」：
  1. 扫描 `presets/*/` 与（若存在）`<app_root>/skills/current/*/`，
     对每个 `SKILL.md` 解析 frontmatter 的 `name` 与 `description`。
  2. 按 DSH 的清单格式估算渲染长度：每条约 `- \`{name}\`: {description}\n`。
  3. 断言总长度 ≤ **8,000 字符**（可通过 `INKSTATUTE_SKILL_BUDGET` 环境变量覆盖）。
  4. 超预算时**打印超出量与最长的 10 条 description**，便于定位。
  5. 另断言：每个 `SKILL.md` 的 frontmatter 可解析、`name` 唯一、`name` 与目录名一致。
  6. 注册进 `run-gates.mjs`，名为 `token-budget`。
- **verify:**
  - `node scripts/gates/v5/token-budget.mjs` 绿灯
  - 人为把预算设为 10（`INKSTATUTE_SKILL_BUDGET=10`）时门禁红灯并打印诊断
  - `node scripts/gates/v5/run-gates.mjs` 输出 `3 passed, 0 failed`
- **acceptance_criteria:** 预算门禁可独立跑、超预算给出可定位诊断
