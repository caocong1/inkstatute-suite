<objective>
Add active-state indication to the console navigation header, make Login/Logout links auth-state-aware, and eliminate the duplicated `_logs_page_template` in logs.py by refactoring it to delegate to `_page_template`.

Purpose: POLISH-02 requires consistent navigation across all pages with active-state indication. Currently `_page_template` renders nav links without any active class or aria-current attribute. This plan adds an optional `active_path` parameter to `_page_template`, derives it automatically for dashboard pages, and threads it through all 8 section renderer files. Login/Logout links become auth-state-aware per Claude's discretion (product-grade UX).

Additionally, `logs.py` contains a COMPLETE DUPLICATE of `_page_template` named `_logs_page_template` (L168-261) with its own hardcoded nav_items, nav_links, CSS style block, and HTML shell — used by the normal Log Viewer rendering path (render_logs_page L165). This duplicate would NOT receive the active-state or auth-aware nav changes, so the /logs page would be inconsistent with every other page. This plan adds an optional `head_extras: str = ""` parameter to `_page_template` so the meta-refresh tag can be injected, then refactors `_logs_page_template` to delegate to `_page_template` with `head_extras='<meta http-equiv="refresh" content="5">'` and `active_path="/logs"`, eliminating the duplication entirely.

Output: Active-state nav on all 16 pages (including /logs), auth-state-aware Login/Logout, no duplicated page template in logs.py, passing TestNavActiveState test class.
</objective>
