<objective>
Add active-state indication to the console navigation header and make Login/Logout links auth-state-aware.

Purpose: POLISH-02 requires consistent navigation across all pages with active-state indication. Currently _page_template renders nav links without any active class or aria-current attribute. This plan adds an optional active_path parameter to _page_template, derives it automatically for dashboard pages, and threads it through all 8 section renderer files. Login/Logout links become auth-state-aware per Claude's discretion (product-grade UX).

Output: Active-state nav on all 16 pages, auth-state-aware Login/Logout, passing TestNavActiveState test class.
</objective>

  <action>
    1. Add `active_path: str | None = None` as an optional parameter to the `_page_template` function signature, placed after the existing `identity` parameter. The full signature becomes: `def _page_template(title: str, body: str, identity: Identity | None = None, active_path: str | None = None) -> str:`. This is backward compatible — all 16+ existing call sites that do not pass active_path will continue to work with active_path=None.

    2. Modify the nav_links rendering comprehension (currently at dashboard.py ~L88-91) to add active-state. When `href == active_path`, append ` active` to the class attribute value and add ` aria-current="page"` as an attribute on the anchor tag. The rendered link for an active item should be: `<a href="{_esc(href)}" class="nav-link active" aria-current="page">{_esc(label)}</a>`. For inactive items, the link remains: `<a href="{_esc(href)}" class="nav-link">{_esc(label)}</a>`.

    3. Add a `.nav-link.active` CSS rule to the style block in _page_template, placed after the existing `.nav-link:hover` rule (~L110). The rule: `.nav-link.active { color: #fff; border-bottom: 2px solid #aaccff; }`. This gives the active nav link a white text color and a bottom border accent.

    4. Make Login/Logout nav links auth-state-aware. Replace the hardcoded `("/login", "Login")` and `("/logout", "Logout")` entries in the nav_items list (~L85-86) with a conditional: if `identity is not None` (authenticated), append `("/logout", "Logout")` to nav_items; else (anonymous), append `("/login", "Login")`. This means only one of Login/Logout appears at a time, depending on auth state. This is a Claude's discretion decision per CONTEXT.md — product-grade UX shows Login when anonymous and Logout when authenticated.

    5. Add `active_path: str | None = None` as an optional parameter to the `render_dashboard` function signature (~L192), placed after the existing parameters. Inside render_dashboard, define a `_SECTION_TO_PATH` dictionary mapping section names to their nav paths: {"index": "/", "sessions": "/sessions", "tasks": "/tasks", "feedback": "/feedback", "health": "/health", "gates": "/gates", "reports": "/reports"}. If the caller does not pass active_path (it is None), derive it from `_SECTION_TO_PATH.get(section)`. Pass the resolved active_path to `_page_template(title, body, identity, active_path=resolved_active_path)`.

    6. Add a `TestNavActiveState` class to services/admin-web-ui/tests/test_dashboard.py with three test methods:
       - `test_active_link_has_aria_current`: Call `_page_template("Test", "<p>body</p>", active_path="/")`. Assert the output contains `class="nav-link active"` and `aria-current="page"` on the link with href="/". Assert other links do NOT have `active` class.
       - `test_nav_consistent_across_pages`: Call `_page_template` with active_path="/" and active_path="/sessions". Assert both outputs contain the same set of nav link labels (e.g., "Dashboard", "Sessions", "Tasks", "Feedback Review", "Health", "Gates", "Reports", "Logs", "Audit Trail", "Channel Config", "Provider Config", "Model Catalog", "Vision Config"). Assert the nav item count is the same in both outputs.
       - `test_login_logout_auth_aware`: Call `_page_template("Test", "<p>body</p>", identity=None)`. Assert output contains "Login" and does NOT contain "Logout". Then call `_page_template("Test", "<p>body</p>", identity=<a valid Identity object>)`. Assert output contains "Logout" and does NOT contain "Login". Use the Identity type imported in dashboard.py — check the existing import at the top of dashboard.py for the correct import path.
