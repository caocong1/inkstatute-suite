# Plan 04: Second ACP Backend Replaceability + Gate Registration + Full Gate Suite Green

## Goal

Prove backend replaceability by running a second ACP backend (a configurable echo agent variant that simulates `codex-acp` or `claude-agent-acp` behavior) through the exact same `ACPBackendAdapter` test path as the first backend, with zero caller code changes. Register the `acp-client` gate in `scripts/run_v2_gates.py` and verify all 29 gates (28 existing + 1 new) are green.

## Reversibility Gate

**One-way-door:** Adding the `acp-client` gate to `scripts/run_v2_gates.py` makes it a permanent CI requirement. Once added, the gate-coverage meta-test will fail if the gate is removed. Strategy: add the gate additively — do not modify any existing gate entry. Add `packages/acp-client/src` to the `compileall` gate's path list. Task 04-01 is a checkpoint to verify the gate registration is additive and all existing gates still pass before adding the new gate.

<action>
Create `packages/acp-client/tests/test_second_backend.py` with test class `TestSecondBackendReplaceability` using `unittest.IsolatedAsyncioTestCase`. The core principle: the SAME test logic runs against two different backends with different `backend_id` values, and the only difference is the `ACPBackendConfig` passed to the adapter. Tests:

(1) `test_echo_backend_full_cycle` — create `ACPBackendAdapter` with `ACPBackendConfig(backend_id="echo", command=("python", "packages/acp-client/tests/fixtures/echo_agent.py"), required_capabilities=RequiredCapabilities(streaming=True))`. Run the full cycle: `bootstrap_check` → `submit_run` → `stream_events` (collect at least 1 `message.delta` and 1 `message.completed`) → `cancel_run` → `collect_artifacts`. Assert all succeed. Record the event types collected.

(2) `test_codex_acp_backend_full_cycle` — create `ACPBackendAdapter` with `ACPBackendConfig(backend_id="codex-acp", command=("python", "packages/acp-client/tests/fixtures/configurable_echo_agent.py", "--backend-name", "codex-acp", "--capabilities", '{"streaming": true, "elicitation": true, "permissions": true}'), required_capabilities=RequiredCapabilities(streaming=True, elicitation=True, permissions=True))`. Run the EXACT SAME cycle as test (1). Assert all succeed. Record the event types collected.

(3) `test_same_caller_code_different_backends` — define a helper function `async def run_full_cycle(adapter: ACPBackendAdapter, prompt_content: str) -> dict` that performs `bootstrap_check` → `submit_run` → `stream_events` → `cancel_run` → `collect_artifacts` and returns a dict with `backend_id`, `event_types` list, `run_status`. Call this function with both the echo adapter and the codex-acp adapter. Assert both return successfully. Assert the function code is identical for both calls (it is the same function — this is the proof of replaceability). Assert both return `event_types` containing `"message.delta"` and `"message.completed"`.

(4) `test_different_capabilities_negotiated` — assert the echo adapter's `bootstrap_check` metadata shows `elicitation` not supported, while the codex-acp adapter's `bootstrap_check` metadata shows `elicitation` supported. This proves capability negotiation adapts to the backend without caller changes.

(5) `test_thought_chunks_from_second_backend` — when running against the codex-acp fixture, assert `stream_events` yields at least one event with `event_type == "thought.delta"` (the configurable agent emits thought chunks, the base echo agent does not). This proves the adapter handles different event patterns from different backends.

(6) `test_elicitation_from_second_backend` — when running against the codex-acp fixture with prompt content "ask: what is the case number?", assert `stream_events` yields at least one event with `event_type == "elicitation.requested"`. This proves elicitation handling works through the same adapter.

(7) `test_permission_request_not_auto_approved` — when running against the codex-acp fixture with prompt content "permission: run shell command", assert `stream_events` yields at least one event with `event_type == "permission.requested"`. Then call `submit_approval` with `Approval(decision="approved", metadata={"kind": "terminal"})` and assert the run does NOT transition to an approved state — the terminal permission must not be auto-approved.

(8) `test_backend_id_isolated` — assert `echo_adapter.backend_id() == "echo"` and `codex_adapter.backend_id() == "codex-acp"`. Both adapters are `ACPBackendAdapter` instances — the only difference is the config. This proves `backend_id` is config-driven, not code-driven.

Each test must clean up adapters in `tearDown`. Use `asyncio.wait_for` with a 15-second timeout on all async operations.
</action>
