# Phase 78.1: Wire VisionRouter into Turn Runtime - Research

**Researched:** 2026-07-12
**Domain:** InkStatute V2 platform runtime, Python async wiring, operator-config integration
**Confidence:** HIGH (all patterns are internal repo conventions)

## Summary

The missing piece is a runtime consumer for the existing `VisionRouter` decision function. The cleanest integration is to make `DefaultRunRuntime` accept an injected `vision_resolver` closure and an optional `vision_runner` backend. `vision_resolver` returns a `VisionRoutingDecision`; `DefaultRunRuntime` dispatches `multimodal_main` and `text_only` to the main backend, `vision_then_main` to `vision_runner` then the main backend, and `fail_closed` to a synthetic `Run` with an InkStatute-owned notice. The resolver is built from `OperatorConfigStore` + `VisionRouter` + built-in catalog metadata in `operator-config`, so `platform-runtime` remains independent of `operator-config`.

**Primary recommendation:** Inject `vision_resolver` and `vision_runner` into `DefaultRunRuntime`, build a shared `build_vision_resolver` helper in `operator-config`, and update `qqbot-service`/`wecom-service` wiring to pass them.

## User Constraints (from 78.1-CONTEXT.md)

- D-01: `DefaultRunRuntime.create_run()` must call an injected `vision_resolver` before `backend.submit_run()`.
- D-02: `DefaultRunRuntime` accepts an optional `vision_runner` backend for `vision_then_main`.
- D-03: `FAIL_CLOSED` returns a synthetic `Run` with `FAILED` status and the InkStatute-owned notice.
- D-04: `MULTIMODAL_MAIN`/`VISION_THEN_MAIN` attach `vision_decision` metadata.
- D-05: `TEXT_ONLY` attaches metadata but does not invoke vision.
- D-06: `vision_resolver` is built from `OperatorConfigStore` + `VisionRouter` + catalog; `platform-runtime` must not import `operator-config`.
- D-07: `vision_then_main` only when vision pair configured and `vision_runner` injected.
- D-08: `vision_resolver=None` preserves existing behavior.
- D-09: `platform_runtime/__init__.py` re-exports `VisionRoute`, `VisionRoutingDecision`, `VisionRouter`.
- D-10: Fail-closed output passes through `DefaultAssistantOutputBoundary`.

## Architecture Patterns

### System Architecture Diagram

```
Inbound WeCom/QQ callback
        |
        v
ChannelAdapter (verify/ack/normalize)
        |
        v
QQBotRuntimeIngress / WeComRuntimeIngress
        |
        v
RunRequest(turn, attachments, metadata)
        |
        v
DefaultRunRuntime.create_run()
        |-- vision_resolver(req) -> VisionRoutingDecision
        |
        |-- FAIL_CLOSED  -> synthetic Run (notice through output_boundary)
        |-- TEXT_ONLY    -> backend.submit_run(req + vision_decision)
        |-- MULTIMODAL_MAIN -> backend.submit_run(req + vision_decision)
        |-- VISION_THEN_MAIN -> vision_runner.submit_run(req)
        |                       get_run(vision_run_id)
        |                       new_req = turn(content + vision description, no attachments)
        |                       backend.submit_run(new_req + vision_decision)
        |
        v
Run.result -> channel output boundary -> delivery
```

### Pattern 1: Injected Resolver/Runner
**What:** `DefaultRunRuntime` accepts optional `vision_resolver` and `vision_runner` callables/objects.
**When to use:** Any runtime that needs image-aware routing without hard-coding operator-config.
**Example:**
```python
runtime = DefaultRunRuntime(
    backend=backend,
    channels=(adapter,),
    feature_flags=flags,
    vision_resolver=vision_resolver,
    vision_runner=vision_runner,
)
```

### Pattern 2: Operator-Config Resolver Builder
**What:** `build_vision_resolver(store, backend, vision_runner)` returns a closure.
**When to use:** Service wiring needs to resolve `VisionPolicyDoc` and catalog to a `VisionRoutingDecision`.
**Example:**
```python
from inkstatute_operator_config.vision_resolver import build_vision_resolver

resolver = build_vision_resolver(
    store=config_store,
    backend=backend,
    vision_runner=vision_runner,
)
```

### Pattern 3: Fail-Closed Synthetic Run
**What:** When routing cannot satisfy an image-bearing turn, return a `Run` with `FAILED` status and the InkStatute-owned notice.
**When to use:** `VisionRoute.FAIL_CLOSED` or `vision_then_main` without `vision_runner`.

### Pattern 4: Reference-First Metadata
**What:** `vision_decision` metadata contains only reference counts, route reason, and provider/model IDs; no raw image bytes.
**When to use:** Every route.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead |
|---------|-------------|-------------|
| Image-bearing detection | Custom image probing | `VisionRouter.has_image_attachments()` (already exists) |
| OpenAI-compatible vision call | New network client | Extend `OpenAIClientRunner` with `image_url` parts |
| Vision policy lookup | Ad-hoc config parsing | `OperatorConfigStore` + `VisionPolicyDoc` |
| Main model supports_vision | Backend introspection | Built-in catalog `supports_vision` metadata |
| Output sanitization | Custom regex cleanup | `DefaultAssistantOutputBoundary.apply()` |

## Common Pitfalls

### Pitfall 1: Import cycle between `platform-runtime` and `operator-config`
**What goes wrong:** If `platform-runtime` imports `operator-config` at runtime, a circular dependency may form because `operator-config` may need `platform-runtime` types.
**How to avoid:** Keep `platform-runtime` free of `operator-config` imports. Use injected `vision_resolver` closure. `operator-config` may import `platform-runtime` types for the resolver builder.

### Pitfall 2: `VisionRoutingDecision` metadata not JSON-serializable
**What goes wrong:** `VisionRoute` is a `StrEnum`; `dataclasses.asdict()` may leave enum values in `Run` metadata, causing JSON errors.
**How to avoid:** Convert `decision` to a plain dict with `route.value` and `metadata` copied before attaching to `RunRequest.metadata`.

### Pitfall 3: `vision_then_main` leaks raw image bytes
**What goes wrong:** Passing `turn.attachments` to the main backend after vision preprocessing could embed image bytes in the main model call.
**How to avoid:** Replace `turn` with `attachments=[]` and `content` containing the vision description before the main backend call.

### Pitfall 4: `vision_resolver` blocks text-only performance
**What goes wrong:** If `vision_resolver` loads config or checks attachments synchronously, it could slow text-only turns.
**How to avoid:** `has_image_attachments()` is O(n) on the attachment list only; no network, no raw bytes. Config objects can be loaded once at wiring time and captured in the closure.

### Pitfall 5: Fail-closed notice is blocked by `DefaultAssistantOutputBoundary`
**What goes wrong:** The `provider_leak` regex could match `model` in the fail-closed notice.
**How to avoid:** The existing `FAIL_CLOSED_NOTICE` wording is safe (verified by `output_boundary.apply()` test). Always apply the boundary to the fail-closed result and use the returned `visible_text`.

## Code Examples

### VisionResolver usage
```python
from platform_runtime import VisionRoute, VisionRouter, VisionRoutingDecision

decision = VisionRouter().decide(
    turn,
    vision_policy,
    main_supports_vision=True,
    vision_pair_configured=False,
)
assert decision.route == VisionRoute.MULTIMODAL_MAIN
```

### Building `vision_decision` metadata
```python
def _decision_as_dict(decision: VisionRoutingDecision) -> dict[str, object]:
    return {
        "route": str(decision.route.value),
        "notice": decision.notice,
        "reason": decision.reason,
        "metadata": dict(decision.metadata),
    }
```

### Synthetic fail-closed `Run`
```python
from platform_contract.enums import AsyncTaskState, AgentResultStatus, ErrorCategory
from platform_contract.events import AgentResult, ErrorInfo

run = Run(
    run_id=run_id,
    status=AsyncTaskState.FAILED,
    turn_id=req.turn.turn_id,
    solution_id=req.solution.solution_id,
    result=AgentResult(
        result_id=run_id,
        turn_id=req.turn.turn_id,
        status=AgentResultStatus.FAILED,
        reply_type=ReplyType.TEXT,
        content=visible_text,
        error=ErrorInfo(
            category=ErrorCategory.CONTRACT_ERROR,
            code=decision.reason,
            message=decision.notice,
        ),
    ),
    metadata={"vision_decision": decision_dict, "vision_fail_closed": True},
)
```
