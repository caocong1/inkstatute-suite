# Phase 78.1 Context: Wire VisionRouter into Turn Runtime

## Goal
Close the v1.10 audit gap: `VisionRouter.decide()` is implemented and unit-tested but is never invoked by a production message/turn path. Wire the router into `DefaultRunRuntime.create_run()` so image-bearing turns route to `multimodal_main`, `vision_then_main`, or `fail_closed` with an InkStatute-owned notice, and text-only turns never invoke the vision model.

## Requirements
- **VIS-02**: On image-bearing turns, runtime routes: multimodal main if `supports_vision`; else vision→main mix when vision model configured; else fail-closed with InkStatute-owned notice (never silent image drop)
- **VIS-03**: Text-only turns never invoke the vision model; contract/audit evidence stays reference-first (no raw image bytes in contract logs)
- **VIS-04**: Vision/provider error paths pass through the assistant output boundary (no provider stack traces or gateway meta to ordinary users)

## Decisions (locked)

D-01: `DefaultRunRuntime.create_run()` shall invoke an injected `vision_resolver: Callable[[RunRequest], VisionRoutingDecision] | None` before `backend.submit_run()`.

D-02: `DefaultRunRuntime` shall accept an optional `vision_runner: BackendAdapter | None` to execute the vision model for the `vision_then_main` route (runtime-side mix, not backend-side).

D-03: On `VisionRoute.FAIL_CLOSED`, `DefaultRunRuntime` returns a synthetic `Run` with status `FAILED`, result content set to the InkStatute-owned fail-closed notice, and an `ErrorInfo` with category `CONTRACT_ERROR`; it must not call the main backend.

D-04: On `VisionRoute.MULTIMODAL_MAIN` or `VISION_THEN_MAIN`, `DefaultRunRuntime` attaches a JSON-serializable `vision_decision` record to `RunRequest.metadata` and proceeds to the backend/`vision_runner` path.

D-05: `VisionRoute.TEXT_ONLY` turns have `vision_decision` metadata attached but no `vision_runner` invocation.

D-06: `vision_resolver` is built per-service from `OperatorConfigStore` (when available), `VisionRouter`, and the built-in catalog `supports_vision` metadata. `vision_resolver` must be a pure closure; `platform-runtime` must not import `operator-config`.

D-07: `vision_then_main` is only chosen when both a complete vision pair (`vision_provider_id` + `vision_model_id`) is configured and a `vision_runner` backend is injected. If either is missing, the resolver shall treat `vision_pair_configured` as false, causing `fail_closed` on image-bearing turns.

D-08: `DefaultRunRuntime` with `vision_resolver=None` behaves exactly as before (backward-compatible; existing tests keep passing).

D-09: `platform-runtime` re-exports `VisionRoute`, `VisionRoutingDecision`, and `VisionRouter` from `platform_runtime/__init__.py` (already partially; ensure complete).

D-10: Fail-closed output must be passed through `DefaultAssistantOutputBoundary.apply()` before becoming the `Run.result.content` so no provider stack trace or backend meta reaches ordinary users.

## Claude's Discretion

- Location of the `vision_resolver` builder: prefer a new `inkstatute_operator_config.vision_resolver` module to avoid duplication between QQ and WeCom services; keep it in `operator-config`.
- Shape of the `vision_decision` JSON metadata: a dict with `route`, `reason`, `notice`, and `metadata` plus `vision_provider_id`/`vision_model_id` when applicable; keep it JSON-serializable.
- For `vision_then_main`, combine the vision result text with the original user text and clear `attachments` before the main backend call; do not embed raw image bytes in `Run` metadata.
- `OpenAIClientRunner` image support can be limited to `image_url` list entries for `attachments` with `kind="image"` or `mime_type` starting with `image/`.
- Service wiring may be split into `qqbot-service` and `wecom-service` modules; WeCom may not have a prior HTTP host and can use `WeComRuntimeIngress` composition only.
- Whether to add `supports_vision` to `AdapterCapabilitySet` and set `HermesBackendAdapter` to `False` to protect against backend mismatch. If added, `provider_model` can advertise `True` for vision models.
