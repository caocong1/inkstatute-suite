# Plan 41-01 — Cursor-Based Pagination, Time-Range/Dimension Filters, and Max Result Limits

## Goal

Add cursor-based pagination, time-range (`from`/`to`) and dimension (`user_id`, `channel`, `status`) filters, and enforced configurable max result limits to the `conversation-read-view` service via two new list endpoints (`/conversations`, `/tasks`). These are **additive** — existing single-resource routes (`/conversations/{id}`, `/tasks/{id}`, `/feedback`) are untouched.

This plan satisfies READVIEW-01:
- SC1: Operator can query `conversation-read-view` list endpoints with cursor-based pagination, time-range filters (`from`, `to`), and dimension filters (`user_id`, `channel`, `status`), with enforced max result limits preventing unbounded memory usage.

## Context

- The read model is built by `ContractLogReadModel.from_records(records)` at `services/conversation-read-view/src/conversation_read_view/read_model.py:44-127`. It indexes `conversations: dict[str, ConversationView]` and `tasks: dict[str, TaskView]`.
- The API entry point is `handle_get(path, query, read_model, feedback_queue=None)` at `api.py:11-58`. It routes by path prefix and applies `scrub_contract_payload` via `_with_contract_metadata` (`api.py:93-99`) on every 200 response.
- Existing routes: `/conversations/{id}` (single), `/tasks/{id}` (single, lookup by task_id/turn_id/trace_id), `/feedback?status=pending`. These shapes are frozen — Phase 41 must not alter them.
- The package has `dependencies = []` (`pyproject.toml:11`) and must stay dependency-light. Cursor encoding uses stdlib `base64` + `json` only.
- Privacy scrubbing (`privacy.py:51-62`) raises `ValueError` on forbidden keys. New endpoints route through the same scrub path.
- There is no feature flag for the read view — it is always available to operators (read-only derived view, not a runtime lane).
- Contract freeze (SAFETY-02, SAFETY-06): No changes to `packages/platform-contract/` or `packages/platform-runtime/protocols.py`.
