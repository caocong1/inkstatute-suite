# Phase 76 — UI Design Contract

> Visual and interaction contract for Provider Registry + Model Catalog SSR forms.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: 76-CONTEXT.md, REQUIREMENTS PROV-01..04, ROADMAP Phase 76,
> Phase 74 `/config/providers` + `/config/catalog` API sections,
> `packages/operator-config` ProviderDoc / CatalogSelectionDoc schemas,
> `services/admin-web-ui` Phase 75 channels SSR patterns (`channels.py`, `dashboard.py`).

## Design System

| Property | Value |
|----------|-------|
| Tool | none (stdlib SSR — not React/shadcn) |
| Preset | not applicable |
| Component library | none — Python `html.escape` string templates in `admin-web-ui` |
| Icon library | none |
| Font | `system-ui, sans-serif` (existing admin dashboard) |

**Stack lock (from research + existing UI):** Extend `services/admin-web-ui` stdlib `http.server` + escaped HTML + CSP. Do **not** introduce React, Vite, Next, or shadcn. Forms POST through admin-web-ui (CSRF) to `admin-console-api` `PUT /config/providers` (list body) and `PUT /config/catalog` (object body). Incremental SSR forms are in scope; Phase 78 owns complete CSRF SSR surface verification. Connection probe is a non-destructive POST that never mutates config and never logs response bodies or resolved secrets.

## Spacing Scale

Declared values (multiples of 4), inherited verbatim from Phase 75 / existing dashboard (`1rem ≈ 16px`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Checkbox/label gap, status badge padding, badge internal padding |
| sm | 8px | Compact field gaps, table cell padding (`0.4–0.6rem`), provider card stack gap |
| md | 16px | Default field stack gap, card padding (`1rem`), catalog model row padding |
| lg | 24px | Section padding (`1.5rem`), section bottom margin, probe result block margin |
| xl | 32px | Page main padding (`2rem`), header/nav horizontal padding |
| 2xl | 48px | Break between provider cards in the registry list |
| 3xl | 64px | Break between Provider Registry section and Model Catalog section (if combined page) |

Exceptions:
- Touch/click targets for checkboxes, submit, and probe buttons: minimum 44×44px hit area (padding around control), even if visual control is smaller.
- Vision capability badge: 4px horizontal/vertical padding, 8px gap from model name — no new spacing token.

## Typography

Exactly four sizes, two weights — aligned to existing admin dashboard (carried from Phase 75 contract):

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px (`1rem`) | 400 | 1.5 | Form help text, probe results, empty/error body, catalog model descriptions |
| Label | 14px (`0.875rem`) | 600 | 1.4 | Field labels, table keys, nav links, provider kind selector, badge text |
| Heading | 18px (`1.125rem`) | 600 | 1.2 | Section titles (`h2` / provider panel titles / catalog panel title) |
| Display | 20px (`1.25rem`) | 600 | 1.2 | Page brand header only (`InkStatute Admin Dashboard`) |

Do not introduce additional sizes or weights. Monospace for secret-ref values and API base URLs: inherit size from Body/Label; use `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace` for ref inputs, `api_base_url` inputs, and configured-value display only.

**Carried fix from Phase 75 UI-REVIEW:** ensure `.section h2`, provider panel `h3`, and catalog panel `h3` render at exactly `1.125rem` / weight 600 / line-height 1.2 (not browser-default 700). Apply the same style lock to new panel titles so the four-size/two-weight contract holds.

## Color

Preserve existing InkStatute Admin palette (60/30/10), inherited from Phase 75:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f5f5f5` | Page background |
| Secondary (30%) | `#ffffff` sections / `#fafafa` cards / `#1a1a2e` header / `#16213e` nav / `#0f3460` identity bar | Panels, nav chrome |
| Accent (10%) | `#aaccff` | Nav links, identity text, focus outline on form controls |
| Destructive | `#c0392b` | Error messages, invalid-ref banners, probe-fail status, `status-err` only |
| Success | `#27ae60` | Probe-success status, `status-ok`, "ref configured", vision-capable badge |
| Text | `#222222` | Body copy |
| Muted | `#888888` | Empty states, help captions, "ref not set", "no provider selected", vision-not-capable badge text |
| Key muted | `#555555` | Field labels / table keys |

Accent reserved for:
1. Top nav link color (and hover → `#ffffff`)
2. Identity bar secondary text
3. `:focus-visible` outline on inputs/checkboxes/selects/submit/probe buttons (2px solid `#aaccff`)

Accent is **not** for primary submit fill or probe button fill. Primary submit and probe buttons use header navy `#1a1a2e` background + `#ffffff` text (matches brand header; keeps accent scarce). Probe button may reuse `.btn-primary` styling; if a secondary visual is needed, use a bordered variant (`border: 1px solid #1a1a2e; background: #fff; color: #1a1a2e`) — never the accent fill.

**Carried fix from Phase 75 UI-REVIEW:** routine OFF / "not configured" / "no provider" states use muted `#888888` (`.empty`), not destructive `#c0392b`. Reserve `status-err` red for actual errors (probe failure, invalid ref, flag-off). Vision-not-capable badge uses muted text, not red.

## Layout Contract

Two single-purpose pages, each inside the existing `.main` → `.section` shell. Do not combine providers and catalog on one page (each page has one purpose).

### Provider Registry page (`/config/providers`)

```
[InkStatute Admin Dashboard header]
[nav … Channel Config · Provider Config · Model Catalog …]
[identity bar]
[main]
  [section: Provider Config]
    [flash: success | error]          ← only when present
    [probe result block]              ← only when a probe was run this request
    [restart notice]                  ← always visible muted help
    [provider card 1]
      kind selector (built-in vendor | custom)
      provider_id field
      enabled checkbox
      api_base_url field
      api_key_ref field
      model allowlist field (custom only; built-in shows preset note)
      probe button
    [provider card N …]
    [add provider control]            ← appends a blank card (client-side only; no JS — render blank card server-side via query flag or always-present trailing blank)
    [primary CTA: Save provider config]
[/main]
```

### Model Catalog page (`/config/catalog`)

```
[InkStatute Admin Dashboard header]
[nav … Channel Config · Provider Config · Model Catalog …]
[identity bar]
[main]
  [section: Model Catalog]
    [flash: success | error]          ← only when present
    [restart notice]                  ← always visible muted help
    [selection status line]           ← "Main model: …" or "No main model selected"
    [catalog panel.card: Main model selection]
      [model row 1] radio · model_id · vision badge · description
      [model row N …]
    [primary CTA: Save catalog selection]
[/main]
```

Rules:
- Single composition per page: provider registry page is only providers; catalog page is only model selection. No channel/vision forms (Phases 75 / 77).
- Cards are interaction containers for each provider form group and for the catalog model list (existing `.card` pattern) — allowed because they group editable fields.
- Max content width remains `1200px` centered (existing `.main`).
- No SPA client routing; full page reload after POST.
- "Add provider" must not require JavaScript. Preferred MVP approach: render a trailing blank "New provider" card always (or when a `?add=1` query param is present); saving the list persists all non-empty entries and drops blanks. Alternatively, a small "Add provider" submit button POSTs a marker field that re-renders with one extra blank card. Never rely on client-side DOM mutation.

## Provider Registry Interaction Contract (PROV-01, PROV-02)

### Built-in vendor vs custom provider

| Kind | Control | Fields operator edits | Preset behavior |
|------|---------|------------------------|-----------------|
| Built-in vendor | `<select>` of fixed vendor IDs (e.g. `openai`, `anthropic`, …) | `provider_id`, `enabled`, `api_key_ref` | `api_base_url` is shown read-only (vendor preset). Model allowlist shows a read-only note: "Built-in catalog provided — see Model Catalog." |
| Custom OpenAI-compatible | `<select>` option `custom` (or `kind="custom"`) | `provider_id`, `enabled`, `api_base_url`, `api_key_ref`, model allowlist | `api_base_url` is editable text. Model allowlist is a required editable text field (comma-separated model IDs). |

Display requirements:
1. The kind selector is a `<select>` with a visible `<label for=…>` "Provider kind".
2. When a built-in vendor is chosen, `api_base_url` renders as read-only text (not an input) showing the preset base URL. The operator only fills `api_key_ref`.
3. When `custom` is chosen, `api_base_url` becomes an editable `text` input and the model allowlist field appears.
4. `provider_id` is always editable text (operator-chosen stable ID). It is the key the catalog selection references.
5. Built-in vendor list is a fixed, code-defined tuple — not user-editable and not fetched from a remote registry (PROV-F01 live `/models` refresh is deferred).

### Provider list semantics

- The registry is a list (`tuple[ProviderDoc, ...]`). The SSR form renders one card per stored provider plus one trailing blank card for adding a new entry.
- On POST, the handler parses all `providers[N].*` fields. Entries with a blank `provider_id` are dropped (treated as "not added"). Entries with a non-blank `provider_id` are kept.
- Reordering is not required for MVP. If two entries share a `provider_id`, validation rejects the duplicate (server-side; UI shows Error — validation).
- Removing a provider = save the list without that entry (operator clears the `provider_id` field or the card is omitted). No explicit delete button with confirm dialog is required (per Copywriting: destructive confirmation = none).

### Connection probe (PROV-04)

| Concern | Contract |
|---------|----------|
| Trigger | A "Probe connection" submit button inside each provider card. Posts to `/config/providers/probe` with the provider index/id and CSRF token. |
| Mutates config? | No — probe is read-only against the provider endpoint; never calls `store.save`. |
| Fail-closed on missing refs | If `api_key_ref` is unset/blank, probe returns the "missing ref" fail copy without making any network call. Never resolves a ref from the environment on the UI side. |
| Logging | Probe result text is generic status only. Never logs the response body, resolved secret, or `Authorization` header. Server logs at most `provider_id` + success/fail boolean. |
| Result display | Probe result renders in a dedicated block above the provider list (or inline within the probed card) using `.status-ok` / `.status-err` + the exact copy strings. Result is ephemeral (shown on the re-rendered page after POST; not persisted). |
| RBAC | ADMIN/OPERATOR only; lawyer/viewer denied (match API 403). |
| Flag gate | If `operator_config_enabled` is OFF, probe button is disabled and Error — flag off is shown. Probe does not bypass the flag gate. |
| Vision probe | Probe for the vision model is deferred to Phase 77 (vision config is Phase 77). This phase probes the main provider endpoint only. |

## Model Catalog Interaction Contract (PROV-03)

### Built-in catalog display

- The catalog page shows a read-only list of built-in model entries. Each row has:
  - A radio button (`name="model_id"`, `value="{model_id}"`) bound to the current `catalog.model_id` selection.
  - The `model_id` as the row label (monospace or label weight).
  - A **vision capability badge**: "Vision: supported" (`.status-ok` green) when `supports_vision` is true; "Vision: not supported" (muted `.empty`) when false.
  - An optional short description (Body text) if the catalog entry provides one.
- The built-in catalog content is code-defined (a fixed tuple of model entries with `provider_id`, `model_id`, `supports_vision`, and optional description). It is not fetched from a remote `/models` endpoint (PROV-F01 deferred).
- `supports_vision` metadata is **required** on every catalog entry (boolean). This is the Phase 77 contract dependency — the UI must render it per row so operators can see vision capability before Phase 77 routing ships.

### Catalog selection

| Field | Control | Editable |
|-------|---------|----------|
| `catalog.provider_id` | Hidden or `<select>` of provider IDs from the registry | Yes (select if multiple providers; hidden if only one) |
| `catalog.model_id` | Radio button list from built-in catalog | Yes |
| Current selection status | Read-only text line | No |

- The selection status line shows "Main model: `{provider_id}` / `{model_id}`" when set, or "No main model selected" when unset.
- When no providers are configured in the registry, the catalog page shows a muted note: "Add a provider in Provider Config before selecting a main model." The radio list may still render but the save button is disabled (or save is rejected server-side with Error — validation).
- The catalog form POSTs an object body matching Phase 74 `PUT /config/catalog` (`{"provider_id": "...", "model_id": "..."}`).

### Submit payload shape

- Providers POST handler builds a list body matching Phase 74 `PUT /config/providers` (list of provider objects). Prefer unwrapped list value. Do not send raw secret keys (`api_key`, `token`, `password`).
- Catalog POST handler builds an object body matching Phase 74 `PUT /config/catalog`. Do not send raw secret keys.

## Form Field Contract (PROV-01, PROV-02, PROV-04)

### Shared field UX (carried from Phase 75)

| Concern | Contract |
|---------|----------|
| Input type for `api_key_ref` | `text` (not `password`) — operators edit **references**, not secret material |
| Autocomplete | `autocomplete="off"` on all ref fields and `api_base_url` |
| Placeholder examples | `api_key_ref`: `env:INKSTATUTE_PROVIDER_OPENAI_KEY`; `api_base_url`: `https://api.openai.com/v1` |
| Empty value | Submit as omit/null → store `None`; UI shows "Not set" |
| Configured value | Show the **ref string only** (e.g. `env:FOO`); never a resolved secret |
| Status adjacent to field | "Configured (ref stored)" or "Not set" |
| Validation | Server: `normalize_config_secret_ref` shapes only + `validate_document`. On reject, show Error — validation copy; **do not echo** the rejected raw value if it looks like a planted secret (API already avoids echoing) |
| CSRF | Hidden `csrf_token` field required on every POST (providers save, catalog save, probe). Phase 78 verifies full surface; Phase 76 forms that mutate or probe must still include CSRF when present |
| RBAC | ADMIN/OPERATOR only; lawyer/viewer see error or are blocked before form (match API 403) |
| Flag gate | If `operator_config_enabled` is false, render form read-only or disable submit/probe and show Error — flag off |

## Accessibility & Safety

- Every input, select, and checkbox has a visible `<label for=…>` with human text (not raw snake_case). Carried fix from Phase 75 UI-REVIEW: put the label text inside the `<label>` element so screen readers get an accessible name.
- Radio rows use `<label class="field-check">` wrapping the radio + model name + badge so the whole row is a single clickable target with an accessible name.
- Status uses words ("supported" / "not supported" / "succeeded" / "failed") plus color class — never color alone.
- CSP remains strict (existing server CSP `default-src 'self'; script-src 'self'; style-src 'self'`); no inline scripts; no `innerHTML` of untrusted data — all dynamic strings through `html.escape`. The "add provider" interaction must not require JavaScript.
- Output boundary (`AdminUiBoundary`) applies to any free-text API messages before render.
- Never render resolved secrets, `.env` file contents, store filesystem paths, probe response bodies, or `Authorization` headers.
- Probe result copy is generic; it never includes HTTP status codes, response snippets, or resolved key material.
- Do not claim live WeCom/QQ acceptance from saving provider or catalog config.
