# Plan 02: Registration with JSON Schema Tool Schemas + Admission Review

## Objective

Add `McpRegistryAdminPort` (write Protocol) and `InMemoryMcpRegistryAdmin` (implementation) to the mcp-registry package, supporting registration with JSON Schema tool schemas, semantic versioning, soft-delete, and admission review. No auto-execution occurs on registration — the `mcp` SDK is never invoked during registration. This satisfies MCPREG-02.

  <behavior>
    - McpServerRegistrationSpec is a frozen dataclass with: server_id, name, transport, capability_refs, secret_refs, tool_schemas (list[dict]), metadata (dict), version (str = "1.0.0")
    - McpRegistryAdminPort Protocol has 4 write methods:
      - register_server(spec: McpServerRegistrationSpec) -> McpServerDescriptor: validates tool schemas, creates record with active=False, admission_status="pending", returns descriptor
      - update_version(server_id: str, version: str, tool_schemas: list[dict] | None = None) -> McpServerDescriptor: validates new version is greater than current, bumps version, optionally updates tool schemas
      - deactivate_server(server_id: str) -> McpServerDescriptor: sets active=False (soft-delete), returns descriptor
      - approve_server(server_id: str) -> McpServerDescriptor: sets active=True, admission_status="approved", returns descriptor
    - InMemoryMcpRegistryAdmin implements McpRegistryAdminPort, backed by the same InMemoryMcpRegistry store (shared _records dict)
    - register_server validates tool schemas via validate_tool_schemas; raises ValueError if validation fails
    - register_server does NOT invoke the mcp SDK — no auto-execution
    - update_version validates that new version > current version (semantic version string comparison)
    - deactivate_server marks active=False but does NOT remove the record
    - approve_server only works on servers with admission_status="pending"; raises ValueError if already approved or not found
    - All admin methods return McpServerDescriptor (with metadata including version, active, admission_status)
    - The mcp SDK is lazy-imported only inside a _validate_transport method (using importlib.import_module) which is optional and never called during registration
  </behavior>
