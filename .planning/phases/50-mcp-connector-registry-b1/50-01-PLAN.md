  <behavior>
    - McpServerPage is a frozen dataclass with: items: list[McpServerDescriptor], next_cursor: str | None = None, has_more: bool = False
    - McpServerRecord is an internal mutable dataclass with: server_id, name, transport, capability_refs, secret_refs, metadata, active: bool, version: str, admission_status: str, registered_at: str, to_descriptor() -> McpServerDescriptor
    - McpRegistryPort Protocol has 3 read-only methods: list_servers(cursor, limit) -> McpServerPage, get_server(server_id) -> McpServerDescriptor | None, search(query, cursor, limit) -> McpServerPage
    - InMemoryMcpRegistry implements McpRegistryPort:
      - __init__ accepts optional list of McpServerRecord (for pre-loading)
      - list_servers: filters active=True, sorts by server_id, applies cursor pagination, returns McpServerPage
      - get_server: returns descriptor for any server (active or inactive), or None
      - search: filters active=True, matches query against name/capability_refs/server_id (case-insensitive substring), applies cursor pagination
      - Cursor is decoded to last server_id; page starts after that server_id
      - next_cursor is set only when has_more is True and page is non-empty
    - No write methods on McpRegistryPort (structural read-only enforcement)
    - to_descriptor() on McpServerRecord produces a McpServerDescriptor with metadata including "version", "active", and "admission_status" keys
  </behavior>
