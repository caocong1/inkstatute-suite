# Plan 03: Router Tool-Resolution Join

## Objective

Add a pure `resolve_tool_refs` function to the router-service package that joins skill `required_tool_refs` → MCP server `capability_refs` at read time, producing a `ToolResolutionMap` without modifying frozen `RouteDecision` or `NeutralSkillDescriptor` schemas. This satisfies success criterion 3.

  <behavior>
    - ToolResolutionMap is a frozen dataclass with: skill_id: str, required_tool_refs: list[str], resolved_servers: list[McpServerDescriptor], unresolved_refs: list[str]
    - resolve_tool_refs(skill: NeutralSkillDescriptor, mcp_registry: McpRegistryPort) -> ToolResolutionMap:
      - For each tool_ref in skill.required_tool_refs, search the MCP registry for servers whose capability_refs contain tool_ref
      - Uses mcp_registry.search(tool_ref) to find matching servers
      - Collects resolved servers (deduplicated by server_id)
      - Collects unresolved_refs for tool_refs with no matching server
      - Does NOT modify skill or RouteDecision
    - resolve_all_tool_refs(skills: list[NeutralSkillDescriptor], mcp_registry: McpRegistryPort) -> list[ToolResolutionMap]:
      - Calls resolve_tool_refs for each skill
      - Returns list of ToolResolutionMap
    - The function is pure — no side effects, no mutation of inputs
    - TYPE_CHECKING import for McpRegistryPort (avoids hard dependency on mcp-registry at runtime)
    - __init__.py exports resolve_tool_refs, resolve_all_tool_refs, ToolResolutionMap
  </behavior>

       - Define `ToolResolutionMap` frozen dataclass (skill_id, required_tool_refs, resolved_servers, unresolved_refs)
