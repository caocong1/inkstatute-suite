### Task 1: 凭据命令面（Rust）

- **type:** code
- **files:** apps/desktop/src-tauri/src/commands/credentials.rs, apps/desktop/src-tauri/src/lib.rs
- **action:** 暴露设置面板需要的凭据命令（基于 Phase 123-01 的 `credentials.rs`）：

```rust
#[derive(Serialize)]
pub struct ProviderInfo {
    pub id: String,            // "deepseek"
    pub display_name: String,  // "DeepSeek"
    pub env_var: String,       // "DEEPSEEK_API_KEY"
    pub has_key: bool,         // 只返回有无，不返回内容
}

#[tauri::command] pub fn list_providers() -> Vec<ProviderInfo>;
#[tauri::command] pub fn get_active_provider() -> Result<String, String>;
#[tauri::command] pub fn set_active_provider(id: String) -> Result<(), String>;
#[tauri::command] pub fn set_provider_key(id: String, key: String) -> Result<(), String>;
#[tauri::command] pub fn clear_provider_key(id: String) -> Result<(), String>;
/// 用当前配置起一个临时引擎跑一次极短 prompt，验证密钥可用
#[tauri::command] pub async fn test_provider(id: String) -> Result<String, String>;
```

**安全约束：**
- **没有 `get_provider_key`**——密钥只写不读，UI 永远只显示"已配置/未配置"。
- `set_provider_key` 的入参不得进日志；函数内不得 `println!`/`dbg!`。
- `test_provider` 的错误文案走 Phase 124 的中文映射；原始错误只进本地日志。
- 活动供应商存在普通配置文件 `<app_root>/settings.json`（**只存 id，不存密钥**）。

- **verify:**
  - `cargo check && cargo test`
  - 单元测试：`list_providers()` 返回 9 项且 `has_key` 与凭据库状态一致
  - `grep -rn 'get_provider_key\|read_key' src/commands/credentials.rs` 无输出
- **acceptance_criteria:** 密钥只写不读；9 个供应商齐全
