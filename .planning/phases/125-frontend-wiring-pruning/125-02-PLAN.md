### Task 2: 重写 useEventStream.ts

- **type:** code
- **files:** apps/desktop/src/hooks/useEventStream.ts
- **action:** **保持对外接口不变**，把内部从 `createEventStream(gateway...)` 换成 Tauri 订阅：

```ts
export interface UseEventStreamReturn {
  state: () => RenderState;
  isStreaming: () => boolean;
  error: () => Error | null;
  reconnect: () => void;
}

export function useEventStream(conversationId: Accessor<string | null>): UseEventStreamReturn;
```

实现要点：

1. 用 `createStore` 或 signal 持有 `RenderState`，初值取 ui-core 导出的 `initialState`。
2. `createEffect(on(conversationId, ...))`：切换对话时重置 state 并重新订阅。
3. 订阅回调里：
   ```ts
   const next = reduceEvent(current(), envelope);   // ui-core 导出的纯函数
   setState(next);
   ```
   **函数名以 ui-core `src/index.ts` 实际导出为准**（可能是 `reduce` / `applyEvent` / `reduceEvent`，
   执行时先 `grep -n "export" packages/ui-core/src/index.ts | grep -i reduc` 确认）。
4. **按 `run_id` 过滤**：只处理属于当前对话的信封，其它丢弃。
5. `isStreaming` 由 `state().runStatus === "running"` 派生。
6. `onCleanup` 里调用 `UnlistenFn` 解除订阅——**必须解除，否则切对话会重复累积**。
7. `reconnect()` = 重置 state + 重新订阅。

- **verify:**
  - `bunx tsc --noEmit`
  - 测试：mock `@tauri-apps/api/event` 的 `listen`，推入 3 条信封，断言 `state().messages` 正确
  - 测试：切换 conversationId 后旧订阅被解除（断言 unlisten 被调用）
- **acceptance_criteria:** 接口不变、订阅可解除、按 run_id 过滤

### Task 3: 改造 ConversationContext / SessionContext

- **type:** code
- **files:** apps/desktop/src/contexts/ConversationContext.tsx, apps/desktop/src/contexts/SessionContext.tsx
- **action:**

     保留原有 API 形状（`conversations()`、`activeId()`、`select()`、`refresh()` 等），
