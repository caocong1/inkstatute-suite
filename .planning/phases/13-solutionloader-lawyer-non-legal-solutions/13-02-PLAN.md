# Phase 13 Plan 02: Solutions/Lawfirm Neutral Manifest + Hermes Materializer

**Backend-neutral `lawfirm` solution manifest + sanitizing `materialize_for("hermes")` that produces a sanitized profile bundle with explicit side-effects.**

## Objective

Build the first solution pack: `solutions/lawfirm/`. The manifest is **backend-neutral** (north-star §4.3) — the Hermes profile is *derived* via the materializer, never the source of truth. The materializer produces a sanitized profile bundle (no secrets, no customer data, no raw legal payloads) and declares its side-effects so callers can assert "no undeclared side effects" per the north-star invariant.

## Acceptance Criteria

- `solutions/lawfirm/manifest.json` validates against the loader's validator with **zero Issues**.
- `manifest.json` contains `solution_id="lawfirm"`, `version="1.0.0"`, `manifest_ref="solutions/lawfirm/manifest.json"`, `metadata.materialize_targets=["hermes"]`, and `industry_context={"legal_domain": {...}}`. Zero top-level keys matching the validator's reject list.
- `manifest.skills[]` uses neutral descriptors only: `name`, `description`, `intent`, `required_tools[]`, `risk_level`. NO `routing_hints` (Hermes-specific) or `SKILL.md` references.
- `manifest.mcp[]` uses neutral refs: `name`, `transport`, `secret_ref` (template name only, not values).
- `manifest.secret_templates[]` lists secret **names** only (`HERMES_API_KEY`, `LAW_PAYMENT_TOKEN`); no values.
- `manifest.output_policy` is an overlay (`{allow_legal_conclusions: true, require_citation: true, redact_pii: true}`); it does NOT redefine platform output rules.
- `manifest.eval[]` lists paths to fixture files (e.g., `"fixtures/case_qa_eval.json"`) which are placeholders in this milestone (the platform does not yet execute eval runs; eval is a forward-declared field).
- `LawfirmHermesMaterializer.materialize(solution, output_dir)` writes exactly four files into `output_dir/profiles/lawfirm/`:
  1. `SKILL.md.template` — neutral skill template with placeholders (`{{skill.name}}`, `{{skill.description}}`).
  2. `SAMPLE_PERSONA.md` — placeholder SOUL.md text that does NOT contain customer-specific guidance.
  3. `tools.json` — neutral MCP tool descriptors from `manifest.mcp[]`.
  4. `SANITIZATION_REPORT.md` — declares `refused_items=[]`, `stripped_keys=[]`, `redacted_paths=[]`, `bundle_hash=<sha256 prefix>`.
- `LawfirmHermesMaterializer.side_effects()` returns `MaterializerSideEffects(backend_id="hermes", declared_output_dir_relative="profiles/<solution_id>", side_effect_kinds=("write_dir",), notes="...")`.
- `DefaultSolutionLoader.materialize_for(solution, "hermes", output_dir)` returns `(empty_issues, bundle)` where `bundle.bundle_ref == output_dir / "profiles/lawfirm"` and that path resolves inside `output_dir`.
- Sanitization refuses: secret-like strings (sk-, bearer ≥16 chars, hex blobs ≥32 chars), raw_payload keys, callback-body references, log file refs, .db / .sqlite refs, customer doc filenames (case_*.docx, contract_*.pdf), confidential_artifact refs. Each refusal is captured as an Issue and aborts the bundle (does NOT partially write).
- `solutions/lawfirm/tests/test_lawfirm_solution.py` contains ≥ 12 tests covering: neutral manifest validation, zero Issues on a clean bundle, sanitization refusal cases, side-effect declaration, bundle_ref inside output_dir, dist/fixture path round-trip.
- `python scripts/run_v2_gates.py` continues to pass with the new package (no existing gate regresses).
