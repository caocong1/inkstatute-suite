# Plan 01: WritableSkillRegistry Core with Immutable Versioning

## Objective

Create a new `write.py` module in the skill-registry package implementing `SkillRegistryWritePort` Protocol and `WritableSkillRegistry` class with CRUD operations (create, update, deactivate), immutable versioning (every write creates a new version), rollback to any prior version, human-review two-person rule on every write path, and per-tenant skill namespaces. This is a new module — the frozen `registry.py` read-only module remains untouched.

    - `WritableSkillRegistry` implements `SkillRegistryWritePort`:
      - `__init__()` — empty in-memory store: `_versions: dict[str, list[SkillVersion]]` keyed by `"{tenant_id}/{name}"`, `_pending: dict[str, WriteRequest]` keyed by request_id, `_counter: int` for version numbering
      - `submit_create(tenant_id, name, description, requested_by, requested_at, input_schema_ref, output_schema_ref, required_tool_refs, metadata) -> WriteRequest` — creates pending request with operation="create"; raises error if skill already exists and is active
      - `submit_update(tenant_id, skill_id, requested_by, requested_at, description, input_schema_ref, output_schema_ref, required_tool_refs, metadata) -> WriteRequest` — creates pending request with operation="update"; raises error if skill not found or deactivated
      - `submit_deactivate(tenant_id, skill_id, requested_by, requested_at) -> WriteRequest` — creates pending request with operation="deactivate"; raises error if skill not found or already deactivated
      - `submit_rollback(tenant_id, skill_id, target_version, requested_by, requested_at) -> WriteRequest` — creates pending request with operation="rollback"; raises error if skill or target version not found
      - `approve_write(request_id, reviewer, reviewed_at, comment) -> SkillVersion` — commits the pending write:
        - Validates reviewer != requested_by (two-person rule); raises SkillRegistryWriteError on self-approval
        - Creates a new SkillVersion with incrementing version number
        - For create: version=1, status="active"
        - For update: new version with updated fields, status="active"
        - For deactivate: new version with status="deactivated"
        - For rollback: new version copying content from target_version, status="active"
        - Attaches HumanReviewRecord to the new version
        - Marks WriteRequest as "approved" and "committed"
        - Returns the new SkillVersion
      - `reject_write(request_id, reviewer, reviewed_at, comment) -> WriteRequest` — marks request as rejected with HumanReviewRecord
      - `list_versions(tenant_id, skill_id) -> list[SkillVersion]` — returns all versions for a skill; raises error on cross-tenant access
      - `get_version(tenant_id, skill_id, version) -> SkillVersion | None` — returns specific version
      - `get_current(tenant_id, skill_id) -> SkillVersion | None` — returns latest version
      - `list_skills(tenant_id) -> list[SkillVersion]` — returns current active skills for tenant only
      - `list_pending_writes(tenant_id) -> list[WriteRequest]` — returns pending writes for tenant
    - Per-tenant namespace enforcement: all methods take `tenant_id` and validate it matches the skill's tenant; cross-tenant access raises `SkillRegistryWriteError`
    - `skill_id` is constructed as `"{tenant_id}/{name}"` for namespacing
    - `__init__.py` exports: `SkillRegistryWritePort`, `WritableSkillRegistry`, `SkillVersion`, `HumanReviewRecord`, `WriteRequest`, `SkillRegistryWriteError`
