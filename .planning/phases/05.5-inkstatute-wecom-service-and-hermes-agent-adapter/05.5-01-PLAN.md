<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| WeCom callback -> service normalization | Callback payloads are untrusted and may contain secrets, retries, media refs, or malformed fields. |
| Backend result -> ordinary WeCom user | Backend-originated text may contain Hermes operator UI or internal details. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05.5-01-S | Spoofing | callback signature | mitigate | Verify sorted SHA1 callback signatures in protocol helper fixtures. |
| T-05.5-01-T | Tampering | repeated callbacks | mitigate | Compute deterministic idempotency keys and test duplicate collapse inputs. |
| T-05.5-01-I | Information Disclosure | callback/output payloads | mitigate | Reject exact `raw_payload`, use `raw_payload_ref`, block internal paths/tokens/profile/runtime details. |
| T-05.5-01-R | Repudiation | output policy decisions | mitigate | Return privacy-safe audit metadata for allow/rewrite/block decisions. |
| T-05.5-01-D | Denial of Service | ACK path | mitigate | `ack_response()` is independent of agent execution and returns `success` immediately. |
</threat_model>
