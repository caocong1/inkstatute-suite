  2. 实现：

```rust
/// 供应商标识。与 acp.cordis.yml 的 providers 键、与 apiKeyEnv 一一对应。
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub enum Provider { DeepSeek, OpenAI, Anthropic, Google, Groq, XAI, Zhipu, Qwen, Custom }

impl Provider {
    /// "deepseek" / "openai" / ...
    pub fn id(&self) -> &'static str;
    /// "DEEPSEEK_API_KEY" / "OPENAI_API_KEY" / ...
    pub fn env_var(&self) -> &'static str;
    /// 中文显示名，供设置界面用
    pub fn display_name(&self) -> &'static str;
    pub fn from_id(id: &str) -> Option<Self>;
    pub fn all() -> &'static [Provider];
}

/// OS 凭据库读写。service 名固定 "com.sorawatcher.inkstatute"，account 名为 provider.id()。
pub fn store_key(p: Provider, key: &str) -> Result<(), EngineError>;
pub fn load_key(p: Provider) -> Result<Option<String>, EngineError>;
pub fn delete_key(p: Provider) -> Result<(), EngineError>;
/// 只返回"有没有"，不返回内容 —— 供 UI 显示配置状态
pub fn has_key(p: Provider) -> bool;

/// 构建子进程环境。继承当前进程环境，叠加 DSH_HOME 与当前供应商的 API key 变量。
/// 返回值只在 spawn 调用点存活，不得写入任何文件或日志。
pub fn build_engine_env(active: Provider, dsh_home: &Path) -> Result<Vec<(String, String)>, EngineError>;
```

  3. **安全约束，必须在代码中落实**：
     - `Provider` 与凭据相关的所有类型**不得实现 `Debug` 输出密钥内容**。若 struct 持有密钥，手写 `Debug` 打印 `"<redacted>"`。
     - `build_engine_env` 的返回值不得被 `tracing`/`log` 记录。在函数文档注释中写明。
     - 提供 `pub fn redact(s: &str) -> String`，把疑似密钥（长度 ≥ 16 的 `sk-`/`gsk_`/`xai-` 前缀串）替换为 `"****"`，供错误信息使用。

- **verify:**
  - 单元测试：`Provider::from_id("deepseek")` 往返一致；`all()` 覆盖 9 个
  - 单元测试：`env_var()` 与 `engines/acp.cordis.yml` 中的 `apiKeyEnv` 完全一致（测试读取该 yml 并逐项比对）
  - 单元测试：`redact("sk-abcdefghijklmnop")` 返回不含原串
  - 单元测试：`build_engine_env` 结果含 `DSH_HOME` 与目标 env var
  - `grep -rn 'println!\|dbg!\|log::.*key\|tracing.*key' src/engine/credentials.rs` 无泄漏点
- **acceptance_criteria:**

### Task 2: src/engine/supervisor.rs — 子进程生命周期

- **type:** code
- **files:** apps/desktop/src-tauri/src/engine/supervisor.rs
- **action:** 实现（行为参照 `apps/flutter_app/lib/engine/dsh_process.dart`，只读参照，勿改该文件）：

```rust
pub struct EngineSupervisor { /* 私有 */ }

pub struct SpawnConfig {
    pub engine_dir: PathBuf,
    pub node_bin: PathBuf,
    pub dsh_home: PathBuf,
    pub provider: Provider,
}

#[derive(Debug)]
pub enum ShutdownResult {
    CleanExit { code: i32 },
    ForceKilled { pid: u32 },
    NotRunning,
}

impl EngineSupervisor {
    /// spawn 引擎子进程，返回已连通 stdin/stdout 的 supervisor。
    /// 命令行参数中不含任何密钥。
    pub async fn spawn(cfg: SpawnConfig) -> Result<Self, EngineError>;

    pub fn pid(&self) -> Option<u32>;
    pub fn is_alive(&self) -> bool;

    /// initialize 握手健康探针。断言 protocolVersion == 1。
    pub async fn health_probe(&self, timeout: Duration) -> Result<HealthReport, EngineError>;

    /// 优雅关停：关 stdin → 等退出(10s) → SIGTERM → 等(5s) → SIGKILL。
    pub async fn shutdown(&mut self) -> Result<ShutdownResult, EngineError>;

    /// 断言进程已不在系统进程表中。
    pub async fn assert_no_orphans(&self) -> Result<bool, EngineError>;

    /// shutdown + assert_no_orphans
    pub async fn dispose(&mut self) -> Result<ShutdownResult, EngineError>;

    /// 最近 N 行 stderr（仅进本地日志，永不回显 UI）
    pub fn stderr_tail(&self) -> Vec<String>;
}

pub struct HealthReport {
    pub protocol_version: u32,
    pub agent_name: String,
    pub agent_version: String,
    pub elapsed_ms: u128,
}
```

**实现要点，逐条落实：**

1. spawn 命令：
   ```
   <node_bin> <engine_dir>/node_modules/@deepseek-ai/dsh-acp-demo/lib/bin.js
              --config <engine_dir>/acp.cordis.yml
   ```
   - `current_dir(engine_dir)`
   - `envs(build_engine_env(cfg.provider, &cfg.dsh_home)?)`
   - **密钥绝不作为命令行参数**
   - Windows 上设 `CREATE_NO_WINDOW`（`std::os::windows::process::CommandExt::creation_flags(0x0800_0000)`），避免弹出黑窗

2. stderr：独立 task 按行读入环形缓冲（容量 200 行）。**永不进入返回给 UI 的错误文案。**

3. stdout：交给 123-02 的 ACP 客户端，本模块只负责把 `ChildStdout`/`ChildStdin` 交出去。

4. `assert_no_orphans`：
   - Windows：`tasklist /FI "PID eq <pid>" /FO CSV /NH`，
     按行 trim，过滤空行与以 `INFO:` 开头的行，**剩余非空 CSV 行为 0 才算无孤儿**。
     绝不用 `output.contains(&pid.to_string())`（死 PID `123` 会误匹配活 PID `1234`）。
   - Unix：`ps -p <pid>`，`exit_code != 0` 即无孤儿。

5. `shutdown` 幂等：第二次调用返回 `NotRunning`，不 panic、不重复等待。

6. Drop 保护：实现 `Drop`，若进程仍存活则同步 kill（best-effort），保证 app 崩溃路径也不留孤儿。

- **verify:**
  - 单元测试：用一个假 node 脚本（sleep 后退出）验证 `shutdown` 走 CleanExit 路径
  - 单元测试：用一个忽略 stdin 关闭的假脚本验证走 ForceKilled 路径
  - 单元测试：`shutdown` 调用两次第二次返回 `NotRunning`
  - 单元测试：`assert_no_orphans` 在进程退出后返回 true
  - `grep -n 'contains(&pid' src/engine/supervisor.rs` 无输出（防裸匹配回归）
- **acceptance_criteria:**
  - 所有退出路径都保证无孤儿
  - 命令行参数不含密钥
  - Windows 无黑窗
