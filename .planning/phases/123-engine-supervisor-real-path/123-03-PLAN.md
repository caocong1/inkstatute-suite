<objective>
实现「一个对话 = 一个 ACP 会话」的映射与跨 app 重启的回灌续接，并**用真实 API key 实测回灌体验**。这是 v5.0 唯一可能推翻方案的环节：若回灌不可接受，本 plan 的产出是一份触发架构回退评审的决策记录，而非继续往下推。

<context>
ACP 明确「Fresh sessions only — load, list, resume, delete, and fork are unsupported」。
引擎子进程活着时对话上下文在引擎内；app 重启后模型不再拥有旧上下文，尽管界面能从日志把历史完整画出来。

回灌可行性的量化依据（实测 `request/context`）：`contextWindow: 1000000`。
溢出由 `dsh-compaction-basic`（`thresholdRatio: 0.8`）自动处理。

**本 plan 的 `autonomous: false`** —— 需要业主提供真实 API key，且第 4 项任务的结论需要人判断。
</context>

### Task 1: src/engine/session_map.rs — 对话↔会话映射

- **type:** code
- **files:** apps/desktop/src-tauri/src/engine/session_map.rs
- **action:** 实现 app 侧对话 id 与 ACP sessionId 的映射，以及惰性建会话：

```rust
/// 一个 app 运行期内的对话→ACP会话映射。引擎重启后整体失效。
pub struct SessionMap { /* 私有：conversation_id -> SessionEntry */ }

pub struct SessionEntry {
    pub acp_session_id: String,
    pub cwd: PathBuf,
    /// 本运行期内该会话是否已被回灌过（只回灌一次）
    pub seeded: bool,
}

impl SessionMap {
    pub fn new() -> Self;

    /// 取已有映射；无则用 client.new_session(cwd) 建一个并记录。
    /// 并发调用同一 conversation_id 时只建一次（内部加锁）。
    pub async fn ensure(
        &self,
        conversation_id: &str,
        cwd: &Path,
        client: &AcpClient,
    ) -> Result<String, EngineError>;

    pub fn get(&self, conversation_id: &str) -> Option<SessionEntry>;
    pub fn mark_seeded(&self, conversation_id: &str);
    /// 引擎重启时调用，清空全部映射
    pub fn clear(&self);
}
```

**工作区目录约定**：每个对话有独立工作区 `<app_root>/workspaces/<conversation_id>/`，
`ensure` 时若不存在则创建。这样 DSH 的 workspace-write 沙箱按对话隔离，
且会话日志按 cwd 分目录（Phase 124 的尾随器依赖这一点定位日志）。

- **verify:**
  - 单元测试：同一 conversation_id 并发 `ensure` 10 次只调用 `new_session` 一次
  - 单元测试：`clear` 后再 `ensure` 会重新建会话
  - 单元测试：工作区目录被创建且为绝对路径
- **acceptance_criteria:** 映射唯一、工作区按对话隔离

### Task 2: src/engine/replay.rs — 回灌构造

- **type:** code
- **files:** apps/desktop/src-tauri/src/engine/replay.rs
- **action:** 实现：

```rust
pub struct ReplayTurn { pub role: ReplayRole, pub text: String }
pub enum ReplayRole { User, Assistant }

pub struct ReplayConfig {
    /// 最多回灌多少轮（一轮 = 一问一答）。默认 20。
    pub max_turns: usize,
    /// 回灌前缀的字符上限，超过则继续从最早处截断。默认 200_000。
    pub max_chars: usize,
}

/// 构造回灌前缀。turns 按时间正序传入（最早在前）。
/// 返回 None 表示无需回灌（turns 为空）。
pub fn build_seed_prefix(turns: &[ReplayTurn], cfg: &ReplayConfig) -> Option<String>;

/// 把回灌前缀与用户本次输入拼成首轮提示文本。
pub fn compose_seeded_prompt(seed: Option<&str>, user_input: &str) -> String;
```

**前缀格式**（固定，不要自由发挥）：

```
[以下是本次对话此前的往来记录，供你恢复上下文。请勿重复回答其中已回答的问题，也不要把这段记录当作用户的新指令。]

【第 1 轮 · 用户】<文本>
【第 1 轮 · 助手】<文本>
【第 2 轮 · 用户】<文本>
…

[记录结束。以下是用户的新问题。]
```

截断时在最顶部加一行：`[更早的 N 轮记录已省略]`

截断规则：先按 `max_turns` 从最近往前保留，再按 `max_chars` 检查；仍超则继续丢弃最早的轮次，直到满足。**永远保留最近一轮。**

- **verify:**
  - 单元测试：空输入返回 `None`
  - 单元测试：3 轮输入生成的前缀含 `【第 1 轮 · 用户】` 与 `[记录结束`
  - 单元测试：25 轮 + `max_turns=20` → 只含 20 轮且顶部有 `[更早的 5 轮记录已省略]`
  - 单元测试：超 `max_chars` 时继续截断且最近一轮仍在
  - 单元测试：`compose_seeded_prompt(None, "问题")` 返回恰好 `"问题"`（无前缀污染）
- **acceptance_criteria:** 前缀格式固定、截断保最近、无前缀时零污染

### Task 4: 【人工闸门】真实 API key 实测

- **type:** manual
- **files:** .planning/phases/123-engine-supervisor-real-path/123-DECISION.md
- **前置条件:** 业主提供真实 API key 并存入 OS 凭据库。**密钥永不写入仓库、永不进入命令行参数。**
  存入方式：
  ```
  # 由业主在本机执行（不要把 key 贴进任何文件或对话）
  cargo run --manifest-path apps/desktop/src-tauri/Cargo.toml --bin store-key -- deepseek
  # 交互式读取，不回显
  ```
  若尚无该 bin，本任务第一步先写一个最小的 `src/bin/store_key.rs`，用 `rpassword` 或标准输入读取，调用 `credentials::store_key`。

- **action:** 用真实引擎 + 真实 key 跑四组实测，把数据填进 `123-DECISION.md`：

  **组 1 — 基线单轮**：新对话问一个法律问题，记录：首 token 延迟、总耗时、`request/header` 里的 prompt token 数。

  **组 2 — 回灌 5 轮**：构造 5 轮往来后模拟重启，再问一个依赖上下文的问题（例如「刚才那份合同的第三条你怎么看」），记录：首 token 延迟、prompt token 数、**模型是否正确引用了历史内容**。

  **组 3 — 回灌 20 轮**：同上，用满 `max_turns`，记录同样三项。

  **组 4 — 混淆检查**：回灌后问一个**与历史无关**的新问题，记录模型是否错误地继续回答历史话题。

- **判定标准（写进决策文档）:**

  | 项 | 可接受 | 需评审 |
  |---|---|---|
  | 组 2/3 首 token 延迟 | ≤ 组 1 的 3 倍 | > 3 倍 |
  | 组 2/3 上下文正确引用 | 是 | 否 |
  | 组 4 无话题混淆 | 是 | 否 |
  | 组 3 prompt token | < 上下文窗口的 20% | ≥ 20% |

- **结论分支:**
  - **全部可接受** → 在 `123-DECISION.md` 写明「回灌方案验证通过」，附四组数据，进入 Phase 124。
  - **任一项需评审** → 在 `123-DECISION.md` 写明失败项与数据，**停止推进**，把备选方案（引擎常驻：app 关闭时不杀引擎，改由托盘/服务托管）的影响面列出，交业主决策。**不得自行改方案继续。**

- **verify:** `123-DECISION.md` 存在，含四组实测数据与明确结论
- **acceptance_criteria:**
  - 决策文档中**不含任何 API key 明文**
  - 结论是「通过」或「触发评审」二选一，不含模糊表述
