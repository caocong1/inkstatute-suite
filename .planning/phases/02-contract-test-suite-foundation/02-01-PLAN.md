<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Repo fixture JSON -> validation helper | Local JSON data is parsed and validated as untrusted contract input. |
| Platform schema files -> contract-test-suite | The test suite consumes schema files from another package and must not rewrite them. |
| Test runner process -> filesystem | Tests read repo-local files only and must not access secrets, runtime databases, logs, or customer documents. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01-T | Tampering | `schema_validation.py` schema/fixture loading | mitigate | Resolve schema and fixture paths from repo-local constants and read only `packages/platform-contract` plus package-local fixtures. |
| T-02-01-I | Information Disclosure | Fixture validation error messages | mitigate | Error messages include fixture id, event name, and field path only; tests use synthetic fixture data and raw payload refs. |
| T-02-01-D | Denial of Service | Recursive `$ref`/`oneOf` validation | accept | Phase 1 schemas are small, local, and fixed; no network or user-uploaded schema source is introduced in this phase. |
| T-02-01-SC | Tampering | npm/pip/cargo installs | mitigate | No package-manager install task is planned; `pyproject.toml` must keep `dependencies = []`. |
</threat_model>
