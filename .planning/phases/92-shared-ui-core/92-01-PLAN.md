# Plan 92-01: Wave 1 Tracer — ui-core scaffold, theme system, event reducer, ChatPanel with SSE consumer, fixture-driven rendering test

## Goal

Create the `packages/ui-core` package scaffold and prove the end-to-end vertical slice: theme tokens → ChatPanel → event reducer → fixture event stream → rendering test. This is the minimal tracer that proves the shared UI core can build, the 墨律 three-theme system works, the event reducer correctly processes all 13 unified event types from fixture data, and the ChatPanel renders streaming messages from the event stream — all without any `@tauri-apps/*` dependency.

The tracer establishes the foundational patterns for the entire phase: (1) the event reducer as a pure function `(state, RunEventEnvelope) → state` that maps 13 unified event types to UI state transitions, (2) the `EventStreamStore` that wraps `PlatformApiClient.streamRun()` with SolidJS signals and Last-Event-ID reconnection, (3) the adapter pattern for platform-specific operations, and (4) the Vite library mode build configuration with `vite-plugin-solid` and the `solid-markdown` debug shim. Once this slice is green, Plans 92-02 through 92-04 expand by porting the remaining 16 components, adapter interfaces, SDK expansion, and deprecation.

This plan also registers the `ui-core` gate in `scripts/run_v2_gates.py` — per AGENTS.md, every new `packages/*/src` directory must be covered by a gate, and the `gate-coverage` meta-test enforces this. The gate is registered early (Task 01-01) so the CI safety net is in place before any component code lands.

## Reversibility Gate

**One-way-door: Creating `packages/ui-core` and registering its gate.** Once the gate is registered in `scripts/run_v2_gates.py`, the `gate-coverage` meta-test will fail if the gate is removed, and the package becomes a permanent CI requirement. Strategy: the gate addition is purely additive — no existing gate entry is modified. The gate runs TypeScript typecheck + vitest, both of which are standard for a TS package. Task 01-01 is a checkpoint to verify the package scaffolds, compiles, and the gate registration is additive before building components on top.

**One-way-door: Event reducer as the single rendering state machine.** Once the reducer is the sole source of UI state, all components must consume it — there is no parallel state path. Strategy: the reducer is a pure function with fixture-driven tests, making it independently verifiable. Components receive state via props or context, not by subscribing to event sources directly. This prevents the fragmented state management that plagues `lawyer-desktop`'s 1,591-line `conversation.ts`.

**One-way-door: Adapter pattern for platform-specific operations.** Once `@tauri-apps/*` imports are banned from ui-core, any component needing file dialogs, drag-drop, or app info must go through an adapter interface. Strategy: adapter interfaces are defined in this plan (Task 01-05) but implementations are injected by consumers (apps/web, apps/desktop). The interfaces are minimal and well-typed, making the contract explicit.
