# Plan 92-03: Wave 2 — Port document preview & citation panel: DocPreview, CitationPanel, legal types, renderSegs

## Goal

Port the document preview and citation panel — the two most complex UI components that consume `artifact.created` and `citation.recorded` events. These components display the generated legal document (structured or markdown) with edit mode, version pill, citation tags, risk warnings, and docx export, plus the slide-in citation panel with verification badges and tier labels.

This plan also ports the supporting legal types (`types/legal.ts` — 131 lines), utility functions (`renderSegs.tsx`, `legalDocument.ts`, `citationAudit.ts`, `chatTime.ts`), and updates the `DocumentParser` adapter interface to use the proper `LegalDocumentModel` type (replacing the `unknown` placeholder from Plan 92-01).

The DocPreview is the most complex component (323 lines) with two rendering modes (structured document and markdown), edit mode with `contentEditable`, version comparison, and docx export via `FileAdapter.save()`. The CitationPanel is pure presentational (105 lines) driven by `citation.recorded` events.

## Reversibility Gate

**One-way-door: DocumentParser adapter.** Once DocPreview depends on the `DocumentParser` interface instead of the Tauri `parseLegalDocument` invoke, the parsing logic is decoupled from the component. Strategy: the interface is minimal (`parseLegalDocument(rawJson: string): Promise<LegalDocumentModel>`) and both web and desktop implementations call the Gateway. The component is parser-agnostic — it receives parsed data via the adapter.

**One-way-door: Legal types as the document model.** The `LegalDocumentModel` and related types (`Article`, `CitationCard`, `DocMeta`, `TextSegment`) become the canonical document representation in ui-core. Strategy: these types are ported verbatim from `lawyer-desktop/src/types/legal.ts` (131 lines) — they already mirror the backend Rust types and are stable.
