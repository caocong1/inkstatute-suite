# Milestone Audit: v1.4 Long-Term Memory Productization

**Audited:** 2026-07-03
**Status:** gaps_found
**Scores:** 18/20 requirements · 6/6 phases · 8/10 integration points · 1/2 flows

## Summary

All 6 phases (26-31) passed their individual VERIFICATION.md checks and the core memory architecture is sound — the `Memory` Protocol, `HindsightMemory` adapter, `FakeMemory` test double, retention/focus policies, `RetryableMemory` wrapper, and WeCom session runtime integration are all implemented and tested. The V2 gate suite (416 tests across 8 gates) passes after fixing a pre-existing PYTHONPATH regression from v1.2.

However, the integration check found **2 partial requirements** where the infrastructure exists but production wiring is missing:

1. **MEM-07 (singleton initialization):** The memory layer is injectable but no deployment entrypoint constructs a singleton `HindsightMemory` and wires it into `WeComSessionRuntime`. The `ingress_runtime.py` instantiates the runtime without a `memory` parameter.

2. **MEM-16 (contract event observability):** `MemoryOperationEvent` and `MemoryObserver` are defined and `RetryableMemory` emits events, but no production observer is wired in the WeCom service. Events are only captured in tests.

## V2 Gate Regression — Fixed

During the audit, the V2 gate suite (`scripts/run_v2_gates.py`) was found broken since v1.2:

- **wecom-service gate:** Missing `platform_runtime_src` (ingress_runtime imports `platform_runtime` since v1.2)
- **conversation-read-view gate:** Missing `platform_src` and `platform_runtime_src` (feedback memory_wiring imports both since v1.3)
- **feedback-service gate:** Missing `platform_src` and `platform_runtime_src` (same memory_wiring imports)
- **compileall gate:** Missing `packages/platform-runtime/src`

**Fix applied:** Commit `f11af01` — all 8 gates now pass (416 tests total).

## Recommendations

1. **MEM-07 closure:** Add a deployment entrypoint or factory that constructs a singleton `HindsightMemory` from environment configuration and injects it into `WeComSessionRuntime` via `WeComRuntimeIngress`. Document the singleton pattern in `docs/deployment/hindsight.md`.

2. **MEM-16 closure:** Implement a `ContractLogMemoryObserver` that writes `MemoryOperationEvent` to the contract log, and wire it to `RetryableMemory` in the WeCom session runtime initialization.

3. **REQUIREMENTS.md update:** Update the traceability table to reflect actual completion status (18 satisfied, 2 partial).

4. **STATE.md update:** Fix plan counts and mark milestone status accurately.
